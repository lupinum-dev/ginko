# Ginko 1.0: proposal (11.10.2026)

Status: accepted, the scope of 1.0. It widens the original target picture from "restaurant first, minimal" to "complete for any content website". The architecture (G1–G7: one manifest, one read path through the bundle, one write path through operations, a shared platform, pure cores) stays. The scope grows.

Research behind it (internal notes: search, Nuxt 5 + SEO + ISR, editor + collaboration, comark + data files, assets + approval). The research was stopped early to save usage; points marked "unconfirmed" there are still open.

## Six rules that keep 1.0 elegant

1. **One text format: Markdown (comark syntax).** The same string is stored in a Git file, in the platform, in the editor, in agent tools and in `.md` routes. AST v1 retires. Field profiles (`inline`, `basic`, `rich`, `page`) limit what a field allows. This is the original Zielbild decision (K2, chapter 7, "Portable Text / JSON statt MDC" rejected); AST v1 was a shortcut.
2. **The bundle carries everything derived.** One pure core function builds it from Git files or from platform tables: entries with `url` and `alternates`, assets with usage, the link graph, redirects, navigation, search shards, sitemap data. Static, ISR, serverless and platform sites read the same artifacts.
3. **One component registry.** `defineComponent(tag, { props, slots, kind, editor, describe })`, where props are Ginko fields. Renderer, editor (insert menu, prop form), validation, agents and docs read the same definition.
4. **One asset registry.** Content-addressed (SHA-256), with dimensions, focus point, alt text and usage. Images in Markdown and in fields register themselves. Sitemap images, OG fallback, `<GinkoImage>` sizes and the Finder in the Studio all read it.
5. **Headless cores, shadcn-vue UI.** Logic ships as npm packages. Styled UI (editor toolbar, menus, docs components) also ships as a shadcn-vue registry, so an app owns and themes the code. Components use shadcn token names (`--background`, `--primary`, `--border`, `--radius`) with Ginko defaults.
6. **Nuxt 4.6 to 5 in one release.** Server code uses `nuxt/server` (Nuxt ≥ 4.6), handlers can be registered per Nitro version, CI runs a 4.6 and a 5 (nightly until release) matrix.

## Features per package

### ginko-content (and core)

- **Data files.** YAML and JSON: one file = one entry. CSV: one file = many entries (collections only). Values are coerced from the field schema; errors carry file and line. Parser: js-yaml (already used for frontmatter, about 10× faster than `yaml` in our measurement) and a small own CSV parser (ported from the old repo). Drafts (`draft: true`) stay out of production builds.
- **Query engine on the server.** `where`, `order`, `limit`, pagination with totals, field selection, `include` for references, previous/next, facet counts. Only results go into the page payload, not the whole collection.
- **Entries know their URL.** `entry.url` and `entry.alternates` (replaces `pathOf` in v7); URL clashes fail the build (review F1).
- **References.** `f.ref('authors')`, resolved in the bundle; reverse references derived.
- **Navigation.** Trees from folders, order and `parent` refs; breadcrumbs.
- **Markdown features.** comark 0.7 (upgrade from 0.6.2) gives footnotes, emoji, math, mermaid, summary, alerts, Shiki highlighting and TOC; Ginko adds route links (`$blog.my-post`), reusable snippets (a ref to a `snippets` brick, rendered inline), heading anchors with umlauts, and the code copy button.
- **Link check** (core, on the bundle, before HTML exists). Internal links, anchors, assets, references, links that hit a redirect, optional external links (cached, rate-limited). Config `links: { broken: 'error', anchors: 'warn', redirected: 'warn', external: 'off' }`. Shown in build, dev terminal, CLI, Studio editor (blocks publish on `error`) and MCP.
- **Redirects.** Three inputs, one table in the bundle: automatic when a slug changes on the platform, `redirectFrom` in Git frontmatter, patterns in `defineSite`. Git builds emit route rules; platform content uses one Nitro middleware. Always an explicit 301 (Nitro's default is 307).
- **SEO** (owned, data from the bundle). Head (title template, description, canonical, OG/Twitter), `<html lang dir>`, hreflang with `x-default`, sitemap with lastmod, images and alternates, robots.txt (preview and staging hosts get `noindex` automatically), JSON-LD mapped per brick (WebSite, Organization, BreadcrumbList, Article, FAQPage; presets add Restaurant, Menu, Event). OG images: optional integration of `nuxt-og-image`, fallback to the entry's first image.
- **Images register themselves.** Co-located images (`./cover.jpg`) and field images get hash, size and dimensions at build time; `<GinkoImage>` renders width, height, srcset and focus point.
- **Search.** The index is a bundle artifact, built in pure JS (works in a Git build and in a Convex action), sharded per locale, one record per heading section with its anchor, loaded lazily by the client. Static, ISR and serverless sites need no server for search. Engine behind a small `buildIndex`/`search` interface: MiniSearch now (mature, smallest index); ZBSearch static (Orama successor, typo tolerance, sharded) after a spike (German stemming, Convex, 1,000/5,000 docs). Pagefind is out: native indexer, no Convex.
- **Render modes.** Git-only sites prerender everything by default (routes from the bundle, incl. `.md`, llms, sitemap, search shards). Platform sites use ISR with on-demand revalidation from the publish hook. Preview is SSR with `noindex`.
- **Agent output.** `/llms.txt`, `/llms-full.txt`, a `.md` route per page, `Link` headers, `Accept: text/markdown`, a Markdown 404 with suggestions.

### ginko-i18n

- Supported Nuxt range `^4.6.0 || ^5.0.0` (Nuxt 5 is not released yet; roadmap says Q4 2026); move to `nuxt/server` and `addNitroPlugin`.
- Port the browser attack suites (1,400+ checks) and the decision log D1–D14 into the monorepo, rewritten as plain docs.
- One locale owner (review F3/F4): core `Locale` becomes ginko-i18n's `Locale`; the Ginko module passes the full config (strategy included).
- Language switcher that uses entry alternates (translated slugs), formatters for ranges and relative time, plurals.

### ginko-components and ginko-docs

- All old components back as their own package: callout (6 types), tabs, code-group, code-tree, steps, cards, accordion, files, figure with zoom, video and embed (click-to-load for privacy), kbd, badge, columns, timeline, flow, quiz, API blocks, inline TOC; each with props as Ginko fields.
- Docs shell: nested navigation with icons and badges, section tabs, breadcrumbs, TOC with scroll spy and mobile TOC, previous/next, "edit this page" (GitHub for Git, Studio for platform), last updated, dark-mode toggle, theme presets, banner, footer, ⌘K search with heading results, blog with authors and RSS, changelog, copy page as Markdown, "open in ChatGPT/Claude", read-only MCP for docs, OG images, JSON-LD TechArticle.

### ginko-editor

- **Engine:** TipTap 3 (MIT, Vue 3). Markdown in and out through comark (not `@tiptap/markdown`: no component syntax, many open issues). Bridge `comark-tiptap` if it passes the old editor's round-trip corpus, otherwise vendor Nuxt Studio's converters (MIT). A round-trip guard refuses any save that would change Markdown the user did not touch; unknown syntax stays as a raw node.
- **Features:** headings, marks, lists and task lists, quote, divider, code blocks, GFM tables, images and figures from the asset library, embeds, registry components with prop forms and nested editable slots, slash menu, bubble menu, drag handle, Markdown shortcuts and paste, HTML paste cleaned to the field profile, source mode, find and replace, counter with limits, placeholder, read-only, de/en UI, keyboard and screen-reader support, mobile keyboard bar.
- **Real-time co-editing:** OT steps on Convex with `@convex-dev/prosemirror-sync` 0.2.7 on the server and a Vue port of its client (about 500 lines); presence, policy fences and validation from the old editor. One room per entry and locale; snapshot to Markdown after 1–2 s of rest; agents edit as steps; publishing binds a version. Before release: two-person test and load test (Zielbild chapter 7). Yjs only if offline-first becomes a requirement.
- **Forms:** all field types, conditional fields, groups and tabs, reference picker, asset picker (the Finder in picker mode), side-by-side translation, "Anna is editing price" on scalar fields.

### ginko-server and ginko-studio

- **Asset library (Finder).** Sidebar: All, Recent, Unused, Missing alt text, Duplicates, folders, and "Used in: <entry>". Views: icons, list, columns. Space bar = quick look. Info panel: preview, size, type, focus point, alt suggestion, "Used in" (entry, field, locale, with links). Drag and drop to upload and move, multi-select, rename, replace file (references stay, old file kept 30 days), delete only when unused, otherwise trash. Built on what exists: `uploads` gets `folder`, `kept`, `sha256`, `focus`; `fileRefs` is the usage index, written in the same transaction as every save, with a `files.rebuildRefs` check. The 7-day sweep of unreferenced uploads must skip library files.
- **Approval and publishing** (off by default, so a solo owner sees nothing new): one `proposals` table for "a change that needs a yes" (save, publish, unpublish; before/after, base revision, note, optional time, optional release). Applying a proposal runs the normal save/publish, so there is no second write path. Policy is a flag on a task (`needsApproval`) and on an agent key (`review`). Approvers see "Zu prüfen (n)" with the diff and three actions: approve, approve with a time, reject with a sentence. Nobody approves their own proposal. Stale proposals (field changed since) are blocked. Releases group proposals and go live together at a time, as one refresh. Version history: diff from the stored before/after, "back to the version of …" as a new save. Mail per open batch.
- **Studio basics:** ⌘K search, saved list views, duplicate entry, trash with restore, translation status per variant, "refresh site now" button, "why is this not public" explanation, de/en UI, dark mode.
- **Agents:** full tool catalog derived from operations (search, read, draft, propose, translate, find asset usage, check links), OAuth for Claude and ChatGPT connectors, `SKILL.md`.

### Presets

- **gastro:** hours with exceptions ("closes early"), new hours from a date, seasons and holidays; lunch week with planning and copy week; prices from a date; notices with expiry; lunch PDF for print; JSON-LD Restaurant/Menu/OpeningHours; upkeep reminders. Google Business sync as an add-on.
- **agency:** services, case studies, blog, authors, FAQ, legal pages, team, jobs (lupinum-v7 becomes its first user).

## Not in 1.0 (on purpose)

Visual drag-and-drop page layout (block components cover page building), editing Git content from the Studio through GitHub commits, versioned docs (v1/v2 side by side), offline-first editing, built-in machine translation (agents translate), forms backend, newsletter, e-commerce, A/B tests, analytics (integrate Plausible or Umami), image editing beyond focus point, official self-hosting of the platform.
