---
title: Pagination
description: Read one page of a list, or every entry with for await. Cursors, page sizes and filters.
---

Lists such as monitors, incidents and checks can be long, so the API returns them in pages. Each `list()` method gives you a `PageRequest`: await it for one page, or loop over it to read every entry.

## Every entry: for await

```ts
for await (const incident of orbit.incidents.list({ status: 'open' })) {
  console.log(incident.id, incident.cause)
}
```

The client asks for the next page only when the loop needs it. Leave the loop with `break` and no further page is loaded.

## One page

```ts
const page = await orbit.monitors.list({ limit: 50 })

page.data        // Monitor[], at most 50
page.hasMore     // true when there is a next page
page.nextCursor  // string to pass as `cursor`, or null on the last page
```

To show a list with a “Next” button, keep `nextCursor` and pass it with the next request:

```ts
const next = await orbit.monitors.list({ limit: 50, cursor: page.nextCursor })
```

## Page size

`limit` is 20 by default and at most 100. A larger page means fewer requests, which helps with the rate limit of 600 requests per minute.

## Order and filters

Every list is ordered newest first by its creation date. Filters go next to `limit` and `cursor`, for example `status` for monitors and incidents, or `monitorId` and `since` for checks. Keep the same filters for every page of one list: a cursor belongs to the filters it was made with. The parameters of each list are in the reference: [Monitors]($docs.monitors), [Incidents and checks]($docs.incidents-and-checks).

::callout{type="note" title="Cursors expire"}
A cursor works for 24 hours. After that, the request fails with `invalid_cursor` (HTTP 400); start the list again without a cursor.
::
