## Einrichten

:::steps
### Paket installieren

::code-group
```bash [npm]
npm install @orbit-example/sdk
```
```bash [pnpm]
pnpm add @orbit-example/sdk
```
::

### API-Schlüssel setzen

Lege im Orbit-Dashboard unter **Settings > API keys** einen Schlüssel an und trage ihn in die Umgebung deines Servers ein. Zum lokalen Arbeiten reicht eine `.env`-Datei; halte sie aus Git heraus.

```bash [.env]
ORBIT_API_KEY=orb_test_4f9a2c7e1b
```

Ein Schlüssel, der mit `orb_test_` beginnt, wirkt nur auf Testdaten. So kannst du alles ausprobieren, ohne echte Monitore anzulegen.

### Erste Anfrage senden

```ts [check-shop.ts]
import { Orbit } from '@orbit-example/sdk'

const orbit = new Orbit({ apiKey: process.env.ORBIT_API_KEY })

const monitor = await orbit.monitors.create({
  name: 'Shop-Kasse',
  url: 'https://shop.example.com/checkout',
})

console.log(monitor.id, monitor.status) // mon_8f2k1x pending
```

Starte es mit `node --env-file=.env check-shop.ts`. Node.js 22.18 und neuer führen TypeScript-Dateien direkt aus.
:::

## Was passiert ist

1. `new Orbit()` legt einen Client an. Er hält deinen Schlüssel, die Adresse der API und die Einstellungen für Wiederholungen; leg ihn einmal an und nutze ihn überall. Alle Optionen stehen unter [Client-Optionen]($docs.client).
2. `orbit.monitors.create()` sendet eine Anfrage an die API und gibt den neuen Monitor zurück. Orbit prüft die Adresse einmal pro Minute aus der Region `eu-central`, bis du das änderst.
3. Der Status ist `pending`, bis die erste Prüfung gelaufen ist, meist innerhalb einer Minute. Danach ist er `up` oder `down`.

## Wie es weitergeht

- Das Ergebnis jeder Prüfung und jeden Vorfall lesen: [Vorfälle und Prüfungen]($docs.incidents-and-checks).
- Eine Nachricht bekommen, wenn der Shop ausfällt: [Webhooks]($docs.webhooks).
- Eine fehlgeschlagene Anfrage behandeln: [Fehler und Wiederholungen]($docs.errors-and-retries).
