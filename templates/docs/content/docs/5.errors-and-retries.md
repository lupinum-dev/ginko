---
title: Errors and retries
description: What the client retries for you, what reaches your code as an OrbitError, and how to handle each case.
---

A request can fail for two kinds of reasons: something temporary, such as a lost connection or a busy server, or something about the request itself, such as a wrong key or an unknown monitor. The client retries the first kind and throws the second.

## What is retried

| Reason | Code | Retried |
|---|---|---|
| No connection, or the connection broke | `connection_failed` | yes |
| No answer within the timeout | `timeout` | yes |
| Too many requests (HTTP 429) | `rate_limited` | yes, after the time the API asks for |
| Server error (HTTP 500, 502, 503, 504) | `server_error` | yes |
| Any other error (HTTP 4xx) | see [Error codes]($docs.error-codes) | no |

By default the client tries a request up to three times in all: the first attempt and two retries, after about 0.5 and 1 second (a little random time is added, so many clients do not retry at the same moment). Change it with `maxRetries`:

```ts
const orbit = new Orbit({ maxRetries: 5 }) // up to 6 attempts
const strict = new Orbit({ maxRetries: 0 }) // never retry
```

Creating something is safe to retry: the client sends an `Idempotency-Key` header with every `create()`, so the API makes one monitor even when a retry follows an answer that got lost.

## Handle an error

Every error the client throws is an `OrbitError`. Its `code` says what happened; `status` is the HTTP status, or `null` when there was no answer.

```ts
import { Orbit, OrbitError } from '@orbit-example/sdk'

try {
  await orbit.monitors.pause('mon_8f2k1x')
} catch (error) {
  if (!(error instanceof OrbitError)) throw error
  if (error.code === 'not_found') {
    console.warn('That monitor was deleted.')
  } else {
    console.error(error.code, error.message, error.requestId)
    throw error
  }
}
```

`requestId` names the request in Orbit’s logs. Include it when you write to Orbit support.

## Validation errors

When the API refuses the values you sent, the code is `validation_failed` and `details` lists each field:

```ts
error.details // [{ field: 'interval', message: 'Must be 30, 60, 300 or 900.' }]
```

## Timeouts

A request waits 30 seconds for an answer by default. Set `timeout` (in milliseconds) on the client, or for one request:

```ts
const orbit = new Orbit({ timeout: 10_000 })
await orbit.checks.list({ monitorId: 'mon_8f2k1x' }, { timeout: 60_000 })
```

Every code and its HTTP status are listed in [Error codes]($docs.error-codes).
