Listen wie Monitore, Vorfälle und Prüfungen können lang sein, deshalb liefert die API sie in Seiten. Jede `list()`-Methode gibt dir einen `PageRequest`: Wartest du mit `await` darauf, bekommst du eine Seite; gehst du mit einer Schleife darüber, liest du jeden Eintrag.

## Jeder Eintrag: for await

```ts
for await (const incident of orbit.incidents.list({ status: 'open' })) {
  console.log(incident.id, incident.cause)
}
```

Der Client holt die nächste Seite erst, wenn die Schleife sie braucht. Verlässt du die Schleife mit `break`, lädt er keine weitere Seite.

## Eine Seite

```ts
const page = await orbit.monitors.list({ limit: 50 })

page.data        // Monitor[], höchstens 50
page.hasMore     // true, wenn es eine nächste Seite gibt
page.nextCursor  // String für `cursor`, oder null auf der letzten Seite
```

Für eine Liste mit „Weiter“-Knopf merkst du dir `nextCursor` und gibst ihn bei der nächsten Anfrage mit:

```ts
const next = await orbit.monitors.list({ limit: 50, cursor: page.nextCursor })
```

## Seitengröße

`limit` ist standardmäßig 20 und höchstens 100. Größere Seiten bedeuten weniger Anfragen, und das hilft beim Ratenlimit von 600 Anfragen pro Minute.

## Reihenfolge und Filter

Jede Liste ist nach dem Anlagedatum sortiert, die neuesten zuerst. Filter stehen neben `limit` und `cursor`, zum Beispiel `status` bei Monitoren und Vorfällen oder `monitorId` und `since` bei Prüfungen. Behalte für alle Seiten einer Liste dieselben Filter: Ein Cursor gehört zu den Filtern, mit denen er entstanden ist. Die Parameter jeder Liste stehen in der Referenz: [Monitore]($docs.monitors), [Vorfälle und Prüfungen]($docs.incidents-and-checks).

::callout{type="note" title="Cursor laufen ab"}
Ein Cursor gilt 24 Stunden. Danach scheitert die Anfrage mit `invalid_cursor` (HTTP 400); beginne die Liste dann ohne Cursor neu.
::
