slug: fehlercodes
description: Jeder Code von OrbitError, sein HTTP-Status, ob der Client ihn wiederholt und was zu tun ist.
---

Jeder Fehler, den der Client wirft, ist ein `OrbitError` mit diesen Eigenschaften:

| Eigenschaft | Typ | Was sie ist |
|---|---|---|
| `code` | `string` | Einer der Codes unten. |
| `status` | `number \| null` | Der HTTP-Status, oder `null`, wenn keine Antwort kam. |
| `message` | `string` | Ein Satz auf Englisch, der sagt, was schiefging. |
| `requestId` | `string \| null` | Die id der Anfrage in den Protokollen von Orbit, für den Support. |
| `details` | `{ field: string; message: string }[]` | Die ungültigen Felder, nur bei `validation_failed`; sonst leer. |
| `retryAfter` | `number \| null` | Sekunden bis zum nächsten Versuch, nur bei `rate_limited`. |

## Codes

| Code | HTTP | Wiederholt | Bedeutung und was zu tun ist |
|---|---|---|---|
| `missing_api_key` | – | nein | Kein Schlüssel übergeben und `ORBIT_API_KEY` nicht gesetzt. Setze ihn. |
| `invalid_request` | 400 | nein | Die Anfrage ist fehlerhaft. Prüfe die Parameter der Methode. |
| `invalid_cursor` | 400 | nein | Der Cursor ist älter als 24 Stunden oder gehört zu anderen Filtern. Beginne die Liste neu. |
| `unauthorized` | 401 | nein | Der Schlüssel ist falsch oder wurde gelöscht. |
| `forbidden` | 403 | nein | Der Schlüssel darf das nicht, zum Beispiel ein Testschlüssel auf echten Daten. |
| `not_found` | 404 | nein | Kein Monitor, Vorfall oder keine Prüfung mit dieser id. |
| `conflict` | 409 | nein | Die Anfrage passt nicht zum aktuellen Stand, zum Beispiel ein zweiter Monitor für dieselbe Adresse. |
| `validation_failed` | 422 | nein | Ein Wert ist nicht erlaubt. `details` nennt jedes Feld. |
| `rate_limited` | 429 | ja | Mehr als 600 Anfragen in einer Minute. Der Client wartet `retryAfter` Sekunden. |
| `server_error` | 500–504 | ja | Ein Problem bei Orbit. Hält es an, sieh auf der Statusseite nach. |
| `timeout` | – | ja | Keine Antwort innerhalb von `timeout`. |
| `connection_failed` | – | ja | Keine Verbindung zur API, zum Beispiel ein DNS- oder Netzwerkfehler. |
| `invalid_signature` | – | nein | `webhooks.verify()`: Die Signatur passt nicht, oder der Webhook ist älter als fünf Minuten. |

„Wiederholt“ heißt: Der Client sendet die Anfrage selbst erneut, bis zu `maxRetries`-mal, bevor er wirft. Siehe [Fehler und Wiederholungen]($docs.errors-and-retries).
