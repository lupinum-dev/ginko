Jede Anfrage an die Orbit API trägt einen API-Schlüssel. Der Client sendet ihn im `Authorization`-Header; du übergibst ihn nur einmal.

## Schlüssel anlegen

Öffne im Orbit-Dashboard **Settings > API keys** und wähle **Create key**. Orbit zeigt den Schlüssel genau einmal. Kopiere ihn in die Umgebung deines Servers oder in deinen Geheimnisspeicher.

Es gibt zwei Arten von Schlüsseln:

| Präfix | Wirkt auf | Nutze ihn für |
|---|---|---|
| `orb_live_` | deine echten Monitore und Vorfälle | den Betrieb |
| `orb_test_` | eigene Testdaten | Entwicklung, CI, Ausprobieren |

Testmonitore werden wie echte geprüft, ihre Prüfungen und Vorfälle bleiben aber in den Testdaten. Webhooks für Testdaten verschickt Orbit wie echte.

## Schlüssel an den Client geben

Übergibst du keinen Schlüssel, liest der Client `ORBIT_API_KEY` aus der Umgebung:

```ts
import { Orbit } from '@orbit-example/sdk'

const orbit = new Orbit() // liest process.env.ORBIT_API_KEY
```

Übergib `apiKey`, wenn der Schlüssel von woanders kommt, etwa aus einem Geheimnisspeicher:

```ts
const orbit = new Orbit({ apiKey: await secrets.get('orbit-api-key') })
```

Ohne Schlüssel wirft `new Orbit()` sofort einen `OrbitError` mit dem Code `missing_api_key`, nicht erst bei der ersten Anfrage.

## Schlüssel geheim halten

- Nutze den Schlüssel nur in Servercode. In einer Nuxt- oder Next.js-App heißt das: in einer Server-Route oder einem Modul nur für den Server, nie in einer Komponente.
- Halte ihn aus Git heraus: Trag `.env` in `.gitignore` ein.
- Gib jeder App einen eigenen Schlüssel. Dann kannst du einen austauschen, ohne die anderen anzufassen.

::callout{type="warning" title="Ein Schlüssel im Browser ist öffentlich"}
Alles, was der Browser lädt, kann jeder lesen. Ist ein Schlüssel in Client-Code oder in einem öffentlichen Repository gelandet, lösch ihn sofort im Dashboard und leg einen neuen an.
::

## Schlüssel ohne Ausfall austauschen

1. Leg im Dashboard einen zweiten Schlüssel an. Beide Schlüssel gelten gleichzeitig.
2. Veröffentliche deine App mit dem neuen Schlüssel.
3. Lösch den alten Schlüssel. Anfragen damit scheitern jetzt mit `unauthorized` (HTTP 401).
