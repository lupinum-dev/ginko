title: Authentication
description: Create an API key, give it to the client, keep it secret and replace it without downtime.

Every request to the Orbit API carries an API key. The client sends it in the `Authorization` header; you only pass it once.

## Create a key

In the Orbit dashboard, open **Settings > API keys** and choose **Create key**. Orbit shows the key once. Copy it into the environment of your server or into your secret store.

There are two kinds of keys:

| Prefix | Works on | Use it for |
|---|---|---|
| `orb_live_` | your real monitors and incidents | production |
| `orb_test_` | a separate set of test data | development, CI, trying things out |

Test monitors are checked like real ones, but their checks and incidents stay in the test data. Webhooks for test data are sent like real ones.

## Give the key to the client

The client reads `ORBIT_API_KEY` from the environment when you pass no key:

```ts
import { Orbit } from '@orbit-example/sdk'

const orbit = new Orbit() // reads process.env.ORBIT_API_KEY
```

Pass `apiKey` when the key comes from somewhere else, for example a secret store:

```ts
const orbit = new Orbit({ apiKey: await secrets.get('orbit-api-key') })
```

Without a key, `new Orbit()` throws an `OrbitError` with the code `missing_api_key` at once, not at the first request.

## Keep the key secret

- Use the key in server code only. In a Nuxt or Next.js app that means a server route or a server-only module, never a component.
- Keep it out of Git: put `.env` in `.gitignore`.
- Give each app its own key, so you can replace one without touching the others.

::callout{type="warning" title="A key in the browser is a public key"}
Anything the browser loads, anyone can read. If a key ended up in client code or in a public repository, delete it in the dashboard at once and create a new one.
::

## Replace a key without downtime

1. Create a second key in the dashboard. Both keys work at the same time.
2. Deploy your app with the new key.
3. Delete the old key. Requests with it now fail with `unauthorized` (HTTP 401).
