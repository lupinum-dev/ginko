Ein Monitor ist eine Adresse, die Orbit in einem festen Abstand prüft. Alle Methoden hängen an `orbit.monitors`.

## Der Typ Monitor

```ts
interface Monitor {
  id: string                 // 'mon_8f2k1x'
  name: string
  url: string
  interval: 30 | 60 | 300 | 900  // Sekunden zwischen zwei Prüfungen
  regions: Region[]          // 'eu-central' | 'us-east' | 'ap-southeast'
  expectedStatus: number     // HTTP-Status, der als erreichbar gilt
  status: MonitorStatus      // 'pending' | 'up' | 'down' | 'paused'
  createdAt: string          // ISO 8601, UTC
  lastCheckedAt: string | null
}
```

## monitors.create()

```ts
create(params: CreateMonitor, options?: RequestOptions): Promise<Monitor>
```

Legt einen Monitor an. Die erste Prüfung läuft innerhalb eines Intervalls.

| Parameter | Typ | Standard | |
|---|---|---|---|
| `name` | `string` | Pflicht | Erscheint im Dashboard und in Webhooks. Höchstens 100 Zeichen. |
| `url` | `string` | Pflicht | Eine `http`- oder `https`-Adresse. |
| `interval` | `30 \| 60 \| 300 \| 900` | `60` | Sekunden zwischen zwei Prüfungen. |
| `regions` | `Region[]` | `['eu-central']` | Von wo Orbit prüft. Bei mehreren Regionen öffnet sich ein Vorfall erst, wenn die meisten scheitern. |
| `expectedStatus` | `number` | `200` | Der HTTP-Status, der als erreichbar gilt. |

Wirft `conflict`, wenn es für dieselbe `url` schon einen Monitor gibt, und `validation_failed` bei einem ungültigen Wert.

## monitors.get()

```ts
get(id: string, options?: RequestOptions): Promise<Monitor>
```

Gibt einen Monitor zurück. Wirft `not_found`, wenn es keinen Monitor mit dieser id gibt.

## monitors.list()

```ts
list(params?: ListMonitors, options?: RequestOptions): PageRequest<Monitor>
```

Gibt die Monitore zurück, die neuesten zuerst. Mit `await` bekommst du eine Seite, mit `for await` alle (siehe [Paginierung]($docs.pagination)).

| Parameter | Typ | Standard | |
|---|---|---|---|
| `status` | `MonitorStatus` | alle | Nur Monitore mit diesem Status. |
| `limit` | `number` | `20` | Einträge pro Seite, 1 bis 100. |
| `cursor` | `string` | – | `nextCursor` der vorigen Seite. |

## monitors.update()

```ts
update(id: string, changes: UpdateMonitor, options?: RequestOptions): Promise<Monitor>
```

Ändert `name`, `url`, `interval`, `regions` oder `expectedStatus`. Felder, die du weglässt, bleiben, wie sie sind. Gibt den geänderten Monitor zurück.

## monitors.pause()

```ts
pause(id: string, options?: RequestOptions): Promise<Monitor>
```

Hält die Prüfungen an, bis du sie wieder startest, zum Beispiel während einer Wartung. Ein pausierter Monitor eröffnet keinen Vorfall. Einen pausierten Monitor erneut zu pausieren ändert nichts. Neu in 2.1.

## monitors.resume()

```ts
resume(id: string, options?: RequestOptions): Promise<Monitor>
```

Startet die Prüfungen wieder; bis zur nächsten Prüfung ist der Status `pending`. Neu in 2.1.

## monitors.delete()

```ts
delete(id: string, options?: RequestOptions): Promise<void>
```

Löscht den Monitor mit seinen Prüfungen und Vorfällen. Das lässt sich nicht rückgängig machen. Wirft `not_found`, wenn der Monitor schon gelöscht ist.
