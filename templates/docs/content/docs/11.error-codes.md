---
title: Error codes
description: Every code of OrbitError, its HTTP status, whether the client retries it, and what to do.
---

Every error the client throws is an `OrbitError` with these properties:

| Property | Type | What it is |
|---|---|---|
| `code` | `string` | One of the codes below. |
| `status` | `number \| null` | The HTTP status, or `null` when there was no answer. |
| `message` | `string` | A sentence in English that says what went wrong. |
| `requestId` | `string \| null` | The id of the request in Orbit’s logs, for support. |
| `details` | `{ field: string; message: string }[]` | The wrong fields, for `validation_failed` only; else empty. |
| `retryAfter` | `number \| null` | Seconds to wait, for `rate_limited` only. |

## Codes

| Code | HTTP | Retried | Meaning and what to do |
|---|---|---|---|
| `missing_api_key` | – | no | No key was passed and `ORBIT_API_KEY` is not set. Set it. |
| `invalid_request` | 400 | no | The request is malformed. Check the method’s parameters. |
| `invalid_cursor` | 400 | no | The cursor is older than 24 hours or belongs to other filters. Start the list again. |
| `unauthorized` | 401 | no | The key is wrong or was deleted. |
| `forbidden` | 403 | no | The key may not do this, for example a test key on live data. |
| `not_found` | 404 | no | No monitor, incident or check with this id. |
| `conflict` | 409 | no | The request clashes with the current state, for example a second monitor for the same address. |
| `validation_failed` | 422 | no | A value is not allowed. `details` names each field. |
| `rate_limited` | 429 | yes | More than 600 requests in a minute. The client waits `retryAfter` seconds. |
| `server_error` | 500–504 | yes | A problem on Orbit’s side. If it lasts, check the status page. |
| `timeout` | – | yes | No answer within `timeout`. |
| `connection_failed` | – | yes | No connection to the API, for example a DNS or network failure. |
| `invalid_signature` | – | no | `webhooks.verify()`: the signature does not match or the webhook is older than five minutes. |

“Retried” means the client sends the request again by itself, up to `maxRetries` times, before it throws. See [Errors and retries]($docs.errors-and-retries).
