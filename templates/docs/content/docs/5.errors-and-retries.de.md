Eine Anfrage kann aus zwei Arten von Gründen scheitern: an etwas Vorübergehendem, etwa einer abgebrochenen Verbindung oder einem ausgelasteten Server, oder an der Anfrage selbst, etwa einem falschen Schlüssel oder einem unbekannten Monitor. Die erste Art wiederholt der Client, die zweite wirft er.

## Was wiederholt wird

| Grund | Code | Wiederholt |
|---|---|---|
| Keine Verbindung, oder sie ist abgebrochen | `connection_failed` | ja |
| Keine Antwort innerhalb der Wartezeit | `timeout` | ja |
| Zu viele Anfragen (HTTP 429) | `rate_limited` | ja, nach der Zeit, die die API nennt |
| Serverfehler (HTTP 500, 502, 503, 504) | `server_error` | ja |
| Jeder andere Fehler (HTTP 4xx) | siehe [Fehlercodes]($docs.error-codes) | nein |

Standardmäßig versucht der Client eine Anfrage bis zu dreimal: den ersten Versuch und zwei Wiederholungen, nach etwa 0,5 und 1 Sekunde (mit etwas Zufall, damit nicht viele Clients im selben Moment wiederholen). Ändern lässt sich das mit `maxRetries`:

```ts
const orbit = new Orbit({ maxRetries: 5 }) // bis zu 6 Versuche
const strict = new Orbit({ maxRetries: 0 }) // nie wiederholen
```

Das Anlegen lässt sich gefahrlos wiederholen: Der Client sendet bei jedem `create()` einen `Idempotency-Key`-Header. So legt die API nur einen Monitor an, auch wenn eine Wiederholung auf eine verlorene Antwort folgt.

## Einen Fehler behandeln

Jeder Fehler, den der Client wirft, ist ein `OrbitError`. Sein `code` sagt, was passiert ist; `status` ist der HTTP-Status oder `null`, wenn keine Antwort kam.

```ts
import { Orbit, OrbitError } from '@orbit-example/sdk'

try {
  await orbit.monitors.pause('mon_8f2k1x')
} catch (error) {
  if (!(error instanceof OrbitError)) throw error
  if (error.code === 'not_found') {
    console.warn('Diesen Monitor gibt es nicht mehr.')
  } else {
    console.error(error.code, error.message, error.requestId)
    throw error
  }
}
```

`requestId` benennt die Anfrage in den Protokollen von Orbit. Gib sie an, wenn du dem Orbit-Support schreibst.

## Ungültige Werte

Lehnt die API die gesendeten Werte ab, ist der Code `validation_failed`, und `details` nennt jedes Feld:

```ts
error.details // [{ field: 'interval', message: 'Must be 30, 60, 300 or 900.' }]
```

Die Meldungen der API sind immer auf Englisch.

## Wartezeit

Eine Anfrage wartet standardmäßig 30 Sekunden auf eine Antwort. Setze `timeout` (in Millisekunden) am Client oder für eine einzelne Anfrage:

```ts
const orbit = new Orbit({ timeout: 10_000 })
await orbit.checks.list({ monitorId: 'mon_8f2k1x' }, { timeout: 60_000 })
```

Alle Codes mit ihrem HTTP-Status stehen unter [Fehlercodes]($docs.error-codes).
