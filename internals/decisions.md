# Decisions

A short, dated log of choices a future maintainer or agent might otherwise undo.
Add one line per decision: `Dn (YYYY-MM-DD): decision — why.` Replace a line
when a decision changes; git keeps the history.

- D1 (2026-10-13): Release with the Lupinum OSS `library-monorepo` workflow (Changesets, npm trusted publishing, protected `npm` environment) — every Lupinum repository shares one release, security and CI setup.
- D2 (2026-10-13): `@lupinum/ginko` declares no peer dependency on `@lupinum/ginko-content` — `ginko-content` depends on `ginko`, and a cycle between published packages stops `scripts/release.mjs` from packing. `ginko` still loads `ginko-content` with a dynamic import and tells users to install it; it is only a devDependency (types, tests) and an unbuild external.
- D3 (2026-10-14): Every published package accepts Nuxt 4.6 and Nuxt 5: `nuxt` peer range and module `compatibility` are both `^4.6.0 || ^5.0.0-0` — a site can upgrade Nuxt without upgrading Ginko, and npm installs Ginko next to a Nuxt 5 prerelease without a peer conflict. Proof: `pnpm check:pack --nuxt5` (CI job `nuxt5`) builds every starter and the docs site from the tarballs on the Nuxt 5 nightly that `packages/ginko-i18n/browser/apps/n5` pins. Move that pin forward when a newer nightly is needed; drop the `-0` when Nuxt 5 is released.
- D4 (2026-10-14): Ginko writes all SEO output itself and needs no Nuxt SEO module; the one module every starter gets is `nuxt-og-image` (Takumi), because drawing images is not Ginko's job. With a Nuxt SEO module installed (listed, or through `@nuxtjs/seo`, and not `enabled: false`), Ginko leaves that output to it and hands it the site's data through Nuxt `moduleDependencies` defaults (order-independent; the site's own config wins) and per-request `site-config:init` hooks (language, preview hosts). `nuxt-ai-ready` is turned off while Ginko serves llms.txt — two producers of the same addresses. Share cards on a server need `NUXT_APP_SECRET` (nuxt-og-image signs their URLs); Ginko does not invent one, because Nuxt's sessions use the same secret: create-ginko writes one into `.env` and the build warns without it. Proof: the `docs-seo` site in `pnpm check:pack` (sites/docs with `@nuxtjs/seo`), on Nuxt 4 and Nuxt 5. Code: packages/ginko/src/nuxt/nuxt-seo.ts.
- D5 (2026-10-15): An entry is a page only in the languages it is translated into: `untranslated` defaults to `'hide'` for collections with a `route` and to `'fallback'` without one (`untranslatedMode`), and only a *missing* required translation counts, never an outdated one, a slug or an image description — German text under an /en URL (with `lang="en"` and hreflang) is wrong, while a typo fix in German must not turn a live English page into a 404. Opt-in `'fallback'` on a routed collection lists the entry with a link to its main-language page and gives it no URL in that language. `urlsFor` gives the page URLs (bundle, sitemap, hreflang, publicness); `routeUrls` gives every locale's address for cache refresh and URL clash checks. Code: packages/ginko/src/core/resolve.ts.
