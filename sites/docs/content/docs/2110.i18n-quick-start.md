`@lupinum/ginko-i18n` is the language module of Ginko. It also works alone, in any Nuxt app. This tutorial adds English and German to a plain Nuxt app. At the end, `/about` and `/de/ueber-uns` are the same page in two languages, with a language switch and the right head tags.

A site that uses Ginko has the module already. There, start with [Add a language]($docs.add-a-language).

## What makes it different

- **The language comes from the address and from nowhere else.** No cookie and no browser setting changes the language of a page. So the HTML from the server, the page in the browser and every cache agree.
- **Translated addresses.** `/about` and `/de/ueber-uns` are one page.
- **Head tags without code.** Every page gets `lang`, a canonical link, `hreflang` links and `og:locale`.
- **ICU messages, compiled at build time.** Plurals, numbers, dates and tags. The message parser never reaches the browser.
- **Typed keys.** A missing key or parameter fails the type check.

It has two address forms: `/about` and `/de/about` (the default), or `/en/about` and `/de/about`. It has no domains per language and no language without a prefix. If you need those, use `@nuxtjs/i18n`.

## Before you start

You need a Nuxt app on Nuxt 4.6 or newer and Node.js 22.18 or newer. The app must not have `@nuxtjs/i18n` installed.

## Steps

::steps
#### Install the package

```bash
npm install @lupinum/ginko-i18n
```

#### Add the module

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-i18n'],
  i18n: {
    locales: ['en-GB', 'de-AT'],
    defaultLocale: 'en',
    baseUrl: 'https://example.com',
  },
})
```

`locales` are language tags. The code in the address is the first part of the tag: `en` and `de`. Pages of the default language have no prefix. `baseUrl` makes the links in the head complete addresses.

#### Add one message file per language

The files live in `i18n/`, next to `nuxt.config.ts`. The file name is the code of the language:

```json [i18n/en.json]
{
  "nav": { "home": "Home", "about": "About us" },
  "cart": { "items": "{count, plural, =0 {No items} one {# item} other {# items}}" },
  "legal": { "consent": "I accept the <link>privacy policy</link>." }
}
```

```json [i18n/de.json]
{
  "nav": { "home": "Start", "about": "Über uns" },
  "cart": { "items": "{count, plural, =0 {Keine Artikel} one {# Artikel} other {# Artikel}}" },
  "legal": { "consent": "Ich akzeptiere die <link>Datenschutzerklärung</link>." }
}
```

#### Translate in a page

`useI18n` and `<I18nT>` need no import:

```vue [app/pages/about.vue]
<script setup lang="ts">
definePageMeta({ i18n: { paths: { de: '/ueber-uns' } } })

const { t, localePath } = useI18n()
</script>

<template>
  <main>
    <h1>{{ t('nav.about') }}</h1>
    <p>{{ t('cart.items', { count: 3 }) }}</p>
    <I18nT k="legal.consent">
      <template #link="{ text }">
        <NuxtLink :to="localePath('/privacy')">{{ text }}</NuxtLink>
      </template>
    </I18nT>
  </main>
</template>
```

- `definePageMeta` gives the German page its own address. English keeps `/about`.
- `t` returns a message. `count` picks the plural form.
- `<I18nT>` renders a message with a tag. The slot `link` gets the text between `<link>` and `</link>`.
- `localePath('/privacy')` is the address of a page in the current language.

#### Add a language switch

`alternates` is the current page in every language:

```vue [app/components/LanguageSwitcher.vue]
<script setup lang="ts">
const { alternates } = useI18n()
</script>

<template>
  <nav>
    <NuxtLink
      v-for="a in alternates"
      :key="a.code"
      :to="a.path"
      :hreflang="a.language"
      :aria-current="a.current ? 'page' : undefined"
    >
      {{ a.name }}
    </NuxtLink>
  </nav>
</template>
```

```vue [app/app.vue]
<template>
  <LanguageSwitcher />
  <NuxtPage />
</template>
```
::

## Check that it works

Start the app with `npm run dev`.

| Address | Result |
| --- | --- |
| `/about` | "About us", "3 items", and the sentence with a link to `/privacy` |
| `/de/ueber-uns` | "Über uns", "3 Artikel", and the sentence with a link to `/de/privacy` |
| `/de/about` | 404: the German page has its own address |
| `/about/` | A redirect (301) to `/about` |

The source of `/de/ueber-uns` has these head tags:

```html
<html lang="de-AT" dir="ltr">
<link rel="canonical" href="https://example.com/de/ueber-uns">
<link rel="alternate" hreflang="en-GB" href="https://example.com/about">
<link rel="alternate" hreflang="de-AT" href="https://example.com/de/ueber-uns">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_AT">
```

The switch shows "English" and "Deutsch". Each link leads to the same page in the other language.

## Find missing translations

The package has a command line tool. It lists texts that a language does not have:

```bash
npx ginko-i18n check
```

If `i18n/de.json` has no `legal.consent`, it prints this and ends with exit code 1:

```text
error missing de legal.consent i18n/en.json:4: Missing translation
1 errors, 0 warnings
```

On your computer, the path of the file is longer. A missing text shows in the default language, and the dev server warns. [Translate buttons and labels]($docs.translate-buttons-and-labels) shows the tool step by step, and [i18n reference]($docs.i18n-reference#cli) lists its commands.
