Eine Seite mit Bausteinen auf der Plattform braucht diese Inhalte, während du entwickelst. Diese Anleitung startet `npm run dev` gegen die gehostete Plattform. Am Ende zeigt deine lokale Seite die veröffentlichten Inhalte, und du weißt, was ein Baustein zeigt, den du noch nicht freigegeben hast.

## Schritte

::steps
#### Die Adresse der Plattform in die Konfiguration schreiben

```ts [ginko.config.ts]
export default defineSite({
  site: 'linde',
  platform: 'https://platform.example.com',
  // …
})
```

Mit der Adresse in der Konfiguration läuft `npm run dev` in jedem Klon, ohne `.env`-Datei.

#### Die Seite starten

```bash
npm run dev
```

Die Seiten zeigen die veröffentlichten Inhalte der Plattform. Zum Lesen braucht es keinen Schlüssel.

#### Einen Baustein ergänzen und ansehen

Ergänze einen Baustein in der Konfiguration und lies ihn in einer Seite. Vor seinem Release kennt die Plattform den Baustein nicht. Deine lokale Seite zeigt dies:

| Der neue Teil | Zeigt |
| --- | --- |
| ein neuer Baustein | nichts: Ein Einzelstück hat seine Defaults, eine Sammlung ist leer |
| ein neues Feld mit `default` | den Default |
| ein neues optionales Feld | keinen Wert |

Inhaber können die neuen Teile erst nach dem Release füllen. Lass `npx ginko check` laufen, um zu sehen, ob die Plattform die Änderung annimmt.
::

## Eine andere Plattform für einen Lauf

`NUXT_PUBLIC_GINKO_PLATFORM` ersetzt `platform` aus der Konfiguration, zum Beispiel für einen Blick auf eine Testseite:

```bash
NUXT_PUBLIC_GINKO_PLATFORM=https://test-platform.example.com npm run dev
```

## Wie schnell eine Veröffentlichung ankommt

Eine Seite lädt die Inhalte höchstens alle 60 Sekunden neu. Eine Änderung, die eine Inhaberin veröffentlicht, ist innerhalb einer Minute auf der Live-Seite.

Damit es sofort geht, gibst du der Live-Seite ein Token. Öffne im Studio „Team“, dann „Site token“, und wähle „Create token“. Setz es bei deinem Hoster als `NUXT_GINKO_REVALIDATE_TOKEN`. Dann lädt „Update website now“ im Studio die Seite sofort neu.
