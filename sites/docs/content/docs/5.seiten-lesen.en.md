## useGinko

`useGinko(brick)` reads one brick. It returns a `ComputedRef`. In `<script>` you use `.value`; in the template you do not.

- For a single, it returns `{ data, fallback }`. `data` holds the fields.
- For a collection, it returns `{ items }`. Each item has `id`, `data`, `fallback`, and `urls`.

```vue
<script setup lang="ts">
const menu = useGinko('menu')
const { locale } = useI18n()
</script>

<template>
  <ul>
    <li v-for="item in menu.items" :key="item.id">
      {{ item.data.name }}: {{ formatMoney(item.data.price, locale) }}
    </li>
  </ul>
</template>
```

`useI18n()` comes from ginko-i18n. It returns the current locale as `locale`. `useGinko` and `formatMoney` are imported automatically.

The types come from your `ginko.config.ts`. There, `item.data.price` is an `f.money` field, so it is `{ amount, currency }`. An optional field can be `undefined`.

For a collection, `useGinko` returns only visible entries, in the order of the brick. The rule is in "Bricks", section "Visibility".

When a component gets an entry as a prop, use the type `GinkoItem` with the name of the brick. It is imported automatically:

```vue
<script setup lang="ts">
defineProps<{ dish: GinkoItem<'menu'> }>()
</script>
```

## useGinkoEntry

`useGinkoEntry(brick, slug)` reads one entry of a collection that has a `route`. You pass the slug from the address. The file lives, for example, at `app/pages/veranstaltungen/[slug].vue`:

```vue
<script setup lang="ts">
definePageMeta({ i18n: { paths: { en: '/events/:slug()' } } })
const route = useRoute()
const event = useGinkoEntry('events', String(route.params.slug))
</script>

<template>
  <article>
    <h1>{{ event.data.title }}</h1>
    <GinkoMarkdown :value="event.data.description" />
  </article>
</template>
```

`useGinkoEntry` builds the path from the route of the brick and the slug. Then it looks for the visible entry whose address in the current locale is exactly this path. If it finds none, the site answers with a real **404**. This happens for a wrong slug, for an entry that is not visible, and for the slug of another locale.

## useGinkoToday

`useGinkoToday()` returns today's date as `YYYY-MM-DD`, in the time zone of the site. The value is a `Ref`. On the server, the server's value comes first, so that server and browser render the same day. In the browser, the value moves on after midnight: right after load, every minute, and when the visitor returns to the tab. `useGinko` filters with this value. So expired notices disappear without a reload.

Use `useGinkoToday()` for your own date checks too, for example "open today".

## GinkoMarkdown

`<GinkoMarkdown :value>` shows the value of an `f.markdown` field:

```vue
<GinkoMarkdown :value="legal.data.imprint" class="prose" />
```

The text is stored as Markdown and the bundle delivers it as a tree. No parser runs in the browser and nothing uses `v-html`. An unsafe link (for example `javascript:`) becomes plain text. With `:components` you map tags to your own components. See "Content from files" for more.

## useGinkoSeo

`useGinkoSeo` sets the head of a page: title (with `seo.titleTemplate` of the site), description, canonical, Open Graph and Twitter tags, and JSON-LD. Call it once per page, with a function so the values follow the content:

```ts
const route = useRoute()
const event = useGinkoEntry('events', String(route.params.slug))
useGinkoSeo(() => ({
  title: event.value.data.title,
  image: event.value.data.image?.url,
  type: 'article',
}))
```

| Option | Meaning |
| --- | --- |
| `title`, `description` | Defaults: the site name and `seo.description` |
| `image` | A path under `public/` or an absolute URL. Default: `seo.image` |
| `type` | `'website'` (default) or `'article'` |
| `section` | A small label above the title on a generated share card |
| `noindex` | Keeps the page out of search engines |
| `jsonLd` | Extra JSON-LD objects. [SEO and agents]($docs.seo-und-agenten) has an example. |

**Share cards.** Install `nuxt-og-image` and one renderer (`@takumi-rs/core`), and add `'nuxt-og-image'` to `modules`. Then every page without its own `image` gets a generated card with its title, description and the site name. A page with `image` keeps that image. Without the module, Ginko loads nothing of it.

## formatMoney

`formatMoney(money, locale)` turns a money value into text. The module imports the function automatically.

| Call | Result |
| --- | --- |
| `formatMoney({ amount: 1250, currency: 'EUR' }, 'de')` | `12,50 €` |
| `formatMoney({ amount: 1250, currency: 'EUR' }, 'en')` | `€12.50` |
| `formatMoney({ amount: 1250, currency: 'CHF' }, 'de')` | `12,50 CHF` |

Every space in the result is a no-break space. So the price does not wrap, and server and browser show the same text.

## Fallback and the lang attribute

If a field has no translation in the current locale, the bundle shows the text of the main locale. This also happens when the translation is outdated because the main text changed after it. The list `fallback` names each such field by its path. For a field in a list row, the path is the field, the row `_id`, and the column, for example `days.k3Fd9aZ0qx.dish`.

A screen reader pronounces foreign text wrongly if the site does not mark it. So set `lang` to the main locale when the path is in `fallback`.

Ginko ships `ginkoLangOf(item, path)` for this (auto-imported). It returns the language tag of the main locale, for example `de-AT` from `languages` in `ginko.config.ts`, when the field comes from the fallback, otherwise `undefined`:

```vue
<script setup lang="ts">
const menu = useGinko('menu')
</script>

<template>
  <h3 v-for="item in menu.items" :key="item.id" :lang="ginkoLangOf(item, 'name')">{{ item.data.name }}</h3>
</template>
```

For a list row of a single, give the full path:

```vue
<span :lang="ginkoLangOf(lunch, `days.${day._id}.dish`)">{{ day.dish }}</span>
```

For an image, the path of the alt text is `image.alt` if the field is called `image`. A value of `undefined` leaves the attribute out.

ginko-i18n sets the `lang` attribute on the `<html>` element for you. See "Languages".

## Errors and cache

The site loads the bundle once per request. If that fails (network, server error, wrong format, too many requests), the site answers with **503** and never with 404. On Vercel, a 503 keeps the old, good page in the cache; a 404 would replace it. Only an entry that is confirmed missing returns 404. The module turns on ISR for all pages (`expiration: 60`, and query parameters share one cache entry). Only `/__ginko` and `/__ginko/**` run without cache. A site whose bricks all come from files never asks the platform, so the platform cannot cause a 503.

::callout{type="warning"}
Do not read `useGinko` or any other composable that needs the bundle in `error.vue`. On a 503 there is no bundle, and the error page would fail itself.
::

## API reference

### Auto-imports

The Nuxt module imports these functions in every component, page and composable of your site. `brick` is the key of a brick in `ginko.config.ts`. The types follow from your configuration.

| Function | Returns | Use |
| --- | --- | --- |
| `useGinko(brick)` | `ComputedRef<{ data, fallback }>` for a single, `ComputedRef<{ items }>` for a collection | Read one brick. Collections hold only visible entries. |
| `useGinkoEntry(brick, slug: string)` | `ComputedRef<GinkoItem<brick>>` | The visible entry with this slug in the current locale, else a 404. |
| `useGinkoQuery(brick, query?: MaybeRefOrGetter<Query>)` | `ComputedRef<{ items, total, page, pages, facets? }>` | Filter, sort and page the visible entries. `query` has `where`, `order`, `limit`, `page` (from 1), `fields`, `facets` and `include`. The operators are in [Switching]($docs.umstieg). |
| `useGinkoNeighbors(brick, id: MaybeRefOrGetter<string>, order?: string)` | `ComputedRef<{ prev?, next? }>` | The entries before and after `id`, for "previous" and "next" links. |
| `useGinkoNav(bricks: string[])` | `ComputedRef<NavNode[]>` | A navigation tree of the visible entries of these collections. |
| `useGinkoBreadcrumbs(bricks: string[])` | `ComputedRef<NavNode[]>` | The nodes from the root to the current page. Empty if the page is not in the tree. |
| `useGinkoToday()` | `Ref<string>` | Today as `YYYY-MM-DD` in the time zone of the site. |
| `useGinkoWeek()` | `WeekInfo` | The first day of the week and the weekend days of the site. |
| `useGinkoLocale()` | `ComputedRef<GinkoLocale>` | The current locale. |
| `usePagePath()` | `(key: GinkoPageKey, locale?: GinkoLocale) => string` | A function that gives the path of a page from `pages`, in the current or another locale. |
| `useGinkoSeo(input: MaybeRefOrGetter<GinkoSeoInput>)` | `void` | The head of a page. See [useGinkoSeo](#useginkoseo). |
| `useGinkoMarkdown(value: MaybeRefOrGetter<MarkdownValue \| undefined>)` | `Promise<ComputedRef<MarkdownTree \| null>>` | The tree of a Markdown field, to split or read it in code. Use it with `await`. |
| `fetchGinkoMarkdown(value: MarkdownValue \| undefined)` | `Promise<MarkdownTree \| null>` | The same for server code, for example inside `useAsyncData`. |
| `ginkoLangOf(item, path: string)` | `string \| undefined` | The `lang` value for a field from the fallback. See [Fallback and the lang attribute](#fallback-and-the-lang-attribute). |
| `isGinkoVisible(brick, item: { data })` | `boolean` | The visibility rule of the brick for an entry you got elsewhere. |
| `formatMoney(money: Money, locale: string)` | `string` | A money value as text. See [formatMoney](#formatmoney). |
| `ginkoSafeHref(href: string \| undefined)` | `string \| undefined` | The URL if it is safe for `href` or `src` (`http`, `https`, `mailto`, `tel`), else `undefined`. Use it for links and images from content. |

These types are imported automatically too:

| Type | Meaning |
| --- | --- |
| `GinkoItem<'brick'>` | One entry of a collection, for component props: `defineProps<{ dish: GinkoItem<'menu'> }>()` |
| `GinkoPageKey` | A key of `pages` |
| `GinkoLocale` | A locale of the site |
| `GinkoSeoInput` | The argument of `useGinkoSeo` |

### Components

| Component | Props |
| --- | --- |
| `<GinkoMarkdown>` | `value` (a Markdown field), `components` (your own components by tag). See [GinkoMarkdown](#ginkomarkdown). |
| `<GinkoImage>` | `image` (an image field), `sizes` (default `100vw` when the image has sizes), `eager` (load at once, for the main image of a page). It writes `srcset`, `width`, `height` and `alt`. |

### @lupinum/ginko

You import these names yourself:

| Name | Use |
| --- | --- |
| `defineSite`, `single`, `collection`, `f` | The configuration. See [Bricks]($docs.bausteine). |
| `formatMoney(money, locale)` | The same function as the auto-import, for code outside Nuxt. |
| `plainText(tree: MarkdownTree)` | The text of a Markdown tree without formatting, for example for a meta description. |
| `weekStartOf(date: string, week: WeekInfo)` | The first day of the week that contains `date`, as `YYYY-MM-DD`. Pass `useGinkoWeek()` as `week`. |

The package also exports the types of the configuration and of the values: `ItemOf`, `DataOf`, `ValueOf`, `BrickValue`, `Money`, `ImageValue`, `FileValue`, `MarkdownValue`, `MarkdownTree`, `MarkdownToc`, `TocLink`, `NavNode`, `Query`, `QueryResult`, `Condition`, `WeekInfo`, `SiteInput`, `Migration`, `MigrationContext`, `UnknownChoice`, `Locale`, `Currency`, `Label`, `Localized`, `Json`, and the types of fields and bricks (`Field`, `Fields`, `TextField`, …, `SingleBrick`, `CollectionBrick`, `Brick`).

`@lupinum/ginko/vue` exports `GinkoMarkdown` for a Vue app without Nuxt. Render it inside `<Suspense>`.

`@lupinum/ginko/search` reads the search index of a site: `loadIndex`, `search` and the types `SearchHit`, `SearchIndex` and `SearchIndexJson`. [SEO and agents]($docs.seo-und-agenten) has an example. The other names there (`buildIndex`, `searchSections`, `SearchRecord`) are for Ginko's own packages.

These entry points are the public API. `@lupinum/ginko/internal` is for Ginko's own packages and can change in any release.
