An address that worked yesterday should work tomorrow: other sites link to it, and search engines know it. This guide moves a page and sends every visitor of the old address to the new one.

## An entry in a file gets a new slug

::steps
#### Rename the entry

Give the file its new name, or change `slug:` in its frontmatter. The address of `content/news/1.opening.md` is `/news/opening`.

#### Name the old address in the entry

```markdown [content/news/1.opening.md]
---
title: We are open
date: 2026-10-12
redirectFrom: /news/first
---
```

For several old addresses, write a list:

```yaml
redirectFrom:
  - /news/first
  - /news/we-open
```

`redirectFrom` goes into the file of the main language.

#### Check the result

Open the old address. The site answers with a redirect to the new one:

```text
HTTP/2 301
location: /news/opening
```
::

On the platform, the owner changes the address of an entry in the Studio. The old address then redirects by itself.

## Any other address

Rules that do not belong to one entry go into the config:

```ts [ginko.config.ts]
export default defineSite({
  // …
  redirects: [
    { from: '/old-about', to: '/about' },
    { from: '/old-news/:slug', to: '/news/:slug' },
    { from: '/old-blog/*', to: '/blog/:splat', status: 302 },
  ],
})
```

- `:name` matches one part of a path. `to` can use it.
- `*` at the end matches the rest. `to` uses it as `:splat`.
- The first rule that matches wins. The status is 301 unless you set another.
- `to` starts with a fixed path. A rule such as `{ from: '/en/*', to: '/:splat' }` is refused, because a visitor could then choose the target.

A wrong rule stops the build.

## Find links to old addresses

After a move, your own texts may still link to the old address. `ginko check` warns about each one:

```text
content/news/opening: Link /old-about leads to /about through a redirect.
```

Set `linkCheck: { redirected: 'error' }` in the config to make it an error. A link written as `$brick.name` never has this problem. [Link between pages]($docs.link-between-pages) explains that form.

## On a static host

A static site has no server. An exact old address still works, through a small page that sends the browser on. A rule with `:name` or `*` does not. [Build a static site]($docs.static-site#redirects-in-a-static-site) has the details.
