This guide builds a site as plain files. At the end, you have a folder that any static host can serve: no server, no function, no database.

It works for a site whose bricks all have `source: 'files'`. A site with bricks on the platform needs a server: see [Deploy to Vercel]($docs.deploy-to-vercel).

## Steps

::steps
#### Build the site

```bash
npx nuxt generate
```

The build ends with `You can now deploy .output/public to any static hosting!` A broken link or a page that fails to render stops it.

The line `Payload extraction is disabled, which is suboptimal for full-static output` is a warning from Nuxt. Ginko turns payload extraction off on purpose. Ignore the line.

#### Look at the output

The folder `.output/public` holds the whole site:

| In the folder | What it is |
| --- | --- |
| `index.html`, `about/index.html`, `de/index.html`, … | every page in every language |
| `news/opening.md`, … | each entry as Markdown, for agents |
| `sitemap.xml`, `robots.txt` | for search engines |
| `llms.txt`, `llms-full.txt` | for AI agents |
| `__ginko/search/` | the search index of each language |
| `404.html` | the error page |

Drafts, entries after their last day and entries dated in the future are not in the output.

#### Try it on your computer

```bash
npx serve .output/public
```

Open the address that the command prints and click through the site.

#### Upload the folder

Upload `.output/public` to your host. Most hosts take the build command `npx nuxt generate` and the folder `.output/public` as settings and build on every push.
::

## Redirects in a static site

A static host has no server that could redirect. Ginko writes a small page for each exact old address. The page sends the browser on:

```html
<meta http-equiv="refresh" content="0; url=/about">
```

This covers `$redirectFrom` in a content file and exact rules in `redirects`. A rule with a pattern, such as `{ from: '/old-news/:slug', to: '/news/:slug' }`, has no page: the old addresses answer 404. If you need pattern rules, set them in the settings of your host, or deploy to Vercel.

## What a static host cannot do

- **Redirects with patterns**, see above.
- **Keep previews out of search engines.** `robots.txt` is written once, for the production address. Use the setting of your host for preview deployments.
- **The docs MCP endpoint** of a docs site (`/__ginko/docs-mcp`).
- **Publish at a time.** An entry dated in the future appears with the first build on or after its date. Build the site every day if you use dates this way.
