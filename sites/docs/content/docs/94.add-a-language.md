This guide adds French to a site that has English and German. At the end, every page has a French address, the language switch shows French, and search engines learn about the French pages.

The steps use the template `starter` (`npm create ginko@latest my-site -- --template starter`). They are the same for every [template]($docs.templates). For a site with its own structure, read the note at the end of step 1.

## Before you start

- The site runs with `npm run dev`.
- Its content comes from files in `content/`. For content on the platform, the first two steps and step 5 are the same, and the owners translate the content in the Studio.

## Steps

:::steps
#### Add the language to the list

Open `app/routes.ts` and add the language code. The first code is the main language. Keep it first.

```ts [app/routes.ts]
export const locales = ['en', 'de', 'fr'] as const
```

The code is also the language tag of the pages, so use a tag such as `fr` or `it`.

Every address of the new language starts with `/fr`. The templates build these addresses from the list, so you change no address by hand.

::callout{type="note" title="A site without the template's routes.ts"}
The list is `locales` in `ginko.config.ts`. Add the code there. Then add a path for the new language to each entry of `pages` and to each `route` of a collection, for example `route: { en: '/news/[slug]', de: '/de/neuigkeiten/[slug]', fr: '/fr/actualites/[slug]' }`.
::

#### Start the dev server again

Stop `npm run dev` and start it again. The dev server restarts by itself when `ginko.config.ts` changes, but not when a file changes that the config imports, and `app/routes.ts` is such a file.

Open `http://localhost:3000/fr`. The site has a French version now, with these gaps:

- The start page shows the English text. A single without a translation shows the text of the main language.
- The pages of a collection are missing: `/fr/about` answers 404. An entry with its own address appears in a language only when it has a translation there.
- Buttons and labels are English. The terminal says how many are missing: `[ginko-i18n] fr: 29 message(s) missing, showing en text instead`.

The next three steps close these gaps.

#### Translate the singles

A translation is a file next to the original, with the language code before the extension. For the start page, create `content/home.fr.md`:

```markdown [content/home.fr.md]
---
title: Des traductions qui se lisent comme l’original
lead: Je traduis entre l’allemand et l’anglais pour des musées et des éditeurs.
---

## Ce que je traduis

- Textes d’exposition et de catalogue
```

A translation holds only the fields that have a value per language: texts, Markdown and the description of an image. Leave out everything else, such as a date, a price or the photo itself. Those values come from the original. [Field types]($docs.field-types#all-types) lists which types are translatable.

#### Translate the entries of each collection

Do the same for each entry that the French site needs. For the About page, create `content/pages/1.about.fr.md`:

```markdown [content/pages/1.about.fr.md]
---
title: À propos
slug: a-propos
summary: Klara Brenner, traductrice depuis 2014.
---

## Qui je suis

Je suis traductrice depuis 2014.
```

`slug` is the last part of the address: this page is at `/fr/a-propos`. Without `slug`, the address uses the file name, here `/fr/about`.

An entry without a French file stays out of the French site. You can translate the important pages first and add the others later.

#### Translate the buttons and labels

These texts live in `i18n/`, one file per language. List what is missing:

```bash
npx ginko-i18n todo --locale fr
```

Each line names a key, the file it belongs in and the English text:

```text
site.nav.open (missing) → i18n/fr.json: Open navigation
```

Create `i18n/fr.json` and add the keys. A dot in a key is one level of nesting:

```json [i18n/fr.json]
{
  "home": { "more": "En savoir plus" },
  "site": {
    "skip": "Aller au contenu",
    "nav": { "open": "Ouvrir la navigation" }
  }
}
```

The dev server reads these files again when you save them. A key without a French text keeps its English text.

#### Check the result

Start the dev server again, so that it reads the new content files. Then run both checks:

```bash
npm run check
npx ginko-i18n check
```

`npm run check` reports a field that a translation must not have, a broken link and a slug that two entries share. `npx ginko-i18n check` lists every text that still has no French version.

In the browser, check three things:

1. `http://localhost:3000/fr` shows the French start page.
2. The language switch on the About page leads to `/fr/a-propos`.
3. The source of the English About page has a line with `hreflang="fr"`. Search engines read the French address from it. The sitemap at `/sitemap.xml` lists the French pages too.
:::

## What you did not need to do

- **No new pages.** Each page file in `app/pages/` serves every language.
- **No change to the language switch.** It reads the languages from the list.
- **No change for search engines.** The `lang` attribute, the `hreflang` links and the sitemap follow the list and the translations.
