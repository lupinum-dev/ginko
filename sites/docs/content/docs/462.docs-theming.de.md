Diese Anleitung gibt einer Doku-Seite dein Aussehen. Am Ende hat die Seite deine Akzentfarbe im hellen und dunklen Modus und eine eigene Zeile unter jeder Seite.

Ändere zuerst Tokens. Ersetze ein Teil erst, wenn die Tokens das Ergebnis nicht hergeben. Alles auf dieser Seite ist öffentlich und bleibt zwischen Releases stabil.

## Bevor du beginnst

Du brauchst eine Seite mit dem Doku-Kit, siehe [Eine Doku-Seite starten]($docs.start-a-docs-site), und eine CSS-Datei, die die Seite lädt. Das Template hat `app/assets/css/main.css`.

## Schritte

::steps
#### Ein Preset wählen

`theme` wählt eines von zwei Farb-Presets:

```ts [app/app.config.ts]
export default defineAppConfig({
  docs: { theme: 'green' },
})
```

| Preset | Farben |
| --- | --- |
| `default` | Smaragd auf Zink |
| `green` | Grün auf Schiefer |

Ein Preset setzt nur Standardwerte. Jedes Token, das deine Seite setzt, gewinnt über beide.

#### Deine Farben setzen

Das Kit liest Tokens im Stil von shadcn, dieselben, die die Komponenten lesen. Schreib jeden Wert als Paar `light-dark(hell, dunkel)`:

```css [app/assets/css/main.css]
:root {
  --primary: light-dark(#2f6f4f, #7cc59d);
  --primary-foreground: light-dark(#ffffff, #0c1f15);
  --ring: light-dark(#2f6f4f, #7cc59d);
}
```

Setz `--primary-foreground` zusammen mit `--primary`. Eine helle Farbe wie Gelb braucht dunklen Text. Prüf den Kontrast in beiden Modi.

Die Tokens sind `--background`, `--foreground`, `--muted`, `--muted-foreground`, `--accent`, `--border`, `--primary`, `--primary-foreground`, `--card`, `--popover`, `--ring`, `--radius`, `--font-sans` und `--font-mono`.

#### Deine Schrift setzen

Lade die Schrift zuerst in deiner Seite, dann nenn sie:

```css [app/assets/css/main.css]
:root {
  --font-sans: 'Inter', system-ui, sans-serif;
}
```

Das Kit bringt Inter und JetBrains Mono mit. Auf einer Tailwind-4-Seite ohne eigenes `--font-sans` und `--font-mono` gewinnen die Schriften von Tailwind.

#### Ein eigenes Teil hinzufügen

Das Kit hat zwei leere Komponenten. Eine Datei mit demselben Namen in `app/components/` ersetzt eine davon:

```vue [app/components/DocsPageEnd.vue]
<script setup lang="ts">
defineProps<{ doc: { id: string } }>()
</script>

<template>
  <aside class="support">Fragen? <a href="mailto:hilfe@example.com">Schreib uns</a>.</aside>
</template>
```

| Komponente | Props | Wo sie erscheint |
| --- | --- | --- |
| `DocsPageEnd` | `doc`, der Eintrag der Seite | Nach dem Text jeder Doku-Seite, vor „Diese Seite bearbeiten“ |
| `DocsSidebarEnd` | keine | Unter der Navigation, in der Seitenleiste und im Menü auf dem Handy |

Ersetze keine anderen `Docs*`-Komponenten. Sie sind intern und können sich in jedem Release ändern.
::

## Prüfe, ob es funktioniert

- Öffne eine Doku-Seite. Links und die aktive Seite in der Navigation haben deine Farbe. Schalte in der Kopfzeile auf den dunklen Modus: Sie haben den dunklen Wert.
- Mit `theme: 'green'` hat das Element `<html>` das Attribut `data-docs-theme="green"`.
- Unter dem Text jeder Seite erscheint die Zeile „Fragen? Schreib uns.“

## Hell und dunkel

Ohne Wahl folgt die Seite dem System. Der Schalter in der Kopfzeile speichert die Wahl des Lesers in `localStorage` (Schlüssel `docs-color-mode`) und setzt `data-theme="light"` oder `data-theme="dark"` auf `<html>`. Ein kleines Skript im Kopf setzt das vor dem ersten Zeichnen, also flackert nichts.

Eine Klasse `.dark` auf `<html>`, zum Beispiel von `@nuxtjs/color-mode`, geht auch.

## Größen

| Token | Standard | Was es setzt |
| --- | --- | --- |
| `--docs-max` | `90rem` | Breite der Doku samt Rändern |
| `--docs-gutter` | `1rem` | Abstand zwischen Fensterrand und Doku |
| `--docs-top` | `0px` (eigenständig: die Kopfzeile) | Höhe dessen, was über der Doku klebt |
| `--docs-sidebar` | `17rem` | Breite der Navigation |
| `--docs-toc` | `13.5rem` | Breite von „Auf dieser Seite“ neben dem Text (ab 80rem Fensterbreite) |
| `--docs-measure` | `38rem` | Lesebreite des Fließtexts |
| `--docs-h1` | `clamp(1.75rem, …, 2.25rem)` | Größe der Seitentitel |
| `--docs-header` | `4rem` | Höhe der Kopfzeile der eigenständigen Doku |

## Eine eigene Seite im Rahmen der Doku

`<DocsShell>` ist der Körper der Doku: die Navigation, die Suche und die Leiste auf dem Handy. Setz deine eigene Seite hinein:

```vue [app/pages/help/index.vue]
<script setup lang="ts">
const docs = useGinko('docs')
</script>

<template>
  <DocsShell>
    <h1>Wie können wir helfen?</h1>
    <ul>
      <li v-for="item in docs.items" :key="item.id">
        <NuxtLink :to="item.url">{{ item.data.title }}</NuxtLink>
      </li>
    </ul>
  </DocsShell>
</template>
```

- Eine Seite deiner Website an derselben Adresse wie eine Seite des Kits gewinnt, zum Beispiel `app/pages/index.vue`.
- Mit `docs: { search: false }` lässt das Kit seine eigene Suche weg, für eine Seite mit `<DocsSearch />` in ihrer eigenen Kopfzeile.

## Die Texte des Kits ändern

Jeder Text des Kits ist eine Meldung unter `docs.*`. Die Meldungen deiner Seite gewinnen Schlüssel für Schlüssel:

```json [i18n/de.json]
{ "docs": { "searchPlaceholder": "Hilfe durchsuchen …" } }
```

Das Kit bringt Englisch, Deutsch und Französisch mit.

## Das Kit nicht kopieren

Eine Kopie des Kits in deiner Seite bekommt keine Fehlerbehebungen mehr, und es wird unklar, ob ein Token, eine Einstellung oder dein Code entscheidet. Auch die CSS-Klassen des Kits sind kein Vertrag. Gestalte über die Tokens.
