Diese Seite listet, was `@lupinum/ginko-preset-gastro` exportiert. Die Anleitung ist [Eine Restaurant-Seite bauen]($docs.restaurant-site). Alles, was nicht auf dieser Seite steht, ist intern und kann sich mit jedem Release ändern.

```bash
npm install @lupinum/ginko @lupinum/ginko-preset-gastro
```

## Bausteine

| Funktion | Art | Inhalt | Aufgaben des Inhabers |
| --- | --- | --- | --- |
| `hours()` | Einzelstück | Die übliche Woche, Schließtage, was an Feiertagen gilt | Heute geschlossen |
| `hourPlans()` | Sammlung | Andere Wochenzeiten für einen Zeitraum, auch jedes Jahr | |
| `notices()` | Sammlung | Kurze Zeilen, jede bis zu einem Datum | Heute ausgebucht |
| `lunch()` | Einzelstück | Das Mittagsmenü der Woche | Die Mittagswoche |
| `lunchPlans()` | Sammlung | Mittagswochen, im Voraus geplant | |
| `menu()` | Sammlung | Ein Gericht pro Eintrag: Kategorie, Name, Beschreibung, Preis, Allergene, vegetarisch oder vegan | Gericht heute aus, Preis ändern |
| `events({ route })` | Sammlung | Veranstaltungen mit Datum, Beginn, Preis und eigener Seite | Veranstaltung ausgebucht |
| `gallery()` | Einzelstück | Fotos | |

### Einstellungen

| Einstellung | Bei | Standard | Bedeutung |
| --- | --- | --- | --- |
| `source` | allen | die Plattform | `'files'` liest den Baustein aus `content/`. Ohne sie bearbeitet der Inhaber den Baustein im Studio. |
| `plans` | `hours` | keiner | Der Schlüssel des Bausteins `hourPlans()`. Die Zeile für heute im Studio folgt dann dem Plan, der an dem Tag gilt. |
| `allergens` | `menu`, `lunch`, `lunchPlans` | `'EU'` | `'EU'`, `'none'` (kein Allergen-Feld) oder deine eigene Liste `[{ value, label }]`. |
| `weekOf` | `lunch` | keiner | Der Montag der ersten Mittagswoche, `YYYY-MM-DD`. Pflicht für ein `lunch()` auf der Plattform. |
| `lunchBrick` | `lunchPlans` | `'lunch'` | Der Schlüssel des Bausteins `lunch()`, zu dem die geplanten Wochen gehören. |
| `route` | `events` | Pflicht | Die Seite einer Veranstaltung pro Sprache, zum Beispiel `{ en: '/events/[slug]' }`. |

Ohne die Plattform antwortet der Dev-Server mit 503, wenn ein Baustein kein `source: 'files'` hat.

### Gespeicherte Felder

Die Feldnamen sind die Daten deiner Seite. Sie ändern sich nicht.

- **Ein Tag** hat `day` (`mo` bis `su`), `closed` und höchstens zwei Öffnungszeiten: `from1` bis `to1` und `from2` bis `to2`. Das gilt gleich in der Woche, in Plänen und in Ausnahmen.
- **Öffnungszeiten** haben `week`, `exceptions` (jede mit `when`, `reason`, `closed` oder eigenen Zeiten), `closedOn` und `closedNote` (die Aufgabe „Heute geschlossen“), `holidays` (`sunday`, `closed` oder `normal`) und `holidayNoticeDays`.
- **Ein Gericht** hat `onMenu` (aus nach seiner Saison; das Gericht bleibt gespeichert), `soldOutOn` (nur an diesem Tag aus) und `nextPrice` mit `priceFrom` (ein neuer Preis ab einem Datum).
- **Eine Veranstaltung** hat `soldOut` (ausgebucht): Zeig das statt des Buchungslinks.

`onMenu`, `soldOutOn` und `soldOut` sind optional. Ein fehlendes Feld heißt: auf der Speisekarte, nicht aus, buchbar.

## Regeln für Öffnungszeiten

Jede Regel nimmt einen Kontext `{ hours, plans?, calendar? }` und ein Datum `YYYY-MM-DD`. `hours` sind die Daten des Bausteins `hours`, `plans` die Einträge von `hourPlans`.

| Funktion | Gibt zurück |
| --- | --- |
| `hoursOn(ctx, date)` | Was an einem Datum gilt: `{ closed, times, reason?, source, field?, holiday? }`. Alle anderen Regeln bauen auf dieser auf. |
| `todayState(ctx, today)` | `{ kind: 'open', times }`, `{ kind: 'closed', reason }`, `{ kind: 'holiday', holiday }` oder `{ kind: 'restDay' }`. |
| `noticesOn(notices, ctx, today)` | Die Hinweise, die heute erscheinen. An einem Tag, den der Inhaber geschlossen hat, fällt ein Hinweis weg, der heute endet, weil die Schließung gewinnt. |
| `upcomingClosures(ctx, today, days)` | Die Schließtage der nächsten `days` Tage: Ausnahmen des Inhabers, ein Tag in `closedOn` und Feiertage, die das Haus schließen. |
| `closedOnClosure(hours, today)` | Nur den Tag in `closedOn`, wenn er nach `today` liegt. |
| `upcomingHolidayClosures(ctx, today, days)` | Nur die Feiertage, die das Haus schließen. |
| `upcomingPlans(plans, today, days)` | Pläne, die in den nächsten `days` Tagen beginnen, mit `starts` und, wenn der Plan endet, `ends`. |
| `weekFor(ctx, date)` | Die sieben Tage, die an einem Datum gelten: `{ week, plan? }`. |
| `weekdayOf(date)` | Den Schlüssel des Wochentags, `'mo'` bis `'su'`. |
| `timesOf(day, and)` | Die Öffnungszeiten eines Tages als Text: `11:30–14:00 und 17:30–22:00`. Leer, wenn geschlossen. |
| `spansOf(times)`, `spansText(spans, and)` | Die Zeiträume eines Tages, und die Zeiträume als verbundener Text. |

Beispielergebnisse von `todayState` für ein Haus, das montags geschlossen hat:

| Datum | Ergebnis |
| --- | --- |
| Dienstag | `{ kind: 'open', times: [{ from: '11:30', to: '14:00' }, { from: '17:30', to: '22:00' }] }` |
| Montag | `{ kind: 'restDay' }` |
| 26. Oktober, mit `holidays: 'closed'` | `{ kind: 'holiday', holiday: { de: 'Nationalfeiertag', en: 'Austrian National Day' } }` |
| Ein Tag im Sommerurlaub | `{ kind: 'closed', reason: 'Sommerurlaub' }` |

## Feiertage

Die Regeln zählen österreichische Feiertage, wenn du nichts anderes sagst. Gib `calendar` im Kontext jeder Regel mit, die du aufrufst:

| `calendar` | Zählt |
| --- | --- |
| `'AT'` | Österreich. Der Standard. |
| `'DE'` | Deutschland, nur die bundesweiten Tage. |
| `'SG'` | Singapur. Seine Feiertage nach dem Mondkalender, dem islamischen und dem hinduistischen Kalender sind eine Tabelle für 2026 und 2027. |
| `'none'` | Keine Feiertage. |
| eine Funktion `(year) => Holiday[]` | Deine eigenen Tage. |

Halte den Wert in einer Konstante deiner Seite, damit alle Aufrufe übereinstimmen:

```ts
import type { HolidaysOption } from '@lupinum/ginko-preset-gastro'

export const calendar = 'DE' satisfies HolidaysOption

todayState({ hours: data, calendar }, today)
```

Setze `country` in `ginko.config.ts` auf dasselbe Land. Das Studio und die Erinnerungs-Mail zählen dann dieselben Feiertage wie die Seite. Statt `calendar` kannst du `country` im Kontext mitgeben; der Wert ist `useRuntimeConfig().public.ginko.country`.

Das gespeicherte Feld `holidays` ist etwas anderes: die Wahl des Inhabers für diese Tage (wie am Sonntag, geschlossen oder normal).

## Speisekarte und Mittagsmenü

| Name | Was es ist |
| --- | --- |
| `menuCategories` | Die Kategorien von `menu()` in der Reihenfolge der Speisekarte: `starters`, `soups`, `mains`, `desserts`, `drinks`. Gruppiere die Gerichte danach. |
| `allergensEU` | Die 14 EU-Allergene als Optionen `{ value, label }`, mit den Buchstaben A bis R. |
| `allergenNames` | `{ de, en }`: der Name jedes Allergens für Besucher. `allergenNames.en.A` ist `Gluten`. |
| `weekdayNames` | `{ de, en }`: der Name jedes Wochentags. |
| `dishOn(dish, date)` | `{ shown, soldOut }`. `shown` ist false für ein Gericht, das von der Speisekarte genommen ist. `soldOut` ist true an seinem Tag `soldOutOn`. |
| `priceOn(item, date)` | Der Preis an einem Datum. `nextPrice` zählt ab `priceFrom`. |
| `upcomingPrice(item, today, days)` | `{ from, price }` für einen neuen Preis in den nächsten `days` Tagen, sonst `undefined`. |
| `lunchWeekOn(main, planned, today, week)` | Die Mittagswoche, die heute erscheint: eine geplante Woche, die Hauptdaten von `lunch` oder nichts. |

Lass ein Gericht mit `shown: false` aus der Speisekarte, der Allergenliste und dem JSON-LD weg.

## JSON-LD

| Funktion | Gibt zurück |
| --- | --- |
| `restaurantJsonLd(input)` | Daten für schema.org `Restaurant`. Es hat keine Standardwährung und kein Standardland: Gib `currency` und `address.country` mit. |
| `eventJsonLd(input)` | Daten für schema.org `Event` für eine Veranstaltung. Es braucht `timeZone`, die Zeitzone der Seite aus `useGinkoSite()`. Mit `soldOut: true` sagt das Angebot `SoldOut` und hat keinen Buchungslink. |

Beide nehmen Preise so, wie die Seite ein Geldfeld liest: in der kleinsten Einheit, `1250` ist also `12.50`. In einer Inhaltsdatei schreibst du `12.5`.

## Außerhalb Österreichs

Die Standards sind österreichisch. Ändere sie pro Seite:

- **Feiertage.** Gib `calendar` oder `country` mit, siehe oben.
- **Allergene.** `allergens: 'none'` oder deine eigene Liste.
- **Beschriftungen und vorbelegte Texte.** Es gibt sie auf Deutsch und Englisch. Mit einer anderen Hauptsprache startet die Seite ohne die vorbelegten Texte. Ein `lunch()` auf der Plattform kann nicht ohne sie starten: Nimm dort `lunch({ source: 'files' })`. Ein Code mit Region wie `de-CH` zählt nicht als `de`.

```ts [ginko.config.ts]
export default defineSite({
  site: 'kopi-corner',
  name: 'Kopi Corner',
  url: 'https://example.com',
  timeZone: 'Asia/Singapore',
  country: 'SG',
  locales: ['en'],
  currency: 'SGD',
  pages: { home: '/' },
  bricks: {
    hours: hours(),
    notices: notices(),
    lunch: lunch({ weekOf: '2026-10-05', allergens: 'none' }),
    menu: menu({ allergens: 'none' }),
  },
})
```
