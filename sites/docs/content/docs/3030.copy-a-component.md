This guide copies the `callout` component into your app. At the end, its Vue file is in your repository, you can change it, and your Markdown uses your copy.

The npm package is the simple path: you get updates with the package. Copy a component only when you want to own its code. A copy gets no updates.

## Before you start

- The site has the components set up, see [Set up components]($docs.set-up-components).
- The site uses [shadcn-vue](https://www.shadcn-vue.com), so it has Tailwind CSS and a `components.json`. If it does not, follow the Nuxt installation of shadcn-vue first: install Tailwind CSS, then run `npx shadcn-vue@latest init`.

Without `components.json`, the command in step 1 asks to create one and stops there.

## Steps

::steps
#### Run the command

The Ginko docs site serves each component as a shadcn-vue registry item:

```bash
npx shadcn-vue@latest add https://ginko.lupinum.com/r/callout.json
```

The CLI writes the component and the files it needs to `app/components/ginko/`:

```text
✔ Created 13 files:
  - app/components/ginko/ginko-components.css
  - app/components/ginko/Callout.vue
  - app/components/ginko/aliases.ts
  - app/components/ginko/texts.ts
  …
```

The name of an item is the file name in kebab case: `callout`, `code-block`, `timeline-item`. [`/r/registry.json`](https://ginko.lupinum.com/r/registry.json) lists all of them.

#### Import the stylesheet

Import the stylesheet once in your main CSS file. The path is relative to that file:

```css [app/assets/css/tailwind.css]
@import "tailwindcss";
@import "../../components/ginko/ginko-components.css";
```

It reads the shadcn tokens of your site, see [Theme the components]($docs.theme-the-components).

#### Use your copy in Markdown

Pass the copy to `<GinkoMarkdown>` for its tag:

```vue [app/pages/index.vue]
<script setup lang="ts">
import Callout from '~/components/ginko/Callout.vue'

const start = useGinko('start')
</script>

<template>
  <GinkoMarkdown :value="start.data.body" :components="{ callout: Callout }" />
</template>
```

#### Change the component

Open `app/components/ginko/Callout.vue` and change it. It is your code now.
::

## Check that it works

Change the template of `Callout.vue`, for example add a word after the title. Open a page with a `::callout`. The notice shows your change.

## What a copy does not have

- **Updates.** A new version of the package does not change your copy. Run the command again to take the new source, and compare it with yours.
- **Translated texts.** A copied component uses the English texts in `app/components/ginko/texts.ts`. Change them there.
- **The short forms.** `::note`, `::warning` and the other short forms of `callout` are their own tags. `aliases.ts` exports a component for each (`NoteCallout`, `WarningCallout`, …). Pass them the same way: `{ callout: Callout, note: NoteCallout }`.
- **The registry.** The list of tags and props for the check still comes from `@lupinum/ginko-components/registry`. If you add a prop to your copy, describe the tag again in your config, see [Add your own component]($docs.add-your-own-component#replace-a-component-of-the-package).
