This guide builds a restaurant site with the kit `@lupinum/ginko-preset-gastro`. At the end, the site shows whether the house is open today and a menu with prices and allergens.

The kit is a package of ready-made bricks: `hours()`, `menu()`, `lunch()`, `events()` and more. Fields, labels and the owner's quick tasks ("Closed today", "Dish sold out today") are already there. It also has the rules that read them: what applies today, which price counts, which public holidays close the house. The Vue components stay in your site, because their look belongs to your design.

## The fast way: the template

```bash
npm create ginko@latest my-restaurant -- --template restaurant
cd my-restaurant
npm install
npm run dev
```

The template is a complete site: a start page with today's hours, a menu, a lunch week, events with their own pages, a gallery and legal pages, in English, German and Italian. All content is Markdown in `content/`. Change the files and the design, and you are done.

[Templates]($docs.templates) has a live demo. The steps below add the kit to a site of your own design.

## Before you start

You need a Ginko site that runs, for example the one from the [Quick start]($docs.getting-started).

## Steps

::steps
#### Install the kit

```bash
npm install @lupinum/ginko-preset-gastro
```

#### Add the bricks

```ts [ginko.config.ts]
import { defineSite } from '@lupinum/ginko'
import { hours, menu } from '@lupinum/ginko-preset-gastro'

export default defineSite({
  // …
  bricks: {
    hours: hours({ source: 'files' }),
    menu: menu({ source: 'files' }),
  },
})
```

`source: 'files'` reads the brick from `content/`, so the site runs without the platform.

#### Write the opening hours

`hours` is a single: one file. `week` has one row per day. A day has at most two opening periods:

```markdown [content/hours.md]
---
week:
  - day: mo
    closed: true
  - day: tu
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: we
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: th
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: fr
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: sa
    closed: false
    from1: '11:30'
    to1: '22:00'
  - day: su
    closed: false
    from1: '11:30'
    to1: '15:00'
exceptions:
  - when:
      from: 2027-08-02
      to: 2027-08-15
    reason: Summer holiday
    closed: true
holidayNoticeDays: 14
holidays: sunday
---
```

`exceptions` are closures and special days. `holidays` says what happens on a public holiday: `sunday` (as on Sunday), `closed` or `normal`.

#### Write two dishes

`menu` is a collection: one file per dish.

```markdown [content/menu/1.schnitzel.md]
---
category: mains
name: Wiener Schnitzel
description: With roast potatoes and lemon
price: 24.9
allergens: [A, C, G]
veg: none
---
```

```markdown [content/menu/2.strudel.md]
---
category: desserts
name: Apple strudel
price: 6.5
allergens: [A, G]
veg: vegetarian
---
```

`category` is `starters`, `soups`, `mains`, `desserts` or `drinks`. `allergens` are the letters of the 14 EU allergens.

#### Show today's state and the menu

`todayState` says what applies today. `priceOn` gives the price that counts today.

```vue [app/pages/restaurant.vue]
<script setup lang="ts">
import { formatMoney } from '@lupinum/ginko'
import { menuCategories, priceOn, spansText, todayState, type HoursData } from '@lupinum/ginko-preset-gastro'

const hours = useGinko('hours')
const menu = useGinko('menu')
const today = useGinkoToday()

// The stored data in the shape the rules take.
const data = computed<HoursData>(() => {
  const { week, exceptions, closedOn, closedNote, holidays } = hours.value.data
  return {
    week: week.map((day) => ({ ...day, day: String(day.day), closed: day.closed === true })),
    exceptions: exceptions.map((e) => ({ ...e, reason: e.reason ?? '', closed: e.closed === true })),
    closedOn: closedOn ?? undefined,
    closedNote: closedNote ?? undefined,
    holidays: (['sunday', 'closed', 'normal'] as const).find((setting) => setting === holidays),
  }
})
const state = computed(() => todayState({ hours: data.value, calendar: 'AT' }, today.value))

const groups = computed(() => menuCategories.map((category) => ({
  category,
  dishes: menu.value.items.filter((dish) => dish.data.category === category),
})).filter((group) => group.dishes.length))

useGinkoSeo({ title: 'Restaurant' })
</script>

<template>
  <main>
    <p v-if="state.kind === 'open'">Open today: {{ spansText(state.times, 'and') }}</p>
    <p v-else-if="state.kind === 'holiday'">Closed today: {{ state.holiday.en }}</p>
    <p v-else-if="state.kind === 'closed'">Closed today: {{ state.reason }}</p>
    <p v-else>Closed today</p>

    <section v-for="group in groups" :key="group.category">
      <h2>{{ group.category }}</h2>
      <ul>
        <li v-for="dish in group.dishes" :key="dish.id">
          {{ dish.data.name }} · {{ formatMoney(priceOn(dish.data, today), 'en') }} · {{ dish.data.allergens.join(', ') }}
        </li>
      </ul>
    </section>
  </main>
</template>
```

`calendar: 'AT'` counts the Austrian public holidays. [Restaurant reference]($docs.restaurant-reference#public-holidays) has the other countries.
::

## Check that it works

Open `/restaurant`. On a Tuesday the page shows:

```text
Open today: 11:30–14:00 and 17:30–22:00
mains
Wiener Schnitzel · €24.90 · A, C, G
desserts
Apple strudel · €6.50 · A, G
```

On a Monday it shows "Closed today". Then run `npx ginko check` and `npx nuxt typecheck`. Both pass.

## What the four states mean

| `state.kind` | When | What it carries |
| --- | --- | --- |
| `open` | The house opens today. | `times`: the opening periods |
| `closed` | The owner closed this day: an exception, or "Closed today". | `reason`: the owner's text |
| `holiday` | A public holiday closes the house. | `holiday`: its name in German and English |
| `restDay` | The usual week has this day closed. | nothing |

## The other bricks

| Brick | Kind | For |
| --- | --- | --- |
| `hourPlans()` | collection | Other weekly hours for a date range, such as winter hours every year. Pass its key to `hours()`: `hours({ plans: 'hourPlans' })`. |
| `notices()` | collection | Short lines such as "Fully booked tonight", each until a date. |
| `lunch()` | single | The lunch menu of this week, Monday to Friday. |
| `lunchPlans()` | collection | Lunch weeks planned ahead. |
| `events({ route })` | collection | Events with a page each. An event leaves the site after its last day. |
| `gallery()` | single | Photos. |

In `bricks`, put `hourPlans` right after `hours` and `lunchPlans` right after `lunch`. The Studio lists the quick tasks in that order.

## Let the owner change it

With `source: 'files'`, a developer changes the hours and the menu. On the platform, the owner does it from a phone: "Closed today", "Fully booked today", "Dish sold out today", a price change from a date, the lunch week.

To move a brick, remove its `source: 'files'` and release the schema, see [Move a brick to the platform]($docs.move-a-brick-to-the-platform). Two things are special for this kit:

- A platform `lunch()` needs `weekOf`, the Monday of the first week: `lunch({ weekOf: '2026-10-05' })`.
- A platform `lunch()` needs the main language `de` or `en`, because its days start with a placeholder text in one of these.
