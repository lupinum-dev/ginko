Ein Markdown-Feld in Ginko nimmt eine feste Menge von Teilen an, nicht alles, was Markdown schreiben kann. Ein Text mit einem anderen Teil wird abgelehnt: in einer Datei vom Build, auf der Plattform vom Editor. Diese Seite erklärt die Regeln und ihre Gründe.

## Warum es Regeln gibt

- **Inhaber schreiben den Text.** Eine Person, die keine Entwicklerin ist, schreibt auf der Plattform in ein Feld. Nichts, was sie tippt oder einfügt, darf die Seite brechen oder Code ausführen.
- **Das Design gehört dir.** Eine Überschrift in einer Karte mit fester Höhe oder eine Tabelle in einem einzeiligen Teaser bricht ein Layout. Der Entwickler legt fest, was an jede Stelle passt.
- **Der Text hat mehrere Leser.** Derselbe Text speist die Seite, die Suche, die Markdown-Fassung für Agenten und die Vorschaukarte beim Teilen. Eine feste Menge von Teilen funktioniert in allen.

Die Website bekommt einen Markdown-Text als Baum aus bekannten Teilen, nie als HTML. `<GinkoMarkdown>` zeichnet diesen Baum mit Vue-Komponenten. Nichts nutzt `v-html`, und im Browser läuft kein Parser.

## Profile

Jedes Markdown-Feld hat ein Profil. Es sagt, wie viel der Text enthalten darf:

```ts
teaser: f.markdown('Teaser', { profile: 'inline' }),
body: f.markdown('Text', { profile: 'page' }),
```

| Profil | Erlaubt | Gedacht für |
| --- | --- | --- |
| `inline` | Einen Absatz mit fett, kursiv, durchgestrichen, Code und Links | Einen Teaser, eine Bildunterschrift, eine Zeile in einer Karte |
| `basic` | Dazu Überschriften h2 bis h4, Listen, Aufgabenlisten, Zitate, Trennlinien und Fußnoten | Einen Text in einem Abschnitt, etwa eine Stellenbeschreibung |
| `rich` | Dazu Tabellen, Bilder, Codeblöcke, Formeln und Mermaid-Diagramme | Einen Artikel. Der Standard. |
| `page` | Dazu h1, h5, h6 und Komponenten wie `::callout` | Eine ganze Seite, etwa eine Doku-Seite |

Wähl das kleinste Profil, das den Inhalt fasst. Ein Text, der darüber hinausgeht, bekommt eine klare Meldung, die aufzählt, was das Profil erlaubt:

```text
content/start.md (body.en): “body”: “callout” is not allowed here (paragraphs, headings, lists (also with checkboxes), quotes, notices and footnotes).
```

`inline`, `basic` und `rich` haben kein h1. Der Titel der Seite ist das h1, also beginnt ein Text bei h2.

## Komponenten

Nur das Profil `page` nimmt Komponenten an, und nur die, die die Website in `components` von `ginko.config.ts` registriert. Jede Komponente deklariert ihre Props, also kann ein Text nur nutzen, was die Komponente kennt:

```text
There is no component “callot”.
Component “callout”: There is no property “colour”.
Component “pricing”: property “price” is missing.
```

Diese Prüfung ist der Grund, warum du eine Komponente gefahrlos ändern kannst. Wenn du einen Prop umbenennst, findet `ginko check` jeden Text, der noch den alten Namen nutzt. Auf der Plattform prüft ein Release jeden gespeicherten Text erneut, also kann eine Komponente nicht wegfallen, solange ein Text sie noch nutzt.

[Komponenten einrichten]($docs.set-up-components) registriert die fertigen Komponenten. [Eigene Komponente hinzufügen]($docs.add-your-own-component) ergänzt eine eigene.

## Was immer abgelehnt wird

Diese Tags führen Code aus, laden andere Inhalte oder senden Daten. Kein Profil und keine Registry erlaubt sie:

`script`, `style`, `iframe`, `frame`, `frameset`, `object`, `applet`, `link`, `meta`, `base`, `form`, `button`, `textarea`, `select`, `option`, `template`, `noscript`, `svg`, `portal`, `slot`

```text
content/start.md (body.en): “body”: “iframe” is not allowed.
```

Auch `embed` wird abgelehnt, mit einer Ausnahme: Eine Website, die die Komponente `embed` von `@lupinum/ginko-components` registriert, bekommt diese Komponente. Sie zeigt eine Karte oder einen Player von einem bekannten Anbieter und lädt nichts, bevor der Besucher einen Button drückt. Siehe [Medien-Komponenten]($docs.components-media#embed).

Du brauchst ein Formular oder ein iframe in einem Text? Schreib eine Komponente dafür und registriere sie. Dann ist der Code deiner und geprüft, und der Text nennt sie nur.

## Attribute

Ein Teil eines Textes kann Attribute tragen: `**new**{lang="en"}`. Ginko hält eine kurze Liste.

| Attribut | An | Zweck |
| --- | --- | --- |
| `title`, `lang`, `dir`, `aria-*` | jedem Element | Bedeutung und Barrierefreiheit |
| `aspect`, `fit` | einem Bild | Schneidet das Bild auf einen Rahmen zu: `{aspect="4:3" fit="contain"}` |
| die deklarierten Props | einer Komponente | Was die Registry für sie aufführt |

Jedes andere Attribut wird abgelehnt:

```text
content/start.md (body.en): “body”: The property “style” is not allowed.
```

Zwei Fälle überraschen oft:

- **`style`.** Ein Text mit eigenen Farben und Größen geht gegen das Design der Website, und CSS im Inhalt ist ein Weg, Teile einer Seite zu verstecken oder zu verschieben.
- **`class` und `data-*`.** Beide sind Anknüpfungspunkte für das CSS deiner Website. Ein Text, der `class="hidden"` setzen könnte, könnte Teile des Layouts umschalten.

Für einen Teil mit eigenem Aussehen schreib eine Komponente. Ihre Props sind die Wahlmöglichkeiten, die ein Autor hat.

## Links

Eine Link- oder Bildadresse muss eine dieser Formen haben:

| Form | Beispiel |
| --- | --- |
| Eine Webadresse | `https://example.com` |
| Eine E-Mail-Adresse oder Telefonnummer | `mailto:hello@example.com`, `tel:+43 1 234567` |
| Ein Pfad auf der Website | `/menu` |
| Eine Überschrift auf der Seite | `#prices` |
| Ein Link zu einem Eintrag oder einer Seite | `$news.opening`, `$pages.menu` |

Alles andere ist kein Link:

- `[text](javascript:…)` und `[text](data:…)` bleiben Text. Die Seite zeigt die Zeichen so, wie sie getippt wurden, und nichts ist klickbar.
- Eine Adresse, die mit `//` beginnt, führt zu einer anderen Website, ohne das zu sagen. Der Build lehnt sie ab:

```text
content/start.md (body.en): “body”: Link is not allowed (only http, https, mailto, tel or /path).
```

Nimm am besten die letzte Form. Ginko macht aus `$news.opening` die Adresse dieses Eintrags in der Sprache der Seite, und die Link-Prüfung findet ihn, wenn der Eintrag weg ist. [Zwischen Seiten verlinken]($docs.link-between-pages) hat die Schritte.

## Rohes HTML

Ginkos Markdown kennt kein rohes HTML. Ein Tag in einem Text ist Text: `<div class="box">` erscheint auf der Seite als genau diese Zeichen, und ein `<script>` in einem Text läuft nie. Für Struktur über Markdown hinaus gibt es Komponenten.
