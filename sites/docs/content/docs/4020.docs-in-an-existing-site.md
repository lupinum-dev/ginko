This guide adds a handbook under `/handbook` to a site that already has its own pages. At the end, the site keeps its header and footer, and the docs with navigation and search sit inside.

## Before you start

You need a Ginko site that runs, for example the one from the [Quick start]($docs.getting-started). Its `app/app.vue` uses a layout, as in every site from a template:

```vue [app/app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

## Steps

::steps
#### Install the kit

```bash
npm install @lupinum/ginko-i18n @lupinum/ginko-docs
```

#### Extend the kit

```ts [nuxt.config.ts]
import ginko from './ginko.config.ts'

export default defineNuxtConfig({
  extends: ['@lupinum/ginko-docs'],
  modules: ['@lupinum/ginko/nuxt'],
  ginko,
})
```

Keep the modules your site already has.

#### Add the docs brick

Add the brick next to the bricks of the site. `base` is the address of the docs:

```ts [ginko.config.ts]
import { defineSite, f, single } from '@lupinum/ginko'
import { components, docsCollection } from '@lupinum/ginko-docs/config'

const locales = ['en'] as const

export default defineSite({
  // …
  locales,
  components,
  bricks: {
    docs: docsCollection({ locales, base: '/handbook' }),
    // the bricks of the site
  },
})
```

Use the languages of the site. A site from a template has them in `app/routes.ts` already: write `import { locales } from './app/routes.ts'` instead of the `const`. If the site has components of its own, write `components: { ...components, ...own }`. If it imports `components` from `@lupinum/ginko-components/registry` already, keep one of the two imports: the kit passes on the same registry.

#### Write the first pages

```markdown [content/docs/1.welcome.md]
---
title: Welcome
description: How we work, in one place.
section: Basics
---

This is the first page of the handbook.
```

```markdown [content/docs/2.holidays.md]
---
title: Holidays
description: How to ask for days off.
---

Ask your team lead two weeks before.
```

#### Keep your header

With a layout of its own, the site keeps its header and footer. A site from a template needs no change here: its header and footer stay, and the docs show their search above the side navigation. The search is also a component you can put into your own header:

```vue [app/layouts/default.vue]
<template>
  <div>
    <header>
      <NuxtLink to="/">My company</NuxtLink>
      <NuxtLink to="/handbook">Handbook</NuxtLink>
      <DocsSearch />
    </header>
    <slot />
    <footer>© My company</footer>
  </div>
</template>
```

`<DocsLanguage />` is the language menu and `<DocsThemeToggle />` the light/dark switch. Only these three and `<DocsShell>` are public; the other `Docs*` components can change in any release.

#### Open the docs

Open `/handbook`. If it answers 404, stop the dev server and start it again: the kit adds its pages when the server starts.
::

## Check that it works

- `/handbook` leads to `/handbook/welcome`. The page shows your header, the navigation with "Welcome" and "Holidays", and your footer.
- `/` is still the start page of the site.
- `/docs`, `/blog` and `/changelog` answer 404. The kit adds only what your config describes.

## What the kit adds and what it leaves

- **Only the docs pages.** The kit registers the docs at their `base`. It adds `/blog` and `/changelog` only when those bricks exist, and `/` only when the site has no start page. A page of the site at the same address always wins.
- **Styles stay inside.** Every rule of the kit is under a `docs-` class. Your pages keep their look.
- **Titles.** A docs page has the title `Page · Site name` from Ginko (`seo.titleTemplate`). A `titleTemplate` in `app.head` does not apply to it, so the name never shows twice.

## Line the docs up with the site

Map the tokens of your design to the tokens of the kit. Two layout tokens fit the docs into your frame:

```css [app/assets/css/main.css]
:root {
  --primary: var(--color-brand);
  --radius: 0.75rem;
  --docs-max: 82.5rem;  /* the width of your content container */
  --docs-top: 4.5rem;   /* the height of a sticky header */
}
```

[Theme a docs site]($docs.docs-theming) has all tokens.

## Another name for the brick

The kit finds the docs by the brick key `docs`. To use another key, such as `handbook`, give it to the brick and to the kit:

```ts [ginko.config.ts]
handbook: docsCollection({ locales, base: '/handbook', brick: 'handbook' }),
```

```ts [nuxt.config.ts]
ginkoDocs: { brick: 'handbook' },
```

The files then live in `content/handbook/`, and links to the pages read `$handbook.<page>`.
