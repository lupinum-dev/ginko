Ginko has fixed limits. They keep the bundle small enough to load in one response, and they keep the forms in the Studio usable. A config over a schema limit stops `ginko check` and the build, for example with `Too many bricks (at most 30).`

## Schema

| What | Limit |
| --- | --- |
| Bricks per site | 30 |
| Fields per brick | 60 |
| `max` of a collection | 1 to 500 entries |
| Languages per site | 20 |
| Size of the schema | 256 KiB |

## Content on the platform

| What | Limit |
| --- | --- |
| Entries per site, all collections together | 2,000 |
| Content of a site | 4 MiB |
| One entry | 480 KiB |
| Removed entries that the platform keeps | 4 MiB |

The sizes count the stored values of the entries as JSON text. The Studio shows how much of each limit a site uses. When the removed entries pass their limit, the platform deletes the oldest of them early.

## Fields

| What | Limit |
| --- | --- |
| `f.text` | 500 characters at most |
| `f.url` | 2,000 characters |
| `f.longtext` | default 2,000 characters, at most 5,000 |
| `f.markdown` | default 50,000 characters, at most 500,000 |
| `f.money` | 100,000,000 minor units, so 1,000,000.00 in a currency with cents |
| Frames of one image field | 8 |

[Field types]($docs.field-types) has the options of each type.

## Uploads on the platform

| File | Limit |
| --- | --- |
| Image: JPEG, PNG or WebP | 20 MB |
| PDF | 10 MB |

## When a site reaches a limit

- **Entries.** Give old entries an end date, or remove them. A collection for news or events grows without end otherwise. See [Show an entry only for a time]($docs.timed-entries).
- **Fields.** Split a brick with many fields into two bricks. Often the fields belong to two parts of a page.
- **Text.** A text near 500,000 characters is a book. Make it a collection with one entry per chapter.
