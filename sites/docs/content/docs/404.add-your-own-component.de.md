Diese Anleitung gibt deiner Seite einen Tag `::pricing`. Am Ende kann eine Inhaltsdatei ihn nutzen, die Prüfung kennt seine Props, und der Editor im Studio bietet ihn an.

## Bevor du beginnst

Die Seite hat die Komponenten eingerichtet, siehe [Komponenten einrichten]($docs.set-up-components).

## Schritte

::steps
#### Den Tag beschreiben

`defineComponents` beschreibt jeden Tag: seinen Namen im Editor, einen Satz dazu und seine Props. Nimm deine Tags in die Registry des Pakets auf:

```ts [ginko.config.ts]
import { defineComponents, defineSite, f } from '@lupinum/ginko'
import { components } from '@lupinum/ginko-components/registry'

const own = defineComponents({
  pricing: {
    kind: 'block',
    label: 'Preis',
    describe: 'Ein Preis mit Titel, darunter der Text.',
    props: {
      title: f.text('Titel', { max: 80 }),
      price: f.text('Preis', { max: 20 }),
    },
    editor: { example: '::pricing{title="Basis" price="9 €"}\nEine Seite, eine Sprache.\n::' },
  },
})

export default defineSite({
  // …
  components: { ...components, ...own },
})
```

Auf einer Seite mit dem Doku-Kit importierst du `components` aus `@lupinum/ginko-docs/config`.

#### Die Vue-Komponente ergänzen

Ginko sucht eine globale Komponente mit dem Namen des Tags in PascalCase. Der Tag `pricing` ist `Pricing.vue` in `app/components/global/`:

```vue [app/components/global/Pricing.vue]
<script setup lang="ts">
defineProps<{ title: string; price: string }>()
</script>

<template>
  <section class="pricing">
    <h3>{{ title }} <span>{{ price }}</span></h3>
    <slot />
  </section>
</template>
```

Die Props kommen als Text an. Der Text zwischen den beiden `::` ist der Standard-Slot.

#### Den Tag nutzen

```markdown [content/start.md]
::pricing{title="Basis" price="9 €"}
Eine Seite, eine Sprache.
::
```
::

## Prüfe, ob es funktioniert

Öffne die Seite. Sie zeigt die Überschrift „Basis 9 €“ und darunter den Text.

Nimm dann `price` aus dem Tag und starte `npx ginko check`. Die Prüfung nennt die fehlende Prop:

```text
content/start.md (body.en): “body”: Component “pricing”: property “price” is missing.
```

## Die Einstellungen eines Tags

| Einstellung | Typ | Bedeutung |
| --- | --- | --- |
| `kind` | `'block'` oder `'inline'` | Ein Block steht für sich (`::pricing`). Ein Inline-Tag steht in einem Satz (`:badge[neu]`). |
| `label` | Text, oder ein Text je Sprache | Der Name im Editor. |
| `describe` | Text, oder ein Text je Sprache | Ein Satz für Redakteure und für KI-Agenten. |
| `props` | Felder | Die Props des Tags. Eine Prop ist Pflicht, außer sie hat `optional: true`. |
| `slots` | Objekt | Benannte Slots, jeder mit einem `label` und, wenn du willst, einem Markdown-`profile`. |
| `children` | Liste von Tags | Die Tags, die direkt darin stehen dürfen. Ohne die Einstellung jeder Tag. |
| `parents` | Liste von Tags | Der Tag darf nur direkt in einem dieser Tags stehen. |
| `editor` | Objekt | `example` ist das Markdown, das der Editor einfügt, `group` die Überschrift in seinem Menü, `icon` sein Icon. |

Regeln für die Namen:

- Ein Tag ist kleingeschrieben mit Bindestrichen, etwa `price-table`.
- Eine Prop ist camelCase. Sie darf nicht mit `on` beginnen und nicht `as`, `innerHTML`, `outerHTML`, `innerText`, `outerText` oder `textContent` heißen.
- Eine Prop kann `f.text`, `f.longtext`, `f.number`, `f.boolean`, `f.choice`, `f.choices`, `f.image` oder `f.ref` sein.

## Eine Komponente des Pakets ersetzen

`<GinkoMarkdown>` hat die Prop `components`. Ein Tag, den du dort angibst, nutzt deine Vue-Komponente. Alle anderen Tags bleiben, wie sie sind.

```vue [app/pages/index.vue]
<script setup lang="ts">
import MyCallout from '~/components/MyCallout.vue'

const start = useGinko('start')
</script>

<template>
  <GinkoMarkdown :value="start.data.body" :components="{ callout: MyCallout }" />
</template>
```

Deine Komponente bekommt dieselben Props wie die des Pakets. Die Kurzformen sind eigene Tags: `::note` und `::warning` behalten die Komponente des Pakets, bis du auch sie ersetzt.

Beschreibt deine Registry einen Tag mit dem Namen eines Tags aus dem Paket, gewinnt dein Eintrag in der Prüfung und im Editor. Die Seite zeigt aber weiter die Komponente des Pakets, denn eine globale Komponente wirkt nur für Tag-Namen, die das Paket nicht nutzt. Gib deine Komponente wie oben über `components` an.

Die Vue-Komponenten des Pakets kommen aus `@lupinum/ginko-components/components`. So kannst du `Callout` in deine eigene Variante einbetten und musst sie nicht neu schreiben.
