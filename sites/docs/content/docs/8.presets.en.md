## What a preset is

A preset is a package of ready-made bricks. Each factory (`hours()`, `menu()` and so on) returns a brick that you add to `bricks`. Fields, labels, tasks and routes are already there. The components stay in your site, because their look belongs to your site.

## Restaurant: `@lupinum/ginko-preset-gastro`

For restaurants: `hours()`, `hourPlans()`, `notices()`, `lunch()`, `lunchPlans()`, `menu()`, `events()` and `gallery()`, with the owner's quick tasks ("Closed today", "Fully booked today", change a price). It also has the 14 EU allergens (`allergensEU`) and the opening-hours rules `hoursOn` and `todayState`.

Start a new site with this preset:

```bash
npm create ginko@latest my-restaurant -- --preset gastro
```

The starter shows opening hours and a menu, both read from files. Add `--lang de` for a German starter.

### Add the bricks

```ts
// ginko.config.ts
import { defineSite } from '@lupinum/ginko'
import { hours, menu, notices } from '@lupinum/ginko-preset-gastro'

export default defineSite({
  site: 'my-restaurant',
  name: 'My restaurant',
  url: 'https://example.com',
  timeZone: 'Europe/Vienna',
  locales: ['en'],
  currency: 'EUR',
  pages: { home: '/' },
  bricks: {
    hours: hours({ source: 'files' }),
    menu: menu({ allergens: 'none', source: 'files' }),
    notices: notices(),
  },
})
```

### Options

Every factory takes the option `source`. Without it, the owner edits the brick on the Ginko platform. `'files'` reads it from Markdown in `content/`, so the site runs without the platform.

Labels in the Studio and prefilled texts, such as the lunch placeholder or "We are fully booked today.", come in German and English. The site keeps the texts of its own locales when its main locale is `de` or `en`; otherwise it starts without the prefilled texts. A code with a region such as `de-CH` does not count as `de`.

Some factories have more options: `allergens` on `menu()`, `lunch()` and `lunchPlans()` (`'EU'`, `'none'`, or your own list), `weekOf` on `lunch()`, `lunchBrick` on `lunchPlans()`, and `route` on `events()` (required).

The hours rules count Austrian public holidays. For another country, pass `calendar` to each rule you call: `todayState(today, { hours, calendar: 'DE' })` (or `'SG'`, or your own function); `'none'` turns public holidays off. A day has at most two opening periods (lunch and evening).

### Show the opening hours

```ts
import { todayState } from '@lupinum/ginko-preset-gastro'

const state = todayState('2026-10-26', { hours: { week: [], exceptions: [], holidays: 'closed' } })
// { kind: 'holiday', holiday: { de: 'Nationalfeiertag', en: 'Austrian National Day' } }
```

`todayState` returns `open` (with the times), `closed` (with the owner's reason), `holiday` or `restDay`. Join the times in your language with `spansText(state.times, 'and')`.

[`sites/restaurant`](https://github.com/lupinum-dev/ginko/tree/main/sites/restaurant) in the Ginko repository is a complete example. It runs against a fake platform inside the repository, and its page files have German names.
