This guide lets a Nuxt module bring its own translated texts. At the end, the components of the module translate with `useI18n('billing')`, and the app that installs the module can change any of these texts.

`@lupinum/ginko-components` and `@lupinum/ginko-docs` ship their texts this way.

## Before you start

You write a Nuxt module, and the app that uses it has `@lupinum/ginko-i18n` set up, see [i18n quick start]($docs.i18n-quick-start).

## Steps

::steps
#### Add the message files to the module

One file per language, in a folder of the module:

```json [modules/billing/i18n/en.json]
{ "invoice": "Invoice", "paid": "Paid on {day, date, long}" }
```

```json [modules/billing/i18n/de.json]
{ "invoice": "Rechnung", "paid": "Bezahlt am {day, date, long}" }
```

The keys have no prefix. The namespace adds it.

#### Register the folder

```ts [modules/billing/index.ts]
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: { name: 'billing' },
  setup(_options, nuxt) {
    const { resolve } = createResolver(import.meta.url)
    nuxt.hook('ginko-i18n:sources', (sources) => {
      sources.push({ namespace: 'billing', dir: resolve('./i18n') })
    })
  },
})
```

`namespace` is required. So a library can never replace a key of the app.

#### Translate in the module

`useI18n('billing')` takes keys relative to the namespace:

```vue
<script setup lang="ts">
const { t } = useI18n('billing')
</script>

<template>
  <h2>{{ t('invoice') }}</h2>
</template>
```

In a server route of the module, `getI18n(event, 'billing')` does the same.
::

## Check that it works

Use the component in a page. `/` shows "Invoice" and `/de` shows "Rechnung".

## Override a text in the app

The app sets the key under the namespace in its own file. Its text wins:

```json [i18n/en.json]
{ "billing": { "invoice": "Bill" } }
```

So the name of the namespace is reserved for the library. The app must not use it for its own messages.

## Missing translations of a library

`ginko-i18n check` in the app also checks the keys of a library. If the library has no German text for `paid`, the check says:

```text
error missing de billing.paid modules/billing/i18n/en.json:1: Missing translation
```

`ginko-i18n apply` writes a translation of a library key into the files of the app, under the namespace: `i18n/de.json` gets `{ "billing": { "paid": "…" } }`. The files of the library stay as they are.
