Diese Anleitung fügt einer Seite, die schon eigene Seiten hat, ein Handbuch unter `/handbook` hinzu. Am Ende behält die Seite ihre Kopf- und Fußzeile, und die Doku mit Navigation und Suche sitzt darin.

## Bevor du beginnst

Du brauchst eine Ginko-Seite, die läuft, zum Beispiel die aus dem [Schnellstart]($docs.getting-started). Ihre `app/app.vue` nutzt ein Layout:

```vue [app/app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

## Schritte

::steps
#### Das Kit installieren

```bash
npm install @lupinum/ginko-i18n @lupinum/ginko-docs
```

#### Das Kit erweitern

```ts [nuxt.config.ts]
import ginko from './ginko.config.ts'

export default defineNuxtConfig({
  extends: ['@lupinum/ginko-docs'],
  modules: ['@lupinum/ginko/nuxt'],
  ginko,
})
```

Behalte die Module, die deine Seite schon hat.

#### Den Doku-Baustein hinzufügen

Füg den Baustein neben den Bausteinen der Seite hinzu. `base` ist die Adresse der Doku:

```ts [ginko.config.ts]
import { defineSite, f, single } from '@lupinum/ginko'
import { components, docsCollection } from '@lupinum/ginko-docs/config'

const locales = ['en'] as const

export default defineSite({
  // …
  locales,
  components,
  bricks: {
    docs: docsCollection({ locales, base: '/handbook' }),
    // die Bausteine der Seite
  },
})
```

Hat die Seite eigene Komponenten, schreib `components: { ...components, ...own }`.

#### Die ersten Seiten schreiben

```markdown [content/docs/1.welcome.md]
---
title: Willkommen
description: Wie wir arbeiten, an einem Ort.
section: Grundlagen
---

Das ist die erste Seite des Handbuchs.
```

```markdown [content/docs/2.holidays.md]
---
title: Urlaub
description: Wie du freie Tage beantragst.
---

Frag deine Teamleitung zwei Wochen vorher.
```

#### Deine Kopfzeile behalten

Mit einem eigenen Layout behält die Seite ihre Kopf- und Fußzeile. Die Suche der Doku ist eine Komponente, die du in deine Kopfzeile setzen kannst:

```vue [app/layouts/default.vue]
<template>
  <div>
    <header>
      <NuxtLink to="/">Meine Firma</NuxtLink>
      <NuxtLink to="/handbook">Handbuch</NuxtLink>
      <DocsSearch />
    </header>
    <slot />
    <footer>© Meine Firma</footer>
  </div>
</template>
```

`<DocsLanguage />` ist das Sprachmenü und `<DocsThemeToggle />` der Hell-Dunkel-Schalter. Nur diese drei und `<DocsShell>` sind öffentlich; die anderen `Docs*`-Komponenten können sich in jedem Release ändern.

#### Die Doku öffnen

Öffne `/handbook`. Antwortet die Adresse mit 404, stopp den Dev-Server und starte ihn neu: Das Kit fügt seine Seiten beim Start des Servers hinzu.
::

## Prüfe, ob es funktioniert

- `/handbook` führt zu `/handbook/welcome`. Die Seite zeigt deine Kopfzeile, die Navigation mit „Willkommen“ und „Urlaub“ und deine Fußzeile.
- `/` ist weiter die Startseite der Seite.
- `/docs`, `/blog` und `/changelog` antworten mit 404. Das Kit fügt nur hinzu, was deine Konfiguration beschreibt.

## Was das Kit hinzufügt und was es lässt

- **Nur die Doku-Seiten.** Das Kit meldet die Doku unter ihrer `base` an. `/blog` und `/changelog` fügt es nur hinzu, wenn diese Bausteine existieren, und `/` nur, wenn die Seite keine Startseite hat. Eine Seite der Website an derselben Adresse gewinnt immer.
- **Styles bleiben drinnen.** Jede Regel des Kits steht unter einer `docs-`-Klasse. Deine Seiten behalten ihr Aussehen.
- **Titel.** Eine Doku-Seite hat den Titel `Seite · Name der Website` von Ginko (`seo.titleTemplate`). Ein `titleTemplate` in `app.head` gilt für sie nicht, also erscheint der Name nie doppelt.

## Die Doku an der Seite ausrichten

Ordne die Tokens deines Designs den Tokens des Kits zu. Zwei Layout-Tokens passen die Doku in deinen Rahmen ein:

```css [app/assets/css/main.css]
:root {
  --primary: var(--color-brand);
  --radius: 0.75rem;
  --docs-max: 82.5rem;  /* die Breite deines Inhalts-Containers */
  --docs-top: 4.5rem;   /* die Höhe einer klebenden Kopfzeile */
}
```

[Eine Doku-Seite gestalten]($docs.docs-theming) enthält alle Tokens.

## Ein anderer Name für den Baustein

Das Kit findet die Doku über den Baustein-Schlüssel `docs`. Für einen anderen Schlüssel, etwa `handbook`, gib ihn dem Baustein und dem Kit:

```ts [ginko.config.ts]
handbook: docsCollection({ locales, base: '/handbook', brick: 'handbook' }),
```

```ts [nuxt.config.ts]
ginkoDocs: { brick: 'handbook' },
```

Die Dateien liegen dann in `content/handbook/`, und Links auf die Seiten lauten `$handbook.<page>`.
