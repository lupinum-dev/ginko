Diese Seite listet, was `@lupinum/ginko-i18n` bietet. Die Anleitungen beginnen beim [i18n-Schnellstart]($docs.i18n-quick-start).

## Optionen

Die Optionen stehen unter `i18n` in `nuxt.config.ts`.

| Option | Standard | Bedeutung |
| --- | --- | --- |
| `locales` | Pflicht | Sprach-Tags wie `'de-AT'`, oder `{ language, code?, name? }`. Das Kürzel in der Adresse ist der erste Teil des Tags (`de-AT` ergibt `de`). Der Name ist der Name der Sprache in der Sprache selbst. |
| `defaultLocale` | die erste Sprache | Das Kürzel der Sprache ohne Präfix und die Sprache, auf die ein fehlender Text zurückfällt: `'de'`, nicht `'de-AT'`. |
| `strategy` | `'prefix_except_default'` | Oder `'prefix'`: Jede Sprache hat ein Präfix, und `/` leitet weiter. |
| `seo` | `true` | Die Head-Tags. `false` schaltet sie ab. |
| `baseUrl` | `runtimeConfig.public.siteUrl` | Die Adresse der Website, für vollständige Canonical- und `hreflang`-Links. Setz sie in Produktion. |
| `params` | `{}` | Parameter, die jeder Text nutzen kann, zum Beispiel `{ tone: 'sie' }` für `{tone, select, …}`. |
| `exclude` | `[]` | Weitere Pfade ohne Präfix. `/api/**` und die internen Pfade von Nuxt sind immer ausgenommen. |
| `userLocale` | `[]` | Pfade, deren Sprache vom Nutzer kommt, siehe [Apps hinter einem Login]($docs.i18n-apps-behind-a-login). |
| `timeZone` | `'UTC'` | Die Zeitzone der Website, etwa `'Europe/Vienna'`, für Zeiten in `format.date` und in Texten. |

Ein Muster in `exclude` und `userLocale` ist ein genauer Pfad (`'/studio'`) oder ein Präfix, das auf `/**` endet (`'/app/**'` ist `/app` und alles darunter). Kein anderes `*` ist erlaubt.

Jede andere Option stoppt die Einrichtung mit einer Meldung.

## useI18n

`useI18n(namespace?)` braucht in Komponenten, Seiten und Plugins keinen Import.

| Rückgabe | Typ | Bedeutung |
| --- | --- | --- |
| `t(key, params?, options?)` | Text | Der Text in der aktuellen Sprache. Schlüssel und Parameter sind aus den Dateien der Hauptsprache typisiert. |
| `parts(key, params?, options?)` | Liste | Der Text als Textteile und Tag-Teile, um `<tag>…</tag>` selbst zu rendern. |
| `has(key)` | Boolean | Ob es den Schlüssel in der aktuellen Sprache oder der Hauptsprache gibt. |
| `locale` | berechneter Text | Das Kürzel der aktuellen Sprache: `'en'`. |
| `language` | berechneter Text | Der Tag der aktuellen Sprache: `'en-GB'`. |
| `locales` | Liste | Jede Sprache: `{ code, language, name, dir }`. |
| `defaultLocale` | Text | Das Kürzel der Hauptsprache. |
| `localePath(path, code?)` | Text | Dieselbe Seite in `code` oder in der aktuellen Sprache. Es nimmt einen Pfad in jeder Sprache. Es nimmt keine Route-Objekte. |
| `alternates` | berechnete Liste | Die aktuelle Seite in jeder Sprache: die Sprache plus `path`, `current` und `translated`. Wo die Seite keine Übersetzung hat, ist `translated` false und `path` die Startseite dieser Sprache. |
| `switchLocale(code)` | Promise | Geht zur aktuellen Seite in `code` oder ändert die Sprache des Nutzers in einer Zone. Ein unbekanntes Kürzel wirft einen Fehler. |
| `format` | Objekt | Formatierung in der aktuellen Sprache, siehe unten. |

Mit einem Namensraum nimmt `useI18n('billing')` Schlüssel relativ zu ihm: `t('invoice')` für `billing.invoice`.

Ein fehlender Schlüssel zeigt den Schlüssel selbst und warnt im Dev-Modus. Ein Schlüssel, der in einer Sprache fehlt, zeigt den Text der Hauptsprache.

`localePath` übersetzt die Routen der App. Es kennt die Adressen von Inhaltseinträgen nicht: Verlinke diese mit den Pfaden, die dir deine Inhalte geben.

### format

`format` formatiert in der aktuellen Sprache und der `timeZone` der Website. Server und Browser erzeugen denselben Text. Die Beispiele gelten für `de-AT`:

| Methode | Beispiel |
| --- | --- |
| `format.date(value, style?)` | `format.date('2026-10-08')` ergibt `8. Oktober 2026`. `style` ist `'short'`, `'medium'`, `'long'` (Standard), `'full'` oder `Intl.DateTimeFormatOptions`. Ein Kalenderdatum verschiebt sich nie um einen Tag. |
| `format.range(from, to, style?)` | `format.range('2026-06-20', '2026-06-21')` ergibt `20.–21. Juni 2026`. |
| `format.relative(value, now?)` | `vor 5 Minuten`, `gestern`. Ruf es nach dem Mount auf oder übergib `now`, weil der Text von der aktuellen Zeit abhängt. |
| `format.number(value, options?)` | `format.number(1234.5)` ergibt `1 234,5`. |
| `format.currency(value, currency)` | `format.currency(12.5, 'EUR')` ergibt `€ 12,50`. Der Betrag ist in der Haupteinheit. Für ein Geldfeld von Ginko nimm `formatMoney`. |
| `format.list(items, type?)` | `format.list(['Äpfel', 'Birnen', 'Pflaumen'])` ergibt `Äpfel, Birnen und Pflaumen`. `type` ist `'conjunction'` oder `'disjunction'`. |

## I18nT

`<I18nT>` rendert einen Text mit Tags. Jeder Tag ruft den Slot mit demselben Namen mit `{ text }` auf, dem Inhalt des Tags als einfachem Text. Ein Tag ohne Slot rendert seinen Inhalt.

```vue
<I18nT k="legal.consent" :params="{ site: 'Linden Inn' }">
  <template #link="{ text }"><NuxtLink to="/privacy">{{ text }}</NuxtLink></template>
</I18nT>
```

| Prop | Bedeutung |
| --- | --- |
| `k` | Der volle Schlüssel. Ein Schlüssel einer Bibliothek enthält ihren Namensraum. Ein fehlender Schlüssel lässt die Typprüfung scheitern. |
| `params` | Die Parameter des Texts. Sie werden nicht gegen den Schlüssel geprüft; `t()` prüft sie. |

Ein Parameterwert bleibt Text: `<b>` in einem Wert wird nie als HTML gerendert.

## useLocaleSuggestion

Die Sprache wechselt nie von selbst. `useLocaleSuggestion()` liefert die aktuelle Seite in der Sprache des Browsers, wenn das eine andere Sprache ist und es die Seite dort gibt. Auf dem Server und bis die Seite gemountet ist, ist es `null`.

```vue
<script setup lang="ts">
const suggestion = useLocaleSuggestion()
</script>

<template>
  <p v-if="suggestion">
    <NuxtLink :to="suggestion.path">View in {{ suggestion.name }}</NuxtLink>
  </p>
</template>
```

## getI18n

`getI18n(event, namespace?)` braucht in Server-Routen keinen Import. Es liefert `{ locale, language, t, parts, has, format }` für die Sprache der Anfrage, siehe [Server-Routen und Server-Komponenten]($docs.i18n-server-routes).

## Seitenoptionen

Setz sie mit `definePageMeta` in einer Seite:

| Option | Bedeutung |
| --- | --- |
| `i18n: { paths: { de: '/ueber-uns' } }` | Die Adresse der Seite in einer Sprache. |
| `i18n: { locales: ['de'] }` | Die Seite gibt es nur in diesen Sprachen. |
| `i18n: false` | Eine Seite ohne Sprachen, zum Beispiel `/studio`. |
| `i18nAlternates: async (to, { locale, localePath }) => …` | Für eine Seite mit Slug: liefert die Adresse der Seite in jeder Sprache. |

### Seiten mit Slug

Eine Seite, deren Inhalt aus einem CMS kommt, sagt vor dem Rendern, welche Adresse sie in jeder Sprache hat. Dann stimmen Sprachwechsel, `hreflang`-Links und das HTML vom Server überein:

```ts [app/pages/blog/[slug].vue]
definePageMeta({
  i18nAlternates: async (to, { locale, localePath }) => {
    const post = await $fetch<{ slugs: Record<string, string> }>('/api/post', { query: { slug: to.params.slug, locale } })
    return Object.fromEntries(Object.entries(post.slugs).map(([code, slug]) => [code, localePath(`/blog/${slug}`, code)]))
  },
})
```

Gib `undefined` zurück, um die Routen der Seite selbst zu nutzen. Eine Sprache, die im Ergebnis fehlt, gilt als nicht übersetzt.

Ein Nuxt-Modul, dem viele solche Routen gehören, registriert in seinem Plugin einen Resolver mit `addAlternatesResolver(resolver)`. Der Resolver bekommt die Route und `{ locale, localePath }` und liefert einen Pfad pro Sprache, oder `undefined`, wenn die Route nicht seine eigene ist. `i18nAlternates` einer Seite gewinnt gegen ihn.

## Head-Tags und Adressen

- Jede Seite bekommt `<html lang dir>`, einen Canonical-Link, `hreflang`-Links mit `x-default` für die Hauptsprache und `og:locale`. Eine Sprache ohne Übersetzung der Seite bekommt kein `hreflang`.
- Ohne `baseUrl` und `runtimeConfig.public.siteUrl` sind die Links relativ, und der Build warnt.
- Fehlerseiten bekommen `lang`, `dir` und `robots: noindex`, und keinen Canonical-Link.
- Jede Seite hat eine Adresse. Andere Schreibweisen beantwortet der Server mit einem 301: doppelte Schrägstriche (`//blog`), ein Schrägstrich am Ende (`/blog/`) und ein Sprachkürzel in anderer Schreibung (`/EN/about`).
- Mit `@nuxtjs/sitemap` gibt das Modul ihm die übersetzten Adressen der festen Seiten. Seiten mit Slug sind nicht in dieser Liste: Füg sie über deine eigene Sitemap-Quelle hinzu.
- Mit `strategy: 'prefix'` hat `/` keinen Inhalt. Es leitet nach Cookie weiter, dann nach Browsersprache.

## Nachrichten-Syntax

Texte sind ICU MessageFormat:

| Syntax | Beispiel |
| --- | --- |
| Argument | `Hello {name}` |
| Plural (`#` ist die Zahl) | `{count, plural, =0 {No items} one {# item} other {# items}}` |
| Ordinalzahl | `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` |
| Auswahl | `{role, select, admin {Admin} other {Guest}}` |
| Zahl | `{total, number}`, `{share, number, percent}`, `{price, number, ::currency/EUR}` |
| Datum und Zeit | `{day, date, long}`, `{start, time, short}` |
| Tag | `I accept the <link>privacy policy</link>`, gerendert mit `<I18nT>` |
| Wörtlicher Text | `'{'` und `'<'`: Ein Apostroph maskiert |

Jedes `plural` und `select` braucht einen Fall `other`. Ein Schlüssel darf keinen Punkt enthalten und nicht leer sein.

## CLI

Das Tool `ginko-i18n` findet und behebt fehlende, veraltete und kaputte Übersetzungen. Es liest die Sprachdateien und das Manifest, das Nuxt in `.nuxt` schreibt. Fehlt das Manifest, führt es einmal `nuxt prepare` aus.

```bash
npx ginko-i18n check
npx ginko-i18n todo --locale de
npx ginko-i18n apply translations.json
```

| Befehl | Was er tut |
| --- | --- |
| `check` | Meldet fehlende und überzählige Übersetzungen, falsches ICU, abweichende Parameter, fehlende Pluralformen, veraltete Übersetzungen, Schlüssel, die der Code nutzt, aber keine Datei hat, und ungenutzte Schlüssel. |
| `check --locale <code>` | Listet die Befunde einer Sprache. Der Exit-Code zählt trotzdem alle Befunde. |
| `check --html <folder>` | Prüft das gebaute HTML: Canonical-Links, `hreflang`-Links in beide Richtungen, `x-default` und `lang`. |
| `todo --locale <code>` | Listet die zu übersetzenden Texte, jeden mit seinem Quelltext, seinen Parametern und der Stelle, an der der Code ihn nutzt. `--only missing` oder `--only stale` grenzt die Liste ein. |
| `apply <file>` | Schreibt Übersetzungen aus einer JSON-Datei in die Sprachdateien. `apply -` liest von stdin. |

Optionen für alle Befehle: `--cwd <app>`, `--build-dir <dir>`, `--json`, `--help`, `--version`. Um einen einfachen Ordner mit `<code>.json`-Dateien ohne Nuxt-App zu prüfen, ergänze `--dir <folder> --default-locale <code>`.

Die Eingabe von `apply`:

```json
{
  "locale": "de",
  "items": [{ "key": "greeting", "text": "Hallo {name}" }]
}
```

`locale` darf nicht die Hauptsprache sein: Ihre Dateien sind die Quelle. Jedes Element muss gültiges ICU sein und die Parameter der Quelle nutzen. Gültige Elemente werden gespeichert, auch wenn andere abgelehnt werden. `i18n/i18n.lock.json` hält einen Hash jedes übersetzten Quelltexts fest. Ändert sich die Quelle später, meldet `check` die Übersetzung als `stale`.

`i18n/glossary.json` ist eine eigene Datei, in beliebiger Form, für Markennamen und Tonfall. `todo --json` gibt sie an den Übersetzer weiter.

Befunde von `check`:

| Code | Schwere | Bedeutung |
| --- | --- | --- |
| `missing` | error | Eine Sprache hat keine Übersetzung für einen Schlüssel der Hauptsprache. |
| `stale` | warning | Der Quelltext hat sich geändert, nachdem die Übersetzung geschrieben wurde. |
| `extra` | warning | Eine Sprache hat einen Schlüssel, den die Hauptsprache nicht hat. |
| `plural-missing` | warning | Einem Plural-Text fehlt eine Form, die die Sprache braucht. |
| `params-mismatch` | error | Eine Übersetzung nutzt andere Parameter als die Quelle. |
| `invalid-icu` | error | Ein Text ist kein gültiges ICU. |
| `unknown-key` | error | Der Code nutzt einen Schlüssel, den keine Datei hat. |
| `unused` | warning | Das Tool fand keine Nutzung eines Schlüssels im Code. |
| `seo-canonical`, `seo-hreflang-self`, `seo-hreflang-reciprocal`, `seo-x-default`, `seo-lang` | error | Probleme, die `check --html` findet. |

Exit-Codes: `0` ohne Fehler, `1` bei Fehlern oder abgelehnten Elementen, `2` bei einer falschen Kommandozeile. Nur Warnungen ergeben `0`. Mit `--json` ist die Ausgabe ein JSON-Objekt: `{ ok, summary, findings }` für `check`, `{ ok, locale, items, … }` für `todo`, `{ ok, written, rejected, warnings }` für `apply`.

## Ohne Nuxt

Der Übersetzer läuft auch ohne Nuxt: in Convex-Funktionen, E-Mails, Skripten oder einem anderen Framework. Kompiliere die Texte mit `@lupinum/ginko-i18n/compile` und übersetze dann mit `@lupinum/ginko-i18n/core`, das keinen Parser hat:

```ts
import { compileCatalogs } from '@lupinum/ginko-i18n/compile'
import { defineCatalog, type KeysOf } from '@lupinum/ginko-i18n/core'
import de from './i18n/de.json'
import en from './i18n/en.json'

const catalog = defineCatalog<KeysOf<typeof en>>(compileCatalogs({ en, de }), { defaultLocale: 'en' })

catalog.t('de-AT', 'mail.invite.subject', { site: 'Linden Inn' }) // a full tag finds `de`
catalog.t(undefined, 'mail.invite.subject', { site: 'Linden Inn' }) // the default language
```

`compileCatalogs` führt den Parser aus. Ruf es in einem Build-Schritt oder auf einem Server auf, nicht im Browser. Speichere deine Quelldateien, nicht das kompilierte Ergebnis: Seine Form kann sich in jedem Release ändern.

| Export von `/core` | Bedeutung |
| --- | --- |
| `defineCatalog(trees, { defaultLocale, params? })` | Ein Katalog mit `t(locale, key, params?)`, `translator(locale)`, `locales`, `defaultLocale` und `isLocale(value)`. |
| `createTranslator({ messages, fallback?, language, timeZone?, … })` | Ein Übersetzer (`t`, `parts`, `has`) für eine Sprache. |
| `createFormatters(language, { timeZone? })` | Das `format`-Objekt von `useI18n()`. |
| `resolveConfig({ locales, defaultLocale?, strategy?, exclude?, userLocale? })` | Die Sprach-Konfiguration für die Funktionen darunter. |
| `localizePath(path, code, config)` | Fügt das Präfix hinzu: `/about` wird `/de/about`. |
| `stripLocale(path, config)` | Entfernt es. |
| `localeFromPath(path, config)` | Das Kürzel, zu dem ein Pfad gehört. |
| `negotiateLocale(header, config)` | Das beste Kürzel für einen `Accept-Language`-Header. |
| `cleanPath(path, config)` | Die eine Form eines Pfads, oder `undefined`, wenn er schon stimmt. |
| `alternatesOf(paths, config)` | Die `hreflang`-Links einer Seite aus ihrem Pfad pro Kürzel. |
| `ogLocale(language)` | `de-AT` wird `de_AT`. |
| `partsToString(parts)` | Der einfache Text eines Ergebnisses von `parts()`. |

| Export von `/compile` | Bedeutung |
| --- | --- |
| `compileCatalogs({ en, de })` | Kompiliert die Quelldateien jeder Sprache für `defineCatalog`. |
| `compileTree(raw)` | Kompiliert eine Sprache. |
| `MessageError` | Wird bei falschem ICU geworfen. `key` und `source` nennen den Text. |

## Content Security Policy

Die erste Seite hat die Texte ihrer Sprache in einem Inline-`<script>`, so braucht der Browser dafür keine Anfrage. Mit `strategy: 'prefix'` hat ein statisches `/` außerdem ein kleines Inline-Skript für die Weiterleitung. Eine strenge Policy muss beide mit einer Nonce oder einem Hash erlauben. Ist das Inline-Skript blockiert, lädt der Browser die Texte als Skriptdatei.

## Fehler

Jeder Fehler beginnt mit `[ginko-i18n]` und endet mit `Fix: …`.

| Fehler | Ursache und Lösung |
| --- | --- |
| `Unknown option(s) i18n.…` | Eine Option von `@nuxtjs/i18n`. Entferne sie, siehe [Von @nuxtjs/i18n wechseln]($docs.i18n-from-nuxtjs-i18n). |
| `@nuxtjs/i18n is also installed.` | Entferne eines der beiden Module. |
| `Two locales use the URL code "…".` | `de-AT` und `de-CH` werden beide zu `de`. Gib einem von ihnen einen `code`. |
| `Message "…" is not valid ICU` | Der Fehler nennt den Text und seinen Schlüssel. Jedes `plural` und `select` braucht `other`. |
| Das Manifest fehlt (CLI) | Trag das Modul in `nuxt.config.ts` ein und führe `nuxt prepare` aus. |
| Ein Link per Route-Name findet nichts | Die Routen heißen `about__en` und `about__de`. Verlinke mit `localePath('/about')`. |

## Typen

Aus `@lupinum/ginko-i18n`: `ModuleOptions`, `PageI18n`, `MessageSource`, `I18n` (was `useI18n` liefert), `ServerI18n` (was `getI18n` liefert), `Alternate`, `AlternatesResolver` und `TypedTranslator`.

Aus `/core`: `Translator`, `TranslateOptions`, `Params`, `Part`, `MessageTree`, `Catalog`, `Formatters`, `FormatterOptions`, `DateStyle`, `LocaleInfo`, `LocaleInput`, `LocaleConfig`, `Strategy`.
