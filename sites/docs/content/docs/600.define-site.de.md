`defineSite` beschreibt eine Seite. Es ist der Standard-Export von `ginko.config.ts`. Das Nuxt-Modul, das `ginko`-CLI und die Plattform lesen alle diese eine Datei.

```ts [ginko.config.ts]
import { collection, defineSite, f, single } from '@lupinum/ginko'

export default defineSite({
  site: 'cafe-linde',
  name: 'Café Linde',
  url: 'https://cafe-linde.example',
  timeZone: 'Europe/Vienna',
  locales: ['en', 'de'],
  currency: 'EUR',
  pages: {
    home: { en: '/', de: '/de' },
    menu: { en: '/menu', de: '/de/speisekarte' },
  },
  bricks: {
    start: single({ label: 'Startseite', source: 'files', fields: { title: f.text('Titel') } }),
  },
})
```

## Pflichtschlüssel

| Schlüssel | Typ | Bedeutung |
| --- | --- | --- |
| `site` | Text | Die Id der Seite: Kleinbuchstaben, Ziffern und `-`, höchstens 40 Zeichen, vorne ein Buchstabe. Die Plattform kennt die Seite unter dieser Id, und die Schlüssel der Seite enthalten sie. Wähle sie vor dem ersten Release. |
| `name` | Text | Der Name der Seite für Menschen. Er steht im Titel jeder Seite und in `/llms.txt`. |
| `url` | URL | Die Adresse der Live-Seite, mit `https://` und ohne Pfad, Query oder `#`. Canonical-Links, die Sitemap und Teilen-Bilder beginnen damit. Jeder andere Host bekommt `noindex`. |
| `timeZone` | IANA-Name | Die Zeitzone der Seite, zum Beispiel `Europe/Vienna`. „Heute“ und jede Datumsgrenze richten sich danach. |
| `locales` | Liste von Codes | Die Sprachen der Seite. Die erste ist die Hauptsprache: der Standard für Inhalte und für Seiten mit einfachem Pfad. Höchstens 20. |
| `currency` | ISO-4217-Code | Die Währung jedes Geldfeldes, zum Beispiel `EUR`. |
| `pages` | Objekt | Die festen Seiten der Seite nach Schlüssel. Siehe [Seiten](#seiten). |
| `bricks` | Objekt | Die Inhalte der Seite nach Schlüssel. Siehe [single und collection]($docs.bricks). Höchstens 30. |

## Optionale Schlüssel

| Schlüssel | Typ | Standard | Bedeutung |
| --- | --- | --- | --- |
| `platform` | URL | keiner | Die Adresse der Plattform, aus der die Seite liest. Die Variable `NUXT_PUBLIC_GINKO_PLATFORM` hat Vorrang. |
| `languages` | Objekt | der Code selbst | Das vollständige Sprach-Tag pro Code, zum Beispiel `{ de: 'de-AT' }`. Es setzt `lang`, hreflang und die Form von Daten und Zahlen. |
| `firstDayOfWeek` | `1` bis `7` | nach Sprache | Der erste Tag der Woche, `1` für Montag. Ohne Angabe richtet sich der Tag nach der Hauptsprache: Montag für `de-AT`, Sonntag für `en-US`. |
| `country` | ISO-3166-Code | keiner | Das Land der Seite, zum Beispiel `AT`. Es wählt die Feiertage und ist das Standardland in JSON-LD. |
| `calendar` | `'AT'`, `'DE'`, `'SG'`, `'none'` oder eine Funktion | nach `country` | Welche Feiertage für Öffnungszeiten zählen. Siehe [Restaurant-Referenz]($docs.restaurant-reference#feiertage). |
| `linkCheck` | Objekt | siehe unten | Wie streng die Link-Prüfung ist. Siehe [Link-Prüfung](#link-pruefung). |
| `redirects` | Liste | keine | Alte Adressen, die auf neue weiterleiten. Siehe [Weiterleitungen](#weiterleitungen). |
| `seo` | Objekt | siehe unten | Standards für Titel und Teilen-Karten. Siehe [SEO-Standards](#seo-standards). |
| `agents` | Objekt | an | Text für KI-Agenten. Siehe [Agenten](#agenten). |
| `components` | Registry | keine | Die Komponenten, die ein Markdown-Text verwenden darf. Siehe [Komponenten einrichten]($docs.set-up-components). |
| `facts` | Liste | keine | Werte, die Texte zitieren dürfen. Siehe [Fakten](#fakten). |
| `migrations` | Objekt | keine | Funktionen, die ein neues Feld aus alten Werten füllen. Siehe [Schemas wachsen nur]($docs.schemas-only-grow). |
| `retired` | Objekt | keine | Felder und Bausteine, die das Studio verlassen. Siehe [Schemas wachsen nur]($docs.schemas-only-grow). |

## Seiten

`pages` nennt jede feste Seite mit einem Schlüssel und ihrer Adresse. Seiten von Einträgen stehen nicht hier: Eine Sammlung setzt sie mit `route`.

```ts
pages: {
  home: { en: '/', de: '/de' },
  menu: { en: '/menu', de: '/de/speisekarte' },
  imprint: '/imprint',
}
```

- Ein Objekt gibt die Adresse in jeder Sprache an. Die Sitemap und der Sprachwechsel verbinden die Sprachen eines Schlüssels.
- Ein einfacher Pfad ist eine Seite nur in der Hauptsprache.
- Die Startseite ist die Seite, deren Adresse in der Hauptsprache `/` ist.
- Ein Link in einem Text erreicht eine Seite als `$pages.<key>`. Siehe [Zwischen Seiten verlinken]($docs.link-between-pages).

Die Vue-Datei für jede Seite schreibst du selbst. `pages` sagt Ginko, dass die Adresse existiert. So kennen die Link-Prüfung, die Sitemap und hreflang sie. [Adressen übersetzen]($docs.translate-addresses) zeigt, wie Adressen und Dateien zusammenpassen.

## Link-Prüfung

Der Build und `ginko check` prüfen jeden Link in deinen Inhalten. `linkCheck` setzt die Stufe für jede Art von Befund: `'error'` stoppt den Build, `'warn'` gibt eine Zeile aus, `'off'` überspringt die Prüfung.

| Schlüssel | Standard | Befund |
| --- | --- | --- |
| `broken` | `'error'` | Ein Link auf eine Seite, einen Eintrag oder eine Datei, die es nicht gibt. |
| `anchors` | `'warn'` | Ein `#heading`, das die Zielseite nicht hat. |
| `redirected` | `'warn'` | Ein Link auf eine Adresse, die auf eine andere weiterleitet. |
| `external` | aus | Ein Link auf eine andere Website, die nicht antwortet. Die Prüfung fragt über das Netzwerk, im Build und in `ginko check`, nie im Dev-Modus. |

```ts
linkCheck: { anchors: 'error', external: 'warn' }
```

## Weiterleitungen

Eine umgezogene Seite antwortet mit einer Weiterleitung, standardmäßig **301**. Es gibt drei Quellen:

- Ein Eintrag nennt seine alten Adressen in `redirectFrom`. Siehe [Eine Seite umziehen, ohne ihre Adresse zu verlieren]($docs.move-a-page).
- Auf der Plattform ändert ein Inhaber die Adresse einer Seite im Studio. War die Seite online, leitet die alte Adresse auf die neue weiter und bleibt reserviert.
- Die Seite listet Regeln in `redirects`:

```ts
redirects: [
  { from: '/speisekarte', to: '/menu' },
  { from: '/events/:slug', to: '/whats-on/:slug' },
  { from: '/old-blog/*', to: '/blog/:splat', status: 302 },
]
```

| Schlüssel | Typ | Bedeutung |
| --- | --- | --- |
| `from` | Pfad | Die alte Adresse. `:name` passt auf einen Teil des Pfads. Ein `*` am Ende passt auf den Rest. |
| `to` | Pfad oder URL | Die neue Adresse. Sie kann `:name` aus `from` verwenden, und `:splat` für den Teil, auf den `*` gepasst hat. |
| `status` | `301`, `302`, `307` oder `308` | Der Statuscode. Standard `301`. |

Die erste Regel, die passt, gewinnt. Der Query-String bleibt erhalten. Eine ungültige Regel stoppt den Build. Ein statischer Build (`nuxt generate`) unterstützt nur Regeln mit genauen Pfaden, siehe [Eine statische Seite bauen]($docs.static-site).

## SEO-Standards

`seo` setzt Standards für die Head-Tags, die `useGinkoSeo` schreibt.

| Schlüssel | Standard | Bedeutung |
| --- | --- | --- |
| `titleTemplate` | `%s · <name>` | Die Form jedes Seitentitels. `%s` ist der Titel der Seite. |
| `description` | keiner | Die Beschreibung einer Seite, die selbst keine setzt. |
| `image` | keiner | Das Teilen-Bild einer Seite ohne eigenes: ein Pfad in `public/` oder eine volle URL. Eine erzeugte Teilen-Karte ersetzt es. |
| `color` | keiner | Die Markenfarbe als `#rrggbb` oder `#rgb`. Sie ist der Hintergrund erzeugter Teilen-Karten. |
| `organization` | keiner | `{ logo, sameAs }`: das Logo und die Profil-Links für die `Organization`-Daten auf der Startseite. |
| `noindex` | keiner | Schlüssel von `pages`, die aus der Suche bleiben, zum Beispiel eine Danke-Seite. Sie verlassen die Sitemap und antworten mit `X-Robots-Tag: noindex`. |

[Titel und Teilen-Karten setzen]($docs.titles-and-share-cards) zeigt sie im Einsatz.

## Agenten

`agents` steuert, was die Seite KI-Agenten anbietet.

| Schlüssel | Standard | Bedeutung |
| --- | --- | --- |
| `enabled` | `true` | `false` schaltet `/llms.txt`, `/llms-full.txt` und die Markdown-Version jeder Seite ab. |
| `description` | `seo.description` | Die Zeile unter dem Namen der Seite in `/llms.txt`. |
| `review` | `false` | `true` lässt alles, was ein Agent auf der Plattform schreibt, auf ein Ja eines Inhabers warten. |

Siehe [Seiten für KI-Agenten ausliefern]($docs.pages-for-agents).

## Fakten

`facts` listet Werte von Einzelstücken, die Texte zitieren dürfen, jeweils als `brick.field`:

```ts
facts: ['practice.price', 'site.phone']
```

Ein Markdown-Text schreibt dann `:fact{name="practice.price"}`. Die Seite, die Suche und die Markdown-Version zeigen den Wert, der gerade gilt. Ein Preis, den ein Inhaber im Studio ändert, ändert sich also in jedem Text. Ein Fakt kann ein Text-, Zahl-, Geld-, Datums-, Zeit- oder Auswahlfeld sein, oder eine Liste mit einer Spalte.

## Was ein Release vergleicht

Bei einer Seite mit Plattform-Bausteinen schickt `ginko release` das Schema an die Plattform. Das Schema enthält `site`, `name`, `url`, `timeZone`, `locales`, `languages`, `currency`, den ersten Tag der Woche, die Feiertage, `pages`, `bricks`, `components`, `migrations`, `retired` und `agents.review`. [Schemas wachsen nur]($docs.schemas-only-grow) sagt, welche davon sich ändern dürfen und wie.

`platform`, `redirects`, `seo`, `linkCheck` und die anderen Schlüssel von `agents` gehören nicht zum Schema. Sie ändern sich allein mit einem Deploy.

## Sprachoptionen stehen nicht hier

Die Optionen für Adressen und Spracherkennung gehören zum Modul `@lupinum/ginko-i18n`. Setze sie unter `i18n` in `nuxt.config.ts`: `strategy`, `exclude`, `userLocale`, `params` und `seo`. Die [i18n-Referenz]($docs.i18n-reference#optionen) listet sie.

Ginko gibt `locales`, die Hauptsprache, `url` und `timeZone` aus `defineSite` an dieses Modul weiter. Setze `locales`, `defaultLocale`, `baseUrl` oder `timeZone` nicht unter `i18n`: Sonst stoppt der Build.
