This guide adds a blog and a changelog to a docs site. At the end, `/blog` lists your posts, `/blog/rss.xml` is the feed, `/changelog` lists your releases, and the header links to both.

Both parts are optional and do not depend on each other.

## Before you start

You need a site on the docs kit, see [Start a docs site]($docs.start-a-docs-site). The template `docs` already has the changelog.

## Add the blog

::steps
#### Add the bricks and the list page

```ts [ginko.config.ts]
import { blogCollections, components, docsCollection } from '@lupinum/ginko-docs/config'

export default defineSite({
  // …
  pages: {
    home: '/',
    blog: '/blog',
  },
  entries: { docs: '/docs/[slug]', posts: '/blog/[slug]' },
  bricks: {
    docs: docsCollection(),
    ...blogCollections(),
  },
})
```

`blogCollections` returns two bricks, `posts` and `authors`. The line `posts` in `entries` is the page of a post; `blog` in `pages` is the list page, so the sitemap and a static build know it.

#### Add an author

An author is a YAML file. Its name is the id of the author:

```yaml [content/authors/jane.yml]
name: Jane Doe
role: Maintainer
url: https://example.com/jane
```

`avatar` takes an image. Authors have no page of their own.

#### Write a post

```markdown [content/posts/1.hello.md]
---
title: Version 2 is out
description: What is new in version 2.
date: 2026-11-20
authors: [authors/jane]
tags: [release]
---

Version 2 has a new client and typed webhooks.
```

The address comes from the file name: this post is `/blog/hello`. `image` adds a picture to the post and its card.

#### Start the dev server again

Stop the dev server and start it again. The kit adds the blog pages when the server starts.
::

## Add the changelog

::steps
#### Add the brick and the page

```ts [ginko.config.ts]
import { changelogCollection } from '@lupinum/ginko-docs/config'

// …
  pages: { changelog: '/changelog' },
  bricks: { changelog: changelogCollection() },
```

#### Write one file per release

```markdown [content/changelog/v2-0-0.md]
---
version: 2.0.0
date: 2026-11-20
---

- The client has typed webhooks.
- `createMonitor` takes a `regions` list.
```

Write the file name without dots, because a dot reads as a language: `v2-0-0.md`, not `v2.0.0.md`.
::

## Check that it works

- `/blog` shows the post with its date, the author "Jane Doe" and the tag "release". The newest post is first.
- `/blog/hello` shows the post.
- `/blog/rss.xml` is an RSS feed with the title and the description of each post. Other languages have their own feed at `/<language>/blog/rss.xml`.
- `/changelog` shows all releases, newest first. Each has an anchor such as `#v2-0-0`.
- The header has the links "Blog" and "Changelog".

## Things to know

- The feed holds the title and the description of a post, not its text.
- Without `blog` or `changelog` in `pages`, the build warns, and the list page is missing from the sitemap.
- The kit finds its content by the brick keys `posts`, `authors` and `changelog`. Keep these names.
- A post or a release in another language is a file with the language code: `1.hello.de.md`.
