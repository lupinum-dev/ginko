This guide gives a docs site your look. At the end, the site has your accent colour in light and dark mode, and a line of your own under every page.

Change tokens first. Replace a part only when the tokens cannot give you the result. Everything on this page is public and stays stable between releases.

## Before you start

You need a site on the docs kit, see [Start a docs site]($docs.start-a-docs-site), and one CSS file that the site loads. The template has `app/assets/css/main.css`.

## Steps

::steps
#### Pick a preset

`theme` picks one of two colour presets:

```ts [app/app.config.ts]
export default defineAppConfig({
  docs: { theme: 'green' },
})
```

| Preset | Colours |
| --- | --- |
| `default` | Emerald on zinc |
| `green` | Green on slate |

A preset sets defaults only. Every token your site sets wins over both.

#### Set your colours

The kit reads shadcn-style tokens, the same ones the components read. Write each value as a pair `light-dark(light, dark)`:

```css [app/assets/css/main.css]
:root {
  --primary: light-dark(#2f6f4f, #7cc59d);
  --primary-foreground: light-dark(#ffffff, #0c1f15);
  --ring: light-dark(#2f6f4f, #7cc59d);
}
```

Set `--primary-foreground` together with `--primary`. A light colour such as yellow needs dark text. Check the contrast in both modes.

The tokens are `--background`, `--foreground`, `--muted`, `--muted-foreground`, `--accent`, `--border`, `--primary`, `--primary-foreground`, `--card`, `--popover`, `--ring`, `--radius`, `--font-sans` and `--font-mono`.

#### Set your font

Load the font in your site first, then name it:

```css [app/assets/css/main.css]
:root {
  --font-sans: 'Inter', system-ui, sans-serif;
}
```

The kit brings Inter and JetBrains Mono. On a Tailwind 4 site that sets no `--font-sans` and `--font-mono`, the fonts of Tailwind win.

#### Add a part of your own

The kit has two empty components. A file with the same name in `app/components/` replaces one:

```vue [app/components/DocsPageEnd.vue]
<script setup lang="ts">
defineProps<{ doc: { id: string } }>()
</script>

<template>
  <aside class="support">Questions? <a href="mailto:help@example.com">Write to us</a>.</aside>
</template>
```

| Component | Props | Where it appears |
| --- | --- | --- |
| `DocsPageEnd` | `doc`, the entry of the page | After the text of every docs page, before "Edit this page" |
| `DocsSidebarEnd` | none | Below the navigation, in the sidebar and in the phone menu |

Do not replace other `Docs*` components. They are internal and can change in any release.
::

## Check that it works

- Open a docs page. Links and the active page in the navigation have your colour. Switch to dark mode in the header: they have the dark value.
- With `theme: 'green'`, the `<html>` element has `data-docs-theme="green"`.
- Under the text of every page, the line "Questions? Write to us." shows.

## Light and dark

Without a choice, the site follows the system. The switch in the header stores the choice of the reader in `localStorage` (key `docs-color-mode`) and sets `data-theme="light"` or `data-theme="dark"` on `<html>`. A small script in the head applies it before the first paint, so nothing flickers.

A `.dark` class on `<html>`, for example from `@nuxtjs/color-mode`, works too.

## Sizes

| Token | Default | What it sets |
| --- | --- | --- |
| `--docs-max` | `90rem` | Width of the docs, gutters included |
| `--docs-gutter` | `1rem` | Space between the window edge and the docs |
| `--docs-top` | `0px` (standalone: the header) | Height of what sticks above the docs |
| `--docs-sidebar` | `17rem` | Width of the navigation |
| `--docs-toc` | `13.5rem` | Width of "On this page" beside the text (from a window width of 80rem) |
| `--docs-measure` | `38rem` | Reading width of running text |
| `--docs-h1` | `clamp(1.75rem, …, 2.25rem)` | Size of page titles |
| `--docs-header` | `4rem` | Height of the standalone header |

## Your own page in the docs frame

`<DocsShell>` is the body of the docs: the navigation, the search and the bar on phones. Put your own page into it:

```vue [app/pages/help/index.vue]
<script setup lang="ts">
const docs = useGinko('docs')
</script>

<template>
  <DocsShell>
    <h1>How can we help?</h1>
    <ul>
      <li v-for="item in docs.items" :key="item.id">
        <NuxtLink :to="item.url">{{ item.data.title }}</NuxtLink>
      </li>
    </ul>
  </DocsShell>
</template>
```

- A page of your site at the same address as a page of the kit wins, for example `app/pages/index.vue`.
- With `docs: { search: false }` the kit leaves out its own search, for a site with `<DocsSearch />` in its own header.

## Change the texts of the kit

Every text of the kit is a message under `docs.*`. The messages of your site win key by key:

```json [i18n/en.json]
{ "docs": { "searchPlaceholder": "Search help…" } }
```

The kit brings English, German and French.

## Do not copy the kit

A copy of the kit in your site gets no fixes, and it becomes unclear whether a token, an option or your code decides. The CSS classes of the kit are no contract either. Style through the tokens.
