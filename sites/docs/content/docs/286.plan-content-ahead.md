Owners often know a change before it applies: a new price from 1 November, the lunch menu of next week, new opening hours from spring. This guide shows the three ways to prepare such a change, so that the site switches by itself on the day.

All three are for bricks on the platform.

## A new value for one field from a date

`planned` gives a field a second value and the date from which it applies:

```ts [ginko.config.ts]
menu: collection({
  label: 'Menu',
  planned: { field: 'price', next: 'nextPrice', from: 'priceFrom' },
  fields: {
    name: f.text('Name', { max: 120 }),
    price: f.money('Price'),
    nextPrice: f.money('New price', { optional: true }),
    priceFrom: f.date('New price from', { optional: true }),
  },
  max: 150,
  order: 'manual',
}),
```

- `next` has the type of `field`. `from` is a date field. Both are optional: without a plan they stay empty.
- From the date in `priceFrom` on, the value of `nextPrice` applies in place of `price`.

In a page, ask for the value that applies today. `valueOn` takes the plan, the data of the entry, the field and a day:

```ts
import { valueOn } from '@lupinum/ginko'

const plan = { planned: { field: 'price', next: 'nextPrice', from: 'priceFrom' } }
const today = useGinkoToday()
const price = computed(() => valueOn(plan, item.data, 'price', today.value))
```

With a price of 6.50, a new price of 7.00 and `priceFrom: 2026-11-01`, `valueOn` returns 6.50 on 31 October and 7.00 from 1 November on. An entry without a plan returns its price.

`ginko check` reports a task that changes `price` and does not show `nextPrice` and `priceFrom`. So nobody changes a price without seeing the planned one.

## Whole weeks of a single

A lunch menu is a single: one menu for the current week. With `plans`, the entries of a second collection hold the menus of later weeks:

```ts [ginko.config.ts]
lunchPlans: collection({
  label: 'Plan the lunch menu ahead',
  plans: { brick: 'lunch', field: 'weekOf' },
  fields: {
    weekOf: f.date('Week of'),
    // the same fields as the single `lunch`
  },
  max: 12,
  order: { field: 'weekOf', dir: 'asc' },
}),
```

`weekOf` holds the first day of the week. The page shows the planned week from that day on. The restaurant preset has this pair ready: `lunch()` and `lunchPlans()`, and `hours()` with `hourPlans()` for opening hours from a date. [Presets]($docs.presets) describes them.

## Publish at a set time

Every change in the Studio can go live later. The person saves the change, chooses "Publish …" and sets a day and a time. Until then, the site shows the current content.

This needs nothing in the config.

## Which one to use

| The owner wants | Use |
| --- | --- |
| a new price, phone number or text from a known day, and still see the current one | `planned` |
| next week's version of a whole single, entered ahead | `plans` |
| any other change to go live at a time | "Publish …" in the Studio |
