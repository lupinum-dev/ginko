## Sprachen festlegen

Die Sprachen einer Seite stehen in `locales` in der `ginko.config.ts`. Erlaubt ist jedes kanonische Sprach-Tag, zum Beispiel `'es'`, `'pt-BR'` oder `'zh-Hant'`. Das Tag ist auch das Präfix in der Adresse (`/pt-BR/…`). Die erste Sprache ist die **Hauptsprache**. Ihre Seiten haben kein Präfix, die anderen Sprachen bekommen eines:

```ts
export default defineSite({
  site: 'restaurant',
  locales: ['de', 'en'],   // /speisekarte (de) und /en/menu (en)
  // …
})
```

Du installierst kein eigenes i18n-Modul. Das Ginko-Modul installiert **ginko-i18n** (`@lupinum/ginko-i18n`) und gibt ihm die Sprachen aus der Konfiguration. Die Hauptsprache ist die Standardsprache, und `url` dient als Basis für Canonical- und Hreflang-Links. Du darfst `@nuxtjs/i18n` nicht zusätzlich installieren.

ginko-i18n nimmt die Sprache aus der Adresse. Kein Cookie und kein Browser-Header ändert die Sprache einer Seite mit einer lokalisierten Adresse. Eine Ausnahme gibt es für Apps hinter einem Login: Die Pfade in `userLocale` folgen stattdessen dem Benutzer (Cookie `ginko_locale`, dann der Header `Accept-Language`), und `/api/**` immer. `userLocale` ist eine Option von ginko-i18n. Du setzt sie unter `i18n` in `nuxt.config.ts`; das Ginko-Modul reicht die übrigen `i18n`-Optionen weiter:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: { userLocale: ['/app/**'] }, // diese Pfade haben kein Sprachpräfix
})
```

ginko-i18n setzt für jede Seite `lang`, `dir`, `canonical`, `hreflang` und `og:locale`.

Die Texte der Inhalte sind pro Sprache gespeichert. Fehlt eine Übersetzung, zeigt das Bundle den Text der Hauptsprache. Siehe „Seiten lesen“, Abschnitt „Fallback“.

## Seitenpfade pro Sprache

Eine Seitendatei legt den Pfad der Hauptsprache fest. Datei `app/pages/speisekarte.vue` ist `/speisekarte`. Für andere Sprachen setzt du mit `definePageMeta` einen eigenen Pfad:

```vue
<!-- app/pages/speisekarte.vue -->
<script setup lang="ts">
definePageMeta({ i18n: { paths: { en: '/menu' } } })
</script>

<template><PageMenu /></template>
```

Die englische Seite hat den Pfad `/en/menu`. ginko-i18n setzt das Präfix `/en` selbst davor. Ohne Angabe heißt der englische Pfad `/en/speisekarte`.

Trage jeden festen Pfad auch in `pages` in der `ginko.config.ts` ein, mit dem Präfix:

```ts
pages: {
  home: { de: '/', en: '/en' },
  menu: { de: '/speisekarte', en: '/en/menu' },
},
```

Ginko nutzt `pages` für die Sitemap und für das sofortige Neuladen von Seiten.

## useI18n

`useI18n()` liefert die Werkzeuge für Texte und Sprachwechsel:

| Name | Bedeutung |
| --- | --- |
| `t(key, params)` | Gibt einen Text aus den Übersetzungsdateien zurück. |
| `locale` | Die aktuelle Sprache. |
| `localePath(pfad, sprache)` | Gibt den Pfad einer Seite in einer Sprache zurück. Die Sprache ist optional. |
| `alternates` | Die aktuelle Seite in jeder Sprache, für den Sprachwechsel. |

`localePath` nimmt den Pfad der Hauptsprache: `localePath('/speisekarte')` ergibt in der Hauptsprache `/speisekarte`, in der englischen Version `/en/menu`. Nutze `localePath` nur für Seiten deiner Seite. Für Detailseiten von Einträgen nimmst du die URLs aus dem Bundle (`item.urls`).

Ein Sprachwechsel aus `alternates`:

```vue
<script setup lang="ts">
const { alternates } = useI18n()
</script>

<template>
  <nav aria-label="Sprache">
    <NuxtLink
      v-for="a in alternates"
      :key="a.code"
      :to="a.path"
      :hreflang="a.language"
      :aria-current="a.current ? 'true' : undefined"
    >
      {{ a.code.toUpperCase() }}
    </NuxtLink>
  </nav>
</template>
```

## Übersetzungsdateien

Feste Texte der Seite, zum Beispiel Navigation und Beschriftungen, stehen in `i18n/<sprache>.json` neben der `nuxt.config.ts`. Das sind keine Inhalte aus Ginko-Bausteinen. Du legst eine Datei pro Sprache an:

```json [i18n/de.json]
{
  "nav": { "menu": "Speisekarte" },
  "weekOf": "Woche ab {date}"
}
```

```json [i18n/en.json]
{
  "nav": { "menu": "Menu" },
  "weekOf": "Week of {date}"
}
```

```vue
<script setup lang="ts">
const { t } = useI18n()
</script>

<template>
  <h1>{{ t('nav.menu') }}</h1>
  <p>{{ t('weekOf', { date: '5. Oktober' }) }}</p>
</template>
```

Die Texte nutzen das ICU-Format. Damit schreibst du zum Beispiel Mehrzahl-Regeln: `{count, plural, one {# Gericht} other {# Gerichte}}`. Fehlt ein Schlüssel in einer Sprache, zeigt die Seite den Text der Standardsprache. Prüfe die Dateien mit `npx ginko-i18n check`.

Ein Text mit Link oder Hervorhebung schreibt Tags in die Nachricht, zum Beispiel `"Ich akzeptiere die <link>Datenschutzerklärung</link>."`. `<I18nT>` füllt jedes Tag über einen Slot mit dem gleichen Namen:

```vue
<script setup lang="ts">
const { localePath } = useI18n()
</script>

<template>
  <I18nT k="legal.consent">
    <template #link="{ text }"><NuxtLink :to="localePath('/datenschutz')">{{ text }}</NuxtLink></template>
  </I18nT>
</template>
```

Alle Funktionen von ginko-i18n (Formate für Datum und Zahl, `getI18n` in Server-Routen, die Regeln für Links) stehen im [README von ginko-i18n](https://github.com/lupinum-dev/ginko/tree/main/packages/ginko-i18n#readme).

## Detailseiten

Ein Eintrag kann in jeder Sprache eine andere Adresse haben. Das Bundle liefert diese Adressen in `urls`. Die Seitendatei hat nur einen Pfad pro Sprache mit Platzhalter `:slug()`:

```vue
<!-- app/pages/docs/[slug].vue -->
<script setup lang="ts">
definePageMeta({ i18n: { paths: { de: '/doku/:slug()', en: '/docs/:slug()' } } })
const route = useRoute()
const doc = useGinkoEntry('docs', String(route.params.slug))
</script>
```

Der Pfad muss zur `route` des Bausteins passen. Dort steht `/doku/[slug]` für Deutsch und `/en/docs/[slug]` für Englisch.

Du musst keine `alternates` für Detailseiten schreiben. Das Ginko-Modul meldet die Adressen eines Eintrags aus dem Bundle an ginko-i18n. Darum zeigt der Sprachwechsel auf die richtige Adresse in der anderen Sprache, und `hreflang` stimmt. Hat ein Eintrag in einer Sprache keine Seite, gilt diese Seite dort als nicht übersetzt.

Mit `missing` im Baustein steuerst du, was bei fehlender Übersetzung geschieht:

- `'fallback'` (Standard) zeigt den Eintrag in jeder Sprache. Fehlt der Slug, gilt der Slug der Hauptsprache.
- `'hide'` blendet den Eintrag in einer Sprache aus, wenn ein übersetzbares Pflichtfeld dort fehlt oder veraltet ist.

::callout{type="note"}
Für Datei-Bausteine gilt: Eine vorhandene Übersetzung ist immer aktuell. Eine fehlende Datei löst den Fallback aus oder blendet den Eintrag aus, je nach `missing`.
::
