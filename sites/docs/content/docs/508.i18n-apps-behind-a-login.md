This guide gives the part of an app behind a login its own language rule. At the end, `/app` shows in the language of the user, the address has no language in it, and a button changes the language without a reload.

On public pages the language comes from the address. Behind a login that is wrong: the setting of the user decides, and `/app/invoices` is one address for everyone. A *user-locale zone* is a set of paths whose language comes from the user.

## Before you start

The app has `@lupinum/ginko-i18n` set up, see [i18n quick start]($docs.i18n-quick-start). The zone needs a server: it cannot be part of a static build.

## Steps

::steps
#### Name the zone

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-i18n'],
  i18n: {
    locales: ['en-GB', 'de-AT'],
    defaultLocale: 'en',
    baseUrl: 'https://example.com',
    userLocale: ['/app/**'],
  },
})
```

`'/app/**'` is `/app` and everything below it. For an app that is all behind a login, write `['/**']`.

#### Add a page in the zone

```vue [app/pages/app/index.vue]
<script setup lang="ts">
const { t, locale, locales, switchLocale } = useI18n()
</script>

<template>
  <main>
    <h1>{{ t('app.title') }}</h1>
    <button
      v-for="l in locales"
      :key="l.code"
      :disabled="l.code === locale"
      @click="switchLocale(l.code)"
    >
      {{ l.name }}
    </button>
  </main>
</template>
```

```json [i18n/en.json]
{ "app": { "title": "Dashboard" } }
```

```json [i18n/de.json]
{ "app": { "title": "Übersicht" } }
```

Add the two keys to the messages you have.

#### Set the cookie when the user signs in

The server reads the cookie `ginko_locale`. Set it from the setting in the account of the user, so the first page after the login already has the right language:

```text
Set-Cookie: ginko_locale=de; Path=/; Max-Age=31536000; SameSite=Lax
```
::

## Check that it works

- Open `/app`. It shows "Dashboard", or "Übersicht" if your browser asks for German.
- Press "Deutsch". The page shows "Übersicht" at once. The address stays `/app`, and the browser has the cookie `ginko_locale=de`.
- Open `/de/app`. It answers 404: the zone has no prefix.
- Open a public page such as `/about`. It is still English. The cookie does not change pages outside the zone.

## How the zone picks the language

The server sets the language once for each request, in this order:

1. the cookie `ginko_locale`,
2. the `Accept-Language` header of the browser,
3. the default language.

The browser takes the language from the server and never detects it again. So the HTML from the server and the page in the browser agree.

## What is different in a zone

- **No head tags for search engines.** A zone page has `lang` and `dir`, but no canonical link, no `hreflang` and no `og:locale`. There is no other address to point to. `alternates` is an empty list.
- **Not in the sitemap, not prerendered.** The module keeps zone pages out of both.
- **`switchLocale` works in place.** In a zone it writes the cookie, loads the messages and renders again. On a public page it goes to the same page in the other language.
- **Dates follow the region of the browser.** With the language `en`, a browser set to `en-GB` reads 25/10/2026 and one set to `en-US` reads 10/25/2026. A language with a region, such as `de-AT`, keeps it.

::callout{type="warning" title="Do not cache zone pages"}
Do not set `isr`, `swr` or `cache` route rules for a zone. The language comes from a cookie, so every visitor would get the language of the first one. The build warns when a rule does this.
::

## Zone or exclude

| Option | Means | The page shows in |
| --- | --- | --- |
| `userLocale` | localized by the user | the language of the user |
| `exclude` | not localized | the default language |

Paths in `exclude`, `/api/**` and the internal paths of Nuxt are never in a zone. So `userLocale: ['/**']` leaves them alone.
