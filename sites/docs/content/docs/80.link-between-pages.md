This guide links from a Markdown text to another entry or page of the site. At the end, your links survive a new slug or a new route, and a broken link stops the build.

## Steps

::steps
#### Link to an entry by its name

Write `$<brick>.<name>` as the target of the link. The name is the file name without number and language:

```markdown [content/news/1.opening.md]
Read more [about me]($pages.about).
```

This links to the entry of `content/pages/1.about.md`. On the page, the link leads to `/about`, and in the German version to the German address of the same entry.

#### Link to a fixed page by its key

A page of `pages` in `ginko.config.ts` has a key. Link to it with `$page.<key>`:

```markdown
Back to [the start page]($page.home).
```

#### Link to a heading

Add the id of a heading after `#`:

```markdown
See [the opening hours]($pages.contact#opening-hours).
```

The id of a heading is its text in lowercase with `-` between the words. A heading below another heading starts with the id of that heading: "Saturday" below "Opening hours" has the id `opening-hours-saturday`.

#### Run the check

```bash
npx ginko check
```

A link to nothing is an error, here a link to `$pages.nope`:

```text
content/news/opening: Link $pages.nope leads to no entry and no page.
```

A link to an entry that is hidden, such as a draft or an entry after its last day, is the same error.

A heading that does not exist is a warning:

```text
content/news/opening: Anchor #nope is missing: no heading with this id.
```
::

## Why not write the path

A path such as `/about` works today. It breaks without notice when the slug of the entry or the route of the brick changes, and it is wrong in every other language. Ginko writes the address of a `$` link at build time, for the language of the page.

## Set how strict the checks are

Every build and `ginko check` check the links in all Markdown fields.

| Check | What it finds | Default |
| --- | --- | --- |
| `broken` | a `$…` link to an entry or page that does not exist | `'error'` |
| `anchors` | a `#…` that is no heading on the target page | `'warn'` |
| `redirected` | a link to an old address that redirects | `'warn'` |
| `external` | an `http(s)://` link whose server answers 404 or 410, or does not answer | `'off'` |

`'error'` stops the build, `'warn'` prints the problem, `'off'` skips the check. Set the levels in `ginko.config.ts`:

```ts [ginko.config.ts]
export default defineSite({
  // …
  linkCheck: { anchors: 'error', external: 'warn' },
})
```

On a site whose bricks all come from files, `broken` also finds a written path (`/…`) that matches no entry, no page and no file in `public/`. The `external` check asks other servers, so it runs on a build and on `ginko check`, never in the dev server.
