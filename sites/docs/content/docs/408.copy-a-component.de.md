Diese Anleitung kopiert die Komponente `callout` in deine App. Am Ende liegt ihre Vue-Datei in deinem Repository, du kannst sie ändern, und dein Markdown nutzt deine Kopie.

Das npm-Paket ist der einfache Weg: Updates kommen mit dem Paket. Kopiere eine Komponente nur, wenn du ihren Code besitzen willst. Eine Kopie bekommt keine Updates.

## Bevor du beginnst

- Die Seite hat die Komponenten eingerichtet, siehe [Komponenten einrichten]($docs.set-up-components).
- Die Seite nutzt [shadcn-vue](https://www.shadcn-vue.com), hat also Tailwind CSS und eine `components.json`. Wenn nicht, folge zuerst der Nuxt-Installation von shadcn-vue: Installiere Tailwind CSS und starte dann `npx shadcn-vue@latest init`.

Ohne `components.json` fragt der Befehl in Schritt 1, ob er eine anlegen soll, und hört dort auf.

## Schritte

::steps
#### Den Befehl starten

Die Ginko-Doku stellt jede Komponente als Eintrag einer shadcn-vue-Registry bereit:

```bash
npx shadcn-vue@latest add https://ginko.lupinum.com/r/callout.json
```

Die CLI schreibt die Komponente und die Dateien, die sie braucht, nach `app/components/ginko/`:

```text
✔ Created 13 files:
  - app/components/ginko/ginko-components.css
  - app/components/ginko/Callout.vue
  - app/components/ginko/aliases.ts
  - app/components/ginko/texts.ts
  …
```

Der Name eines Eintrags ist der Dateiname in Kebab-Case: `callout`, `code-block`, `timeline-item`. [`/r/registry.json`](https://ginko.lupinum.com/r/registry.json) listet alle.

#### Das Stylesheet importieren

Importiere das Stylesheet einmal in deiner Haupt-CSS-Datei. Der Pfad ist relativ zu dieser Datei:

```css [app/assets/css/tailwind.css]
@import "tailwindcss";
@import "../../components/ginko/ginko-components.css";
```

Es liest die shadcn-Tokens deiner Seite, siehe [Komponenten gestalten]($docs.theme-the-components).

#### Deine Kopie in Markdown nutzen

Gib die Kopie für ihren Tag an `<GinkoMarkdown>`:

```vue [app/pages/index.vue]
<script setup lang="ts">
import Callout from '~/components/ginko/Callout.vue'

const start = useGinko('start')
</script>

<template>
  <GinkoMarkdown :value="start.data.body" :components="{ callout: Callout }" />
</template>
```

#### Die Komponente ändern

Öffne `app/components/ginko/Callout.vue` und ändere sie. Es ist jetzt dein Code.
::

## Prüfe, ob es funktioniert

Ändere das Template von `Callout.vue`, setz zum Beispiel ein Wort hinter den Titel. Öffne eine Seite mit einem `::callout`. Der Hinweis zeigt deine Änderung.

## Was einer Kopie fehlt

- **Updates.** Eine neue Version des Pakets ändert deine Kopie nicht. Starte den Befehl noch einmal, um den neuen Quelltext zu holen, und vergleiche ihn mit deinem.
- **Übersetzte Texte.** Eine kopierte Komponente nutzt die englischen Texte in `app/components/ginko/texts.ts`. Ändere sie dort.
- **Die Kurzformen.** `::note`, `::warning` und die anderen Kurzformen von `callout` sind eigene Tags. `aliases.ts` exportiert für jede eine Komponente (`NoteCallout`, `WarningCallout`, …). Gib sie genauso an: `{ callout: Callout, note: NoteCallout }`.
- **Die Registry.** Die Liste der Tags und Props für die Prüfung kommt weiter aus `@lupinum/ginko-components/registry`. Gibst du deiner Kopie eine neue Prop, beschreib den Tag in deiner Konfiguration neu, siehe [Eigene Komponente hinzufügen]($docs.add-your-own-component#eine-komponente-des-pakets-ersetzen).
