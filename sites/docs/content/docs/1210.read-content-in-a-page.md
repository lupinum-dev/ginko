This guide shows the content of your bricks in a page. At the end, a page shows the values of a single and the list of a collection, with types from your config.

## Before you start

The site has a single and a collection. The examples use a single `start` with a title and a text, and a collection `prices` with a title, a price and a yes/no value. [Model your content]($docs.model-your-content) shows how to add bricks.

## Steps

::steps
#### Read a single

`useGinko` reads one brick by its name. For a single, the fields are in `data`:

```vue [app/pages/index.vue]
<script setup lang="ts">
const start = useGinko('start')
</script>

<template>
  <main>
    <h1>{{ start.data.title }}</h1>
  </main>
</template>
```

You do not import `useGinko`. The Ginko module makes it available in every page and component.

#### Show a formatted text

A Markdown field is not a string. Show it with `<GinkoMarkdown>`:

```vue
<GinkoMarkdown :value="start.data.body" />
```

The component writes headings, lists and links as HTML elements. It runs no parser in the browser and never inserts raw HTML.

#### List a collection

For a collection, the entries are in `items`. Each item has an `id` and its fields in `data`:

```vue
<script setup lang="ts">
const prices = useGinko('prices')
</script>

<template>
  <ul>
    <li v-for="item in prices.items" :key="item.id">
      {{ item.data.title }}
    </li>
  </ul>
</template>
```

The list has the order that the brick sets, and it holds only the entries that are visible today.

#### Use a value in the script

`useGinko` returns a ref. In the template you write `start.data.title`. In `<script>` you add `.value`:

```ts
const start = useGinko('start')
const title = start.value.data.title
```

#### Check the result

Open the page. It shows the title of the single and one line per entry. In the German version of the page, each text shows its German translation. A text without a translation shows the text of the main language.
::

## Types come from your config

Your editor knows the fields of each brick. `item.data.` lists them, and a field that the brick does not have is an error in the editor. An optional field can be `undefined`.

When a component gets an entry as a prop, use the type `GinkoItem` with the name of the brick. You do not import it:

```vue [app/components/PriceRow.vue]
<script setup lang="ts">
defineProps<{ item: GinkoItem<'prices'> }>()
</script>

<template>
  <li>{{ item.data.title }}</li>
</template>
```
