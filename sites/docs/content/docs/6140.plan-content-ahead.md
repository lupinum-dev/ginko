Owners often know a change before it applies: a new price from 1 November, the lunch menu of next week, new opening hours from spring. This guide shows the three ways to prepare such a change, so that the site switches by itself on the day.

All three are for bricks on the platform.

## New values from a day on

A dated change sets fields of an entry from a day on: a new price from 1 November. Two settings make it easy for owners and staff:

```ts [ginko.config.ts]
menu: collection({
  label: 'Menu',
  fields: {
    name: f.text('Name', { max: 120 }),
    price: f.money('Price'),
  },
  timeline: { public: ['price'] },
  tasks: [
    { id: 'price', label: 'Change a price', kind: 'edit', pick: true, fields: ['price'], when: { from: 'ask' } },
  ],
  max: 150,
  order: 'manual',
}),
```

- `when: { from: 'ask' }` gives the task's form a field "Starts on". Empty saves at once. A day saves the new price as a change for that day, and the page keeps the current price until then.
- On that day the platform writes the new price into the entry. The history says who planned it.
- `timeline: { public: ['price'] }` lets the page read the coming prices. Without it, a waiting value never leaves the server.

The page reads today's price as usual, and the coming ones from `upcoming`:

```vue
<span>{{ formatMoney(dish.data.price, language) }}</span>
<small v-for="change in dish.upcoming" :key="change.from">
  <template v-if="change.data.price">from {{ change.from }}: {{ formatMoney(change.data.price, language) }}</template>
</small>
```

In the Studio, the entry shows each waiting change with its day. "Change day" moves it, "Cancel" removes it; the entry stays online. A content file writes the same change as `$changes` ([Content from files]($docs.content-from-files#dated-changes)).

## Whole weeks of a single

A lunch menu is a single: one menu for the current week. With `plans`, the entries of a second collection hold the menus of later weeks:

```ts [ginko.config.ts]
lunchPlans: collection({
  label: 'Plan the lunch menu ahead',
  plans: { brick: 'lunch', field: 'weekOf' },
  fields: {
    weekOf: f.date('Week of'),
    // the same fields as the single `lunch`
  },
  max: 12,
  order: { field: 'weekOf', dir: 'asc' },
}),
```

`weekOf` holds the first day of the week. The page shows the planned week from that day on. The restaurant preset has this pair ready: `lunch()` and `lunchPlans()`, and `hours()` with `hourPlans()` for opening hours from a date. [Restaurant reference]($docs.restaurant-reference) describes them.

## Publish on a day or at a time

The unpublished changes of an online entry can go live on a later day: in the editor, "Publish …" offers a day. They then wait as one dated change. A draft that is not online yet can go live at a day and a time.

This needs nothing in the config.

## Which one to use

| The owner wants | Use |
| --- | --- |
| a new price or phone number from a known day, and still see the current one | a task with `when: { from: 'ask' }` |
| next week's version of a whole single, entered ahead | `plans` |
| other changes of an online entry from a day, or a new entry at a time | "Publish …" in the Studio |
