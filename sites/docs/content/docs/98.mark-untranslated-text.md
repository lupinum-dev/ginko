A text without a translation shows in the main language. On a German page, the name of a dish may then be English. This guide marks such a text, so that a screen reader pronounces it in the right language.

## Before you start

A page lists a collection, and some entries have no translation. [Read content in a page]($docs.read-content-in-a-page) shows the list.

## Steps

::steps
#### Ask which language a value has

`useGinkoLang` returns a function. It takes an item and the name of a field. It returns the language tag of the main language when the value is a fallback, and `undefined` when the value is translated:

```vue
<script setup lang="ts">
const prices = useGinko('prices')
const langOf = useGinkoLang()
</script>

<template>
  <ul>
    <li v-for="item in prices.items" :key="item.id" :lang="langOf(item, 'title')">
      {{ item.data.title }}
    </li>
  </ul>
</template>
```

Vue leaves out an attribute whose value is `undefined`. A translated text gets no `lang` attribute and takes the language of the page.

#### Check the result

Open the German page and look at the list in the browser's inspector. With "Tea" translated to "Tee" and the other entries not translated:

```html
<li lang="en">Coffee</li>
<li>Tee</li>
<li lang="en">Cake</li>
```
::

## Values inside a single or a list field

For a single, pass the single itself: `langOf(start, 'title')`.

For a row of a list field, name the row by its `_id`:

```vue
<span :lang="langOf(lunch, `days.${day._id}.dish`)">{{ day.dish }}</span>
```

For the description of an image field `photo`, the name is `photo.alt`.

## What decides the fallback

A brick without a route shows untranslated entries in the main language. A brick with a route leaves them out of the language. [Give entries their own pages]($docs.entry-pages#what-you-get-with-a-route) explains the setting `untranslated`.
