A site from a template has more files than the examples in these docs. This page goes through them once, so you know where to look. Nine of the ten templates have the same layout. The examples come from the template `starter`, the site of [Quick start]($docs.getting-started). The template `docs` is different: the docs kit brings its pages and layout, see [Start a docs site]($docs.start-a-docs-site).

The `README.md` in your folder is the manual of your template. It names the file behind each part of the site. This page explains the parts that every template has, and the idea of Ginko behind each one.

## The folder

```text
my-site/
  ginko.config.ts         the bricks: which content the site has
  content/                the content, as Markdown files
  app/
    pages/                the pages that show the content
    bricks/               bricks of this template, used in ginko.config.ts (not in every template)
    routes.ts             the languages, and the address of a page in each one
    app.config.ts         the menu, the footer links, the line under the name
    components/           header, footer and the blocks of the pages
    assets/css/main.css   the colours and the fonts
  i18n/                   the texts of buttons and labels, per language
  public/                 images and files
  README.md               the manual of this template
```

## One text, from the file to the page

Three files take part in every text on the site. Follow the title of the home page. The three excerpts are shortened:

::code-group
```markdown [content/home.md]
---
title: Translations that read like the original
lead: I translate between German and English for museums, research institutes and publishers.
---

## What I translate
```
```ts [ginko.config.ts]
bricks: {
  home: single({
    label: { de: 'Startseite', en: 'Home page' },
    fields: {
      title: f.text({ de: 'Titel', en: 'Title' }, { max: 80, default: 'Welcome' }),
      lead: f.longtext({ de: 'Einleitung', en: 'Lead' }, { max: 300 }),
      body: f.markdown({ de: 'Text', en: 'Text' }, { profile: 'page', optional: true }),
    },
  }),
}
```
```vue [app/pages/index.vue]
<script setup lang="ts">
const home = useGinko('home')
</script>

<template>
  <BlockHero :title="home.data.title" :lead="home.data.lead" />
</template>
```
::

- **The file** holds the content. Its name is the name of the brick: `home.md` fills the brick `home`. The lines between the two `---` fill the fields. The text below them fills the Markdown field.
- **The config** describes the brick: its fields, their types and their limits. From it Ginko checks every file and makes the types of `home.data`.
- **The page** reads the brick with `useGinko('home')` and shows it.

To change a text, you change the file. To add a field, you add it to the config, fill it in the file and show it in the page.

## The bricks in `ginko.config.ts`

The config of a template has bricks in three forms:

```ts [ginko.config.ts]
studio: { id: 'my-site', bricks: [] },     // the bricks owners edit on the platform: none yet
entries: {
  legal: localized('/legal/[slug]'),       // the page of one legal text
  pages: localized('/[slug]'),             // the page of one free page
},
bricks: {
  home: single({ /* fields */ }),          // written here
  notices: notices(),                      // ready-made
  legal: legal(),                          // ready-made, with pages
  pages,                                   // from app/bricks/
}
```

- **Written here.** `single` is a brick with one entry, such as the home page. `collection` is a brick with many entries. [Model your content]($docs.model-your-content) shows how to write one.
- **Ready-made.** `notices()`, `site()` and `legal()` come from `@lupinum/ginko/patterns`. Their fields are fixed, so one line is enough. [Use ready-made bricks]($docs.ready-made-bricks) lists them.
- **From `app/bricks/`.** `pages` is a collection in `app/bricks/pages.ts`. Several templates share it. Open the file to see its fields, and change them there.

Three settings decide where a brick lives, where its entries are, and what editors read:

| Setting | Meaning |
| --- | --- |
| `studio.bricks` | The bricks whose content comes from the platform, where owners edit it. The others read `content/`. See [Files or platform]($docs.files-or-platform). |
| `entries` | Each entry of the brick gets its own page at this address. See [Give entries their own pages]($docs.entry-pages). |
| `label` | The name of the brick or the field for an editor on the platform, as one text or as one text per language. A site that reads files never shows it. |

Some bricks also have `tasks`. A task is a short form for a frequent change on the platform, see [Add tasks for owners]($docs.tasks-for-owners). A site that reads files does not use them.

## The content in `content/`

| Brick | Files |
| --- | --- |
| a single, such as `home` | `content/home.md` |
| a collection, such as `pages` | one file per entry in `content/pages/`: `1.about.md`, `2.contact.md` |

The number at the start of a file name sets the order. A translation has the same name plus the language code: `1.about.de.md`. It holds only the fields it translates, and it can set its own address with `slug:`.

Other files point to an entry by its id: the folder and the file name without number and language. `content/pages/1.about.md` is `pages/about`.

[Write content in files]($docs.write-content-in-files) has the details.

## The languages in `app/routes.ts`

```ts [app/routes.ts]
export const locales = ['en', 'de'] as const
```

The first language is the main one. Its addresses have no prefix, the others start with the language code: `/about` and `/de/ueber-mich`.

`localized()` in the same file writes one address per language, so the config stays short:

```ts
localized('/legal/[slug]')   // { en: '/legal/[slug]', de: '/de/legal/[slug]' }
```

The texts of buttons and labels are in `i18n/`. The folder `i18n/site/` holds the texts of the shared parts, such as the header and the footer. To change one of them, set it under `"site"` in `i18n/<language>.json`.

[Add a language]($docs.add-a-language) adds one more language to a template.

## The pages in `app/pages/`

| File | Shows |
| --- | --- |
| `index.vue` | the home page |
| `[...slug].vue` | every entry of `pages`, each at its own address |
| `legal/[slug].vue` | one legal text |

A page for one entry reads it by the slug in the address:

```vue [app/pages/[...slug].vue]
<script setup lang="ts">
const route = useRoute()
const page = useGinkoEntry('pages', () => route.params.slug)
</script>
```

An address without an entry answers with a real 404. [Read content in a page]($docs.read-content-in-a-page) shows the composables.

## Name, menu and design

| What | Where |
| --- | --- |
| The name of the site, its description for search engines | `name` and `seo.description` in `ginko.config.ts` |
| The menu, the footer links, the line under the name | `app/app.config.ts` |
| Address, email and phone | `content/site.md` |
| Colours and fonts | `app/assets/css/main.css` |
| The rules of the design | `DESIGN.md` |

## Files you rarely open

| File or folder | What it does |
| --- | --- |
| `nuxt.config.ts` | Turns on the Nuxt modules of the site: Ginko, fonts, colour mode, share cards. |
| `site-url.ts` | Reads the address of the live site from `NUXT_PUBLIC_SITE_URL`. See [Deploy to Vercel]($docs.deploy-to-vercel). |
| `modules/` | Small Nuxt modules of the template. They load the texts of `i18n/`, give each Vue page its address per language and list the RSS feeds for a static build. |
| `app/components/ui/` | [shadcn-vue](https://www.shadcn-vue.com) components, such as the button. |
| `.env` | `NUXT_APP_SECRET`, which signs the addresses of the share cards. |
