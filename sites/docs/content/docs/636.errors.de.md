Diese Seite listet die Fehler, die du am ehesten siehst, jeden mit Ursache und Lösung. Such auf der Seite nach einem Teil deiner Meldung. Die Namen in den Beispielen, etwa `news` oder `promo`, sind in einer echten Meldung deine eigenen.

## Wo Fehler erscheinen

| Wo | Wann | Was passiert |
| --- | --- | --- |
| `nuxt build`, `nuxt generate` | Ein Fehler in der Konfiguration, in einer Inhaltsdatei oder in einem Link | Der Build bricht ab. |
| `nuxt dev` | Dieselben Fehler | Der Server läuft weiter. Das Log nennt den Fehler, und die Datei fehlt auf der Seite. |
| `ginko check` | Dieselben Fehler und eine Schema-Änderung, die die Plattform ablehnen würde | Exit-Code 1. |
| `ginko release` | Eine abgelehnte Schema-Änderung oder ein Problem mit dem Schlüssel oder der Plattform | Exit-Code 1 bis 4, siehe [ginko-CLI]($docs.cli#ausgabe-und-exit-codes). |

::callout{type="warning" title="Eine Seite fehlt im Dev-Server"}
Im Dev-Server hält ein Fehler in einer Datei den Server nicht an. Im Log steht dann eine Zeile, die mit `[ginko] Errors in content/` beginnt, und die Dateien darunter fehlen auf der Seite.
::

## Inhaltsdateien

Die Meldung nennt die Datei und dann das Feld in Klammern.

| Meldung | Ursache | Lösung |
| --- | --- | --- |
| `content/news/1.opening.md (colour): Unknown field “colour”.` | Das Frontmatter hat einen Schlüssel, den der Baustein nicht hat. | Korrigiere den Namen oder füg das Feld zum Baustein hinzu. |
| `content/news/1.opening.de.md (date): “date” is set in the main-language file only.` | Eine Übersetzungsdatei setzt ein Feld, das einen Wert für alle Sprachen hat. | Entferne den Schlüssel aus der Übersetzungsdatei. |
| `Invalid YAML … Put text with a colon in quotes` | Ein Wert im Frontmatter hat einen `:` mit einem Leerzeichen danach. | Setz den Wert in Anführungszeichen: `description: "Open: daily"`. |
| `content/menu/prices.csv:3 (price): Column “price”: “3,5” is not a number. Use a point as the decimal separator (12.5, not 12,5).` | Eine Zelle einer CSV-Datei passt nicht zu ihrem Feld. `:3` ist die Zeile. | Korrigiere die Zelle. |

Andere Ursachen in Inhaltsdateien:

- ein Sprachcode im Dateinamen, den die Seite nicht hat
- eine Übersetzung ohne Datei in der Hauptsprache
- zwei Einträge mit demselben Slug in einer Sprache
- ein Bild oder eine Datei, die es nicht gibt
- ein Wert, den das Feld ablehnt, etwa ein Titel über seinem `max`
- Text unter dem Frontmatter in einem Baustein ohne Markdown-Feld
- eine YAML-, JSON- oder CSV-Datei, die sich nicht lesen lässt

[Inhaltsdateien]($docs.content-from-files) hat die Regeln für Dateinamen und Frontmatter.

## Markdown und Komponenten

| Meldung | Ursache | Lösung |
| --- | --- | --- |
| `“body”: “callout” is not allowed here (paragraphs, headings, lists (also with checkboxes), quotes, notices and footnotes).` | Das Profil des Markdown-Feldes erlaubt diesen Teil nicht. Die Klammern listen, was es erlaubt. | Setz ein weiteres Profil auf das Feld, etwa `profile: 'page'` für Komponenten. Siehe [Was Markdown enthalten darf]($docs.what-markdown-may-contain). |
| `“body”: “iframe” is not allowed.` | Der Tag führt Code aus, lädt fremde Inhalte oder sendet Daten. Kein Profil erlaubt ihn. | Schreib eine Komponente dafür und registriere sie. |
| `“body”: The property “style” is not allowed.` | Das Attribut steht nicht auf der kurzen Liste für Markdown, oder die Komponente deklariert es nicht. | Entferne das Attribut. Für einen Teil mit eigenem Aussehen schreib eine Komponente. |
| `“body”: Link is not allowed (only http, https, mailto, tel or /path).` | Die Adresse ist kein sicherer Link, sie beginnt zum Beispiel mit `//`. | Schreib eine vollständige `https://`-Adresse, einen Pfad auf der Seite oder `$brick.name`. |
| `There is no component “callot”.` | Der Name steht nicht in `components` der Seite. | Korrigiere den Namen oder registriere die Komponente. |
| `Component “callout”: There is no property “colour”.` | Die Komponente deklariert diese Prop nicht. | Korrigiere den Namen oder deklariere die Prop. |
| `Component “pricing”: property “price” is missing.` | Eine Pflicht-Prop hat keinen Wert. | Füg die Prop zum Text hinzu. |

[Komponenten einrichten]($docs.set-up-components) und [Eigene Komponente hinzufügen]($docs.add-your-own-component) zeigen, wie du eine Komponente registrierst.

## Links

| Meldung | Stufe | Ursache | Lösung |
| --- | --- | --- | --- |
| `content/news/opening: Link $news.summer-break leads to no entry and no page.` | error | Den Eintrag oder die Seite gibt es nicht, oder es ist ein Entwurf oder außerhalb seiner Daten. | Korrigiere den Link oder veröffentliche das Ziel. |
| `content/news/opening: Link $pages.nope leads to no entry and no page.` | error | `pages` in der Konfiguration hat keinen solchen Schlüssel. | Nutze einen Schlüssel von `pages`. |
| `Path /docs/old matches no entry, no page and no file in public/.` | error | Ein Link mit einem einfachen Pfad führt ins Leere. | Korrigiere den Pfad. Besser: Schreib den Link als `$brick.name`. |
| `content/news/opening: Anchor #nope is missing: no heading with this id.` | warning | Die Zielseite hat keine Überschrift mit dieser Id. | Korrigiere den Teil nach `#`. |
| `content/news/opening: Link /old-about leads to /about through a redirect.` | warning | Der Link zeigt auf eine Adresse, die weiterleitet. | Verlinke die neue Adresse. |

`linkCheck` in der Konfiguration ändert die Stufe jeder Art, siehe [defineSite]($docs.define-site#link-pruefung). [Zwischen Seiten verlinken]($docs.link-between-pages) erklärt die Link-Formen.

## Konfiguration

| Meldung | Ursache | Lösung |
| --- | --- | --- |
| `Too many bricks (at most 30).` | Die Seite überschreitet eine feste Grenze. | Siehe [Grenzen]($docs.limits). |
| Der Build bricht ab und nennt `locales`, `defaultLocale`, `baseUrl` oder `timeZone` unter `i18n` | `nuxt.config.ts` setzt eine Einstellung, die Ginko selbst übergibt. | Entferne die Einstellung aus `i18n`. Der Wert kommt aus `ginko.config.ts`. |
| `ginko check` scheitert an einem Import, `nuxt build` nicht | Das CLI lädt die Konfiguration mit Node. Ein relativer Import braucht die Endung `.ts`, und `~/` funktioniert nicht. | Schreib `import { menu } from './bricks/menu.ts'`. |

## Schema-Prüfung und Release

`ginko check` und `ginko release` vergleichen die Konfiguration mit dem Schema in Produktion. Eine abgelehnte Änderung beginnt mit `✗`, und die Zeilen darunter sagen, was zu tun ist.

| Meldung | Ursache | Lösung |
| --- | --- | --- |
| `✗ promo.until: Field “promo.until” is missing.` | Die Konfiguration hat ein Feld nicht mehr, das die Produktion hat. | Setz das Feld zurück und zieh es zurück: `retired: { 'promo.until': { drop: true } }`. |
| `✗ promo.headline: New single: required field “headline” needs a default.` | Ein neues Einzelstück hat ein Pflichtfeld ohne `default`. Die Plattform muss das Einzelstück mit einem Wert anlegen. | Gib dem Feld ein `default` oder setz `optional: true`. |

Jede Regel steht auf [Schemas wachsen nur]($docs.schemas-only-grow). [Eine Schema-Änderung freigeben]($docs.release-a-schema-change) hat die Schritte.

## Das CLI

| Meldung oder Exit-Code | Ursache | Lösung |
| --- | --- | --- |
| `The environment variable GINKO_PLATFORM is missing.` | Die Seite hat einen Plattform-Baustein, und das CLI kennt die Plattform nicht. | Setz `GINKO_PLATFORM`. Das CLI liest `.env` nicht. |
| `The environment variable GINKO_COMMIT is missing.` | `ginko release` läuft außerhalb von GitHub Actions. | Setz `GINKO_COMMIT=$(git rev-parse HEAD)`. |
| Exit-Code 3 | Die Plattform hat nicht geantwortet, oder das Ergebnis ist unbekannt. | Lass denselben Commit noch einmal laufen. Das ist sicher. |
| Exit-Code 4 | Die Plattform lehnt den Schlüssel ab, oder etwas vor der Plattform lehnt die Anfrage ab. | Prüfe `GINKO_KEY` und seinen Umfang, dann `GINKO_PLATFORM`. |

[Umgebungsvariablen]($docs.environment-variables#das-cli) listet die Variablen.

## Übersetzungen

`ginko-i18n check` meldet einen Schlüssel, den eine Sprache nicht hat:

```text
error missing de legal.consent i18n/en.json:4: Missing translation
```

Füg den Schlüssel zur Datei dieser Sprache hinzu. `ginko-i18n todo` listet jeden fehlenden Schlüssel, siehe [Buttons und Beschriftungen übersetzen]($docs.translate-buttons-and-labels).

## Die laufende Seite

| Antwort | Ursache | Lösung |
| --- | --- | --- |
| **503** auf jeder Seite mit Plattform-Inhalten | Die Seite kann die Inhalte nicht laden: Die Adresse der Plattform fehlt oder ist falsch, oder die Plattform antwortet nicht. | Setz `NUXT_PUBLIC_GINKO_PLATFORM`, siehe [Umgebungsvariablen]($docs.environment-variables). Im Dev-Server ohne Plattform gib dem Baustein `source: 'files'`. |
| **404** auf der Seite eines Eintrags | Den Eintrag gibt es nicht, er ist ein Entwurf, außerhalb seiner Daten, oder er hat keine Übersetzung in dieser Sprache. | Prüfe den Eintrag. Siehe [Fehlende Übersetzungen]($docs.missing-translations). |
| **404** auf einer neuen Kit-Seite nach einer Änderung der Konfiguration im Dev-Server | Der Dev-Server hat die neuen Seiten nicht registriert. | Starte den Dev-Server neu. |
| Jede Share-Karte antwortet mit einem Fehler | Die Seite rendert auf einem Server und hat kein `NUXT_APP_SECRET`. | Setz die Variable beim Host. |

Ein 503 ist Absicht: Ein Host wie Vercel behält dafür die letzte gute Seite. Ein 404 würde die Seite ersetzen. [Mit fehlenden Inhalten umgehen]($docs.missing-content) zeigt, was du für beide Fälle baust.
