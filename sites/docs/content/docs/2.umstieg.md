## Ginko oder Nuxt Content

Beide lesen Markdown aus `content/` und zeigen es in einer Nuxt-Site. Sie lösen verschiedene Aufgaben.

**Nimm Ginko**, wenn Menschen die Site bearbeiten, die nicht entwickeln. Derselbe Baustein kann heute aus Dateien kommen und morgen von der Plattform: Der Code der Site bleibt gleich. Inhaber bearbeiten im Studio, mit Freigabe, Zeitplan, Verlauf und einer Link-Prüfung, bevor etwas live geht. Sprachen, Adressen pro Sprache und hreflang sind dabei.

**Nimm Nuxt Content**, wenn nur Entwickler bearbeiten, in Git, und du etwas brauchst, das Ginko nicht hat: Nuxt Studio, oder mehr als 500 Einträge in einer Sammlung (die Grenze von Ginko). [Datendateien in YAML, JSON und CSV]($docs.inhalte-aus-dateien#datendateien-yaml-json-csv) und Abfragen mit `where`, `order` und `limit` hat Ginko auch.

Eine Site kann auch nur mit Datei-Bausteinen von Ginko starten. Dann braucht sie keine Plattform und kein Konto.

## Von Nuxt Content

| Nuxt Content | Ginko |
| --- | --- |
| `content.config.ts` mit `defineCollection` | `ginko.config.ts` mit `collection({ source: 'files', … })` |
| ein `schema` mit Zod | Felder mit `f.*`: `f.text`, `f.markdown`, `f.image`, … |
| `queryCollection('docs').path(path).first()` | `useGinkoEntry('docs', slug)` |
| `queryCollection('blog').where(…).order(…).all()` | `useGinkoQuery('blog', { where, order, limit })` |
| `queryCollectionNavigation` | `useGinkoNav(['docs'])` |
| `queryCollectionItemSurroundings` | `useGinkoNeighbors('docs', id)` |
| `queryCollectionSearchSections` | der Suchindex unter `/__ginko/search/<locale>.json` |
| `<ContentRenderer :value="page" />` | `<GinkoMarkdown :value="doc.data.body" />` |
| MDC `::callout` | dieselbe Schreibweise; die Komponenten ordnest du mit `:components` zu |
| `useSeoMeta` pro Seite | `useGinkoSeo({ … })` |

Was sich beim Umstieg ändert:

- **Eine Datei pro Eintrag und Sprache.** `1.einstieg.md` ist die Hauptsprache, `1.einstieg.en.md` die Übersetzung. Siehe [Inhalte aus Dateien]($docs.inhalte-aus-dateien).
- **Das Frontmatter wird geprüft.** Ein Schlüssel, den der Baustein nicht kennt, stoppt den Build. Die Meldung nennt Datei und Feld.
- **Abfragen lesen das Bundle.** `useGinkoQuery` läuft auf den Daten der Seite, nicht auf einer Datenbank. `where` kennt `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in` und `contains`; `order` ist ein Text wie `'date desc'`.
- **Links zwischen Einträgen folgen der Sprache.** In Markdown zeigt `[Bausteine]($docs.bausteine)` auf den Eintrag in der Sprache der Seite. Ein Link, der ins Leere zeigt, stoppt den Build.

## Von @nuxtjs/i18n

Das Ginko-Modul installiert **ginko-i18n** und gibt ihm die Sprachen der Site. Entferne `@nuxtjs/i18n`: Sind beide installiert, stoppt das Setup mit einer Meldung.

| @nuxtjs/i18n | ginko-i18n |
| --- | --- |
| `i18n: { locales, defaultLocale, strategy }` in `nuxt.config.ts` | `locales` in `ginko.config.ts`; die erste ist die Standardsprache |
| `$t('key')`, `useI18n().t` | `useI18n().t` |
| `useLocalePath()` | `useI18n().localePath` |
| `useSwitchLocalePath()`, `useLocaleHead()` | `useI18n().alternates`; die Head-Tags setzt ginko-i18n selbst |
| `defineI18nRoute({ paths })` | `definePageMeta({ i18n: { paths } })` |
| `i18n/locales/*.json` mit vue-i18n-Syntax | `i18n/<locale>.json` mit ICU-Syntax |
| `detectBrowserLanguage` | `useLocaleSuggestion()`: ein Link, den der Besucher wählen kann |

Was sich beim Umstieg ändert:

- **Mehrzahl mit ICU.** Aus `'kein Gericht | ein Gericht | {count} Gerichte'` wird `'{count, plural, =0 {kein Gericht} one {# Gericht} other {# Gerichte}}'`.
- **Zwei Strategien.** `prefix_except_default` (Standard) und `prefix`. Domains pro Sprache und `no_prefix` gibt es nicht.
- **Die Adresse bestimmt die Sprache.** Kein Cookie und kein Browser-Header wechselt eine Seite. Für Apps hinter einem Login lässt `userLocale` bestimmte Pfade stattdessen dem Benutzer folgen.
- **Detailseiten brauchen keinen Extra-Code.** Die Adressen eines Eintrags in jeder Sprache kommen aus dem Bundle. So stimmen Sprachumschalter und hreflang ohne `setI18nParams`.

Die Einzelheiten stehen unter [Sprachen]($docs.sprachen).
