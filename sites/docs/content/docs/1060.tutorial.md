This tutorial builds a small site from an empty folder. You write every file yourself, so you see what each one does. Each chapter ends with something you can open in the browser.

The site belongs to Studio Nord, a small design studio. At the end it has:

1. **A first page**: a home page that reads its text from a Markdown file. This chapter.
2. [Pages and a menu]($docs.tutorial-pages): About and Contact, each from its own file, in a menu.
3. [A blog]($docs.tutorial-blog): posts with a date and an author, a list and a page for each post.
4. [A second language]($docs.tutorial-languages): the whole site in English and German, with a language switch.
5. [Titles, check and build]($docs.tutorial-check-and-build): page titles, a check of all content, and the finished site.

To get a complete site with a design in a few minutes, use the [Quick start]($docs.getting-started) instead. This tutorial shows what happens below a template.

You need Node.js 22.18 or newer (22, 24 or 26) and npm. pnpm and bun work too.

## Steps

::steps
#### Create the folder and the package

Create an empty folder `my-site` and put this `package.json` into it:

```json [package.json]
{
  "name": "my-site",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "nuxt dev",
    "check": "ginko check",
    "build": "nuxt build",
    "preview": "nuxt preview",
    "postinstall": "nuxt prepare"
  },
  "dependencies": {
    "@lupinum/ginko": "^0.18.0",
    "@lupinum/ginko-content": "^0.18.0",
    "nuxt": "^4.6.4",
    "vue": "^3.5.45"
  }
}
```

`@lupinum/ginko` is Ginko itself. `@lupinum/ginko-content` reads the Markdown files. [The packages]($docs.packages) says what the others do.

Then install:

```bash
cd my-site
npm install
```

npm may warn that esbuild has an install script. The site runs without it. With pnpm 11, first add a `pnpm-workspace.yaml` with `allowBuilds:` and `esbuild: true` below it, because pnpm otherwise stops at that script.

#### Describe the content

Ginko calls one kind of content a **brick**. This site has one brick so far: the home page. Describe it in `ginko.config.ts`:

```ts [ginko.config.ts]
import { defineSite, f, single } from '@lupinum/ginko'

export default defineSite({
  site: 'my-site',              // the id: lower case letters, digits and hyphens
  name: 'Studio Nord',          // the name people read
  url: 'https://example.com',   // the address of the live site
  timeZone: 'Europe/Vienna',
  week: { firstDay: 'mo', workdays: ['mo', 'tu', 'we', 'th', 'fr'] },
  locales: ['en'],              // the languages; the first one is the main language
  currency: 'EUR',
  pages: { home: '/' },         // the fixed pages: a key and an address
  bricks: {
    home: single({
      label: 'Home page',
      source: 'files',          // the content is in files in content/
      fields: {
        title: f.text('Title'),
        body: f.markdown('Text', { profile: 'basic' }),
      },
    }),
  },
})
```

`single` is a brick with exactly one entry. Each field has a type and a label. The profile `basic` allows paragraphs, headings, lists, quotes and links in the text, but no images or tables.

#### Turn on the Nuxt module

```ts [nuxt.config.ts]
import ginko from './ginko.config.ts'

export default defineNuxtConfig({
  compatibilityDate: '2026-10-01',
  modules: ['@lupinum/ginko/nuxt'],
  ginko,
})
```

The module checks `ginko.config.ts` at startup. A mistake in it, for example an unknown key, stops the dev server with a message.

#### Write the page

```vue [app/app.vue]
<template>
  <NuxtPage />
</template>

<style>
body { font-family: system-ui, sans-serif; line-height: 1.5; max-width: 40rem; margin: 2rem auto; padding: 0 1rem; }
</style>
```

```vue [app/pages/index.vue]
<script setup lang="ts">
const home = useGinko('home')
</script>

<template>
  <main>
    <h1>{{ home.data.title }}</h1>
    <GinkoMarkdown :value="home.data.body" />
  </main>
</template>
```

`useGinko('home')` reads the brick `home`. For a single, `data` holds its fields. `GinkoMarkdown` shows a Markdown field. The module imports both for you, and your editor knows the fields from `ginko.config.ts`.

#### Write the content

```markdown [content/home.md]
---
title: Studio Nord
---

We design books and posters in Vienna. This text lives in `content/home.md`.
```

The file name is the brick name. The lines between the two `---` fill the fields. The text below them fills the Markdown field.

#### Start the site

```bash
npm run dev
```

Open `http://localhost:3000`. The page shows "Studio Nord" and the sentence below it.

Change the sentence in `content/home.md` and save. The page in the browser shows the new text. The dev server reads changed files in `content/` at once.
::

## What you have now

```text
my-site/
  package.json
  ginko.config.ts     the bricks and their fields
  nuxt.config.ts
  app/
    app.vue
    pages/index.vue   the page that shows the brick home
  content/
    home.md           the content of the brick home
```

The content is in files, so the site needs no account and no database. A brick without `source: 'files'` reads its content from the Ginko platform instead, where an owner edits it in the Studio. The page stays the same. [Files or platform]($docs.files-or-platform) explains the two sources.
