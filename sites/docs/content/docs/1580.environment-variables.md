A site whose bricks all come from files needs none of these variables, except `NUXT_APP_SECRET` for share cards on a server.

## The site

Set these where the site builds and runs: in `.env` on your computer, and in the settings of your host.

| Variable | Needed when | What it does |
| --- | --- | --- |
| `NUXT_PUBLIC_GINKO_PLATFORM` | The site has platform bricks and `ginko.config.ts` sets no `platform`. | The address of the platform. It wins over `platform` in the config. |
| `NUXT_GINKO_REVALIDATE_TOKEN` | Optional, for a platform site on Vercel. | The site token. With it, a publish reaches the site at once. Without it, a change arrives within 60 seconds. |
| `NUXT_APP_SECRET` | The site has share cards and renders on a server. | A random secret of 32 or more characters. `nuxt-og-image` signs the card addresses with it. |
| `NUXT_PUBLIC_GINKO_NOINDEX` | A site that must stay out of search engines. | `true` makes `robots.txt` block everything, and every response sends `X-Robots-Tag: noindex`. |
| `GINKO_CONTENT` | Optional, a site whose bricks have `source: 'files'`. | `platform` makes every brick read the platform, as if `source: 'files'` were gone. Set it for the build and for `ginko release`, for example to run a copy of a template as a demo without a change in its code. Any other value stops the build. |
| `NUXT_PUBLIC_SITE_URL` | Optional, sites from a template. | The address of the site. The templates read it as `url` in `ginko.config.ts`, so one repository can serve several addresses. |

### `NUXT_PUBLIC_GINKO_PLATFORM`

Without this variable and without `platform` in the config:

- In dev, the site reads the platform on `http://localhost:3100`. That address is for work on Ginko itself; a page with platform content answers 503.
- On a host, every page with platform content answers 503, and the server log says so once.
- A production build on Vercel stops with an error. A preview build prints a warning.

On Vercel, set the variable for Production and for Preview. A variable that exists only for Preview leaves the production site without content.

### `NUXT_GINKO_REVALIDATE_TOKEN`

An owner creates the token in the Studio: Team, "Site token". The platform shows it once.

- With the token, the platform renders the changed pages again right after a publish, and owners can use "Update website now".
- The server of the site sends the token when it loads content. So visitors cannot use up the request limit of the site.
- A new token ends the old one at once. Set the new value on the host and deploy again right after.
- Ginko gives the token to Vercel as `bypassToken`, unless your `nuxt.config.ts` sets `nitro.vercel.config.bypassToken` itself.

### `NUXT_APP_SECRET`

`create-ginko` writes one into `.env` for your computer. Set one on the host too: without it, every share card answers with an error, and the build warns. A static build (`nuxt generate`) draws every card at build time and needs none.

Make one with:

```bash
openssl rand -hex 32
```

### `NUXT_PUBLIC_GINKO_NOINDEX`

Search engines index a site only on the address in `url`. Every other host, such as a preview deployment, gets `noindex` without this variable.

Set `NUXT_PUBLIC_GINKO_NOINDEX=true` for a demo, or for a site that runs on a temporary address until its domain is ready. Remove it when the site moves to its own domain.

## The CLI

The `ginko` CLI reads these variables. It does not read `.env`: set them in the shell or in the settings of your CI.

| Variable | Needed for | What it is |
| --- | --- | --- |
| `GINKO_PLATFORM` | every command on a site with platform bricks | The address of the platform. Without it, the CLI reads `NUXT_PUBLIC_GINKO_PLATFORM`. |
| `GINKO_KEY` | `check` against the platform, `release`, `export` | A key of the site, in the form `ginko_<site>_<32 characters>`. An owner creates it in the Studio: Team, "Publishing keys", "New key". A key has scopes: `check`, `release`, `export` and `pull`. |
| `GINKO_COMMIT` | `release` | The commit that the release belongs to. Without it, the CLI reads `GITHUB_SHA`, which GitHub Actions sets. |
| `GINKO_BRANCH` | optional | The branch of the release. Default `main`. |
| `GINKO_REMOTE` | optional | The git remote the CLI compares the commit with. Default `origin`. |

A missing variable stops the command with exit code 2:

```text
The environment variable GINKO_PLATFORM is missing.
```

By hand, a release looks like this:

```bash
GINKO_PLATFORM=https://cms.example.com GINKO_KEY=ginko_cafe-linde_… GINKO_COMMIT=$(git rev-parse HEAD) npx ginko release
```

Keep `GINKO_KEY` a secret of your CI. Do not commit it.

## Not for sites

`GINKO_LOCAL` and `GINKO_REGISTRY_URL` are for work on Ginko itself. A site does not set them.
