This guide moves one brick from files to the platform. At the end, the owner changes that content in the Studio, and the site shows a change within a minute, without a deploy.

## Before you start

Lupinum hosts the platform and opens it by invitation. You need three things:

- **Your site on the platform.** Ask Lupinum for it. You get an invitation as owner of the site.
- **The address of the platform.** You get it with the invitation.
- **A key.** In the Studio, open Team, then "Publishing keys", then "New key". Give it a name, choose "Publish and back up" and create it. The Studio shows the key once: "You see this key only now." Keep it as a secret.

## Steps

::steps
#### Tell the site where the platform is

```ts [ginko.config.ts]
export default defineSite({
  site: 'linde',
  platform: 'https://platform.example.com',
  // …
})
```

`site` is the id of your site on the platform. The pages now load the content of platform bricks from that address.

#### Remove the source of the brick

```ts [ginko.config.ts]
promo: single({
  label: 'Promotion',
  // source: 'files' was here
  fields: {
    headline: f.text('Headline', { default: 'Fresh this week' }),
    until: f.date('Show until', { optional: true }),
  },
}),
```

A single on the platform exists from the first moment, so each required field needs a start value. Give it a `default`, or make it optional. `f.markdown`, `f.image` and `f.file` have no `default`: make them optional.

#### Check the change against the platform

Set the address and the key in your shell, then run the check:

```bash
export GINKO_PLATFORM=https://platform.example.com
export GINKO_KEY=ginko_linde_…
npx ginko check
```

The check compares your config with the site on the platform and lists what would change:

```text
Site “linde”: schema version 1, content 1.
Allowed changes:
  + New brick “promo”.
OK: A release with this schema would be accepted.
```

A required field without a start value is refused, with the fix:

```text
✗ promo.headline: New single: required field “headline” needs a default.
  → Set a `default` or make the field optional.
```

#### Release the change

Commit and push the config. Then run the release, in CI or by hand. [Release a schema change]($docs.release-a-schema-change) shows both.

After the release, the Studio lists the brick under Content.

#### Bring the content over

The platform does not read your files. The brick starts with its defaults, and a collection starts empty.

- For a few texts, type them into the Studio.
- For many entries, ask Lupinum to import them.

Then delete the files of the brick from `content/`. The site no longer reads them.

#### Check the result

1. Change the text in the Studio and choose "Publish".
2. Reload the page of the site. It shows the new text within a minute.
::

## What stays the same

The pages do not change. `useGinko('promo')` reads the brick from the platform as it read it from files.
