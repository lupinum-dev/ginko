Ginko is seven packages on npm. A site installs two or three of them. This page says what each one does and when you need it.

## The packages at a glance

| Package | What it does | A site needs it |
| --- | --- | --- |
| `@lupinum/ginko` | The core: `defineSite`, the bricks and field types, the composables such as `useGinko`, the Nuxt module, the `ginko` command line tool and the ready-made bricks in `@lupinum/ginko/patterns`. | always |
| `@lupinum/ginko-content` | Reads the Markdown, YAML, JSON and CSV files of a brick. You install it and never import it: the Ginko module loads it. | when a brick has `source: 'files'` |
| `@lupinum/ginko-i18n` | The languages: an address per language, message files, the links for a language switch and the head tags for search engines. | always; `@lupinum/ginko` brings it |
| `@lupinum/ginko-components` | Components for Markdown text: notices, tabs, steps, cards, code groups and more. | when a text uses them |
| `@lupinum/ginko-docs` | The docs kit: a documentation site with navigation, search, a blog and a changelog. | for a docs site or a docs section |
| `@lupinum/ginko-preset-gastro` | The restaurant kit: bricks for opening hours, a menu with allergens, a lunch week and events, with their rules. | for a restaurant site |
| `create-ginko` | The command `npm create ginko` that starts a new site. | never: you run it once and do not install it |

Each product has its own tab at the top of the navigation: [i18n]($docs.add-a-language), [Components]($docs.set-up-components), [Docs kit]($docs.start-a-docs-site) and [Restaurant kit]($docs.restaurant-site).

## What a site installs

A site whose content is in files needs two packages next to Nuxt:

```bash
npm install @lupinum/ginko @lupinum/ginko-content
```

`@lupinum/ginko` depends on `@lupinum/ginko-i18n`, so every Ginko site has it. The templates also name it in their own dependencies. Do the same when you run its command line tool `ginko-i18n` or import from it, because pnpm only lets a site reach the packages it names.

You add another package when you need what it does:

| You want | Install | Then read |
| --- | --- | --- |
| notices, tabs or cards in a Markdown text | `@lupinum/ginko-components` | [Set up components]($docs.set-up-components) |
| a docs section in your site | `@lupinum/ginko-docs` | [Add docs to an existing site]($docs.docs-in-an-existing-site) |
| opening hours and a menu | `@lupinum/ginko-preset-gastro` | [Build a restaurant site]($docs.restaurant-site) |
| two languages in a Nuxt app without Ginko | `@lupinum/ginko-i18n` alone | [i18n quick start]($docs.i18n-quick-start) |

## One version for all

The seven packages always release together, with one version number. Keep every Ginko package of a site on the same version. Packages of different versions are not tested together.

To update, name all of them in one command:

```bash
npm install @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```

[Upgrade Ginko]($docs.upgrade) has the steps and the changes that need a change in your site.

## The platform is not a package

Owners edit content in the Studio, a web app that you [host yourself]($docs.host-the-platform). A website installs nothing for it. A site reaches it through `@lupinum/ginko`: a brick without `source: 'files'` reads its content from the platform. [Files or platform]($docs.files-or-platform) explains the two sources.
