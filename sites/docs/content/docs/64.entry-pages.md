This guide gives each entry of a collection its own page, for example `/news/opening` for one news post. At the end, the list links to each entry, a wrong address answers with a real 404, and the sitemap names every entry.

## Before you start

You have a collection, for example `news`, and a page that lists it. [Model your content]($docs.model-your-content) shows how to add a collection.

## Steps

::steps
#### Add a slug field and a route

The slug is the last part of the address. The route says where the pages live, with one path per language:

```ts [ginko.config.ts]
news: collection({
  label: 'News',
  source: 'files',
  max: 100,
  order: { field: 'date', dir: 'desc' },
  route: { en: '/news/[slug]', de: '/de/neuigkeiten/[slug]' },
  fields: {
    title: f.text('Title'),
    date: f.date('Date'),
    slug: f.slug('Address', { from: 'title' }),
    body: f.markdown('Text'),
  },
}),
```

- The route has a path for every language of the site. Each path contains `[slug]`.
- The path of another language includes its prefix, here `/de`.
- The slug field has the name `slug`.

In a site from a template, write `route: localized('/news/[slug]')`. The helper in `app/routes.ts` adds the prefix of each language.

#### Know where the slug comes from

| The brick lives | The slug is |
| --- | --- |
| in files | the file name without number and language: `content/news/1.opening.md` has the slug `opening`. A `slug:` line in the frontmatter replaces it. |
| on the platform | made once from the field in `from` when the entry is created: "We are open" becomes `we-are-open`. The owner can change it in the Studio. |

Each language has its own slug. A translation file sets it with `slug:`:

```markdown [content/news/1.opening.de.md]
---
title: Wir haben geöffnet
slug: wir-haben-geoeffnet
---

Die neue Seite ist online.
```

#### Write the page for one entry

Create a page file whose path matches the route of the main language:

```vue [app/pages/news/[slug].vue]
<script setup lang="ts">
definePageMeta({ i18n: { paths: { de: '/neuigkeiten/:slug()' } } })
const route = useRoute()
const post = useGinkoEntry('news', () => route.params.slug)
</script>

<template>
  <article>
    <h1>{{ post.data.title }}</h1>
    <GinkoMarkdown :value="post.data.body" />
  </article>
</template>
```

`useGinkoEntry` finds the entry by its slug in the language of the address. The line with `definePageMeta` is needed only when another language has a different path. It names that path without the language prefix.

#### Link to the entries

Every item of a collection with a route carries its address in `url`. Use it for the links:

```vue [app/pages/news/index.vue]
<script setup lang="ts">
const news = useGinko('news')
</script>

<template>
  <ul>
    <li v-for="item in news.items" :key="item.id">
      <NuxtLink :to="item.url">{{ item.data.title }}</NuxtLink>
    </li>
  </ul>
</template>
```

Do not build the path yourself. `url` is right in every language and stays right when the route changes.

#### Check the result

1. Open the list and follow a link. The address is `/news/opening`.
2. Open `/news/does-not-exist`. The answer is a 404 page.
3. Open the German list. It shows only the entries that have a German file, each under its German slug.
4. Open `/sitemap.xml`. It names each entry in each language it is translated into.
::

## What you get with a route

- **A 404 for unknown slugs.** `useGinkoEntry` answers with a real 404, also on navigation in the browser.
- **Links between languages.** The page of an entry gets `hreflang` links to its translations, and the language switch leads to the same entry.
- **Hidden until translated.** In a language without a translation, an entry with a route is left out. Set `untranslated: 'fallback'` on the brick to list it with a link to its page in the main language.
