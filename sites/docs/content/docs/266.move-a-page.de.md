Eine Adresse, die gestern ging, soll morgen gehen: Andere Seiten verlinken sie, und Suchmaschinen kennen sie. Diese Anleitung zieht eine Seite um und schickt jeden Besucher der alten Adresse zur neuen.

## Ein Eintrag in einer Datei bekommt einen neuen Slug

::steps
#### Den Eintrag umbenennen

Gib der Datei ihren neuen Namen oder ändere `slug:` in ihrem Frontmatter. Die Adresse von `content/news/1.opening.md` ist `/news/opening`.

#### Die alte Adresse im Eintrag nennen

```markdown [content/news/1.opening.md]
---
title: We are open
date: 2026-10-12
redirectFrom: /news/first
---
```

Für mehrere alte Adressen schreibst du eine Liste:

```yaml
redirectFrom:
  - /news/first
  - /news/we-open
```

`redirectFrom` steht in der Datei der Hauptsprache.

#### Das Ergebnis prüfen

Öffne die alte Adresse. Die Seite antwortet mit einer Weiterleitung zur neuen:

```text
HTTP/2 301
location: /news/opening
```
::

Auf der Plattform ändert die Inhaberin die Adresse eines Eintrags im Studio. Die alte Adresse leitet dann von selbst weiter.

## Jede andere Adresse

Regeln, die nicht zu einem Eintrag gehören, stehen in der Konfiguration:

```ts [ginko.config.ts]
export default defineSite({
  // …
  redirects: [
    { from: '/old-about', to: '/about' },
    { from: '/old-news/:slug', to: '/news/:slug' },
    { from: '/old-blog/*', to: '/blog/:splat', status: 302 },
  ],
})
```

- `:name` passt auf einen Teil eines Pfads. `to` kann ihn nutzen.
- `*` am Ende passt auf den Rest. `to` nutzt ihn als `:splat`.
- Die erste passende Regel gewinnt. Der Status ist 301, wenn du keinen anderen setzt.
- `to` beginnt mit einem festen Pfad. Eine Regel wie `{ from: '/en/*', to: '/:splat' }` wird abgelehnt, weil ein Besucher sonst das Ziel wählen könnte.

Eine falsche Regel bricht den Build ab.

## Links auf alte Adressen finden

Nach einem Umzug verlinken deine eigenen Texte vielleicht noch die alte Adresse. `ginko check` warnt vor jedem:

```text
content/news/opening: Link /old-about leads to /about through a redirect.
```

Setz `linkCheck: { redirected: 'error' }` in der Konfiguration, um daraus einen Fehler zu machen. Ein Link in der Form `$baustein.name` hat dieses Problem nie. [Zwischen Seiten verlinken]($docs.link-between-pages) erklärt diese Form.

## Auf einem statischen Hoster

Eine statische Seite hat keinen Server. Eine exakte alte Adresse geht trotzdem, über eine kleine Seite, die den Browser weiterschickt. Eine Regel mit `:name` oder `*` geht nicht. [Eine statische Seite bauen]($docs.static-site#weiterleitungen-in-einer-statischen-seite) hat die Details.
