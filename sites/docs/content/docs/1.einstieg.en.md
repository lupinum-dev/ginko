## What Ginko is

Ginko connects a Nuxt site with its content. The site stays normal Nuxt code. The content comes from a **bundle**. A bundle is one JSON response that holds all content of the site in one language.

The content has two possible sources:

- **Platform.** Owners edit content on the hosted Ginko platform, for example opening hours, a menu, or events. The site fetches the bundle from there.
- **Files.** Developers keep texts as Markdown files in the repo, for example these docs or legal pages. The build turns them into the same bundle.

A site can mix both sources. The site reads both the same way, with `useGinko`.

Ginko uses four terms:

- **Brick**: a type of content, for example "Menu". You describe it in `ginko.config.ts`.
- **Field**: one value in a brick, for example a title or a price.
- **Entry**: one record of a brick, for example one dish.
- **Bundle**: all bricks with their values, as the site reads them.

## When to use Ginko

Use Ginko when a site has content that someone changes often, and that person should not touch code. Examples: opening hours, a lunch menu, events, job ads.

Use the file source for texts that developers maintain: docs, a blog, legal pages.

Ginko is not a page builder. You define the bricks and fields. The layout stays code in your Nuxt site. A site without changing content does not need Ginko.

## Your first site in five minutes

The first site uses the file source. It needs no platform and runs right away.

The fastest way is the starter:

```bash
npm create ginko my-site
cd my-site
npm install
npm run dev
```

Open `http://localhost:3000`. The page shows the sample text from `content/start.md`.

The steps below build the same site by hand and explain every file the starter creates.

### 1. Create the package

```json
// package.json
{
  "name": "my-site",
  "private": true,
  "type": "module",
  "dependencies": {
    "@lupinum/ginko": "^1.0.0",
    "@lupinum/ginko-content": "^1.0.0",
    "nuxt": "^4.6.0",
    "vue": "^3.5.0"
  },
  "scripts": {
    "dev": "nuxt dev",
    "build": "nuxt build",
    "postinstall": "nuxt prepare"
  }
}
```

The package `@lupinum/ginko-content` reads the Markdown files. You only need it for bricks with `source: 'files'`.

Then run `npm install`.

### 2. Describe the bricks

```ts
// ginko.config.ts
import { defineSite, f, single } from '@lupinum/ginko'

export default defineSite({
  site: 'my-site',              // identifier: lowercase letters, digits, hyphens
  name: 'My site',
  url: 'https://example.com',   // address of the live site
  timezone: 'Europe/Vienna',
  locales: ['en'],              // the first locale is the main locale
  currency: 'EUR',
  pages: { home: '/' },         // fixed pages: key and path
  bricks: {
    start: single({
      label: 'Start page',
      source: 'files',
      fields: {
        title: f.text('Title'),
        body: f.markdown('Text'),
      },
    }),
  },
})
```

`single` describes a brick with exactly one entry. Each field gets a label and optional settings. The page "Bricks" has the details.

### 3. Turn on the Nuxt module

```ts
// nuxt.config.ts
import ginko from './ginko.config'

export default defineNuxtConfig({
  compatibilityDate: '2026-10-01',
  modules: ['@lupinum/ginko/nuxt'],
  ginko,
})
```

The module checks the configuration at startup. An error in it stops the build.

### 4. Write a page that reads `useGinko`

```vue
<!-- app/app.vue -->
<template>
  <NuxtPage />
</template>
```

```vue
<!-- app/pages/index.vue -->
<script setup lang="ts">
const start = useGinko('start')
</script>

<template>
  <main>
    <h1>{{ start.data.title }}</h1>
    <GinkoMarkdown :value="start.data.body" />
  </main>
</template>
```

For a single, `useGinko('start')` returns `data` with the fields. The types come from your `ginko.config.ts`. The module imports `useGinko` and `GinkoMarkdown` for you.

### 5. Add the content as a file

```markdown
<!-- content/start.md -->
---
title: Hello Ginko
---

This text lives in `content/start.md`.
```

The file name is the brick name. The frontmatter fills the fields. The text below it fills the Markdown field.

Start the site with `npm run dev`. The page shows "Hello Ginko". In dev mode, Ginko reads changed files in `content/` again.

::callout{type="note"}
A site with platform bricks uses the same composables. You leave out `source: 'files'` and, in production, set `NUXT_PUBLIC_GINKO_PLATFORM` to the platform address. The pages "Reading content" and "Platform and CLI" have the details.
::
