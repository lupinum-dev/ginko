This page lists the errors you are most likely to see, each with its cause and its fix. Search the page for a part of your message. The names in the examples, such as `news` or `promo`, are yours in a real message.

## Where errors appear

| Where | When | What happens |
| --- | --- | --- |
| `nuxt build`, `nuxt generate` | An error in the config, in a content file or in a link | The build stops. |
| `nuxt dev` | The same errors | The server keeps running. The log names the error, and the file is missing from the site. |
| `ginko check` | The same errors, and a schema change that the platform would refuse | Exit code 1. |
| `ginko release` | A refused schema change, or a problem with the key or the platform | Exit code 1 to 4, see [ginko CLI]($docs.cli#output-and-exit-codes). |

::callout{type="warning" title="A page is missing in dev"}
In dev, an error in a file does not stop the server. Look in the log for `[ginko] Errors in content/ (these files are missing from the site):`.
::

## Content files

The message names the file, then the field in brackets.

| Message | Cause | Fix |
| --- | --- | --- |
| `content/news/1.opening.md (colour): Unknown field “colour”.` | The frontmatter has a key that the brick does not have. | Correct the name, or add the field to the brick. |
| `content/news/1.opening.de.md (date): “date” is set in the main-language file only.` | A translation file sets a field that has one value for all languages. | Remove the key from the translation file. |
| `Invalid YAML … Put text with a colon in quotes` | A frontmatter value has a `:` followed by a space. | Put the value in quotes: `description: "Open: daily"`. |
| `content/menu/prices.csv:3 (price): Column “price”: “3,5” is not a number. Use a point as the decimal separator (12.5, not 12,5).` | A cell of a CSV file does not fit its field. `:3` is the line. | Correct the cell. |

Other causes in content files:

- a language code in the file name that the site does not have
- a translation without a file in the main language
- two entries with the same slug in one language
- an image or file that is not there
- a value that the field refuses, such as a title over its `max`
- text below the frontmatter in a brick without a Markdown field
- a YAML, JSON or CSV file that cannot be read

[Content files]($docs.content-from-files) has the rules for file names and frontmatter.

## Markdown and components

| Message | Cause | Fix |
| --- | --- | --- |
| `“body”: “callout” is not allowed here (paragraphs, headings, lists (also with checkboxes), quotes, notices and footnotes).` | The profile of the Markdown field does not allow this part. The brackets list what it allows. | Set a wider profile on the field, such as `profile: 'page'` for components. See [What Markdown may contain]($docs.what-markdown-may-contain). |
| `“body”: “iframe” is not allowed.` | The tag runs code, loads other content or sends data. No profile allows it. | Write a component for it and register it. |
| `“body”: The property “style” is not allowed.` | The attribute is not on the short list for Markdown, or the component does not declare it. | Remove the attribute. For a part with its own look, write a component. |
| `“body”: Link is not allowed (only http, https, mailto, tel or /path).` | The address is not a safe link, for example it starts with `//`. | Write a full `https://` address, a path on the site, or `$brick.name`. |
| `There is no component “callot”.` | The name is not in `components` of the site. | Correct the name, or register the component. |
| `Component “callout”: There is no property “colour”.` | The component does not declare this property. | Correct the name, or declare the property. |
| `Component “pricing”: property “price” is missing.` | A required property has no value. | Add the property to the text. |

[Set up the components]($docs.set-up-components) and [Add your own component]($docs.add-your-own-component) show how a component is registered.

## Links

| Message | Level | Cause | Fix |
| --- | --- | --- | --- |
| `content/news/opening: Link $news.summer-break leads to no entry and no page.` | error | The entry or page does not exist, or it is a draft or out of its dates. | Correct the link, or publish the target. |
| `content/news/opening: Link $pages.nope leads to no entry and no page.` | error | `pages` in the config has no such key. | Use a key of `pages`. |
| `Path /docs/old matches no entry, no page and no file in public/.` | error | A link with a plain path leads nowhere. | Correct the path. Better: write the link as `$brick.name`. |
| `content/news/opening: Anchor #nope is missing: no heading with this id.` | warning | The target page has no heading with this id. | Correct the part after `#`. |
| `content/news/opening: Link /old-about leads to /about through a redirect.` | warning | The link points at an address that forwards. | Link to the new address. |

`linkCheck` in the config changes the level of each kind, see [defineSite]($docs.define-site#link-check). [Link between pages]($docs.link-between-pages) explains the link forms.

## Config

| Message | Cause | Fix |
| --- | --- | --- |
| `Too many bricks (at most 30).` | The site is over a fixed limit. | See [Limits]($docs.limits). |
| The build stops and names `locales`, `defaultLocale`, `baseUrl` or `timeZone` under `i18n` | `nuxt.config.ts` sets an option that Ginko passes itself. | Remove the option from `i18n`. The value comes from `ginko.config.ts`. |
| `ginko check` fails on an import, and `nuxt build` does not | The CLI loads the config with Node. A relative import needs the `.ts` suffix, and `~/` does not work. | Write `import { menu } from './bricks/menu.ts'`. |

## Schema check and release

`ginko check` and `ginko release` compare the config with the schema in production. A refused change starts with `✗`, and the lines below it say what to do.

| Message | Cause | Fix |
| --- | --- | --- |
| `✗ promo.until: Field “promo.until” is missing.` | The config no longer has a field that production has. | Put the field back and retire it: `retired: { 'promo.until': { drop: true } }`. |
| `✗ promo.headline: New single: required field “headline” needs a default.` | A new single has a required field without a `default`. The platform must create the single with a value. | Give the field a `default`, or set `optional: true`. |

Every rule is on [Schemas only grow]($docs.schemas-only-grow). [Release a schema change]($docs.release-a-schema-change) has the steps.

## The CLI

| Message or exit code | Cause | Fix |
| --- | --- | --- |
| `The environment variable GINKO_PLATFORM is missing.` | The site has a platform brick, and the CLI does not know the platform. | Set `GINKO_PLATFORM`. The CLI does not read `.env`. |
| `The environment variable GINKO_COMMIT is missing.` | `ginko release` runs outside GitHub Actions. | Set `GINKO_COMMIT=$(git rev-parse HEAD)`. |
| Exit code 3 | The platform did not answer, or the outcome is not known. | Run the same commit again. This is safe. |
| Exit code 4 | The platform refuses the key, or something in front of the platform refuses the request. | Check `GINKO_KEY` and its scope, then `GINKO_PLATFORM`. |

[Environment variables]($docs.environment-variables#the-cli) lists the variables.

## Translations

`ginko-i18n check` reports a key that a language does not have:

```text
error missing de legal.consent i18n/en.json:4: Missing translation
```

Add the key to the file of that language. `ginko-i18n todo` lists every missing key, see [Translate buttons and labels]($docs.translate-buttons-and-labels).

## The running site

| Answer | Cause | Fix |
| --- | --- | --- |
| **503** on every page with platform content | The site cannot load the content: the platform address is missing or wrong, or the platform does not answer. | Set `NUXT_PUBLIC_GINKO_PLATFORM`, see [Environment variables]($docs.environment-variables). In dev without the platform, give the brick `source: 'files'`. |
| **404** on the page of an entry | The entry does not exist, is a draft, is out of its dates, or has no translation in this language. | Check the entry. See [Missing translations]($docs.missing-translations). |
| **404** on a new kit page after a config change in dev | The dev server did not register the new pages. | Restart the dev server. |
| Every share card answers with an error | The site renders on a server and has no `NUXT_APP_SECRET`. | Set the variable on the host. |

A 503 is on purpose: a host such as Vercel keeps the last good page for it. A 404 would replace the page. [Handle missing content]($docs.missing-content) shows what to build for both.
