title: Mit fehlenden Inhalten umgehen

---

Diese Anleitung sorgt dafür, dass Seiten halten, wenn Inhalte fehlen. Jeder Fall hat seine eigene Antwort: ein Wert, der nicht gesetzt ist, eine Liste ohne Einträge, ein Eintrag, den es nicht gibt, und Inhalte, die sich gar nicht laden lassen.

## Ein Wert ist nicht gesetzt

Ein optionales Feld kann `undefined` sein. Zeig seinen Teil der Seite nur, wenn es einen Wert hat:

```vue
<GinkoImage v-if="post.data.photo" :image="post.data.photo" />
<p v-if="post.data.until">Bis {{ format.date(post.data.until) }}</p>
```

Auf der Plattform beginnt ein Pflichtfeld eines Einzelstücks mit seinem `default` und hat deshalb einen Wert. Für Dateien siehe unten „Eine Datei fehlt“.

## Eine Liste hat keine Einträge

Eine Sammlung ohne sichtbare Einträge liefert eine leere Liste. Sag das auf der Seite:

```vue
<ul v-if="news.items.length">
  <li v-for="item in news.items" :key="item.id">{{ item.data.title }}</li>
</ul>
<p v-else>Zurzeit keine Neuigkeiten.</p>
```

Lies `news.items[0]` nicht ohne Prüfung. Bei einer leeren Liste ist es `undefined`, und die Seite bricht mit einem Fehler 500 ab.

## Eine Datei fehlt

Ein Einzelstück in Dateien liest eine Datei, zum Beispiel `content/start.md`. Gibt es die Datei nicht, ist jedes Feld des Einzelstücks `undefined`, auch die Pflichtfelder, und die Seite zeigt leere Stellen. `ginko check` meldet diesen Fall nicht.

Leg die Datei jedes Datei-Einzelstücks an, auch wenn sie nur die Pflichtfelder enthält.

## Einen Eintrag gibt es nicht

`useGinkoEntry` antwortet mit einem 404, wenn kein sichtbarer Eintrag den Slug der Adresse hat. Das gilt für eine falsche Adresse, einen Eintrag nach seinem letzten Tag, einen Entwurf in einem Build und einen Eintrag ohne Übersetzung in dieser Sprache.

Nuxt zeigt dafür `app/error.vue`. Eine minimale Fehlerseite:

```vue [app/error.vue]
<script setup lang="ts">
const props = defineProps<{ error: { statusCode: number } }>()
</script>

<template>
  <main>
    <h1>{{ props.error.statusCode === 404 ? 'Seite nicht gefunden' : 'Etwas ist schiefgegangen' }}</h1>
    <a href="/">Zur Startseite</a>
  </main>
</template>
```

::callout{type="warning" title="Keine Inhalte in der Fehlerseite"}
Ruf in `error.vue` weder `useGinko` noch eine andere Funktion auf, die Inhalte liest. Lassen sich die Inhalte nicht laden, würde auch die Fehlerseite scheitern.
::

## Die Inhalte lassen sich nicht laden

Eine Seite mit Bausteinen auf der Plattform lädt ihre Inhalte von dort. Schlägt das fehl, antwortet die Seite mit 503 und nie mit 404. Auf Vercel hält ein 503 die letzte gute Seite im Cache; ein 404 würde sie ersetzen.

Eine Seite, deren Bausteine alle aus Dateien kommen, kennt diesen Fall nicht. Ihre Inhalte sind Teil des Builds.
