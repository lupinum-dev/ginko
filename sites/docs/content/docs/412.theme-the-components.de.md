Diese Anleitung ändert das Aussehen der Komponenten mit CSS-Variablen. Am Ende nutzen die Komponenten die Farben deiner Seite, und du weißt, wie du eine Komponente oder alle zwischen Rahmen und Fläche umschaltest.

## Bevor du beginnst

Die Seite hat die Komponenten eingerichtet, siehe [Komponenten einrichten]($docs.set-up-components). Du brauchst eine CSS-Datei, die die Seite lädt, zum Beispiel `app/assets/css/main.css`, eingetragen unter `css` in der `nuxt.config.ts`.

## Die Farben deiner Seite nutzen

Die Komponenten lesen die shadcn-Tokens. Eine Seite mit shadcn-vue hat sie schon, und die Komponenten folgen ihrem Theme ohne weiteren Schritt.

Eine Seite ohne shadcn-vue setzt die Tokens, die sie ändern will. Jede Farbe muss ein ganzer Farbwert sein: `oklch(…)`, `hsl(…)` oder Hex.

```css [app/assets/css/main.css]
:root {
  --background: #fffdf8;
  --foreground: #1c1917;
  --muted: #f5f0e6;
  --muted-foreground: #78716c;
  --border: #e7e0d2;
  --primary: #166534;
  --primary-foreground: #ffffff;
  --radius: 0.5rem;
}
```

| Token | Wofür |
| --- | --- |
| `--background`, `--card` | Die Fläche einer ruhigen Komponente. |
| `--foreground` | Text. |
| `--muted` | Die Fläche einer getönten Komponente. |
| `--muted-foreground` | Nebentext, etwa eine Bildunterschrift. |
| `--border` | Rahmen. |
| `--primary`, `--primary-foreground` | Akzente: der Hinweis `idea`, eine gewählte Quiz-Antwort, Haken in Schritten, der Abspielknopf beim Darüberfahren. |
| `--ring` | Der Fokusring. Ohne das Token `--primary`. |
| `--radius` | Runde Ecken. |
| `--font-mono` | Code. |

Fehlt ein Token, nutzt die Komponente einen neutralen Standard.

::callout{type="warning" title="Alte shadcn-Themes"}
Themes für Tailwind 3 speichern nur Zahlen, etwa `--muted: 210 40% 96%`. Das ist keine Farbe. Schreib den ganzen Wert: `--muted: hsl(210 40% 96%)`.
::

## Rahmen oder Fläche

Jede Komponente mit Rahmen ist *ruhig* (ein Rahmen) oder *getönt* (eine gefüllte Fläche). Hinweise und Zitate sind getönt, alle anderen ruhig.

````md preview
::note{title="Ruhig" appearance="quiet"}
Ein Rahmen, keine Fläche.
::

::note{title="Getönt"}
Eine Fläche, kein Rahmen.
::
````

`appearance="quiet"` oder `appearance="tint"` ändert eine Komponente. Karten folgen ihrer Gruppe `cards`.

Für die ganze Seite setzt du zwei Tokens:

```css [app/assets/css/main.css]
:root {
  --ginko-surface: var(--muted);
  --ginko-surface-border: transparent;
}
```

Dieses Beispiel macht jede Komponente mit Rahmen getönt.

## Die Farben der Hinweise

Jede Art von Hinweis hat ihr eigenes Token:

```css [app/assets/css/main.css]
:root {
  --ginko-info: #1d4ed8;
  --ginko-warning: #b45309;
  --ginko-error: #b91c1c;
  --ginko-success: #15803d;
  --ginko-idea: #7c3aed;
}
```

## Dunkler Modus

Die Komponenten sind dunkel, wo die Seite dunkel ist: mit `color-scheme: dark`, mit der Klasse `.dark` oder mit `data-theme="dark"` an einem Elternelement. Eine Seite, die nur hell ist, bleibt hell, auch auf einem dunklen System.

Mit shadcn-Tokens setzt du die dunklen Werte wie gewohnt unter `.dark`. Die Standardfarben der Komponenten haben eine eigene dunkle Hälfte.

Code steht immer auf einer dunklen Fläche, in beiden Modi.

## Prüfe, ob es funktioniert

Öffne eine Seite mit einem Hinweis und einer Karte. Setz `--ginko-warning` auf eine deutliche Farbe wie `magenta` und speichere. Das Zeichen eines Hinweises `::warning` hat diese Farbe. Entferne die Zeile wieder.

## Was stabil bleibt

Richte deine eigenen Regeln nur auf diese Namen aus. Sie ändern sich nur in einem Minor-Release, mit einem Eintrag im Changelog. Alle anderen Klassennamen und `--ginko-*`-Variablen sind intern.

| Art | Namen |
| --- | --- |
| Tokens | `--ginko-surface`, `--ginko-surface-border`, `--ginko-tint` (die Fläche von getönt, Standard `--muted`), `--ginko-info`, `--ginko-warning`, `--ginko-error`, `--ginko-success`, `--ginko-idea`, `--ginko-scroll-margin` (Abstand über einem API-Eintrag, zu dem ein Link springt, Standard `5rem`) |
| Code-Fläche | `--ginko-code-frame`, `--ginko-code-bg`, `--ginko-code-fg`, `--ginko-code-muted`, `--ginko-code-hover` |
| Klassen | `ginko-<tag>` am äußeren Element jedes Tags, zum Beispiel `ginko-callout` oder `ginko-card`. Ausnahmen: Der Codeblock ist `ginko-code`, ein Markdown-Bild `ginko-img`, und `collapse` ohne `title` ist `ginko-clip`. |
| Attribut | `data-appearance="quiet"` oder `"tint"` am äußeren Element |
