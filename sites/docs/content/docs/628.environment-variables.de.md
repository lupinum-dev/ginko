Eine Seite, deren Bausteine alle aus Dateien kommen, braucht keine dieser Variablen. Die Ausnahme ist `NUXT_APP_SECRET` für Teilen-Karten auf einem Server.

## Die Seite

Setze diese Variablen dort, wo die Seite gebaut wird und läuft: in `.env` auf deinem Computer und in den Einstellungen deines Hosts.

| Variable | Nötig, wenn | Was sie tut |
| --- | --- | --- |
| `NUXT_PUBLIC_GINKO_PLATFORM` | Die Seite hat Plattform-Bausteine, und `ginko.config.ts` setzt kein `platform`. | Die Adresse der Plattform. Sie hat Vorrang vor `platform` in der Konfiguration. |
| `NUXT_GINKO_REVALIDATE_TOKEN` | Freiwillig, für eine Plattform-Seite auf Vercel. | Das Site-Token. Damit erreicht eine Veröffentlichung die Seite sofort. Ohne es kommt eine Änderung innerhalb von 60 Sekunden an. |
| `NUXT_APP_SECRET` | Die Seite hat Teilen-Karten und rendert auf einem Server. | Ein zufälliges Secret mit 32 oder mehr Zeichen. `nuxt-og-image` signiert damit die Adressen der Karten. |
| `NUXT_PUBLIC_GINKO_NOINDEX` | Eine Seite, die aus Suchmaschinen bleiben muss. | `true` lässt `robots.txt` alles sperren, und jede Antwort schickt `X-Robots-Tag: noindex`. |
| `NUXT_PUBLIC_SITE_URL` | Freiwillig, Seiten aus einem Template. | Die Adresse der Seite. Die Templates lesen sie als `url` in `ginko.config.ts`. So kann ein Repository mehrere Adressen bedienen. |

### `NUXT_PUBLIC_GINKO_PLATFORM`

Ohne diese Variable und ohne `platform` in der Konfiguration:

- Im Dev-Modus liest die Seite die Plattform unter `http://localhost:3100`. Diese Adresse ist für die Arbeit an Ginko selbst; eine Seite mit Plattform-Inhalten antwortet mit 503.
- Auf einem Host antwortet jede Seite mit Plattform-Inhalten mit 503, und das Server-Log sagt es einmal.
- Ein Production-Build auf Vercel stoppt mit einem Fehler. Ein Preview-Build gibt eine Warnung aus.

Setze die Variable auf Vercel für Production und für Preview. Eine Variable, die es nur für Preview gibt, lässt die Produktionsseite ohne Inhalte.

### `NUXT_GINKO_REVALIDATE_TOKEN`

Ein Inhaber erstellt das Token im Studio: Team, „Site token“. Die Plattform zeigt es einmal.

- Mit dem Token rendert die Plattform die geänderten Seiten direkt nach einer Veröffentlichung neu, und Inhaber können „Update website now“ verwenden.
- Der Server der Seite schickt das Token mit, wenn er Inhalte lädt. So können Besucher das Anfragelimit der Seite nicht aufbrauchen.
- Ein neues Token beendet das alte sofort. Setze den neuen Wert direkt danach auf dem Host und deploye neu.
- Ginko gibt das Token als `bypassToken` an Vercel, außer deine `nuxt.config.ts` setzt `nitro.vercel.config.bypassToken` selbst.

### `NUXT_APP_SECRET`

`create-ginko` schreibt eines in `.env` für deinen Computer. Setze auch eines auf dem Host: Ohne es antwortet jede Teilen-Karte mit einem Fehler, und der Build warnt. Ein statischer Build (`nuxt generate`) zeichnet jede Karte beim Build und braucht keines.

Erzeuge eines mit:

```bash
openssl rand -hex 32
```

### `NUXT_PUBLIC_GINKO_NOINDEX`

Suchmaschinen indexieren eine Seite nur unter der Adresse in `url`. Jeder andere Host, etwa ein Preview-Deployment, bekommt auch ohne diese Variable `noindex`.

Setze `NUXT_PUBLIC_GINKO_NOINDEX=true` für eine Demo oder für eine Seite, die auf einer vorläufigen Adresse läuft, bis ihre Domain bereit ist. Entferne die Variable, wenn die Seite auf ihre eigene Domain umzieht.

## Das CLI

Das `ginko`-CLI liest diese Variablen. Es liest `.env` nicht: Setze sie in der Shell oder in den Einstellungen deiner CI.

| Variable | Nötig für | Was sie ist |
| --- | --- | --- |
| `GINKO_PLATFORM` | jeden Befehl bei einer Seite mit Plattform-Bausteinen | Die Adresse der Plattform. Ohne sie liest das CLI `NUXT_PUBLIC_GINKO_PLATFORM`. |
| `GINKO_KEY` | `check` gegen die Plattform, `release`, `export` | Ein Schlüssel der Seite, in der Form `ginko_<site>_<32 Zeichen>`. Ein Inhaber erstellt ihn im Studio: Team, „Publishing keys“, „New key“. Ein Schlüssel hat Bereiche: `check`, `release`, `export` und `pull`. |
| `GINKO_COMMIT` | `release` | Der Commit, zu dem das Release gehört. Ohne ihn liest das CLI `GITHUB_SHA`, das GitHub Actions setzt. |
| `GINKO_BRANCH` | freiwillig | Der Branch des Releases. Standard `main`. |
| `GINKO_REMOTE` | freiwillig | Das git-Remote, mit dem das CLI den Commit vergleicht. Standard `origin`. |

Eine fehlende Variable stoppt den Befehl mit Exit-Code 2:

```text
The environment variable GINKO_PLATFORM is missing.
```

Von Hand sieht ein Release so aus:

```bash
GINKO_PLATFORM=https://cms.example.com GINKO_KEY=ginko_cafe-linde_… GINKO_COMMIT=$(git rev-parse HEAD) npx ginko release
```

Halte `GINKO_KEY` als Secret in deiner CI. Committe ihn nicht.

## Nicht für Seiten

`GINKO_LOCAL` und `GINKO_REGISTRY_URL` sind für die Arbeit an Ginko selbst. Eine Seite setzt sie nicht.
