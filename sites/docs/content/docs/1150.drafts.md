This guide keeps an unfinished entry out of the live site while you still see it on your own computer. It is for bricks with `source: 'files'`. On the platform, a new entry is a draft until someone publishes it in the Studio.

## Steps

::steps
#### Mark the entry as a draft

```markdown [content/news/3.spring.md]
---
title: Spring opening
date: 2026-11-10
$draft: true
---

Not ready yet.
```

In a YAML or JSON file, `$draft: true` is a key like the others. In a CSV file, it is a column `$draft` with the cell `true`.

#### See it in the dev server

Run `npm run dev`. The entry is in its list and has its page, so you can read it as a visitor would.

#### Publish it

Remove the line `$draft: true` and deploy the site. The next build includes the entry.
::

## What leaves a draft out

`nuxt build`, `nuxt generate` and `ginko check` leave out every draft. The live site has no list entry, no page and no sitemap line for it.

`ginko check` does not read drafts at all. A mistake in a draft shows up only when you remove `$draft: true`.

## Put an entry online at a time

`$publishAt` holds an entry back like a draft until its time:

```markdown [content/news/4.summer.md]
---
title: Summer menu
date: 2026-12-01
$publishAt: 2026-12-01T09:00
---
```

Write a day (`2026-12-01`, which means 00:00) or a day and a time (`2026-12-01T09:00`), on the clock of the site's `timeZone`. No offset and no seconds. Quotes are optional. The key goes in the file of the main language, and the time holds for every language.

Before that time, the entry is treated as a draft: the dev server shows it, and a build leaves it out. From that time on, it is online. Unlike a draft, the build and `ginko check` check it in full, so a mistake in it fails the build now and not on the day nobody watches. `$draft: true` and `$publishAt` together are an error: a draft with a time is `$publishAt` alone.

A date field does not hold an entry back. A post with a `date` in the future and no `$publishAt` is online. When the collection names its date field in `publishedOn` (the posts and the changelog of Ginko do), `ginko check` notes such a post, and a post whose date is before the day of its `$publishAt`.

File content is part of the build, so nothing changes between two builds. To publish at the time, build the site then, for example with a scheduled deploy hook of your host every morning.
