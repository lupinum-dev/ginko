Diese Anleitung verlinkt aus einem Markdown-Text auf einen anderen Eintrag oder eine andere Seite. Am Ende überstehen deine Links einen neuen Slug oder eine neue Route, und ein kaputter Link bricht den Build ab.

## Schritte

::steps
#### Auf einen Eintrag über seinen Namen verlinken

Schreib `$<baustein>.<name>` als Ziel des Links. Der Name ist der Dateiname ohne Nummer und Sprache:

```markdown [content/news/1.opening.md]
Read more [about me]($pages.about).
```

Das verlinkt auf den Eintrag aus `content/pages/1.about.md`. Auf der Seite führt der Link zu `/about`, in der deutschen Fassung zur deutschen Adresse desselben Eintrags.

#### Auf eine feste Seite über ihren Schlüssel verlinken

Eine Seite aus `pages` in `ginko.config.ts` hat einen Schlüssel. Verlinke sie mit `$page.<schlüssel>`:

```markdown
Back to [the start page]($page.home).
```

#### Auf eine Überschrift verlinken

Häng die Id einer Überschrift nach `#` an:

```markdown
See [the opening hours]($pages.contact#opening-hours).
```

Die Id einer Überschrift ist ihr Text in Kleinbuchstaben mit `-` zwischen den Wörtern. Eine Überschrift unter einer anderen beginnt mit deren Id: „Saturday“ unter „Opening hours“ hat die Id `opening-hours-saturday`.

#### Die Prüfung laufen lassen

```bash
npx ginko check
```

Ein Link ins Leere ist ein Fehler, hier ein Link auf `$pages.nope`:

```text
content/news/opening: Link $pages.nope leads to no entry and no page.
```

Ein Link auf einen verborgenen Eintrag, etwa einen Entwurf oder einen Eintrag nach seinem letzten Tag, ist derselbe Fehler.

Eine Überschrift, die es nicht gibt, ist eine Warnung:

```text
content/news/opening: Anchor #nope is missing: no heading with this id.
```
::

## Warum nicht den Pfad schreiben

Ein Pfad wie `/about` geht heute. Er bricht ohne Hinweis, wenn sich der Slug des Eintrags oder die Route des Bausteins ändert, und er ist in jeder anderen Sprache falsch. Ginko schreibt die Adresse eines `$`-Links beim Build, für die Sprache der Seite.

## Festlegen, wie streng die Prüfungen sind

Jeder Build und `ginko check` prüfen die Links in allen Markdown-Feldern.

| Prüfung | Was sie findet | Standard |
| --- | --- | --- |
| `broken` | einen `$…`-Link auf einen Eintrag oder eine Seite, die es nicht gibt | `'error'` |
| `anchors` | ein `#…`, das keine Überschrift auf der Zielseite ist | `'warn'` |
| `redirected` | einen Link auf eine alte Adresse, die weiterleitet | `'warn'` |
| `external` | einen `http(s)://`-Link, dessen Server mit 404 oder 410 antwortet oder nicht antwortet | `'off'` |

`'error'` bricht den Build ab, `'warn'` gibt das Problem aus, `'off'` lässt die Prüfung weg. Setz die Stufen in `ginko.config.ts`:

```ts [ginko.config.ts]
export default defineSite({
  // …
  linkCheck: { anchors: 'error', external: 'warn' },
})
```

Auf einer Seite, deren Bausteine alle aus Dateien kommen, findet `broken` auch einen geschriebenen Pfad (`/…`), der zu keinem Eintrag, keiner Seite und keiner Datei in `public/` passt. Die Prüfung `external` fragt andere Server. Sie läuft deshalb bei einem Build und bei `ginko check`, nie im Dev-Server.
