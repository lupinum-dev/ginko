Mit dieser Anleitung bringt ein Nuxt-Modul seine eigenen übersetzten Texte mit. Am Ende übersetzen die Komponenten des Moduls mit `useI18n('billing')`, und die App, die das Modul installiert, kann jeden dieser Texte ändern.

`@lupinum/ginko-components` und `@lupinum/ginko-docs` liefern ihre Texte so mit.

## Bevor du beginnst

Du schreibst ein Nuxt-Modul, und in der App, die es nutzt, ist `@lupinum/ginko-i18n` eingerichtet, siehe [i18n-Schnellstart]($docs.i18n-quick-start).

## Schritte

::steps
#### Die Sprachdateien ins Modul legen

Eine Datei pro Sprache, in einem Ordner des Moduls:

```json [modules/billing/i18n/en.json]
{ "invoice": "Invoice", "paid": "Paid on {day, date, long}" }
```

```json [modules/billing/i18n/de.json]
{ "invoice": "Rechnung", "paid": "Bezahlt am {day, date, long}" }
```

Die Schlüssel haben kein Präfix. Das fügt der Namensraum hinzu.

#### Den Ordner registrieren

```ts [modules/billing/index.ts]
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: { name: 'billing' },
  setup(_options, nuxt) {
    const { resolve } = createResolver(import.meta.url)
    nuxt.hook('ginko-i18n:sources', (sources) => {
      sources.push({ namespace: 'billing', dir: resolve('./i18n') })
    })
  },
})
```

`namespace` ist Pflicht. So kann eine Bibliothek nie einen Schlüssel der App ersetzen.

#### Im Modul übersetzen

`useI18n('billing')` nimmt Schlüssel relativ zum Namensraum:

```vue
<script setup lang="ts">
const { t } = useI18n('billing')
</script>

<template>
  <h2>{{ t('invoice') }}</h2>
</template>
```

In einer Server-Route des Moduls macht `getI18n(event, 'billing')` dasselbe.
::

## Prüfe, ob es funktioniert

Nutze die Komponente in einer Seite. `/` zeigt „Invoice“ und `/de` zeigt „Rechnung“.

## Einen Text in der App überschreiben

Die App setzt den Schlüssel unter dem Namensraum in ihrer eigenen Datei. Ihr Text gewinnt:

```json [i18n/en.json]
{ "billing": { "invoice": "Bill" } }
```

Der Name des Namensraums ist also für die Bibliothek reserviert. Die App darf ihn nicht für ihre eigenen Texte nutzen.

## Fehlende Übersetzungen einer Bibliothek

`ginko-i18n check` in der App prüft auch die Schlüssel einer Bibliothek. Hat die Bibliothek keinen deutschen Text für `paid`, meldet die Prüfung:

```text
error missing de billing.paid modules/billing/i18n/en.json:1: Missing translation
```

`ginko-i18n apply` schreibt die Übersetzung eines Bibliotheks-Schlüssels in die Dateien der App, unter dem Namensraum: `i18n/de.json` bekommt `{ "billing": { "paid": "…" } }`. Die Dateien der Bibliothek bleiben, wie sie sind.
