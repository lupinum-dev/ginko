## What you get without code

The Nuxt module serves these addresses for every site. You write no code for them:

| Address | Content |
| --- | --- |
| `/sitemap.xml` | Every page and entry with an address, in every locale |
| `/robots.txt` | Crawling rules, with the sitemap |
| `/llms.txt` | An index of the site for AI agents |
| `/llms-full.txt` | All entries of the main locale as Markdown in one file |
| `<page>.md` | One entry as Markdown |

A file of the same name in `public/` wins: your own `public/robots.txt` or `public/llms.txt` replaces Ginko's.

## Head tags and JSON-LD

Call `useGinkoSeo` once per page. It sets the title, the description, Open Graph and Twitter tags, and JSON-LD. ginko-i18n adds the canonical URL, `hreflang` with `x-default`, and `<html lang>`. The options are on [Reading content]($docs.seiten-lesen).

The site-wide defaults go in `seo` in `ginko.config.ts`:

```ts
// ginko.config.ts
import { defineSite } from '@lupinum/ginko'

export default defineSite({
  site: 'linde',
  name: 'Linden Inn',
  url: 'https://linde.example',
  timeZone: 'Europe/Vienna',
  locales: ['en'],
  currency: 'EUR',
  pages: { home: '/' },
  bricks: {},
  seo: {
    titleTemplate: '%s · Linden Inn',    // %s is the page title
    description: 'Country inn with a garden.',
    image: '/og.png',                  // share image of pages without their own
    organization: { logo: '/logo.png', sameAs: ['https://www.instagram.com/linde'] },
  },
})
```

The home page gets `WebSite` JSON-LD, and with `seo.organization` also `Organization`. Every other kind you pass yourself with `jsonLd`, for example an event:

```ts
const route = useRoute()
const event = useGinkoEntry('events', () => route.params.slug)
useGinkoSeo(() => ({
  title: event.value.data.title,
  type: 'article',
  jsonLd: [{
    '@context': 'https://schema.org',
    '@type': 'Event',
    name: event.value.data.title,
    startDate: event.value.data.date,
  }],
}))
```

The preset `@lupinum/ginko-preset-gastro` brings JSON-LD for restaurants, menus, opening hours and events (see [Presets]($docs.presets)).

## Sitemap

`/sitemap.xml` lists every page from `pages` and every visible entry that has an address, in every locale. Each address names its translations (`hreflang`, with `x-default`). Entries carry `lastmod` from their last change and up to 20 images.

Do you need more, for example pages from your own code? Install `@nuxtjs/sitemap`. Then that module owns `/sitemap.xml`, and ginko-i18n gives it the translations of your static pages. Ginko's entry addresses (news, events, docs pages, with their `lastmod` and images) are then no longer in the sitemap: add them through your own sitemap source.

## robots.txt

On the site's own address (`url` in `ginko.config.ts`), `/robots.txt` allows everything and names the sitemap. `www.` counts as the same address. On every other host, for example a preview deployment, staging or `localhost`, it forbids everything, and every response carries `X-Robots-Tag: noindex`. So a preview never lands in a search engine.

## Redirects

A moved page answers with a redirect, by default **301**. There are two sources:

- An entry names its old addresses in `redirectFrom`. See [Content from files]($docs.inhalte-aus-dateien).
- The site lists rules in `redirects`:

```ts
// ginko.config.ts
export default defineSite({
  // …
  redirects: [
    { from: '/speisekarte', to: '/menu' },
    { from: '/events/:slug', to: '/whats-on/:slug' },
    { from: '/old-blog/*', to: '/blog/:splat', status: 302 },
  ],
})
```

`:name` matches one path segment. A `*` at the end matches the rest, which `to` uses as `:splat`. The first matching rule wins, and the query string stays. An invalid rule stops the build.

## Text for AI agents

Agents read Markdown better than HTML. So every entry of a collection with a `route` also exists as Markdown:

- **`<page>.md`**: `/en/docs/languages.md` returns the page `/en/docs/languages` as Markdown.
- **`Accept: text/markdown`**: a request for the normal address returns the same Markdown when its `Accept` header prefers `text/markdown` over HTML. This needs a server, and it is not stable yet: the ISR cache on Vercel may ignore `Vary: Accept`, so use the `.md` addresses. On a static host only the `.md` addresses work (see [Publishing]($docs.veroeffentlichen)).
- **`Link` header**: pages of file entries name their Markdown version (`rel="alternate"`), so an agent finds it.
- **Not found**: a `.md` address without an entry answers with 404 in Markdown and suggests similar pages.
- **A dot in the slug** (`/blog/v1.2`) changes nothing: the Markdown is at `/blog/v1.2.md`, and `Accept` and `Link` work as on any page.

`/llms.txt` lists the entries of the main locale with links to their Markdown. Under the site name, it shows `agents.description`, else `seo.description`. `/llms-full.txt` holds the text of all these entries in one file.

```ts
// ginko.config.ts
export default defineSite({
  // …
  agents: { description: 'Opening hours, menu and events of the Linden Inn.' },
})
```

`agents: { enabled: false }` turns off all of it: `/llms.txt`, `/llms-full.txt` and the Markdown versions.

`agents: { review: true }` makes every agent that writes through the platform write a proposal that needs a yes from an owner or admin (see [Platform and CLI]($docs.plattform-und-cli)).

## The docs MCP endpoint

A docs site with `@lupinum/ginko-docs` also answers at `POST /__ginko/docs-mcp`. This is an [MCP](https://modelcontextprotocol.io) server (Streamable HTTP) with two read-only tools:

- `search_docs(query, locale?)`: the best matching pages and sections, with path and excerpt,
- `read_doc(path)`: one page as Markdown.

An agent connects with the address, for example in Claude Code:

```bash
claude mcp add --transport http my-docs https://docs.example.com/__ginko/docs-mcp
```

The endpoint needs no key and shows only what the public site shows. It needs a server: a static build (`nuxt generate`) has no endpoint.

## Addresses and headers

Agents, scripts and crawlers may rely on these addresses and headers. Until 1.0, a stable one changes its name or meaning only in a minor release, and the changelog names the change.

| Address or header | What it is |
|---|---|
| `<page>.md` | The entry as Markdown, `Content-Type: text/markdown; charset=utf-8`. Without an entry: 404, also in Markdown. |
| `Accept: text/markdown` | Not stable yet. On a page's normal address: the same Markdown, with `Vary: Accept`. Needs a server, and the ISR cache on Vercel may ignore `Vary`. Agents use `<page>.md` and the `Link` header. |
| `Link: <page.md>; rel="alternate"; type="text/markdown"` | On pages of file entries, with `Vary: Accept`. |
| `/llms.txt`, `/llms-full.txt` | The entries of the main locale: a list with links, and the full text. |
| `/sitemap.xml`, `/robots.txt` | See [Sitemap](#sitemap) and [robots.txt](#robotstxt). |
| `X-Robots-Tag: noindex` | On every host other than `url`, and on every address under `/__ginko/`. |
| `/__ginko/search/<locale>.json` | The search index (see below). Its format is `SearchIndexJson` of `@lupinum/ginko/search`. |
| `/__ginko/docs-mcp` | The MCP endpoint of a docs site. |
| `/_ginko/img/<hash>.<ext>` | Images next to content files, cached for a year. The hash comes from the content: treat it as opaque, and take the address from the entry, never build it yourself. |

Everything else is internal and can change in any release: the other addresses under `/__ginko/` (such as the preview and `/__ginko/files/`) and the headers `x-ginko-rev`, `x-ginko-min-rev` and `x-ginko-site-token`. The full list is in [Internal, do not use]($docs.plattform-und-cli#internal-do-not-use).

## Search for your own site

For bricks with `source: 'files'`, the build makes a search index per locale: one record for the text before the first `##` heading of an entry, and one for each `##` and `###` section. The site serves it at `/__ginko/search/<locale>.json`. The docs layer uses it for its ⌘K search. In your own site, you read it with `@lupinum/ginko/search`:

```vue
<!-- app/components/SiteSearch.vue -->
<script setup lang="ts">
import type { SearchHit, SearchIndex, SearchIndexJson } from '@lupinum/ginko/search'

const { locale } = useI18n()
const query = ref('')
const hits = ref<SearchHit[]>([])
const indexes = new Map<string, SearchIndex>()

watch(query, async (text) => {
  // Load the search engine and the index only when someone searches.
  const { loadIndex, search } = await import('@lupinum/ginko/search')
  let index = indexes.get(locale.value)
  if (!index) {
    index = await loadIndex(await $fetch<SearchIndexJson>(`/__ginko/search/${locale.value}.json`))
    indexes.set(locale.value, index)
  }
  hits.value = search(index, text, { limit: 8 })
})
</script>

<template>
  <input v-model="query" type="search" aria-label="Search">
  <ul>
    <li v-for="hit in hits" :key="hit.id">
      <NuxtLink :to="hit.url">{{ hit.heading ?? hit.title }}</NuxtLink>
      <p>{{ hit.excerpt }}</p>
    </li>
  </ul>
</template>
```

`search` finds words by their beginning and accepts small typos. A hit has `id`, `url` (with the `#anchor` of its section), `title`, `heading`, `excerpt` and `score`. Each index follows its language. German, English, French, Italian, Spanish, Dutch and Portuguese find other forms of a word ("connecting" finds "connected", "Gerichte" finds "Gericht"). Other languages match words by their beginning. Accents do not matter: "cafe" finds "café", and in German "ae" finds "ä". Content from the platform is not in this index.
