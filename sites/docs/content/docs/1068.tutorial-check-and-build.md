In [chapter 4]($docs.tutorial-languages) the site got a second language. This last chapter makes it ready to go online: every page gets a title, `ginko check` finds mistakes in the content, and a build makes the finished site. At the end, the built site runs on your computer as it will run online.

## Steps

::steps
#### Set the defaults for titles

Add `seo` to `ginko.config.ts`, next to `currency`:

```ts [ginko.config.ts]
seo: { titleTemplate: '%s · Studio Nord', description: 'Book and poster design in Vienna.' },
```

`titleTemplate` wraps the title of each page; `%s` stands for that title. `description` is the description of every page that sets none.

#### Give each page its title

Call `useGinkoSeo` once in each page:

```vue [app/pages/index.vue]
<script setup lang="ts">
const home = useGinko('home')
useGinkoSeo({})
</script>
```

```vue [app/pages/[slug].vue]
<script setup lang="ts">
const route = useRoute()
const page = useGinkoEntry('pages', () => route.params.slug)
useGinkoSeo(() => ({ title: page.value.data.title, description: page.value.data.summary }))
</script>
```

```vue [app/pages/blog/index.vue]
<script setup lang="ts">
const posts = useGinko('posts')
const { t, format } = useI18n()
useGinkoSeo(() => ({ title: t('nav.blog') }))
</script>
```

```vue [app/pages/blog/[slug].vue]
<script setup lang="ts">
const route = useRoute()
const post = useGinkoEntry('posts', () => route.params.slug)
const authors = useGinko('authors')
const { format } = useI18n()
useGinkoSeo(() => ({ title: post.value.data.title, description: post.value.data.description, type: 'article' }))
const names = computed(() => authors.value.items
  .filter((author) => post.value.data.authors?.includes(author.id))
  .map((author) => author.data.name))
</script>
```

The templates of the pages stay as they are. Pass a function, so the title follows the content. The home page passes no title and gets the name of the site: "Studio Nord".

Open `http://localhost:3000/de/ueber-uns`. The browser tab reads "Über uns · Studio Nord". [Set titles and share cards]($docs.titles-and-share-cards) adds images for links in chats and social networks.

#### Check the content

```bash
npm run check
```

`ginko check` reads every content file and every link between them:

```text
OK: schema and links are fine.
```

Now make two mistakes. In `content/posts/hello.md`, name an author who does not exist, `authors: [authors/jonas]`. In `content/posts/new-poster-series.md`, add a link to a page that does not exist, `[about us](/about-us)`. Run the check again:

```text
content/posts/hello.md (authors): There is no entry “authors/jonas”. An id is the folder and the file name without number and language: content/authors/anna.yml is authors/anna.
content/posts/new-poster-series: Path /about-us matches no entry, no page and no file in public/.
ginko check found problems. Each one is listed on stderr.
```

Each line names the file and the field. Fix both and run the check once more. The build runs the same checks: a mistake in the content stops it.

#### Build and run the finished site

```bash
npm run build
npm run preview
```

Open `http://localhost:3000`. This is the site as it runs on a server. Open `http://localhost:3000/blog/next-book`: the draft from chapter 3 answers with the 404 page, and the blog list leaves it out.
::

## What you built

A site with a home page, pages with a menu, a blog with authors and drafts, in two languages, with titles, a checked set of content files and a build. Every text is a Markdown or YAML file in `content/`; `ginko.config.ts` says which content exists, and the pages in `app/pages/` show it.
