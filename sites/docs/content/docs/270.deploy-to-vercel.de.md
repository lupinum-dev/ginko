Diese Anleitung stellt eine Seite auf Vercel online. Am Ende antwortet die Seite unter ihrer Adresse, Seiten kommen aus dem Cache, und Suchmaschinen indexieren nur die Produktionsadresse.

Vercel ist der Hoster, für den Ginko gebaut und getestet ist. Eine Seite mit Bausteinen auf der Plattform braucht ihn oder einen anderen Hoster mit Server. Eine Seite, deren Bausteine alle aus Dateien kommen, kann auch eine statische Seite sein: siehe [Eine statische Seite bauen]($docs.static-site).

## Bevor du beginnst

- Die Seite liegt in einem Git-Repository auf GitHub, GitLab oder Bitbucket.
- `npx ginko check` läuft ohne Fehler.

## Schritte

::steps
#### Die Produktionsadresse setzen

```ts [ginko.config.ts]
export default defineSite({
  site: 'linde',
  url: 'https://www.linde.example',
  // …
})
```

`url` ist die Adresse, die die Seite haben wird. Ginko schreibt sie in die Canonical-Links und die Sitemap. Jede andere Adresse, unter der die Seite läuft, etwa eine Vorschau auf `*.vercel.app`, sagt Suchmaschinen, dass sie fernbleiben sollen.

#### Das Repository auf Vercel importieren

Wähle im Vercel-Dashboard „Add New“, dann „Project“, und nimm das Repository. Vercel erkennt Nuxt und führt `nuxt build` aus. Ändere nichts an den Build-Einstellungen.

#### Die Umgebungsvariablen setzen

| Variable | Wann du sie brauchst | Wert |
| --- | --- | --- |
| `NUXT_APP_SECRET` | Die Seite hat Teilen-Karten (`nuxt-og-image`, in jedem Template). | Ein zufälliger Text mit mindestens 32 Zeichen. Ohne ihn antwortet jede Teilen-Karte mit einem Fehler. |
| `NUXT_PUBLIC_GINKO_PLATFORM` | Die Seite hat Bausteine auf der Plattform, und `ginko.config.ts` setzt `platform` nicht. | Die Adresse der Plattform. |
| `NUXT_GINKO_REVALIDATE_TOKEN` | Die Seite hat Bausteine auf der Plattform. Freiwillig. | Das Site-Token aus dem Studio („Team“, „Site token“). Damit ist eine Veröffentlichung sofort zu sehen. |

Setz jede Variable für Production und für Preview. Eine Variable, die es nur für Preview gibt, fehlt der Produktionsseite.

Eine Seite, deren Bausteine alle aus Dateien kommen und die keine Teilen-Karten hat, braucht keine Variable.

#### Veröffentlichen und prüfen

Vercel baut die Seite bei jedem Push. Prüf das Ergebnis mit `curl`:

```bash
curl -sI https://www.linde.example/about
```

Bei der ersten Anfrage wird die Seite gerendert, bei der zweiten kommt sie aus dem Cache:

```text
HTTP/2 200
x-vercel-cache: HIT
```

#### Deine Domain ergänzen

Öffne im Projekt auf Vercel „Settings“, dann „Domains“, und trag die Adresse aus `url` ein. Ab dann dürfen Suchmaschinen die Seite unter dieser Adresse indexieren.
::

## Was die Seite auf Vercel tut

Jede Zeile wurde an einer veröffentlichten Seite gemessen.

| Du fragst nach | Die Seite antwortet |
| --- | --- |
| einer Seite | `200`, aus dem Cache und höchstens alle 60 Sekunden neu gerendert |
| einer Seite mit Schrägstrich am Ende oder Großbuchstaben (`/about/`, `/About`) | `301` zur einen Adresse der Seite |
| einer alten Adresse aus `redirects` oder `redirectFrom`, auch mit Muster | `301` zur neuen Adresse |
| einer Adresse, die es nicht gibt | ein echtes `404` mit deiner Fehlerseite |
| einer Seite mit `.md` am Ende | die Seite als Markdown, für Agenten |
| irgendeiner Adresse auf einem anderen Host als `url` | dasselbe, mit `x-robots-tag: noindex`, und `robots.txt` sagt `Disallow: /` |

## Von der Kommandozeile veröffentlichen

`vercel deploy` lädt den Ordner hoch und baut ihn, ohne Git-Import:

```bash
npx vercel deploy
```

::callout{type="warning" title="Das erste Deployment ist Production"}
Das erste Deployment eines neuen Projekts wird sein Production-Deployment, auch ohne `--prod`. Vercel sagt das in der Ausgabe. Spätere Läufe von `vercel deploy` sind Vorschauen.
::

## Eine Seite, die noch nicht für Suchmaschinen bereit ist

Eine Seite, die unter ihrer endgültigen Adresse läuft, bevor sie fertig ist, setzt auf diesem Deployment eine weitere Variable:

```text
NUXT_PUBLIC_GINKO_NOINDEX=true
```

`robots.txt` sperrt dann alles, und jede Antwort hat `x-robots-tag: noindex`. Entferne die Variable, wenn die Seite gefunden werden darf.

## Vor dem Deploy freigeben

Eine Seite mit Bausteinen auf der Plattform führt in CI vor dem Deploy `ginko release` aus und deployt nur, wenn das Release es sagt. [Eine Schema-Änderung freigeben]($docs.release-a-schema-change) hat das Snippet.
