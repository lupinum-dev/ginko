Ginko hat feste Grenzen. Sie halten das Bundle klein genug, um es in einer Antwort zu laden, und sie halten die Formulare im Studio bedienbar. Eine Konfiguration über einer Schema-Grenze stoppt `ginko check` und den Build, zum Beispiel mit `Too many bricks (at most 30).`

## Schema

| Was | Grenze |
| --- | --- |
| Bausteine pro Seite | 30 |
| Felder pro Baustein | 60 |
| `max` einer Sammlung | 1 bis 500 Einträge |
| Sprachen pro Seite | 20 |
| Größe des Schemas | 256 KiB |

## Inhalte auf der Plattform

| Was | Grenze |
| --- | --- |
| Einträge pro Seite, alle Sammlungen zusammen | 2.000 |
| Inhalte einer Seite | 4 MiB |
| Ein Eintrag | 480 KiB |
| Entfernte Einträge, die die Plattform aufbewahrt | 4 MiB |

Die Größen zählen die gespeicherten Werte der Einträge als JSON-Text. Das Studio zeigt, wie viel jeder Grenze eine Seite nutzt. Wenn die entfernten Einträge ihre Grenze überschreiten, löscht die Plattform die ältesten davon früher.

## Felder

| Was | Grenze |
| --- | --- |
| `f.text` | höchstens 500 Zeichen |
| `f.url` | 2.000 Zeichen |
| `f.longtext` | Standard 2.000 Zeichen, höchstens 5.000 |
| `f.markdown` | Standard 50.000 Zeichen, höchstens 500.000 |
| `f.money` | 100.000.000 kleinste Einheiten, also 1.000.000,00 in einer Währung mit Cent |
| Ausschnitte eines Bildfeldes | 8 |

[Feldtypen]($docs.field-types) nennt die Einstellungen jedes Typs.

## Uploads auf der Plattform

| Datei | Grenze |
| --- | --- |
| Bild: JPEG, PNG oder WebP | 20 MB |
| PDF | 10 MB |

## Wenn eine Seite eine Grenze erreicht

- **Einträge.** Gib alten Einträgen ein Enddatum, oder entferne sie. Eine Sammlung für Neuigkeiten oder Veranstaltungen wächst sonst ohne Ende. Siehe [Einträge nur für eine Zeit zeigen]($docs.timed-entries).
- **Felder.** Teile einen Baustein mit vielen Feldern in zwei Bausteine. Oft gehören die Felder zu zwei Teilen einer Seite.
- **Text.** Ein Text mit fast 500.000 Zeichen ist ein Buch. Mach daraus eine Sammlung mit einem Eintrag pro Kapitel.
