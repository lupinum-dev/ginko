Jeder Baustein hat eine Quelle. Mit `source: 'files'` sind seine Inhalte Dateien im Repo. Ohne liegen seine Inhalte auf der Plattform. Du entscheidest pro Baustein, und eine Seite kann beides mischen.

```ts [ginko.config.ts]
bricks: {
  legal: single({ label: 'Legal notice', source: 'files', fields: { /* … */ } }),   // files
  hours: single({ label: 'Opening hours', fields: { /* … */ } }),                   // platform
}
```

## Der Unterschied

| | Dateien | Plattform |
| --- | --- | --- |
| Wo die Inhalte liegen | `content/` im Repo | Die Plattform, die Lupinum betreibt |
| Wer sie ändert | Ein Entwickler, in einem Editor | Ein Inhaber oder sein Team, im Studio, auch am Handy |
| Wie eine Änderung live geht | Ein Commit und ein Deploy | Ein Klick auf „Publish“. Die Seite zeigt sie innerhalb von 60 Sekunden. |
| Verlauf | git | Das Studio behält jede Version und kann rückgängig machen |
| Freigabe, Planung, schnelle Aufgaben | nein | ja |
| Was die Seite braucht | Nichts. Ein statischer Host reicht. | Einen Server, die Adresse der Plattform und eine Einladung von Lupinum |
| Eine Schema-Änderung | Konfiguration und Dateien in einem Commit ändern | `ginko release`, und das Schema wächst nur |
| Wenn die Quelle nicht erreichbar ist | Kann nicht passieren: Die Inhalte sind Teil des Builds | Die Seite antwortet mit 503, und der Host behält die letzte gute Seite |

## Was gleich bleibt

Der Code einer Seite. `useGinko('hours')` liest einen Datei-Baustein und einen Plattform-Baustein auf dieselbe Weise, mit denselben Typen. Felder, Prüfungen, Übersetzungen, Datumsgrenzen, Links und Suche funktionieren für beide.

Die Quelle ist also eine Entscheidung, die du ändern kannst. Ein Text kann als Datei beginnen, während du die Seite baust, und auf die Plattform umziehen, wenn der Inhaber übernimmt.

## Wie du wählst

Frag, wer die Inhalte ändert und wie oft.

**Nimm Dateien, wenn:**

- ein Entwickler die Inhalte schreibt: Doku, ein Blog des Teams, Rechtstexte
- sich die Inhalte mit dem Code ändern, etwa ein Changelog
- die Seite auf einem statischen Host laufen soll, ohne Server
- du keinen Zugang zur Plattform hast

**Nimm die Plattform, wenn:**

- eine Person ohne Code-Editor die Inhalte ändert: Öffnungszeiten, eine Speisekarte, Termine, Stellenanzeigen
- eine Änderung in einer Minute live gehen muss, ohne Deploy
- eine zweite Person eine Änderung freigeben soll oder eine Änderung an einem Datum starten soll

Viele Seiten nutzen beides: Die Seiten, die verkaufen, sind Dateien, die Fakten, die sich jede Woche ändern, liegen auf der Plattform.

## Was sich ändert, wenn ein Baustein auf die Plattform umzieht

- **Die Inhalte ziehen einmal um.** Die Plattform liest deine Dateien nicht. Ein Einzelstück beginnt mit dem `default` jedes Feldes, und eine Sammlung beginnt leer. Du tippst die Inhalte ins Studio, oder du bittest Lupinum, viele Einträge zu importieren.
- **Pflichtfelder eines Einzelstücks brauchen ein `default`.** Die Plattform muss das Einzelstück anlegen können, bevor jemand etwas getippt hat. `f.markdown`, `f.image` und `f.file` haben kein `default`: Mach sie optional.
- **Das Schema wird freigegeben.** `ginko release` schickt das Schema vor dem Deploy an die Plattform. Ab dann wächst das Schema nur: Du ziehst ein Feld zurück, du löschst es nicht. Siehe [Schemas wachsen nur]($docs.schemas-only-grow).
- **Die Seite braucht einen Server.** Ein statischer Build passt nicht mehr, weil sich die Inhalte nach dem Build ändern.
- **Die Dateien zählen nicht mehr.** Entferne die Dateien des Bausteins aus `content/`, damit niemand sie aus Versehen bearbeitet.

[Einen Baustein auf die Plattform verlegen]($docs.move-a-brick-to-the-platform) hat die Schritte.

## Der Weg zurück

`ginko export` speichert das Schema, alle Einträge und alle Dateien einer Seite in einen Ordner. Dieser Ordner ist ein Backup im Format von Ginko, nicht im Aufbau von `content/`: Um einen Plattform-Baustein wieder zu einem Datei-Baustein zu machen, schreibst du die Dateien aus dem Export selbst. Siehe [Inhalte exportieren und sichern]($docs.export-and-backup).
