This guide moves a site to the newest Ginko version. At the end, all Ginko packages of the site have the same new version, and the checks pass.

## Before you start

- The site is in git and has no open changes, so you can see what the upgrade changes.
- You know your current version:

```bash
npm ls --depth=0
```

```text
+-- @lupinum/ginko-content@0.16.5
+-- @lupinum/ginko-i18n@0.16.5
+-- @lupinum/ginko@0.16.5
```

## Steps

:::steps
#### Read the changelog

Open the [changelog](/changelog) and read the entries between your version and the newest one. Look at **Changed** and **Removed**: these notes say what works in another way. The table [Changes that need action](#changes-that-need-action) on this page lists the important ones.

#### Update all packages in one step

Name every Ginko package the site has, each with `@latest`:

::code-group
```bash [npm]
npm install @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```
```bash [pnpm]
pnpm add @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```
```bash [yarn]
yarn add @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```
::

A site with more packages adds them to the same command: `@lupinum/ginko-components@latest`, `@lupinum/ginko-docs@latest`, `@lupinum/ginko-preset-gastro@latest`.

::callout{type="warning" title="npm update is not enough"}
`npm update` stays inside the range in `package.json`. For a version before 1.0, the range `^0.16.0` ends before 0.17.0. So `npm update` gives you the newest patch, never the next minor version.
::

#### Run the checks

```bash
npx ginko check
npx nuxt typecheck
```

`ginko check` reads the config, the content files and the links with the new version. `nuxt typecheck` finds code that uses a function or a field that changed.

#### Look at the site

Start the dev server and open the pages with the most content. Then build once, as your host does:

```bash
npm run build
```
:::

## Check that it works

`npm ls --depth=0` shows the same new version for every Ginko package:

```text
+-- @lupinum/ginko-content@0.17.0
+-- @lupinum/ginko-i18n@0.17.0
+-- @lupinum/ginko@0.17.0
```

`npx ginko check` ends with:

```text
OK: schema and links are fine.
```

## A site on the platform

An upgrade of the packages does not change the content on the platform. After the upgrade, run `ginko check` with `GINKO_PLATFORM` and `GINKO_KEY` set. It compares the schema that the new version makes from your config with the schema in production, and lists every difference. Release a difference as usual, see [Release a schema change]($docs.release-a-schema-change).

## A site from a template

`create-ginko` copies a template once. After that, the files are your code, and an upgrade does not touch them. A fix in a template reaches new sites only. A changelog note that names the templates tells you what changed there; copy the change by hand when you want it.

## Changes that need action

Each row names the first version with the change. A site that comes from an older version does what the row says. Rows about the Studio need no change in the code.

| Version | Change | What to do |
| --- | --- | --- |
| 0.17.0 | Math uses KaTeX 0.19. | A site that installs `katex` itself needs `^0.19.1`. |
| 0.15.1 | New sites start on Nuxt 4.6.3, which fixes a security issue in Nuxt. | Update `nuxt` to 4.6.3 or later. |
| 0.14.0 | A new entry in a collection with `order: 'manual'` is first, not last. | Nothing in code. Tell owners who add entries by hand. |
| 0.13.0 | In the Studio, "Save" never puts anything online. "Publish" does. | Nothing in code. Tell the owners. |
| 0.12.0 | Docs pages stored on the platform show no "Edit this page" link to the Studio. | Set `docs.studioEditLink: true` in `app.config.ts` to keep the link. |
| 0.10.0 | Images from the platform load from the address of the site, under `/__ginko/file/`. Image addresses in JSON-LD are absolute. | Remove code that expects the address of the storage host. |
| 0.9.0 | A code block without a code component has `data-language`, not `language`. | Change CSS or code that reads the attribute `language`. |
| 0.9.0 | A component cannot declare a property whose name ends in `Html`. | Rename the property. |
| 0.5.0 | A collection with a `route` leaves an entry out of a language until its required texts are translated. | Set `untranslated: 'fallback'` on the brick to list such entries. See [Missing translations]($docs.missing-translations). |
| 0.5.0 | An outdated translation stays on the site. `fallback` lists only missing translations. | Remove code that treats `fallback` as "outdated". |
| 0.5.0 | A Markdown field of an entry holds a reference, not the tree. | Show the text with `<GinkoMarkdown>`. For the tree or the table of contents, use `useGinkoMarkdown`. |
| 0.5.0 | A brick cannot have the key `page` or `file`. | Give the brick another key before its first release. |
| 0.5.0 | `useGinkoSeo({ noindex: true })` writes `noindex, follow`. | Nothing, unless you relied on `nofollow`. |
| 0.5.0 | In a content file, a required multi-choice field needs a value. `none` says that there are none. | Write `none` where a file had an empty list. |
| 0.5.0 | The task `menu.priceFrom` of the restaurant kit is gone. "Change a price" plans a price for a date. | Grant "Change a price" to staff who had the old task. |
| 0.5.0 | Uploads no longer accept HEIC photos. | Save such a photo as JPEG first. |

## When a check fails after the upgrade

1. Read the message. [Errors]($docs.errors) lists the common ones with their fix.
2. Search the changelog for the name in the message, such as the function or the option.
3. To go back, restore `package.json` and the lock file from git and install again.
