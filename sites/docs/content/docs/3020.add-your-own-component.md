This guide adds a tag `::pricing` to your site. At the end, a content file can use it, the check knows its props, and the editor in the Studio offers it.

## Before you start

The site has the components set up, see [Set up components]($docs.set-up-components).

## Steps

::steps
#### Describe the tag

`defineComponents` describes each tag: its label, one sentence about it, and its props. Add your tags to the registry of the package:

```ts [ginko.config.ts]
import { defineComponents, defineSite, f } from '@lupinum/ginko'
import { components } from '@lupinum/ginko-components/registry'

const own = defineComponents({
  pricing: {
    kind: 'block',
    label: 'Price',
    describe: 'A price with a title, the text below.',
    props: {
      title: f.text('Title', { max: 80 }),
      price: f.text('Price', { max: 20 }),
    },
    editor: { example: '::pricing{title="Basic" price="9 €"}\nOne site, one language.\n::' },
  },
})

export default defineSite({
  // …
  components: { ...components, ...own },
})
```

On a docs kit site, import `components` from `@lupinum/ginko-docs/config`.

#### Add the Vue component

Ginko looks for a global component with the name of the tag in PascalCase. The tag `pricing` is `Pricing.vue` in `app/components/global/`:

```vue [app/components/global/Pricing.vue]
<script setup lang="ts">
defineProps<{ title: string; price: string }>()
</script>

<template>
  <section class="pricing">
    <h3>{{ title }} <span>{{ price }}</span></h3>
    <slot />
  </section>
</template>
```

The props arrive as strings. The text between the two `::` is the default slot.

#### Use the tag

```markdown [content/start.md]
::pricing{title="Basic" price="9 €"}
One site, one language.
::
```
::

## Check that it works

Open the page. It shows the heading "Basic 9 €" and the text below it.

Then take `price` out of the tag and run `npx ginko check`. The check names the missing prop:

```text
content/start.md (body.en): “body”: Component “pricing”: property “price” is missing.
```

## The settings of a tag

| Setting | Type | Meaning |
| --- | --- | --- |
| `kind` | `'block'` or `'inline'` | A block stands alone (`::pricing`). An inline tag stands in a sentence (`:badge[new]`). |
| `label` | text, or one text per language | The name in the editor. |
| `describe` | text, or one text per language | One sentence for editors and for AI agents. |
| `props` | fields | The props of the tag. A prop is required unless it has `optional: true`. |
| `slots` | object | Named slots, each with a `label` and, if you want, a Markdown `profile`. |
| `children` | list of tags | The tags allowed directly inside. Without it, any tag. |
| `parents` | list of tags | The tag may stand only directly inside one of these. |
| `editor` | object | `example` is the Markdown the editor inserts, `group` the heading in its menu, `icon` its icon. |

Rules for the names:

- A tag is lower case with hyphens, such as `price-table`.
- A prop is camelCase. It may not start with `on` and may not be `as`, `innerHTML`, `outerHTML`, `innerText`, `outerText` or `textContent`.
- A prop can be `f.text`, `f.longtext`, `f.number`, `f.boolean`, `f.choice`, `f.choices`, `f.image` or `f.ref`.

## Replace a component of the package

`<GinkoMarkdown>` has a `components` prop. A tag you give there uses your Vue component. All other tags stay as they are.

```vue [app/pages/index.vue]
<script setup lang="ts">
import MyCallout from '~/components/MyCallout.vue'

const start = useGinko('start')
</script>

<template>
  <GinkoMarkdown :value="start.data.body" :components="{ callout: MyCallout }" />
</template>
```

Your component gets the same props as the one of the package. The short forms are their own tags: `::note` and `::warning` keep the component of the package until you replace them too.

If your registry describes a tag with the name of a package tag, your entry wins in the check and in the editor. The page still shows the component of the package, because a global component works only for tag names the package does not use. Pass your component through `components` as above.

The Vue components of the package are exported from `@lupinum/ginko-components/components`. So you can wrap `Callout` in your own variant and need not write it again.
