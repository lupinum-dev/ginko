A task is a shortcut in the Studio for a change that happens often: "Closed today", "Change a price", "Add a dish". This guide adds a task to a brick. At the end, the Today page of the Studio has a button that opens a form with two fields, and "Publish" puts the change online.

## Before you start

The brick lives on the platform. [Move a brick to the platform]($docs.move-a-brick-to-the-platform) shows how. A brick in files has no tasks, because nobody edits it in the Studio.

## Steps

::steps
#### Add the task to the brick

```ts [ginko.config.ts]
promo: single({
  label: 'Promotion',
  fields: {
    headline: f.text('Headline', { default: 'Fresh this week' }),
    until: f.date('Show until', { optional: true }),
  },
  tasks: [
    { id: 'change', label: 'Change the promotion', kind: 'edit', fields: ['headline', 'until'] },
  ],
}),
```

- `id` names the task. Keep it when you change the label.
- `label` is the text on the button.
- `kind` is `'edit'`, `'create'` or `'remove'`.
- `fields` lists the fields the form shows.

#### Check and release

```bash
npx ginko check
```

A task is not part of the data. The check lists it as an allowed change, and the release does not raise the schema version:

```text
Allowed changes:
  + Tasks changed.
```

Commit, push and release as in [Release a schema change]($docs.release-a-schema-change).

#### Check the result

1. Open the Studio. The Today page has the heading "Promotion" with the button "Change the promotion".
2. Press the button. The form shows "Headline" and "Show until", and nothing else.
3. Change the headline and press "Publish". The Studio answers "Published. On the website in about a minute."
4. Reload the page of the site. It shows the new headline.
::

## The three kinds of task

| Kind | What it does | Notes |
| --- | --- | --- |
| `edit` | Changes the fields in `fields`. | On a collection, add `pick: true`: the person first picks an entry. |
| `create` | Adds an entry to a collection. | With `fields`, the form asks for those only. Every required field without a default must be in `fields` or `prefill`. |
| `remove` | Deletes an entry of a collection. | |

## Fill a field in advance

`prefill` sets a value before the form opens:

```ts
{ id: 'closedToday', label: 'Closed today', kind: 'edit', fields: ['closedOn', 'closedNote'], prefill: { closedOn: '@today' } }
```

`'@today'` is today's date in the time zone of the site. `'@workWeek'` and `'@nextWorkWeek'` are the first day of this and the next work week. Each of them needs a date field.

## Ask for a yes before it goes live

With `needsApproval: true`, a change that a staff member makes through the task waits until an owner approves it:

```ts
{ id: 'lunch', label: 'This week’s lunch menu', kind: 'edit', fields: ['days'], needsApproval: true }
```

## Who may use a task

An owner may do everything on the site. A staff member may only use the tasks that the owner granted to that person. Tasks are therefore also the way to give someone a narrow job, such as the cook who enters the lunch menu.
