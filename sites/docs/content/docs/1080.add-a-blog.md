This recipe adds a blog to a site that runs and was made from a template, for example the `starter` of the [Quick start]($docs.getting-started). At the end, `/news` lists the posts, each post has its own page with date, reading time and author, and every language has an RSS feed.

You do not write the pages yourself. The templates share their features, and the template `blog` has the finished blog. You copy its files into your site.

The copied pages use the layout and the blocks of a template site (`BlockPageHeader`, `usePageSeo` and others). For a site you built by hand, write the pages yourself, as in [Tutorial 3: a blog]($docs.tutorial-blog).

## What you add

| Part | Where |
| --- | --- |
| Bricks | `posts` and `people` from `@lupinum/ginko/basics`, in `ginko.config.ts` |
| Content | `content/posts/<slug>.md` and `content/people/<n>.<name>.md` |
| Pages | `app/pages/news/index.vue` (the list), `news/[slug].vue` (a post), `news/tags/[tag].vue` (a tag) |
| Code | `app/components/blog/`, `app/composables/useBlog.ts`, `server/middleware/news-feed.ts` (the feed) |
| Texts | `i18n/blog/<language>.json` |

## Steps

::steps
#### Get the files

Create a copy of the template `blog` next to your site, in the languages of your site. You only copy files from it, so it needs no `npm install`:

```bash
npm create ginko@latest ../blog-files -- --template blog --locales en,de
```

Run the command in your site's folder. Use the same version of `create-ginko` as your Ginko packages: with `@latest`, update the site first ([Upgrade Ginko]($docs.upgrade)).

#### Copy the blog into your site

```bash
cp -R ../blog-files/app/components/blog app/components/
cp ../blog-files/app/composables/useBlog.ts app/composables/
cp -R ../blog-files/app/pages/news app/pages/
cp -R ../blog-files/i18n/blog i18n/
mkdir -p server/middleware
cp ../blog-files/server/middleware/news-feed.ts server/middleware/
```

On Windows, copy the same folders and files in the file manager.

#### Add the bricks and the page

```ts [ginko.config.ts]
import { legal, notices, people, posts, site } from '@lupinum/ginko/basics'

export default defineSite({
  // …
  pages: {
    home: localized('/'),
    news: localized('/news'),
  },
  bricks: {
    // … the bricks you have
    posts: posts({ source: 'files', authors: 'people', route: localized('/news/[slug]') }),
    people: people({ source: 'files' }),
  },
})
```

`posts` holds the posts, newest first. `authors: 'people'` says that a post names its authors from the brick `people`. If your site has `people` already, keep it and add only `posts`.

The page key must stay `news`, because the pages live in `app/pages/news/`. The address is free: `news: localized('/blog')` serves the list at `/blog`, and then the route should be `localized('/blog/[slug]')`.

#### Write an author and a post

```markdown [content/people/1.klara-brenner.md]
---
name: Klara Brenner
role: Translator
---
```

```markdown [content/posts/new-catalogue.md]
---
title: A catalogue for the city museum
description: 120 pages on the history of the harbour, from German into English.
date: 2026-11-10
authors: [people/klara-brenner]
tags: ["Museums"]
---

This autumn I translated the catalogue of the harbour exhibition. Here is what I learned about ships' names.
```

```markdown [content/posts/new-catalogue.de.md]
---
title: Ein Katalog für das Stadtmuseum
slug: ein-katalog-fuer-das-stadtmuseum
description: 120 Seiten zur Geschichte des Hafens, aus dem Deutschen ins Englische.
tags: ["Museen"]
---

Diesen Herbst habe ich den Katalog der Hafenausstellung übersetzt. Das habe ich über Schiffsnamen gelernt.
```

`authors` names people by id: the folder and the file name without number and language. A translation holds only the fields that change with the language, so the date and the authors stay in the main file. Tags are free text in each language.

#### Put the blog into the menu

```ts [app/app.config.ts]
nav: [{ entry: 'pages/about' }, { page: 'news', label: { en: 'News', de: 'Neuigkeiten' } }, { entry: 'pages/contact' }],
```

An item with `page` links a key of `pages`, with a label per language.
::

## Check that it works

- Open `http://localhost:3000/news`. It shows the post with date and author, the tag "Museums" above it, and a link to the RSS feed.
- Click the post. Its page shows the date, the reading time and "Klara Brenner".
- Open `http://localhost:3000/de/news`. It lists the German post.
- `http://localhost:3000/news/rss.xml` is the feed, and `/news/tags/museums` lists the posts with that tag.
- Run `npm run check`. It prints `OK: schema and links are fine.`

Then delete the folder `../blog-files`.

## Drafts and scheduled posts

A post with `draft: true` in its file shows in the dev server and stays out of the build. A post dated after the day of the build waits until the first build on or after its date. [Keep a draft out of the live site]($docs.drafts) explains both.

## Change it

- **Texts.** The title and the lead of the list, "Older post", the reading time and the other fixed texts are in `i18n/blog/<language>.json`. To change one, set the same key under `blog` in your `i18n/<language>.json`: `{ "blog": { "title": "Journal" } }`.
- **The word "tags" in the address.** The tag pages live under `<news page>/tags/`. To translate the word, add `segments` to `app/routes.ts` as in the template `blog`.
- **Authors with their own page.** Give `people` a route, and the names in a post link to the person. The template `blog` shows it with its team feature.

## Other features

The templates have more features. They come into a site in the same way: make the template that has the feature, copy its files, add its bricks and its page key.

| Feature | In the template |
| --- | --- |
| Team page | `blog`, `company`, `local-business`, `nonprofit`, `portfolio` |
| Job ads | `company` |
| Downloads | `company`, `nonprofit` |
| Gallery | `events`, `local-business`, `portfolio`, `restaurant` |
| Services with prices | `company`, `local-business` |
| Projects | `nonprofit`, `portfolio` |
| Changelog | `saas` |
| Opening hours | `local-business`, `restaurant` |
| Menu and lunch | `restaurant` |
| Programme and speakers | `events` |
| Customer logos and quotes | `company`, `events`, `nonprofit`, `saas` |

`templates/_features/README.md` in the [Ginko repository](https://github.com/lupinum-dev/ginko/tree/main/templates/_features) lists the files of each feature and what it needs in `ginko.config.ts`. Only the four recipes on these pages are walked step by step.
