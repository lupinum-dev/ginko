Diese Anleitung bringt eine Website auf die neueste Ginko-Version. Am Ende haben alle Ginko-Pakete der Website dieselbe neue Version, und die Prüfungen laufen durch.

## Bevor du beginnst

- Die Website liegt in git und hat keine offenen Änderungen, damit du siehst, was das Update ändert.
- Du kennst deine aktuelle Version:

```bash
npm ls --depth=0
```

```text
+-- @lupinum/ginko-content@0.16.5
+-- @lupinum/ginko-i18n@0.16.5
+-- @lupinum/ginko@0.16.5
```

## Schritte

:::steps
#### Das Changelog lesen

Öffne das [Changelog](/changelog) und lies die Einträge zwischen deiner Version und der neuesten. Achte auf **Changed** und **Removed**: Diese Notizen sagen, was jetzt anders funktioniert. Die Tabelle [Änderungen mit Handlungsbedarf](#aenderungen-mit-handlungsbedarf) auf dieser Seite listet die wichtigen.

#### Alle Pakete in einem Schritt aktualisieren

Nenn jedes Ginko-Paket der Website, jedes mit `@latest`:

::code-group
```bash [npm]
npm install @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```
```bash [pnpm]
pnpm add @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```
```bash [yarn]
yarn add @lupinum/ginko@latest @lupinum/ginko-content@latest @lupinum/ginko-i18n@latest
```
::

Eine Website mit mehr Paketen hängt sie an denselben Befehl an: `@lupinum/ginko-components@latest`, `@lupinum/ginko-docs@latest`, `@lupinum/ginko-preset-gastro@latest`.

::callout{type="warning" title="npm update reicht nicht"}
`npm update` bleibt innerhalb des Bereichs in `package.json`. Für eine Version vor 1.0 endet der Bereich `^0.16.0` vor 0.17.0. Also gibt dir `npm update` den neuesten Patch, nie die nächste Minor-Version.
::

#### Die Prüfungen laufen lassen

```bash
npx ginko check
npx nuxt typecheck
```

`ginko check` liest die Konfiguration, die Inhaltsdateien und die Links mit der neuen Version. `nuxt typecheck` findet Code, der eine geänderte Funktion oder ein geändertes Feld nutzt.

#### Die Website ansehen

Starte den Dev-Server und öffne die Seiten mit dem meisten Inhalt. Mach dann einmal einen Build, so wie dein Host:

```bash
npm run build
```
:::

## Prüfe, ob es funktioniert

`npm ls --depth=0` zeigt für jedes Ginko-Paket dieselbe neue Version:

```text
+-- @lupinum/ginko-content@0.17.0
+-- @lupinum/ginko-i18n@0.17.0
+-- @lupinum/ginko@0.17.0
```

`npx ginko check` endet mit:

```text
OK: schema and links are fine.
```

## Eine Website auf der Plattform

Ein Update der Pakete ändert die Inhalte auf der Plattform nicht. Führ nach dem Update `ginko check` mit gesetztem `GINKO_PLATFORM` und `GINKO_KEY` aus. Es vergleicht das Schema, das die neue Version aus deiner Konfiguration macht, mit dem Schema in Production und listet jeden Unterschied. Gib einen Unterschied wie gewohnt frei, siehe [Eine Schema-Änderung freigeben]($docs.release-a-schema-change).

## Eine Website aus einem Template

`create-ginko` kopiert ein Template einmal. Danach sind die Dateien dein Code, und ein Update fasst sie nicht an. Ein Fix in einem Template erreicht nur neue Websites. Eine Notiz im Changelog, die die Templates nennt, sagt dir, was sich dort geändert hat; übernimm die Änderung von Hand, wenn du sie willst.

## Änderungen mit Handlungsbedarf

Jede Zeile nennt die erste Version mit der Änderung. Eine Website, die von einer älteren Version kommt, tut, was die Zeile sagt. Zeilen zum Studio brauchen keine Änderung im Code.

| Version | Änderung | Was zu tun ist |
| --- | --- | --- |
| 0.17.0 | Formeln nutzen KaTeX 0.19. | Eine Website, die `katex` selbst installiert, braucht `^0.19.1`. |
| 0.15.1 | Neue Websites starten mit Nuxt 4.6.3, das eine Sicherheitslücke in Nuxt behebt. | Aktualisiere `nuxt` auf 4.6.3 oder neuer. |
| 0.14.0 | Ein neuer Eintrag in einer Sammlung mit `order: 'manual'` steht zuerst, nicht zuletzt. | Nichts im Code. Sag es den Inhabern, die Einträge von Hand anlegen. |
| 0.13.0 | Im Studio stellt „Speichern“ nie etwas online. Das tut „Veröffentlichen“. | Nichts im Code. Sag es den Inhabern. |
| 0.12.0 | Doku-Seiten, die auf der Plattform gespeichert sind, zeigen keinen Link „Seite bearbeiten“ zum Studio. | Setz `docs.studioEditLink: true` in `app.config.ts`, um den Link zu behalten. |
| 0.10.0 | Bilder von der Plattform laden von der Adresse der Website, unter `/__ginko/file/`. Bildadressen in JSON-LD sind absolut. | Entferne Code, der die Adresse des Storage-Hosts erwartet. |
| 0.9.0 | Ein Codeblock ohne Code-Komponente hat `data-language`, nicht `language`. | Ändere CSS oder Code, der das Attribut `language` liest. |
| 0.9.0 | Eine Komponente kann keinen Prop deklarieren, dessen Name auf `Html` endet. | Benenne den Prop um. |
| 0.5.0 | Eine Sammlung mit `route` lässt einen Eintrag in einer Sprache weg, bis seine Pflichttexte übersetzt sind. | Setz `untranslated: 'fallback'` am Baustein, um solche Einträge zu listen. Siehe [Fehlende Übersetzungen]($docs.missing-translations). |
| 0.5.0 | Eine veraltete Übersetzung bleibt auf der Website. `fallback` listet nur fehlende Übersetzungen. | Entferne Code, der `fallback` als „veraltet“ behandelt. |
| 0.5.0 | Ein Markdown-Feld eines Eintrags enthält einen Verweis, nicht den Baum. | Zeig den Text mit `<GinkoMarkdown>`. Für den Baum oder das Inhaltsverzeichnis nimm `useGinkoMarkdown`. |
| 0.5.0 | Ein Baustein kann nicht den Schlüssel `page` oder `file` haben. | Gib dem Baustein vor seinem ersten Release einen anderen Schlüssel. |
| 0.5.0 | `useGinkoSeo({ noindex: true })` schreibt `noindex, follow`. | Nichts, außer du hast dich auf `nofollow` verlassen. |
| 0.5.0 | In einer Inhaltsdatei braucht ein Pflicht-Mehrfachauswahlfeld einen Wert. `none` sagt, dass es keine gibt. | Schreib `none`, wo eine Datei eine leere Liste hatte. |
| 0.5.0 | Die Aufgabe `menu.priceFrom` des Restaurant-Kits gibt es nicht mehr. „Preis ändern“ plant einen Preis für ein Datum. | Gib „Preis ändern“ den Mitarbeitern, die die alte Aufgabe hatten. |
| 0.5.0 | Uploads nehmen keine HEIC-Fotos mehr an. | Speichere ein solches Foto zuerst als JPEG. |

## Wenn eine Prüfung nach dem Update fehlschlägt

1. Lies die Meldung. [Fehler]($docs.errors) listet die häufigen mit ihrer Lösung.
2. Such im Changelog nach dem Namen aus der Meldung, etwa der Funktion oder der Einstellung.
3. Um zurückzugehen, stell `package.json` und die Lock-Datei aus git wieder her und installiere erneut.
