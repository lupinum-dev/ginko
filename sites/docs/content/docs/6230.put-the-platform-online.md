This guide puts your platform project online. At the end, the Studio answers on its own address, its backend runs on Convex, sign-in mail goes through Resend, and you are signed in as admin.

## Before you start

- You have the platform project from [Start the platform on your computer]($docs.platform-on-your-computer).
- You have accounts at Convex, Vercel and Resend.
- You have an API key from Resend, and a domain you can verify in Resend.

## Steps

::steps
#### Log in to Convex and Vercel

Log in to both command-line tools once. Each opens the browser.

```bash
npx convex login
```

```bash
npm install --global vercel
```

```bash
vercel login
```

If your Vercel account has more than one team, choose the team for the Studio with `vercel switch`. Setup uses the team that the Vercel CLI has selected.

#### Run setup

In the folder of the platform project:

```bash
npx ginko-platform setup
```

Without `--region`, Convex creates the backend in the default region of your Convex team. To choose another, add `--region`, for example `--region eu` for Ireland. [Regions](https://docs.convex.dev/production/regions) in the Convex docs lists the names; usage outside the US costs more. Convex sets the region once, when it creates the deployment, and it cannot be changed later.

Setup asks four questions:

| Question | What to enter |
| --- | --- |
| Studio address | Press Enter to use the address Vercel gives the project. You can change it later to your own domain. |
| Admin email | The address that may sign in first. |
| Resend API key | The key from Resend. The input is hidden. |
| Sender address for sign-in mail | For example `Studio <login@example.com>`. The domain must be the one you verify in Resend. |

Then setup does the rest:

1. It creates a Vercel project and links the folder to it.
2. It creates a Convex project with a production deployment, and a deploy key for Vercel.
3. It sets the values of the backend on Convex and the values of the Studio on Vercel. Secrets never appear on the screen.
4. It deploys. The Vercel build deploys the backend first, then builds the Studio. This takes a few minutes.
5. It creates the key that signs sign-ins.

At the end, it prints the address of the Studio, the address of the backend and how to sign in. The first line is:

```text
The Studio runs on https://my-cms.vercel.app
```

The project name is the folder name. Setup saves the production deployment and the Studio address in `ginko-platform.json`. That file holds no secret. Your local backend for `npm run dev` stays as it is.

#### Verify the sending domain in Resend

Resend sends only from a domain you verified there. Add the domain of the sender address in Resend and set the DNS records it shows. Until Resend shows the domain as verified, sign-in mail does not arrive.

#### Sign in

Open the Studio address and sign in with the admin email. The code comes by mail. The first sign-in with that address makes it the admin of the platform.

Nobody else can sign in yet: the platform has no open sign-up. An account exists only for the admin email and for people someone invites. [Connect a website]($docs.connect-a-website) shows how to invite owners.
::

## See the steps first

```bash
npx ginko-platform setup --dry-run
```

The dry run prints every step and its command, and changes nothing. Values that are secret show as `<hidden>`.

## Run it again

Setup is safe to run again. It reuses what exists, sets only the values that are missing and never replaces a secret. If nothing changed, it says:

```text
Nothing changed, so nothing was deployed.
```

If a step fails, setup stops and prints what it did before, and the command that failed:

```text
Setup stopped at step 7: Create its production deployment.
```

Fix the cause, then run setup again. It continues from the step that failed.

## Use your own domain

1. Add the domain to the Vercel project, in the Vercel dashboard.
2. Run setup with the new address:

```bash
npx ginko-platform setup --site-url https://cms.example.com
```

Setup changes the address on Convex and on Vercel and deploys again. The links in mails from the platform, such as invitations, approval notices and weekly reminders, then point to the new address.

## Options

Without a terminal, for example in a script, give the answers as options. The Resend API key never goes into an option: setup reads it from the environment variable `RESEND_API_KEY`, or asks for it.

| Option | Value |
| --- | --- |
| `--site-url <address>` | The Studio address. Default: the address Vercel gives the project. |
| `--admin <email>` | The address that may sign in first. |
| `--mail-from <sender>` | The sender of sign-in mail, for example `"Studio <login@example.com>"`. |
| `--project <name>` | The name of the Convex and the Vercel project. Default: the folder name. |
| `--team <slug>` | The Convex team, when your Convex account has more than one. |
| `--region <region>` | The Convex region of the production deployment. Default: your Convex team's default region. |
| `--dry-run` | Print the steps and their commands, change nothing. |
