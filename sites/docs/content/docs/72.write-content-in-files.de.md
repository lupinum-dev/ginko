Diese Anleitung legt die Inhalte eines Bausteins in Dateien im Repository. Am Ende zeigt die Seite die Inhalte deiner Dateien, und `ginko check` findet Fehler darin, bevor ein Build es tut.

## Bevor du beginnst

Das Paket `@lupinum/ginko-content` steht in den Abhängigkeiten der Seite. Jedes Template hat es. Ohne das Paket bricht der Build ab und sagt, was zu installieren ist.

## Schritte

::steps
#### Die Quelle des Bausteins setzen

```ts [ginko.config.ts]
news: collection({
  label: 'Neuigkeiten',
  source: 'files',
  max: 100,
  order: { field: 'date', dir: 'desc' },
  fields: {
    title: f.text('Titel'),
    date: f.date('Datum'),
    body: f.markdown('Text'),
  },
}),
```

Ein Baustein hat eine Quelle. Mit `source: 'files'` sieht die Plattform ihn nie.

#### Die Datei am richtigen Ort anlegen

Alle Dateien liegen in `content/`, neben `nuxt.config.ts`.

| Baustein | Wohin sein Inhalt gehört |
| --- | --- |
| ein Einzelstück `contact` | eine Datei: `content/contact.md` |
| eine Sammlung `news` | eine Datei pro Eintrag in einem Ordner: `content/news/1.opening.md` |

Die Nummer am Anfang eines Dateinamens setzt die Reihenfolge bei `order: 'manual'`. Sie gehört nicht zur Adresse.

#### Die Felder und den Text schreiben

```markdown [content/news/1.opening.md]
---
title: We are open
date: 2026-11-01
---

The new site is live.
```

Der Block zwischen den beiden `---` ist das Frontmatter. Jede Zeile füllt ein Feld. Der Text darunter füllt das Markdown-Feld des Bausteins. Ein Baustein hat höchstens ein Markdown-Feld.

[Inhalte aus Dateien]($docs.content-from-files#frontmatter) zeigt, wie du jeden Feldtyp schreibst, zum Beispiel einen Preis, ein Bild oder eine Liste.

#### Eine Übersetzung ergänzen

Eine Übersetzung ist eine Datei mit demselben Namen und dem Sprachkürzel vor der Endung:

```markdown [content/news/1.opening.de.md]
---
title: Wir haben geöffnet
---

Die neue Seite ist online.
```

Sie enthält nur die Felder, die einen Wert pro Sprache haben. Das Datum bleibt in der Hauptdatei. Eine Übersetzungsdatei mit so einem Feld ist ein Fehler:

```text
content/news/1.opening.de.md (date): “date” is set in the main-language file only.
```

#### Die Dateien prüfen

```bash
npx ginko check
```

Der Befehl liest jede Datei und nennt jedes Problem mit Datei und Feld. Ein Build bricht bei denselben Problemen ab.
::

## Inhalte ohne Fließtext

Ein Baustein ohne Markdown-Feld kann auch YAML-, JSON- und CSV-Dateien lesen. Nimm sie für strukturierte Inhalte wie eine Preisliste.

**YAML oder JSON.** Eine Datei ist ein Eintrag. Die Datei enthält, was in Markdown im Frontmatter steht:

```yaml [content/prices/1.coffee.yml]
title: Coffee
price: 3.5
vegan: true
```

**CSV.** Eine Datei enthält viele Einträge, einen pro Zeile. Die erste Zeile nennt die Spalten:

```text [content/prices/list.csv]
slug,locale,title,price,vegan
coffee,,Coffee,3.5,true
tea,,Tea,2.8,true
coffee,de,Kaffee,,
```

- `slug` ist Pflicht. Das ist der Name des Eintrags.
- `locale` ist freiwillig. Eine leere Zelle heißt Hauptsprache. Die letzte Zeile ist die deutsche Übersetzung von `coffee`.
- Ein Betrag steht in Einheiten der Währung. Die Seite liest `3.5` als 350 Cent.
- Eine Zelle fasst keine Liste, kein Bild und keinen Datumsbereich. Nimm dafür eine YAML- oder Markdown-Datei.
