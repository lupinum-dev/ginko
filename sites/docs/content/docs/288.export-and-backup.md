The content on the platform belongs to the owner of the site. This guide gets a full copy of it: once by hand, and every week by itself.

## Download a backup in the Studio

An owner opens Team, then "Backup", and chooses "Download backup". The download is a ZIP file with all content, drafts and removed entries included, and all pictures and PDFs. Team, history and keys are not in it.

## Back up from the command line

::steps
#### Create a key for backups

In the Studio, open Team, then "Publishing keys", then "New key". Choose "Back up only". Such a key can read the content and cannot publish.

#### Run the export

```bash
export GINKO_PLATFORM=https://platform.example.com
export GINKO_KEY=ginko_linde_…
npx ginko export ginko-export-linde
```

The folder must be new or empty. Without a folder name, the command uses `ginko-export-<site>-<date>`. It prints one line:

```json
{"ok":true,"dir":"ginko-export-linde","entries":7,"files":0}
```

#### Check the result

The folder holds `export.json` and a folder `files/`:

- `export.json` has the schema and every entry, removed ones too.
- `files/` has every picture and PDF.

`export.json` is written last. A folder that has this file is complete.
::

## Back up every week

Run the export in CI on a schedule and keep the folder as an artifact:

```yaml [.github/workflows/backup.yml]
on:
  schedule:
    - cron: '0 3 * * 1'
jobs:
  backup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with: { node-version: 24 }
      - run: npm ci
      - run: npx ginko export backup
        env:
          GINKO_PLATFORM: ${{ secrets.GINKO_PLATFORM }}
          GINKO_KEY: ${{ secrets.GINKO_BACKUP_KEY }}
      - uses: actions/upload-artifact@v6
        with: { name: ginko-backup, path: backup }
```

## Restore

Lupinum loads an export folder back into a site. Send the folder, and say which site it is for.

## Leave the platform

An export is also the way out. `export.json` holds every text in every language in a documented form, so a script can turn it into files for another system. [Compare and switch]($docs.switching#leaving-the-platform) says what you take with you.
