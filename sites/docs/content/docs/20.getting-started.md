In five minutes you have a site that runs on your computer and reads its text from a Markdown file. It needs no account and no platform.

You need Node.js 22.18 or newer (22, 24 or 26) and npm, pnpm or bun.

## Create and run the site

::steps
#### Create the site

```bash
npm create ginko@latest my-site
```

The command creates the folder `my-site` with a small site in English: one page and one text.

#### Install and start

```bash
cd my-site
npm install
npm run dev
```

Open `http://localhost:3000`. The page shows "Hello Ginko".

#### Change the text

Open `content/start.md`. The lines between the two `---` are the fields, the text below them is the Markdown field:

```markdown [content/start.md]
---
title: Hello Ginko
---

This text lives in `content/start.md`. Change it, and the page shows the new text.
```

Change the title and save the file. The page in the browser shows the new title.
::

## What is in the folder

| File | What it does |
| --- | --- |
| `ginko.config.ts` | Describes the content of the site: one brick `start` with a title and a text. |
| `content/start.md` | The content of that brick. |
| `app/pages/index.vue` | The page. It reads the brick with `useGinko('start')`. |
| `nuxt.config.ts` | Turns on the Ginko module. |

A brick is one kind of content. [What Ginko is]($docs.what-ginko-is) explains the words, and [Build a site by hand]($docs.build-a-site-by-hand) writes these files one by one.

## Start from a template

The small site is good for a first look. For a real site, start from a template. A template is a complete site with pages, sample content, a design and two or more languages:

```bash
npm create ginko@latest my-restaurant -- --template restaurant
```

Write the options after `--`. Without it, npm keeps them for itself.

`--locales` picks the languages and their order. The first one is the main language:

```bash
npm create ginko@latest my-restaurant -- --template restaurant --locales de,en
```

[Templates]($docs.templates) shows all ten templates with a live demo of each.
