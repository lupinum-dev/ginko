Diese Anleitung baut eine Seite als reine Dateien. Am Ende hast du einen Ordner, den jeder statische Hoster ausliefern kann: ohne Server, ohne Funktion, ohne Datenbank.

Das geht für eine Seite, deren Bausteine alle `source: 'files'` haben. Eine Seite mit Bausteinen auf der Plattform braucht einen Server: siehe [Auf Vercel veröffentlichen]($docs.deploy-to-vercel).

## Schritte

::steps
#### Die Seite bauen

```bash
npx nuxt generate
```

Der Build endet mit `You can now deploy .output/public to any static hosting!` Ein kaputter Link oder eine Seite, die sich nicht rendern lässt, bricht ihn ab.

Die Zeile `Payload extraction is disabled, which is suboptimal for full-static output` ist eine Warnung von Nuxt. Ginko schaltet die Payload-Extraktion absichtlich aus. Ignoriere die Zeile.

#### Die Ausgabe ansehen

Der Ordner `.output/public` enthält die ganze Seite:

| Im Ordner | Was es ist |
| --- | --- |
| `index.html`, `about/index.html`, `de/index.html`, … | jede Seite in jeder Sprache |
| `news/opening.md`, … | jeder Eintrag als Markdown, für Agenten |
| `sitemap.xml`, `robots.txt` | für Suchmaschinen |
| `llms.txt`, `llms-full.txt` | für KI-Agenten |
| `__ginko/search/` | der Suchindex jeder Sprache |
| `404.html` | die Fehlerseite |

Entwürfe, Einträge nach ihrem letzten Tag und Einträge mit einem Datum in der Zukunft sind nicht in der Ausgabe.

#### Sie auf deinem Rechner ausprobieren

```bash
npx serve .output/public
```

Öffne die Adresse, die der Befehl ausgibt, und klick dich durch die Seite.

#### Den Ordner hochladen

Lade `.output/public` zu deinem Hoster hoch. Die meisten Hoster nehmen den Build-Befehl `npx nuxt generate` und den Ordner `.output/public` als Einstellungen und bauen bei jedem Push.
::

## Weiterleitungen in einer statischen Seite

Ein statischer Hoster hat keinen Server, der weiterleiten könnte. Ginko schreibt für jede exakte alte Adresse eine kleine Seite. Sie schickt den Browser weiter:

```html
<meta http-equiv="refresh" content="0; url=/about">
```

Das deckt `redirectFrom` in einer Inhaltsdatei und exakte Regeln in `redirects` ab. Eine Regel mit Muster, etwa `{ from: '/old-news/:slug', to: '/news/:slug' }`, hat keine Seite: Die alten Adressen antworten mit 404. Brauchst du Regeln mit Muster, setz sie in den Einstellungen deines Hosters oder veröffentliche auf Vercel.

## Was ein statischer Hoster nicht kann

- **Weiterleitungen mit Muster**, siehe oben.
- **Vorschauen aus Suchmaschinen heraushalten.** `robots.txt` wird einmal geschrieben, für die Produktionsadresse. Nimm für Vorschau-Deployments die Einstellung deines Hosters.
- **Den Doku-MCP-Zugang** einer Doku-Seite (`/__ginko/docs-mcp`).
- **Zu einem Zeitpunkt veröffentlichen.** Ein Eintrag mit einem Datum in der Zukunft erscheint mit dem ersten Build an oder nach seinem Datum. Bau die Seite jeden Tag, wenn du Daten so nutzt.
