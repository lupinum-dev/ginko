Diese Anleitung ergänzt Bausteine, die fast jede Seite braucht, ohne ihre Felder zu schreiben: Rechtstexte, ein Team, einen Blog, Stellenanzeigen, Fragen und Antworten, Downloads. Am Ende liest die Seite einen fertigen Baustein, und seine Einträge tragen die Daten, die Suchmaschinen suchen.

Die Bausteine kommen mit `@lupinum/ginko`. Du installierst nichts.

## Schritte

::steps
#### Die Bausteine auswählen

| Funktion | Art | Inhalt |
| --- | --- | --- |
| `site()` | Einzelstück | rechtlicher Name, Adresse, E-Mail, Telefon, Register- und USt-Nummer |
| `legal()` | Sammlung | ein Rechtstext pro Eintrag: Datenschutz, Impressum, AGB und andere |
| `people()` | Sammlung | Name, Rolle, Kurzbiografie, E-Mail, Telefon, Foto |
| `posts()`, `authors()` | Sammlungen | Beiträge mit Datum, Autoren und Schlagworten |
| `changelog()` | Sammlung | ein Eintrag pro Version |
| `jobs()` | Sammlung | Stellenanzeigen, die die Seite nach ihrem letzten Tag verlassen |
| `faq()` | Sammlung | Frage und Antwort |
| `downloads()` | Sammlung | Titel, Zusammenfassung, Datum und ein PDF |

#### Sie in die Konfiguration eintragen

Jede Funktion gibt einen Baustein zurück. Setz ihn unter den Schlüssel, den du willst:

```ts [ginko.config.ts]
import { defineSite } from '@lupinum/ginko'
import { faq, jobs, legal, site } from '@lupinum/ginko/basics'

export default defineSite({
  // site, name, url, timeZone, locales, currency, pages
  bricks: {
    site: site({ source: 'files' }),
    legal: legal({ source: 'files', route: { en: '/[slug]', de: '/de/[slug]' } }),
    jobs: jobs({ source: 'files', route: { en: '/jobs/[slug]', de: '/de/jobs/[slug]' } }),
    faq: faq({ source: 'files' }),
  },
})
```

- Mit `source: 'files'` liegen die Inhalte in Dateien. Ohne die Einstellung ändert die Inhaberin den Baustein auf der Plattform.
- `legal()`, `posts()` und `jobs()` nehmen eine `route`. So bekommt jeder Eintrag seine eigene Seite.
- `label` ersetzt den Namen des Bausteins im Studio.

#### Einen Eintrag schreiben

Die Felder jedes Bausteins stehen fest. Bei `faq()` sind es `question` und `answer`:

```markdown [content/faq/1.hours.md]
---
question: When are you open?
answer: Monday to Friday, 9 to 17.
---
```

Dein Editor zeigt die Felder eines Bausteins, wenn du ihn in einer Seite liest: `item.data.` listet sie auf.

#### Den Baustein in einer Seite lesen

Ein fertiger Baustein liest sich wie dein eigener:

```vue
<script setup lang="ts">
const faq = useGinko('faq')
</script>

<template>
  <dl>
    <template v-for="item in faq.items" :key="item.id">
      <dt>{{ item.data.question }}</dt>
      <dd>{{ item.data.answer }}</dd>
    </template>
  </dl>
</template>
```

Das Layout gehört dir. Die Bausteine bringen Inhaltstypen, keine Komponenten.

#### Das Ergebnis prüfen

Lass `npx ginko check` laufen und öffne dann die Seite. Die Frage und die Antwort aus der Datei sind zu sehen.
::

## Was ein fertiger Baustein mitbringt

- **Felder und ihre Beschriftungen** für das Studio, auf Deutsch, Englisch, Spanisch und Französisch.
- **Aufgaben für Inhaber** auf der Plattform, zum Beispiel „Frage hinzufügen“.
- **Daten für Suchmaschinen.** Die meisten Bausteine haben eine Hilfsfunktion, die die schema.org-Daten ihrer Einträge schreibt, zum Beispiel `faqJsonLd` und `jobJsonLd`. [Composables und Komponenten]($docs.reading-content#fertige-bausteine-und-helfer) nennt sie.
