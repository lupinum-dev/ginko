`defineSite` describes one site. It is the default export of `ginko.config.ts`. The Nuxt module, the `ginko` CLI and the platform all read this one file.

```ts [ginko.config.ts]
import { collection, defineSite, f, single } from '@lupinum/ginko'

export default defineSite({
  site: 'cafe-linde',
  name: 'Café Linde',
  url: 'https://cafe-linde.example',
  timeZone: 'Europe/Vienna',
  locales: ['en', 'de'],
  currency: 'EUR',
  pages: {
    home: { en: '/', de: '/de' },
    menu: { en: '/menu', de: '/de/speisekarte' },
  },
  bricks: {
    start: single({ label: 'Start page', source: 'files', fields: { title: f.text('Title') } }),
  },
})
```

## Required keys

| Key | Type | Meaning |
| --- | --- | --- |
| `site` | text | The id of the site: lower case letters, digits and `-`, at most 40 characters, a letter first. The platform knows the site by this id, and the keys of the site contain it. Choose it before the first release. |
| `name` | text | The name of the site for people. It is in the title of every page and in `/llms.txt`. |
| `url` | URL | The address of the live site, with `https://` and without a path, query or `#`. Canonical links, the sitemap and share images start with it. Every other host gets `noindex`. |
| `timeZone` | IANA name | The time zone of the site, such as `Europe/Vienna`. "Today" and every date limit follow it. |
| `locales` | list of codes | The languages of the site. The first is the main language: the default for content and for pages with a plain path. At most 20. |
| `currency` | ISO 4217 code | The currency of every money field, such as `EUR`. |
| `pages` | object | The fixed pages of the site by key. See [Pages](#pages). |
| `bricks` | object | The content of the site by key. See [single and collection]($docs.bricks). At most 30. |

## Optional keys

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `platform` | URL | none | The address of the platform the site reads from. The variable `NUXT_PUBLIC_GINKO_PLATFORM` wins over it. |
| `languages` | object | the code itself | The full language tag per code, such as `{ de: 'de-AT' }`. It sets `lang`, hreflang and the form of dates and numbers. |
| `firstDayOfWeek` | `1` to `7` | by language | The first day of the week, `1` for Monday. Without it, the day follows the main language: Monday for `de-AT`, Sunday for `en-US`. |
| `country` | ISO 3166 code | none | The country of the site, such as `AT`. It picks the public holidays and is the default country in JSON-LD. |
| `calendar` | `'AT'`, `'DE'`, `'SG'`, `'none'` or a function | by `country` | Which public holidays count for opening hours. See [Restaurant reference]($docs.restaurant-reference#public-holidays). |
| `linkCheck` | object | see below | How strict the link check is. See [Link check](#link-check). |
| `redirects` | list | none | Old addresses that forward to new ones. See [Redirects](#redirects). |
| `seo` | object | see below | Defaults for titles and share cards. See [SEO defaults](#seo-defaults). |
| `agents` | object | on | Text for AI agents. See [Agents](#agents). |
| `components` | registry | none | The components a Markdown text may use. See [Set up the components]($docs.set-up-components). |
| `facts` | list | none | Values that texts may quote. See [Facts](#facts). |
| `migrations` | object | none | Functions that fill a new field from old values. See [Schemas only grow]($docs.schemas-only-grow). |
| `retired` | object | none | Fields and bricks that leave the Studio. See [Schemas only grow]($docs.schemas-only-grow). |

## Pages

`pages` names every fixed page with a key and its address. Pages of entries are not here: a collection sets them with `route`.

```ts
pages: {
  home: { en: '/', de: '/de' },
  menu: { en: '/menu', de: '/de/speisekarte' },
  imprint: '/imprint',
}
```

- An object gives the address in each language. The sitemap and the language switch pair the languages of one key.
- A plain path is a page in the main language only.
- The home page is the page whose main-language address is `/`.
- A link in a text reaches a page as `$pages.<key>`. See [Link between pages]($docs.link-between-pages).

You write the Vue file for each page yourself. `pages` tells Ginko that the address exists, so the link check, the sitemap and hreflang know it. [Translate addresses]($docs.translate-addresses) shows how the addresses and the files fit together.

## Link check

The build and `ginko check` check every link in your content. `linkCheck` sets the level of each kind of finding: `'error'` stops the build, `'warn'` prints a line, `'off'` skips the check.

| Key | Default | Finding |
| --- | --- | --- |
| `broken` | `'error'` | A link to a page, entry or file that does not exist. |
| `anchors` | `'warn'` | A `#heading` that the target page does not have. |
| `redirected` | `'warn'` | A link to an address that forwards to another one. |
| `external` | off | A link to another site that does not answer. The check asks over the network, in the build and in `ginko check`, never in dev. |

```ts
linkCheck: { anchors: 'error', external: 'warn' }
```

## Redirects

A moved page answers with a redirect, by default **301**. There are three sources:

- An entry names its old addresses in `redirectFrom`. See [Move a page]($docs.move-a-page).
- On the platform, an owner changes the address of a page in the Studio. If the page was online, the old address forwards to the new one and stays reserved.
- The site lists rules in `redirects`:

```ts
redirects: [
  { from: '/speisekarte', to: '/menu' },
  { from: '/events/:slug', to: '/whats-on/:slug' },
  { from: '/old-blog/*', to: '/blog/:splat', status: 302 },
]
```

| Key | Type | Meaning |
| --- | --- | --- |
| `from` | path | The old address. `:name` matches one part of the path. A `*` at the end matches the rest. |
| `to` | path or URL | The new address. It can use `:name` from `from`, and `:splat` for the part that `*` matched. |
| `status` | `301`, `302`, `307` or `308` | The status code. Default `301`. |

The first rule that matches wins. The query string stays. A rule that is not valid stops the build. A static build (`nuxt generate`) supports only rules with exact paths, see [Build a static site]($docs.static-site).

## SEO defaults

`seo` sets defaults for the head tags that `useGinkoSeo` writes.

| Key | Default | Meaning |
| --- | --- | --- |
| `titleTemplate` | `%s · <name>` | The form of every page title. `%s` is the title of the page. |
| `description` | none | The description of a page that sets none. |
| `image` | none | The share image of a page without one: a path in `public/` or a full URL. A generated share card replaces it. |
| `color` | none | The brand colour as `#rrggbb` or `#rgb`. It is the background of generated share cards. |
| `organization` | none | `{ logo, sameAs }`: the logo and the profile links for the `Organization` data on the home page. |
| `noindex` | none | Keys of `pages` that stay out of search, such as a thank-you page. They leave the sitemap and answer with `X-Robots-Tag: noindex`. |

[Set titles and share cards]($docs.titles-and-share-cards) shows them in use.

## Agents

`agents` controls what the site offers to AI agents.

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | `false` turns off `/llms.txt`, `/llms-full.txt` and the Markdown version of every page. |
| `description` | `seo.description` | The line below the site name in `/llms.txt`. |
| `review` | `false` | `true` makes everything an agent writes on the platform wait for a yes from an owner. |

See [Offer pages to AI agents]($docs.pages-for-agents).

## Facts

`facts` lists values of single bricks that texts may quote, each as `brick.field`:

```ts
facts: ['practice.price', 'site.phone']
```

A Markdown text then writes `:fact{name="practice.price"}`. The page, the search and the Markdown version show the value that is in effect, so a price that an owner changes in the Studio changes in every text. A fact can be a text, number, money, date, time or choice field, or a list with one column.

## What a release compares

On a site with platform bricks, `ginko release` sends the schema to the platform. The schema holds `site`, `name`, `url`, `timeZone`, `locales`, `languages`, `currency`, the first day of the week, the holidays, `pages`, `bricks`, `components`, `migrations`, `retired` and `agents.review`. [Schemas only grow]($docs.schemas-only-grow) says which of these may change and how.

`platform`, `redirects`, `seo`, `linkCheck` and the other keys of `agents` are not part of the schema. They change with a deploy alone.

## Language options are not here

The options for addresses and language detection belong to the module `@lupinum/ginko-i18n`. Set them under `i18n` in `nuxt.config.ts`: `strategy`, `exclude`, `userLocale`, `params` and `seo`. The [i18n reference]($docs.i18n-reference#options) lists them.

Ginko passes `locales`, the main language, `url` and `timeZone` from `defineSite` to that module. Do not set `locales`, `defaultLocale`, `baseUrl` or `timeZone` under `i18n`: the build stops when you do.
