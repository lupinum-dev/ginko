Diese Anleitung gibt deinem Markdown-Text fertige Komponenten: Hinweise, Reiter, Karten, Code-Gruppen, Video und mehr. Am Ende zeigt ein `::callout` in einer Inhaltsdatei einen Hinweis auf der Seite, und `ginko check` meldet einen Tag, den es nicht kennt.

## Bevor du beginnst

Du brauchst eine Ginko-Seite, die läuft, zum Beispiel die aus dem [Schnellstart]($docs.getting-started).

Eine Seite mit dem Doku-Kit (`@lupinum/ginko-docs`) braucht keinen dieser Schritte. Das Kit bringt Paket, Modul und Registry mit.

## Schritte

:::steps
#### Das Paket installieren

```bash
npm install @lupinum/ginko-i18n @lupinum/ginko-components
```

Die Komponenten nehmen ihre festen Texte, etwa „Code kopieren“, aus `@lupinum/ginko-i18n`.

#### Das Modul eintragen

```ts [nuxt.config.ts]
import ginko from './ginko.config.ts'

export default defineNuxtConfig({
  modules: ['@lupinum/ginko/nuxt', '@lupinum/ginko-components'],
  ginko,
})
```

Das Modul verbindet jeden Tag mit seiner Vue-Komponente und lädt die Styles. Es braucht `@lupinum/ginko/nuxt` in derselben Liste. Ohne das bricht der Build ab und sagt es.

#### Die Registry angeben

Die Registry ist die Liste aller Tags mit ihren Props. Ginko prüft deinen Text gegen diese Liste.

```ts [ginko.config.ts]
import { defineSite, f, single } from '@lupinum/ginko'
import { components } from '@lupinum/ginko-components/registry'

export default defineSite({
  // …
  components,
})
```

#### Komponenten im Textfeld erlauben

Ein Markdown-Feld nimmt Komponenten nur mit dem Profil `page` an:

```ts [ginko.config.ts]
body: f.markdown('Text', { profile: 'page' }),
```

Mit einem anderen Profil lehnt die Prüfung den Tag ab:

```text
content/start.md (body.en): “body”: “callout” is not allowed here (paragraphs, headings, lists (also with checkboxes), quotes, notices and footnotes).
```

[Feldtypen]($docs.field-types#text-fmarkdown) listet, was jedes Profil erlaubt.

#### Eine Komponente schreiben

```markdown [content/start.md]
---
title: Hallo Ginko
---

::callout{type="warning" title="Vorsicht"}
Das gilt nur für neue Seiten.
::
```

Eine Block-Komponente beginnt mit `::` und ihrem Namen und endet mit `::`. Props stehen in geschweiften Klammern nach dem Namen.
:::

## Prüfe, ob es funktioniert

Öffne die Seite. Sie zeigt einen Hinweis mit Warnzeichen, dem Titel „Vorsicht“ und dem Text.

Starte dann die Prüfung:

```bash
npx ginko check
```

```text
OK: schema and links are fine.
```

## Was die Prüfung findet

Mit der Registry prüft Ginko jeden Tag streng. Jeder dieser Fehler stoppt `ginko check` und den Build:

| Fehler | Meldung |
| --- | --- |
| Ein Tag, den es nicht gibt, `::callot` | `There is no component “callot”.` |
| Eine Prop, die es nicht gibt, `colour="red"` | `Component “callout”: There is no property “colour”.` |
| Eine Prop mit Bindestrich, `icon-color` | `Component “card”: There is no property “icon-color”.` |

So fällt ein Tippfehler auf deinem Computer auf und nicht erst bei deinen Lesern.

Ohne `components` in der Konfiguration nimmt ein Komponenten-Tag nur `title`, `lang`, `dir` und `aria-*`, und der Parser lehnt Slots ab.

## Icons hinzufügen

Manche Komponenten nehmen ein `icon`, zum Beispiel `::card{icon="lucide:rocket"}`. Das Icon erscheint über die Komponente `<Icon>` von `@nuxt/icon`. Ohne dieses Modul bleibt der Platz des Icons leer.

```bash
npm install @nuxt/icon @iconify-json/lucide
```

```ts [nuxt.config.ts]
modules: ['@lupinum/ginko/nuxt', '@lupinum/ginko-components', '@nuxt/icon'],
```

`@iconify-json/lucide` ist der Icon-Satz Lucide. Es gehen nur die Icon-Sätze, die du installierst. Hinweise brauchen das Modul für ihre sechs eigenen Zeichen nicht.

## Die festen Texte ändern

Feste Texte, zum Beispiel „Code kopieren“ oder „Abspielen“, kommen aus dem Paket und folgen der Sprache der Seite. Um einen zu ändern, setz seinen Schlüssel in deiner eigenen Sprachdatei:

```json [i18n/de.json]
{ "components": { "code": { "copy": "Kopieren" } } }
```

`components` ist ein reservierter Name: Nutze ihn nicht für deine eigenen Texte. Die [Komponenten-Referenz]($docs.components#feste-texte) listet die Schlüssel.
