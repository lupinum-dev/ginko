This guide adds ready-made components to your Markdown text: notices, tabs, cards, code groups, video and more. At the end, a `::callout` in a content file shows as a notice on the page, and `ginko check` reports a tag it does not know.

## Before you start

You need a Ginko site that runs, for example the one from the [Quick start]($docs.getting-started).

A site on the docs kit (`@lupinum/ginko-docs`) needs none of these steps. The kit brings the package, the module and the registry.

## Steps

:::steps
#### Install the package

```bash
npm install @lupinum/ginko-i18n @lupinum/ginko-components
```

The components take their fixed texts, such as "Copy code", from `@lupinum/ginko-i18n`.

#### Add the module

```ts [nuxt.config.ts]
import ginko from './ginko.config.ts'

export default defineNuxtConfig({
  modules: ['@lupinum/ginko/nuxt', '@lupinum/ginko-components'],
  ginko,
})
```

The module connects each tag to its Vue component and loads the styles. It needs `@lupinum/ginko/nuxt` in the same list. Without it, the build stops and says so.

#### Pass the registry

The registry is the list of all tags with their props. Ginko checks your text against it.

```ts [ginko.config.ts]
import { defineSite } from '@lupinum/ginko'
import { components } from '@lupinum/ginko-components/registry'

export default defineSite({
  // …
  components,
})
```

#### Allow components in the text field

A Markdown field takes components only with the profile `page`:

```ts [ginko.config.ts]
body: f.markdown('Text', { profile: 'page' }),
```

With another profile, the check refuses the tag:

```text
content/start.md (body.en): “body”: “callout” is not allowed here (paragraphs, headings, lists (also with checkboxes), quotes, notices and footnotes).
```

[Field types]($docs.field-types#text-fmarkdown) lists what each profile allows.

#### Write a component

```markdown [content/start.md]
---
title: Hello Ginko
---

::callout{type="warning" title="Careful"}
This applies to new pages only.
::
```

A block component starts with `::` and its name, and ends with `::`. Props go in curly braces after the name.
:::

## Check that it works

Open the page. It shows a notice with a warning sign, the title "Careful" and the text.

Then run the check:

```bash
npx ginko check
```

```text
OK: schema and links are fine.
```

## What the check catches

With the registry, Ginko checks every tag strictly. Each of these stops `ginko check` and the build:

| Mistake | Message |
| --- | --- |
| A tag that does not exist, `::callot` | `There is no component “callot”.` |
| A prop that does not exist, `colour="red"` | `Component “callout”: There is no property “colour”.` |
| A prop written with a hyphen, `icon-color` | `Component “card”: There is no property “icon-color”.` |

So a typo shows up on your computer and not for your readers.

Without `components` in the config, a component tag takes only `title`, `lang`, `dir` and `aria-*`, and the parser refuses slots.

## Add icons

Some components take an `icon`, for example `::card{icon="lucide:rocket"}`. The icon renders through the `<Icon>` component of `@nuxt/icon`. Without that module the place of the icon stays empty.

```bash
npm install @nuxt/icon @iconify-json/lucide
```

```ts [nuxt.config.ts]
modules: ['@lupinum/ginko/nuxt', '@lupinum/ginko-components', '@nuxt/icon'],
```

`@iconify-json/lucide` is the Lucide icon set. Only the icon sets you install work. Notices do not need the module for their own six signs.

## Change the fixed texts

Fixed texts, for example "Copy code" or "Play", come from the package and follow the language of the page. To change one, set its key in your own message file:

```json [i18n/en.json]
{ "components": { "code": { "copy": "Copy" } } }
```

`components` is a reserved name: do not use it for your own messages. [Component reference]($docs.components#fixed-texts) lists the keys.
