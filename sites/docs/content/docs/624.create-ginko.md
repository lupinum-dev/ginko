`create-ginko` creates a new Nuxt site with Ginko in a new folder. The [Quick start]($docs.getting-started) uses it.

::code-group
```bash [npm]
npm create ginko@latest my-site
```
```bash [pnpm]
pnpm create ginko my-site
```
```bash [yarn]
yarn create ginko my-site
```
```bash [bun]
bun create ginko my-site
```
::

Without options, the command creates the plain starter in English: one page that reads its text from `content/start.md`.

## Options

With npm, write `--` before the options. Without it, npm keeps the options for itself.

```bash
npm create ginko@latest my-site -- --template restaurant --locales de,en
```

| Option | Values | Default |
| --- | --- | --- |
| `--template <name>` | `starter`, `restaurant`, `local-business`, `company`, `saas`, `nonprofit`, `events`, `portfolio`, `blog` or `docs` | the plain starter |
| `--locales <codes>` | The languages to keep, with commas between them. The first is the main language. | all languages of the template; `en` for the plain starter |
| `-h`, `--help` | Shows the options and the templates. | |

`--template=<name>` and `--locales=<codes>` work too. [Templates]($docs.templates) shows each template with a live demo.

### Languages of the templates

| Template | Languages |
| --- | --- |
| plain starter | `en` or `de`, one of them |
| `starter`, `blog`, `company`, `docs`, `events`, `local-business`, `portfolio` | `en`, `de` |
| `restaurant` | `en`, `de`, `it` |
| `saas` | `en`, `de`, `fr` |
| `nonprofit` | `en`, `de`, `fr`, `ar` |

### Deprecated options

| Option | Use this |
| --- | --- |
| `--preset gastro` | `--template restaurant` |
| `--preset docs` | `--template docs` |
| `--locale <code>` | `--locales <code>` |

Both still work and print a note. A later release removes them.

## What the command does

With a template, the command:

- copies the template into the folder
- keeps only the languages of `--locales`: their content files, their `i18n/<code>.json` and their addresses
- moves the dates of sample entries, such as events, by whole weeks to this week
- sets `site` in `ginko.config.ts`
- writes a `.env` with `NUXT_APP_SECRET`, which the share cards need on a server (see [Environment variables]($docs.environment-variables))

It does not install the packages and does not start git. The last lines of the output name the next commands:

```text
Created my-site from the blog template in German.
The sample dates in 1 content file moved to this week.

Next:

  cd my-site
  npm install
  npm run dev
```

## The site id

`site` in `ginko.config.ts` comes from the folder name: lower case, every run of other characters becomes `-`, at most 40 characters. When the id differs from the folder name, the command says so:

```text
The site id is "my-caf-site": the folder name in lower case, with other characters replaced by "-", at most 40 characters. Change `site` in ginko.config.ts to use another one.
```

Choose the id before the first release: the platform knows the site by it.

## Errors

A wrong call creates nothing. The command prints the cause and the usage.

| Message | Exit code | Fix |
| --- | --- | --- |
| `Give the name of the folder to create.` | 2 | Add the folder name. |
| `Unknown option "--colour".` | 2 | Use one of the options above. With npm, check that `--` is before the options. |
| `Unknown template "nope". Choose one of: …` | 2 | Use a name from the list in the message. |
| `Unknown locale "xx". The blog template has: en, de.` | 2 | Use the languages the template has. |
| `The plain starter has one language. Choose one of: en, de, or use a --template.` | 2 | Give one language, or pick a template. |
| `The folder y exists and is not empty. Choose another name.` | 1 | Use a new folder name, or empty the folder. |
