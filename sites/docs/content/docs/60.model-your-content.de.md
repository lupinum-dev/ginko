Diese Anleitung macht aus einer Liste von „Dingen, die sich auf der Seite ändern“ die `bricks` in `ginko.config.ts`. Am Ende nimmt `ginko check` deine Konfiguration an, und jeder Baustein hat einen klaren Besitzer.

Das Beispiel ist ein Gasthaus mit Kontaktdaten, einer Speisekarte und Neuigkeiten.

## Schritte

::steps
#### Aufschreiben, was sich ändert und wer es ändert

Schreib jeden Teil der Seite auf, den jemand nach dem Start ändern wird. Lass weg, was nur ein Entwickler zusammen mit dem Layout anfasst.

| Inhalt | Wer ihn ändert | Wie oft |
| --- | --- | --- |
| Adresse und Telefon | die Inhaberin | einmal im Jahr |
| Gerichte und Preise | die Inhaberin | jede Woche |
| Neuigkeiten | der Entwickler, vorerst | jeden Monat |

#### Entscheiden: ein Ding oder viele

Ein **Einzelstück** (`single`) hat genau einen Eintrag. Eine **Sammlung** (`collection`) hat viele Einträge mit denselben Feldern.

| Der Inhalt ist | Nimm | Beispiel |
| --- | --- | --- |
| ein Satz von Werten für die ganze Seite | `single` | Kontaktdaten, Öffnungszeiten, die Startseite |
| eine Liste, die wächst und schrumpft | `collection` | Gerichte, Neuigkeiten, Veranstaltungen, Teammitglieder |

Zeilen in einem Eintrag, etwa die Tage eines Mittagsmenüs, sind ein Listenfeld (`f.list`), keine Sammlung.

#### Die Felder benennen

Gib jedem Baustein die Werte, die er braucht, und nicht mehr. Jedes Feld hat einen Typ. [Feldtypen]($docs.field-types) nennt alle.

```ts [ginko.config.ts]
import { collection, defineSite, f, single } from '@lupinum/ginko'

export default defineSite({
  // site, name, url, timeZone, locales, currency, pages
  bricks: {
    contact: single({
      label: 'Adresse und Kontakt',
      source: 'files',
      fields: {
        street: f.text('Straße und Hausnummer', { max: 80, translate: false }),
        phone: f.text('Telefon', { format: 'tel' }),
      },
    }),
    menu: collection({
      label: 'Speisekarte',
      source: 'files',
      fields: {
        name: f.text('Name', { max: 120 }),
        price: f.money('Preis'),
      },
      max: 150,
      order: 'manual',
    }),
  },
})
```

`source: 'files'` hält die Inhalte eines Bausteins in Dateien im Repository. Schritt 5 entscheidet, ob sie dort bleiben.

Der Schlüssel (`contact`, `menu`) ist der Name des Bausteins. Er beginnt mit einem Kleinbuchstaben und hat nur Buchstaben und Ziffern.

#### Größe und Reihenfolge jeder Sammlung festlegen

Eine Sammlung braucht zwei weitere Einstellungen:

- `max` ist die größte Zahl von Einträgen, von 1 bis 500.
- `order` ist die Reihenfolge, in der die Seite sie liest. `'manual'` behält die Reihenfolge, die die Inhaberin setzt. `{ field: 'date', dir: 'desc' }` sortiert nach einem Feld, hier das Neueste zuerst.

#### Entscheiden, wo jeder Baustein liegt

Ein Baustein mit `source: 'files'` liegt in Dateien im Repository, und ein Entwickler ändert ihn. Ein Baustein ohne `source` liegt auf der Plattform, und die Inhaberin ändert ihn im Studio.

Nimm die Tabelle aus Schritt 1: Was der Entwickler ändert, bleibt in Dateien, was die Inhaberin ändert, kommt auf die Plattform. Um einen Baustein auf die Plattform zu verlegen, entfernst du seine Zeile `source`:

```ts
menu: collection({
  label: 'Speisekarte',
  // kein source: die Inhaberin pflegt die Speisekarte im Studio
  // …
}),
```

Ein Baustein kann später umziehen, und die Seiten, die ihn lesen, bleiben gleich. Eine Seite kann mit allen Bausteinen in Dateien beginnen und braucht keine Plattform, bis der erste Baustein umzieht. [Inhalte in Dateien schreiben]($docs.write-content-in-files) zeigt die Dateien.

#### Die Konfiguration prüfen

```bash
npx ginko check
```

Der Befehl gibt `OK: schema and links are fine.` aus oder nennt jedes Problem mit Baustein und Feld.

Mit einem Baustein auf der Plattform vergleicht der Befehl deine Konfiguration auch mit der Plattform und braucht ihre Adresse. Ohne sie bricht er ab mit `The environment variable GINKO_PLATFORM is missing.` [Umgebungsvariablen]($docs.environment-variables) hat die Variablen.
::

## Ein langes Formular leichter machen

Ein Baustein auf der Plattform mit vielen Feldern gibt der Inhaberin ein langes Formular. Gib Feldern eine `group`, und das Studio zeigt jede Gruppe unter ihrer Überschrift. Mit `layout: 'tabs'` werden die Gruppen auf breiten Bildschirmen zu Tabs.

```ts
legal: single({
  label: 'Rechtliches',
  layout: 'tabs',
  fields: {
    imprint: f.markdown('Impressum', { group: 'Impressum' }),
    privacy: f.markdown('Datenschutz', { group: 'Datenschutz' }),
  },
}),
```

Gruppen ändern nur das Formular. Die Daten bleiben gleich. Dieses Beispiel ist ein Baustein auf der Plattform: Ein Baustein in Dateien hat höchstens ein Markdown-Feld.

## Grenzen

Eine Seite hat höchstens 30 Bausteine. Ein Baustein hat höchstens 60 Felder.
