Inhaber kennen eine Änderung oft, bevor sie gilt: ein neuer Preis ab 1. November, das Mittagsmenü der nächsten Woche, neue Öffnungszeiten ab dem Frühling. Diese Anleitung zeigt die drei Wege, so eine Änderung vorzubereiten, damit die Seite am Tag von selbst umschaltet.

Alle drei gelten für Bausteine auf der Plattform.

## Ein neuer Wert für ein Feld ab einem Datum

`planned` gibt einem Feld einen zweiten Wert und das Datum, ab dem er gilt:

```ts [ginko.config.ts]
menu: collection({
  label: 'Speisekarte',
  planned: { field: 'price', next: 'nextPrice', from: 'priceFrom' },
  fields: {
    name: f.text('Name', { max: 120 }),
    price: f.money('Preis'),
    nextPrice: f.money('Neuer Preis', { optional: true }),
    priceFrom: f.date('Neuer Preis ab', { optional: true }),
  },
  max: 150,
  order: 'manual',
}),
```

- `next` hat den Typ von `field`. `from` ist ein Datumsfeld. Beide sind optional: Ohne Plan bleiben sie leer.
- Ab dem Datum in `priceFrom` gilt der Wert von `nextPrice` statt `price`.

Frag in einer Seite nach dem Wert, der heute gilt. `valueOn` nimmt den Plan, die Daten des Eintrags, das Feld und einen Tag:

```ts
import { valueOn } from '@lupinum/ginko'

const plan = { planned: { field: 'price', next: 'nextPrice', from: 'priceFrom' } }
const today = useGinkoToday()
const price = computed(() => valueOn(plan, item.data, 'price', today.value))
```

Bei einem Preis von 6,50, einem neuen Preis von 7,00 und `priceFrom: 2026-11-01` liefert `valueOn` am 31. Oktober 6,50 und ab dem 1. November 7,00. Ein Eintrag ohne Plan liefert seinen Preis.

`ginko check` meldet eine Aufgabe, die `price` ändert und `nextPrice` und `priceFrom` nicht zeigt. So ändert niemand einen Preis, ohne den geplanten zu sehen.

## Ganze Wochen eines Einzelstücks

Ein Mittagsmenü ist ein Einzelstück: ein Menü für die laufende Woche. Mit `plans` halten die Einträge einer zweiten Sammlung die Menüs späterer Wochen:

```ts [ginko.config.ts]
lunchPlans: collection({
  label: 'Mittagsmenü vorausplanen',
  plans: { brick: 'lunch', field: 'weekOf' },
  fields: {
    weekOf: f.date('Woche ab'),
    // dieselben Felder wie das Einzelstück `lunch`
  },
  max: 12,
  order: { field: 'weekOf', dir: 'asc' },
}),
```

`weekOf` enthält den ersten Tag der Woche. Die Seite zeigt die geplante Woche ab diesem Tag. Das Gastro-Preset hat dieses Paar fertig: `lunch()` und `lunchPlans()`, und `hours()` mit `hourPlans()` für Öffnungszeiten ab einem Datum. [Restaurant-Referenz]($docs.restaurant-reference) beschreibt sie.

## Zu einem Zeitpunkt veröffentlichen

Jede Änderung im Studio kann später live gehen. Die Person speichert die Änderung, wählt „Publish …“ und setzt Tag und Uhrzeit. Bis dahin zeigt die Seite die aktuellen Inhalte.

Das braucht nichts in der Konfiguration.

## Welchen Weg du nimmst

| Die Inhaberin will | Nimm |
| --- | --- |
| einen neuen Preis, eine neue Telefonnummer oder einen neuen Text ab einem bekannten Tag und den aktuellen weiter sehen | `planned` |
| die Fassung eines ganzen Einzelstücks für die nächste Woche vorab eintragen | `plans` |
| jede andere Änderung zu einem Zeitpunkt live schalten | „Publish …“ im Studio |
