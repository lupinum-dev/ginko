Diese Anleitung baut eine Restaurant-Seite mit dem Kit `@lupinum/ginko-preset-gastro`. Am Ende zeigt die Seite, ob das Haus heute geöffnet hat, und eine Speisekarte mit Preisen und Allergenen.

Das Kit ist ein Paket mit fertigen Bausteinen: `hours()`, `menu()`, `lunch()`, `events()` und mehr. Felder, Beschriftungen und die Aufgaben des Inhabers („Heute geschlossen“, „Gericht heute aus“) sind schon da. Dazu kommen die Regeln, die sie lesen: was heute gilt, welcher Preis zählt, welche Feiertage das Haus schließen. Die Vue-Komponenten bleiben in deiner Seite, weil ihr Aussehen zu deinem Design gehört.

## Der schnelle Weg: das Template

```bash
npm create ginko@latest my-restaurant -- --template restaurant
cd my-restaurant
npm install
npm run dev
```

Das Template ist eine vollständige Seite: eine Startseite mit den Öffnungszeiten von heute, eine Speisekarte, eine Mittagswoche, Veranstaltungen mit eigenen Seiten, eine Galerie und Rechtstexte, auf Englisch, Deutsch und Italienisch. Alle Inhalte sind Markdown in `content/`. Ändere die Dateien und das Design, und du bist fertig.

[Templates]($docs.templates) hat eine Live-Demo. Die Schritte unten tragen das Kit in eine Seite mit deinem eigenen Design ein.

## Bevor du beginnst

Du brauchst eine Ginko-Seite, die läuft, zum Beispiel die aus dem [Schnellstart]($docs.getting-started).

## Schritte

::steps
#### Das Kit installieren

```bash
npm install @lupinum/ginko-preset-gastro
```

#### Die Bausteine eintragen

```ts [ginko.config.ts]
import { defineSite } from '@lupinum/ginko'
import { hours, menu } from '@lupinum/ginko-preset-gastro'

export default defineSite({
  // …
  bricks: {
    hours: hours({ source: 'files' }),
    menu: menu({ source: 'files' }),
  },
})
```

`source: 'files'` liest den Baustein aus `content/`. So läuft die Seite ohne die Plattform.

#### Die Öffnungszeiten schreiben

`hours` ist ein Einzelstück: eine Datei. `week` hat eine Zeile pro Tag. Ein Tag hat höchstens zwei Öffnungszeiten:

```markdown [content/hours.md]
---
week:
  - day: mo
    closed: true
  - day: tu
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: we
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: th
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: fr
    closed: false
    from1: '11:30'
    to1: '14:00'
    from2: '17:30'
    to2: '22:00'
  - day: sa
    closed: false
    from1: '11:30'
    to1: '22:00'
  - day: su
    closed: false
    from1: '11:30'
    to1: '15:00'
exceptions:
  - when:
      from: 2027-08-02
      to: 2027-08-15
    reason: Sommerurlaub
    closed: true
holidayNoticeDays: 14
holidays: sunday
---
```

`exceptions` sind Schließtage und besondere Tage. `holidays` sagt, was an einem Feiertag gilt: `sunday` (wie am Sonntag), `closed` oder `normal`.

#### Zwei Gerichte schreiben

`menu` ist eine Sammlung: eine Datei pro Gericht.

```markdown [content/menu/1.schnitzel.md]
---
category: mains
name: Wiener Schnitzel
description: With roast potatoes and lemon
price: 24.9
allergens: [A, C, G]
veg: none
---
```

```markdown [content/menu/2.strudel.md]
---
category: desserts
name: Apple strudel
price: 6.5
allergens: [A, G]
veg: vegetarian
---
```

`category` ist `starters`, `soups`, `mains`, `desserts` oder `drinks`. `allergens` sind die Buchstaben der 14 EU-Allergene.

#### Den Zustand von heute und die Speisekarte zeigen

`todayState` sagt, was heute gilt. `priceOn` gibt den Preis, der heute zählt.

```vue [app/pages/restaurant.vue]
<script setup lang="ts">
import { formatMoney } from '@lupinum/ginko'
import { menuCategories, priceOn, spansText, todayState, type HoursData } from '@lupinum/ginko-preset-gastro'

const hours = useGinko('hours')
const menu = useGinko('menu')
const today = useGinkoToday()

// Die gespeicherten Daten in der Form, die die Regeln nehmen.
const data = computed<HoursData>(() => {
  const { week, exceptions, closedOn, closedNote, holidays } = hours.value.data
  return {
    week: week.map((day) => ({ ...day, day: String(day.day), closed: day.closed === true })),
    exceptions: exceptions.map((e) => ({ ...e, reason: e.reason ?? '', closed: e.closed === true })),
    closedOn: closedOn ?? undefined,
    closedNote: closedNote ?? undefined,
    holidays: (['sunday', 'closed', 'normal'] as const).find((setting) => setting === holidays),
  }
})
const state = computed(() => todayState({ hours: data.value, calendar: 'AT' }, today.value))

const groups = computed(() => menuCategories.map((category) => ({
  category,
  dishes: menu.value.items.filter((dish) => dish.data.category === category),
})).filter((group) => group.dishes.length))

useGinkoSeo({ title: 'Restaurant' })
</script>

<template>
  <main>
    <p v-if="state.kind === 'open'">Heute geöffnet: {{ spansText(state.times, 'und') }}</p>
    <p v-else-if="state.kind === 'holiday'">Heute geschlossen: {{ state.holiday.de }}</p>
    <p v-else-if="state.kind === 'closed'">Heute geschlossen: {{ state.reason }}</p>
    <p v-else>Heute geschlossen</p>

    <section v-for="group in groups" :key="group.category">
      <h2>{{ group.category }}</h2>
      <ul>
        <li v-for="dish in group.dishes" :key="dish.id">
          {{ dish.data.name }} · {{ formatMoney(priceOn(dish.data, today), 'de') }} · {{ dish.data.allergens.join(', ') }}
        </li>
      </ul>
    </section>
  </main>
</template>
```

`calendar: 'AT'` zählt die österreichischen Feiertage. Die [Restaurant-Referenz]($docs.restaurant-reference#feiertage) nennt die anderen Länder.
::

## Prüfe, ob es funktioniert

Öffne `/restaurant`. An einem Dienstag zeigt die Seite:

```text
Heute geöffnet: 11:30–14:00 und 17:30–22:00
mains
Wiener Schnitzel · 24,90 € · A, C, G
desserts
Apple strudel · 6,50 € · A, G
```

An einem Montag zeigt sie „Heute geschlossen“. Dann führe `npx ginko check` und `npx nuxt typecheck` aus. Beide laufen ohne Fehler durch.

## Was die vier Zustände bedeuten

| `state.kind` | Wann | Was er mitbringt |
| --- | --- | --- |
| `open` | Das Haus öffnet heute. | `times`: die Öffnungszeiten |
| `closed` | Der Inhaber hat diesen Tag geschlossen: eine Ausnahme oder „Heute geschlossen“. | `reason`: der Text des Inhabers |
| `holiday` | Ein Feiertag schließt das Haus. | `holiday`: sein Name auf Deutsch und Englisch |
| `restDay` | In der üblichen Woche ist dieser Tag ein Ruhetag. | nichts |

## Die anderen Bausteine

| Baustein | Art | Wofür |
| --- | --- | --- |
| `hourPlans()` | Sammlung | Andere Wochenzeiten für einen Zeitraum, etwa Winterzeiten jedes Jahr. Gib `hours()` den Schlüssel mit: `hours({ plans: 'hourPlans' })`. |
| `notices()` | Sammlung | Kurze Zeilen wie „Heute Abend ausgebucht“, jede bis zu einem Datum. |
| `lunch()` | Einzelstück | Das Mittagsmenü dieser Woche, Montag bis Freitag. |
| `lunchPlans()` | Sammlung | Mittagswochen, im Voraus geplant. |
| `events({ route })` | Sammlung | Veranstaltungen mit je einer Seite. Eine Veranstaltung verschwindet nach ihrem letzten Tag von der Seite. |
| `gallery()` | Einzelstück | Fotos. |

Setze in `bricks` den Baustein `hourPlans` direkt nach `hours` und `lunchPlans` direkt nach `lunch`. Das Studio listet die Aufgaben in dieser Reihenfolge.

## Den Inhaber ändern lassen

Mit `source: 'files'` ändert ein Entwickler die Öffnungszeiten und die Speisekarte. Auf der Plattform macht es der Inhaber vom Handy aus: „Heute geschlossen“, „Heute ausgebucht“, „Gericht heute aus“, ein neuer Preis ab einem Datum, die Mittagswoche.

Um einen Baustein zu verlegen, entferne sein `source: 'files'` und gib das Schema frei, siehe [Einen Baustein auf die Plattform verlegen]($docs.move-a-brick-to-the-platform). Zwei Dinge sind bei diesem Kit besonders:

- Ein `lunch()` auf der Plattform braucht `weekOf`, den Montag der ersten Woche: `lunch({ weekOf: '2026-10-05' })`.
- Ein `lunch()` auf der Plattform braucht die Hauptsprache `de` oder `en`, weil seine Tage mit einem Platzhaltertext in einer dieser Sprachen beginnen.
