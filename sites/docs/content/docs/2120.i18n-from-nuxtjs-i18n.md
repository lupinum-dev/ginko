This guide moves a Nuxt app from `@nuxtjs/i18n` to `@lupinum/ginko-i18n`. At the end, the app has the same pages and addresses, the head tags come without code, and the translation check runs in CI.

## Check first whether it fits

Ginko i18n has one rule: the language comes from the address. Stay with `@nuxtjs/i18n` if you need one of these:

- a domain per language (`example.de`, `example.com`),
- pages without a language in the address (`no_prefix`), outside of an app behind a login,
- a redirect by browser language on every page.

| | Ginko i18n | @nuxtjs/i18n 10.6 |
| --- | --- | --- |
| Where the language comes from | The address only. The browser language only drives a suggestion. | The address, and by default `/` redirects by cookie and browser language. |
| Address forms | `prefix_except_default`, `prefix` | Also `no_prefix`, `prefix_and_default` and domains. |
| Translated addresses | `definePageMeta({ i18n: { paths } })` | The same, or the `pages` option. |
| Head tags | On every page, without code. | `useLocaleHead()`, which you call in your layout. |
| Message format | ICU, compiled at build time | vue-i18n syntax |
| JavaScript it adds in the browser | 5.4 KB gzipped | 29.3 KB gzipped |
| Translation tool | `ginko-i18n check`, `todo`, `apply` | none |

The sizes were measured on 12 October 2026 with Nuxt 4.6.0, two languages, three messages and one page.

## Steps

::steps
#### Remove the old module

```bash
npm uninstall @nuxtjs/i18n
npm install @lupinum/ginko-i18n
```

Both modules cannot be installed together. The setup stops with:

```text
[ginko-i18n] @nuxtjs/i18n is also installed. Fix: remove one; two modules cannot both own the locale.
```

#### Change the options

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-i18n'],
  i18n: {
    locales: ['en-GB', 'de-AT'],
    defaultLocale: 'en',
    baseUrl: 'https://example.com',
  },
})
```

| @nuxtjs/i18n | Ginko i18n |
| --- | --- |
| `locales: [{ code, language, file }]` | `locales: ['en-GB', { language: 'de-AT', code: 'de' }]`. The files are always `i18n/<code>.json`. |
| `defaultLocale` | `defaultLocale` |
| `strategy: 'prefix_except_default'` or `'prefix'` | the same |
| `strategy: 'no_prefix'`, `'prefix_and_default'`, `differentDomains` | Not supported. For an app behind a login, use `userLocale`. |
| `detectBrowserLanguage` | No redirect. `useLocaleSuggestion()` offers a link. |
| `customRoutes: 'config'`, `pages: {…}` | `definePageMeta({ i18n: { paths } })` in each page |
| `baseUrl` | `baseUrl` |
| `vueI18n: './i18n.config.ts'` | Not needed. Formats come from `Intl`. |

An option that Ginko i18n does not know stops the setup and names it:

```text
[ginko-i18n] Unknown option(s) i18n.detectBrowserLanguage. Fix: remove them; ginko-i18n is not @nuxtjs/i18n.
```

#### Move the message files

Put one JSON file per language into `i18n/`, named by the code: `i18n/en.json`, `i18n/de.json`. A key is a name, and nesting separates names: `t('nav.about')` reads `{ "nav": { "about": … } }`. A key must not contain a dot.

#### Rewrite the messages that are not plain text

Ginko i18n reads ICU, not the vue-i18n syntax. Plain text and `{name}` stay as they are.

| vue-i18n | ICU |
| --- | --- |
| `Hello {name}` | `Hello {name}` |
| `no apples \| one apple \| {count} apples` | `{count, plural, =0 {no apples} one {one apple} other {# apples}}` |
| `{n} items` with `$t(key, n)` | `{n, plural, other {# items}}` with `t(key, { n })` |
| `@:common.brand` (a linked message) | Not supported. Write the text, or pass it as a parameter. |
| `{'@'}` | `@` needs no escape. Quote `{` as `'{'`. |
| `@.lower:key` (a modifier) | Not supported. Format in code. |

Every `plural` and `select` needs an `other` case.

#### Change the code

| @nuxtjs/i18n | Ginko i18n |
| --- | --- |
| `$t('key')` in a template | `const { t } = useI18n()`, then `t('key')` |
| `locale.value = 'en'`, `setLocale('en')` | `switchLocale('en')` |
| `localePath('about')` with a route name, `localeRoute`, `<NuxtLinkLocale>` | `localePath('/about')` with a path, and `<NuxtLink>` |
| `switchLocalePath('en')` | `alternates`, or `localePath(route.path, 'en')` |
| `<i18n-t keypath="…">` | `<I18nT k="…">` with a slot per tag |
| `useLocaleHead()` | Nothing. The head tags come without code. |
| `$n`, `$d` | `format.number`, `format.date` |
| Route names `about___en` | `about__en`. Link by path. |

Do not navigate by route name. The module makes one route per language, named `<name>__<code>`. `navigateTo({ name: 'about' })` finds nothing.

#### Run the checks

```bash
npx nuxt typecheck
npx ginko-i18n check
```

The type check finds a key that does not exist and a parameter that is missing. The translation check finds texts that a language does not have, wrong ICU and unused keys.
::

## Check that it works

- Every page answers on the same address as before, in every language.
- The source of a page has `lang`, a canonical link and one `hreflang` link per language.
- `npx ginko-i18n check` ends with `0 errors`.

## What changes for visitors

- `/` no longer redirects by browser language. A visitor with a German browser who opens `/` sees the default language. Offer a link with `useLocaleSuggestion()`, see [i18n reference]($docs.i18n-reference#uselocalesuggestion).
- Other spellings of an address redirect to the one address: `/about/` and `/DE/ueber-uns` answer with a 301.
