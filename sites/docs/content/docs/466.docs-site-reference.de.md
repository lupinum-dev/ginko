Diese Seite listet, was das Doku-Kit `@lupinum/ginko-docs` anbietet. Die Anleitungen beginnen bei [Eine Doku-Seite starten]($docs.start-a-docs-site).

## Einstiegspunkte

Importiere nur diese Pfade. Jede andere Datei im Paket ist intern und kann sich in jedem Release ändern.

| Einstiegspunkt | Was er ist |
| --- | --- |
| `@lupinum/ginko-docs` | Die Nuxt-Ebene für `extends` in `nuxt.config.ts`. Sie bringt die Seiten, das Layout, die Komponenten, das CSS und `@lupinum/ginko-components` mit. |
| `@lupinum/ginko-docs/config` | Die Bausteine und Seitenadressen für `ginko.config.ts`. |
| `@lupinum/ginko-docs/pages` | Ein Nuxt-Modul, das die Seiten des Kits anmeldet. Die Ebene lädt es selbst. |
| `@lupinum/ginko-docs/icons` | Ein Nuxt-Modul, das die Icons beim Build bündelt. Die Ebene lädt es selbst. |

Trag die beiden Module nicht in `modules` ein. `extends: ['@lupinum/ginko-docs']` bringt sie mit.

Die einzige Einstellung in `nuxt.config.ts` ist `ginkoDocs.brick`: der Schlüssel des Doku-Bausteins, wenn er nicht `docs` heißt.

## Config-Funktionen

```ts
import { blogCollections, blogPages, changelogCollection, changelogPages, components, docsCollection, docsHome, homePages } from '@lupinum/ginko-docs/config'
```

| Export | Gibt zurück |
| --- | --- |
| `docsCollection({ locales, base?, source?, brick?, navExtras?, label?, max? })` | Den Doku-Baustein. |
| `docsHome({ source? })` | Den Baustein der Startseite: `content/home.md`. |
| `blogCollections({ locales, source?, max? })` | Den Blog: `{ posts, authors }`. Breite ihn in `bricks` aus. |
| `changelogCollection({ source?, max? })` | Den Changelog-Baustein. |
| `homePages({ locales })` | Die Adressen der Startseite je Sprache, für `pages.home`. |
| `blogPages({ locales })` | Die Adressen der Blog-Liste, für `pages.blog`. |
| `changelogPages({ locales })` | Die Adressen des Changelogs, für `pages.changelog`. |
| `components` | Die Registry der Markdown-Komponenten, für `components` in `defineSite`. |

Einstellungen von `docsCollection`:

| Einstellung | Typ | Standard | Bedeutung |
| --- | --- | --- | --- |
| `locales` | Liste von Sprachcodes | Pflicht | Die Sprachen der Seite, die Hauptsprache zuerst. |
| `base` | Pfad | `'/docs'` | Die Adresse der Doku. Andere Sprachen bekommen ihr Präfix: `/de/docs`. |
| `source` | `'files'` oder `'platform'` | `'files'` | Wo die Seiten liegen. Mit `'platform'` ändern Redakteure sie im Studio. |
| `brick` | Text | `'docs'` | Der Schlüssel des Bausteins, wenn er nicht `docs` heißt. Setz `ginkoDocs.brick` auf denselben Schlüssel. |
| `navExtras` | Boolean | `true` | `false` lässt die Felder `tab`, `badge` und `icon` weg. |
| `label` | Text | `'Docs'` | Der Name des Bausteins im Studio. |
| `max` | Zahl | `500` | Höchstzahl der Seiten. |

Setz `navExtras`, wenn die Seite startet. Auf einer Seite mit freigegebenen Seiten entfernt es Felder, und das lehnt die Plattform ab; nimm die drei Felder dort außer Dienst, siehe [Eine Schema-Änderung freigeben]($docs.release-a-schema-change).

Das Kit findet seine Inhalte über den Baustein-Schlüssel. Behalte diese Namen: `docs`, `home`, `posts`, `authors` und `changelog`. Nur `docs` ist Pflicht, und nur `docs` kann einen anderen Schlüssel haben.

## Adressen

| Adresse | Seite | Existiert, wenn |
| --- | --- | --- |
| `<base>` | Führt zur ersten Doku-Seite | immer |
| `<base>/<name>` | Eine Doku-Seite | immer |
| `/` | Die Startseite oder die erste Doku-Seite | die Website dort keine eigene Seite hat |
| `/blog`, `/blog/<name>`, `/blog/rss.xml` | Der Blog, ein Beitrag, der Feed | die Bausteine `posts` und `authors` existieren |
| `/changelog` | Alle Releases | der Baustein `changelog` existiert |

Andere Sprachen haben ihr Präfix: `/de/blog`. Eine Seite der Website an derselben Adresse gewinnt.

## Felder einer Doku-Seite

Das Frontmatter einer Datei in `content/docs/`:

| Feld | Pflicht | Bedeutung |
| --- | --- | --- |
| `title` | ja | Der Titel der Seite. |
| `description` | ja | Ein oder zwei Sätze, für Suchergebnisse und Link-Vorschauen. |
| `navTitle` | nein | Ein kurzer Titel für die Navigation, die Brotkrumen und die Links zur vorherigen und nächsten Seite. |
| `section` | nein | Beginnt eine Gruppe in der Navigation mit dieser Überschrift. |
| `parent` | nein | Ordnet die Seite unter einer anderen ein: `parent: docs/<name>`. |
| `tab` | nein | Beginnt einen Reiter über der Navigation. |
| `badge` | nein | Ein kurzes Etikett nach dem Titel, höchstens 20 Zeichen. |
| `icon` | nein | Ein Iconify-Name. Setz ihn nur in der Hauptsprache. |
| `slug` | nein | Die Adresse der Seite in dieser Sprache. Ohne ihn der Dateiname. |

## Optionen

Die Einstellungen stehen unter `docs` in `app/app.config.ts`. Alle sind optional. TypeScript prüft sie ohne Import.

| Einstellung | Typ | Standard | Bedeutung |
| --- | --- | --- | --- |
| `title` | Text | `name` der Seite | Der Name in der Kopfzeile. |
| `logo` | `{ light, dark?, wordmark? }` | keiner | Ein Logo vor dem Titel. `dark` erscheint im dunklen Modus. `wordmark: true` zeigt das Logo ohne den Titel. |
| `theme` | `'default'` oder `'green'` | `'default'` | Das Farb-Preset. |
| `nav` | Liste von `{ id, href }` | keine | Links in der Kopfzeile nach Docs, Blog und Changelog. Text: Meldung `docs.nav.<id>`. |
| `social` | Liste von `{ icon, href, label }` | keine | Icon-Links am Ende der Kopfzeile. |
| `banner` | `{ id, href? }` | keiner | Ein Hinweis über der Kopfzeile, den Leser schließen können. Text: Meldung `docs.banner.<id>`. |
| `repository` | `{ url, branch?, editUrl?, issueUrl? }` | keines | Fügt Seiten aus Dateien „Diese Seite bearbeiten“ hinzu, und für GitHub „Problem melden“. |
| `studioEditLink` | Boolean | `false` | Fügt Seiten auf der Plattform „Diese Seite bearbeiten“ hinzu, mit einem Link ins Studio. |
| `markdownActions` | `{ copy?, openIn? }` | Kopieren an, beide Chats | „Seite kopieren“ und die Chats, in denen sein Menü die Seite öffnet: `'chatgpt'`, `'claude'`. `[]` für keinen. |
| `search` | Boolean | `true` | `false` lässt die Suche des Kits weg. |
| `footer` | `{ links?, attribution? }` | Hinweis an | Links in der Fußzeile `{ id, href }` mit dem Text aus `docs.footer.<id>`. `attribution: false` entfernt „Built with Ginko“. |

Details:

- Ein interner Pfad in `nav`, `footer.links` und `banner.href` folgt der Sprache des Lesers: Aus `/guide` wird `/de/guide`. Eine vollständige URL bleibt, wie sie ist.
- Ein Leser, der das Banner schließt, sieht es nicht wieder. Eine neue `id` zeigt es allen.
- Eingebaute `social`-Icons: `docs:github`, `docs:discord`, `docs:x`, `docs:bluesky`, `docs:mastodon`, `docs:linkedin`, `docs:youtube`. Jeder andere Iconify-Name geht auch.
- `repository.branch` ist standardmäßig `main`. `editUrl` ist ein Template mit `{url}`, `{branch}` und `{source}`; der Standard ist `{url}/edit/{branch}/{source}`. `issueUrl` ist ein Template mit `{url}`, `{title}` und `{page}`.

## Komponenten

Diese Komponenten sind öffentlich und bleiben zwischen Releases stabil:

| Komponente | Props und Slots | Wofür |
| --- | --- | --- |
| `<DocsSearch />` | `shortcut` (Standard `true`): `/` und Strg oder ⌘ K öffnen die Suche | Die Suche, zum Beispiel in der Kopfzeile der Website |
| `<DocsLanguage />` | `list`: eine Reihe Links statt eines Menüs | Die Sprachen der aktuellen Seite |
| `<DocsThemeToggle />` | `segmented`: der Schalter mit Auto, Hell und Dunkel | Der Hell-Dunkel-Schalter |
| `<DocsShell>` | Slot `default` für die Seite, Slot `bar` für Bedienelemente in der Leiste auf dem Handy | Navigation und Suche um eine eigene Seite |
| `<Icon name="lucide:…" />` | `name` | Ein Icon aus dem Bündel des Kits. Installiert die Website `@nuxt/icon`, gewinnt deren `Icon`. |

Zwei leere Komponenten sind Stellen für eigene Teile, siehe [Eine Doku-Seite gestalten]($docs.docs-theming#schritte): `DocsPageEnd` und `DocsSidebarEnd`.

## Tokens

Die Farb-Tokens und die Maße (`--docs-max`, `--docs-top` und weitere) stehen auf [Eine Doku-Seite gestalten]($docs.docs-theming#groessen).

## Intern

Alles andere kann sich in jedem Release ändern: die übrigen `Docs*`-Komponenten, die `useDocs*`-Composables, die Dateien unter `app/` und die CSS-Klassen. Für das Aussehen sind die Tokens die öffentliche Schnittstelle, nicht die Klassen.
