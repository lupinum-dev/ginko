In ten minutes you have a complete site on your computer: a home page, an About and a Contact page, a menu, legal texts, light and dark mode, in English and German. Then you change a text and add a page.

The site reads all its content from Markdown files in its own folder. It needs no account and no platform.

You need Node.js 22.18 or newer (22, 24 or 26) and npm, pnpm or bun.

## Create and run the site

::steps
#### Create the site

```bash
npm create ginko@latest my-site -- --template starter
```

Write the options after `--`. Without it, npm keeps them for itself. pnpm, yarn and bun take the same command.

The command creates the folder `my-site` from the template `starter`, a plain site to start from. Its sample content is the site of a translator, Klara Brenner.

#### Install and start

```bash
cd my-site
npm install
npm run dev
```

npm may warn that esbuild has an install script. The site runs without it.

Open `http://localhost:3000`. The home page shows "Translations that read like the original".

#### Change a text

Open `content/home.md`. The lines between the two `---` are the fields of the home page. The text below them is its body:

```markdown [content/home.md]
---
title: Translations that read like the original
lead: I translate between German and English for museums, research institutes and publishers.
---

## What I translate

- Exhibition and catalogue texts for museums and galleries
```

Change the title and save the file. The page in the browser shows the new title.

#### Add a page

Add a file in `content/pages/`. The number sets the order, the rest of the name is the address:

```markdown [content/pages/3.services.md]
---
title: Services
summary: What I offer and what it costs.
---

## Translation

From 0.18 € per word.
```

Open `http://localhost:3000/services`. The page is there, and the home page shows it as a card next to About and Contact.

To put the page in the menu, open `app/app.config.ts` and add it to `nav`:

```ts [app/app.config.ts]
nav: [{ entry: 'pages/about' }, { entry: 'pages/services' }, { entry: 'pages/contact' }],
```

`pages/services` is the folder and the file name without the number.

#### Check the content

```bash
npm run check
```

The command reads every content file and reports a missing field, a wrong date or a broken link with the file and the field. When all is right, it prints `OK: schema and links are fine.`
::

The new page exists in English only, so `/de/services` answers "not found". A German version is a second file, `content/pages/3.services.de.md`. [Write content in files]($docs.write-content-in-files) shows how a translation looks.

## What you have now

| Folder or file | What it holds |
| --- | --- |
| `content/` | The content: one Markdown file per text, in one folder per kind of content. |
| `ginko.config.ts` | The description of the content: which kinds exist and which fields each one has. |
| `app/pages/` | The Nuxt pages that show the content. |
| `app/app.config.ts` | The menu, the footer links and the line under the name. |
| `README.md` | The manual of the template: the file behind every part of the site, and how to make it yours. |

Ginko calls one kind of content a brick. The home page, the pages and the legal texts are three bricks of this site. [What Ginko is]($docs.what-ginko-is) explains the words, and [How a template is built]($docs.template-tour) goes through the folder file by file.

## Start with another template or other languages

`starter` is one of ten templates. The others are complete sites for a restaurant, a company, a software product, a nonprofit, an event, a portfolio, a blog and more. The steps on this page work the same way in each one. [Templates]($docs.templates) shows them with a live demo.

`--locales` picks the languages and their order. The first one is the main language:

```bash
npm create ginko@latest my-site -- --template restaurant --locales de,en
```
