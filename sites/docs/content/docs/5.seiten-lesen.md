## useGinko

`useGinko(baustein)` liest einen Baustein. Der Rückgabewert ist ein `ComputedRef`. In `<script>` greifst du mit `.value` zu, im Template nicht.

- Für ein Einzelstück liefert er `{ data, fallback }`. `data` enthält die Felder.
- Für eine Sammlung liefert er `{ items }`. Jedes Element hat `id`, `data`, `fallback` und `urls`.

```vue
<script setup lang="ts">
const menu = useGinko('menu')
const { locale } = useI18n()
</script>

<template>
  <ul>
    <li v-for="item in menu.items" :key="item.id">
      {{ item.data.name }}: {{ formatMoney(item.data.price, locale) }}
    </li>
  </ul>
</template>
```

`useI18n()` gehört zu ginko-i18n. Es liefert die aktuelle Sprache als `locale`. `useGinko` und `formatMoney` sind automatisch importiert.

Die Typen kommen aus deiner `ginko.config.ts`. `item.data.price` ist dort ein `f.money`-Feld, also ein `{ amount, currency }`. Ein freiwilliges Feld kann `undefined` sein.

`useGinko` gibt bei einer Sammlung nur sichtbare Einträge zurück, in der Reihenfolge des Bausteins. Die Regel steht in „Bausteine“, Abschnitt „Sichtbarkeit“.

Der Typ eines Eintrags heißt `ItemOf`. Du importierst ihn aus `@lupinum/ginko`, wenn eine Komponente einen Eintrag als Prop bekommt:

```vue
<script setup lang="ts">
import type { ItemOf } from '@lupinum/ginko'

type Doc = ItemOf<(typeof import('../../ginko.config').default)['bricks']['docs']['fields']>
defineProps<{ doc: Doc }>()
</script>
```

## useGinkoEntry

`useGinkoEntry(baustein, slug)` liest einen Eintrag einer Sammlung mit `route`. Du gibst den Slug aus der Adresse mit. Die Datei liegt zum Beispiel unter `app/pages/veranstaltungen/[slug].vue`:

```vue
<script setup lang="ts">
definePageMeta({ i18n: { paths: { en: '/events/:slug()' } } })
const route = useRoute()
const event = useGinkoEntry('events', String(route.params.slug))
</script>

<template>
  <article>
    <h1>{{ event.data.title }}</h1>
    <GinkoMarkdown :value="event.data.description" />
  </article>
</template>
```

`useGinkoEntry` baut den Pfad aus der Route des Bausteins und dem Slug. Dann sucht es den sichtbaren Eintrag, dessen Adresse in der aktuellen Sprache genau dieser Pfad ist. Findet es keinen, antwortet die Seite mit einem echten **404**. Das passiert bei einem falschen Slug, bei einem nicht sichtbaren Eintrag und beim Slug einer anderen Sprache.

## useGinkoToday

`useGinkoToday()` liefert das heutige Datum als `YYYY-MM-DD`, in der Zeitzone der Seite. Der Wert ist ein `Ref`. Auf dem Server gilt zuerst der Wert des Servers, damit Server und Browser denselben Tag rendern. Im Browser läuft der Wert nach Mitternacht weiter, direkt nach dem Laden, jede Minute und beim Zurückkehren in den Tab. `useGinko` filtert mit diesem Wert. Abgelaufene Hinweise verschwinden also ohne Neuladen.

Nutze `useGinkoToday()` auch für eigene Datumsvergleiche, zum Beispiel „heute geöffnet“.

## GinkoMarkdown

`<GinkoMarkdown :value>` zeigt den Wert eines `f.markdown`-Feldes an:

```vue
<GinkoMarkdown :value="legal.data.imprint" class="prose" />
```

Der Text liegt als Markdown vor, das Bundle liefert ihn schon als Baum. Es läuft kein Parser im Browser und kein `v-html`. Ein unsicherer Link (zum Beispiel `javascript:`) wird zu reinem Text. Mit `:components` ordnest du Tags eigene Komponenten zu. Mehr dazu unter „Inhalte aus Dateien“.

## useGinkoSeo

`useGinkoSeo` setzt den Kopf einer Seite: Titel (mit `seo.titleTemplate` der Site), Beschreibung, Canonical, Open-Graph- und Twitter-Tags und JSON-LD. Ruf es einmal pro Seite auf, mit einer Funktion, damit die Werte dem Inhalt folgen:

```ts
const event = useGinkoEntry('events', String(route.params.slug))
useGinkoSeo(() => ({
  title: event.value.data.title,
  image: event.value.data.image?.url,
  type: 'article',
  jsonLd: [eventLd.value],
}))
```

| Option | Bedeutung |
| --- | --- |
| `title`, `description` | Standard: der Name der Site und `seo.description` |
| `image` | Ein Pfad unter `public/` oder eine absolute URL. Standard: `seo.image` |
| `type` | `'website'` (Standard) oder `'article'` |
| `section` | Ein kleines Label über dem Titel auf einer erzeugten Vorschaukarte |
| `noindex` | Hält die Seite aus Suchmaschinen heraus |
| `jsonLd` | Weitere JSON-LD-Objekte |

**Vorschaukarten.** Installiere `nuxt-og-image` und einen Renderer (`@takumi-rs/core`) und trag `'nuxt-og-image'` in `modules` ein. Dann bekommt jede Seite ohne eigenes `image` eine erzeugte Karte mit Titel, Beschreibung und Namen der Site. Eine Seite mit `image` behält dieses Bild. Ohne das Modul lädt Ginko nichts davon.

## formatMoney

`formatMoney(geld, sprache)` macht aus einem Geldwert einen Text. Das Modul importiert die Funktion automatisch.

| Aufruf | Ergebnis |
| --- | --- |
| `formatMoney({ amount: 1250, currency: 'EUR' }, 'de')` | `12,50 €` |
| `formatMoney({ amount: 1250, currency: 'EUR' }, 'en')` | `€12.50` |
| `formatMoney({ amount: 1250, currency: 'CHF' }, 'de')` | `12,50 CHF` |

Alle Leerzeichen im Ergebnis sind geschützte Leerzeichen. So bricht der Preis nicht um, und Server und Browser zeigen denselben Text.

## Fallback und das Attribut lang

Fehlt die Übersetzung eines Feldes in der aktuellen Sprache, zeigt das Bundle den Text der Hauptsprache. Das gilt auch, wenn die Übersetzung veraltet ist, weil sich der Haupttext danach geändert hat. Die Liste `fallback` nennt jedes solche Feld mit seinem Pfad. Bei einem Feld in einer Listenzeile besteht der Pfad aus Feld, Zeilen-`_id` und Spalte, zum Beispiel `days.k3Fd9aZ0qx.dish`.

Ein Screenreader liest einen fremden Text mit der falschen Aussprache, wenn die Seite ihn nicht markiert. Setze deshalb `lang` auf die Hauptsprache, wenn der Pfad in `fallback` steht.

Ginko bringt dafür `langOf(item, path)` mit (automatisch importiert). Es gibt den Sprach-Tag der Hauptsprache zurück, zum Beispiel `de-AT` aus `languages` in `ginko.config.ts`, wenn das Feld aus dem Fallback kommt, sonst `undefined`:

```vue
<script setup lang="ts">
const menu = useGinko('menu')
</script>

<template>
  <h3 v-for="item in menu.items" :key="item.id" :lang="langOf(item, 'name')">{{ item.data.name }}</h3>
</template>
```

Für eine Listenzeile eines Einzelstücks nennst du den vollen Pfad:

```vue
<span :lang="langOf(lunch, `days.${day._id}.dish`)">{{ day.dish }}</span>
```

Bei einem Bild heißt der Pfad des Alternativtexts `image.alt`, wenn das Feld `image` heißt. Ein Wert `undefined` lässt das Attribut weg.

Das Attribut `lang` am `<html>`-Element setzt ginko-i18n für dich. Siehe „Sprachen“.

## Fehler und Cache

Die Seite lädt das Bundle einmal pro Anfrage. Scheitert das (Netzwerk, Serverfehler, falsches Format, zu viele Anfragen), antwortet die Seite mit **503** und nie mit 404. Auf Vercel behält ein 503 die alte, gute Seite im Cache, ein 404 würde sie ersetzen. Nur ein bestätigt fehlender Eintrag liefert 404.  Das Modul schaltet für alle Seiten ISR ein (`expiration: 60`, Abfrageparameter teilen sich einen Cache-Eintrag), nur `/__ginko` und `/__ginko/**` laufen ohne Cache. Eine Seite, deren Bausteine alle aus Dateien kommen, fragt die Plattform nie und kann deshalb keinen 503 wegen der Plattform liefern.

::callout{type="warning"}
Lies in `error.vue` weder `useGinko` noch andere Composables, die das Bundle brauchen. Bei einem 503 gibt es kein Bundle, und die Fehlerseite würde selbst scheitern.
::
