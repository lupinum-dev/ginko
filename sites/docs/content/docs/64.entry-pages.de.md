Diese Anleitung gibt jedem Eintrag einer Sammlung eine eigene Seite, zum Beispiel `/news/opening` für eine Neuigkeit. Am Ende verlinkt die Liste jeden Eintrag, eine falsche Adresse antwortet mit einem echten 404, und die Sitemap nennt jeden Eintrag.

## Bevor du beginnst

Du hast eine Sammlung, zum Beispiel `news`, und eine Seite, die sie auflistet. [Inhalte modellieren]($docs.model-your-content) zeigt, wie du eine Sammlung anlegst.

## Schritte

::steps
#### Ein Slug-Feld und eine Route ergänzen

Der Slug ist der letzte Teil der Adresse. Die Route sagt, wo die Seiten liegen, mit einem Pfad pro Sprache:

```ts [ginko.config.ts]
news: collection({
  label: 'Neuigkeiten',
  source: 'files',
  max: 100,
  order: { field: 'date', dir: 'desc' },
  route: { en: '/news/[slug]', de: '/de/neuigkeiten/[slug]' },
  fields: {
    title: f.text('Titel'),
    date: f.date('Datum'),
    slug: f.slug('Adresse', { from: 'title' }),
    body: f.markdown('Text'),
  },
}),
```

- Die Route hat einen Pfad für jede Sprache der Seite. Jeder Pfad enthält `[slug]`.
- Der Pfad einer weiteren Sprache enthält ihr Präfix, hier `/de`.
- Das Slug-Feld heißt `slug`.

In einer Seite aus einem Template schreibst du `route: localized('/news/[slug]')`. Die Hilfsfunktion in `app/routes.ts` ergänzt das Präfix jeder Sprache.

#### Wissen, woher der Slug kommt

| Der Baustein liegt | Der Slug ist |
| --- | --- |
| in Dateien | der Dateiname ohne Nummer und Sprache: `content/news/1.opening.md` hat den Slug `opening`. Eine Zeile `slug:` im Frontmatter ersetzt ihn. |
| auf der Plattform | einmal aus dem Feld in `from` gebildet, wenn der Eintrag entsteht: „We are open“ wird zu `we-are-open`. Die Inhaberin kann ihn im Studio ändern. |

Jede Sprache hat ihren eigenen Slug. Eine Übersetzungsdatei setzt ihn mit `slug:`:

```markdown [content/news/1.opening.de.md]
---
title: Wir haben geöffnet
slug: wir-haben-geoeffnet
---

Die neue Seite ist online.
```

#### Die Seite für einen Eintrag schreiben

Leg eine Seitendatei an, deren Pfad zur Route der Hauptsprache passt:

```vue [app/pages/news/[slug].vue]
<script setup lang="ts">
definePageMeta({ i18n: { paths: { de: '/neuigkeiten/:slug()' } } })
const route = useRoute()
const post = useGinkoEntry('news', () => route.params.slug)
</script>

<template>
  <article>
    <h1>{{ post.data.title }}</h1>
    <GinkoMarkdown :value="post.data.body" />
  </article>
</template>
```

`useGinkoEntry` findet den Eintrag über seinen Slug in der Sprache der Adresse. Die Zeile mit `definePageMeta` brauchst du nur, wenn eine andere Sprache einen anderen Pfad hat. Sie nennt diesen Pfad ohne das Sprachpräfix.

#### Die Einträge verlinken

Jeder Eintrag einer Sammlung mit Route trägt seine Adresse in `url`. Nimm sie für die Links:

```vue [app/pages/news/index.vue]
<script setup lang="ts">
const news = useGinko('news')
</script>

<template>
  <ul>
    <li v-for="item in news.items" :key="item.id">
      <NuxtLink :to="item.url">{{ item.data.title }}</NuxtLink>
    </li>
  </ul>
</template>
```

Bau den Pfad nicht selbst. `url` stimmt in jeder Sprache und bleibt richtig, wenn sich die Route ändert.

#### Das Ergebnis prüfen

1. Öffne die Liste und folge einem Link. Die Adresse ist `/news/opening`.
2. Öffne `/news/gibt-es-nicht`. Die Antwort ist eine 404-Seite.
3. Öffne die deutsche Liste. Sie zeigt nur die Einträge, die eine deutsche Datei haben, jeden unter seinem deutschen Slug.
4. Öffne `/sitemap.xml`. Sie nennt jeden Eintrag in jeder Sprache, in die er übersetzt ist.
::

## Was eine Route mitbringt

- **Ein 404 für unbekannte Slugs.** `useGinkoEntry` antwortet mit einem echten 404, auch beim Navigieren im Browser.
- **Links zwischen den Sprachen.** Die Seite eines Eintrags bekommt `hreflang`-Links zu seinen Übersetzungen, und der Sprachwechsel führt zum selben Eintrag.
- **Verborgen, bis er übersetzt ist.** In einer Sprache ohne Übersetzung bleibt ein Eintrag mit Route weg. Setz `untranslated: 'fallback'` am Baustein, dann steht er in der Liste, mit einem Link zu seiner Seite in der Hauptsprache.
