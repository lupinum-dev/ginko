A site with bricks on the platform needs that content while you develop. This guide runs `npm run dev` against the hosted platform. At the end, your local site shows the published content, and you know what a brick shows that you have not released yet.

## Steps

::steps
#### Put the platform address into the config

```ts [ginko.config.ts]
export default defineSite({
  site: 'linde',
  platform: 'https://platform.example.com',
  // …
})
```

With the address in the config, `npm run dev` works in every clone, without an `.env` file.

#### Start the site

```bash
npm run dev
```

The pages show the published content of the platform. Reading needs no key.

#### Add a brick and look at it

Add a brick to the config and read it in a page. Before its release, the platform does not know the brick. Your local site shows this:

| The new part | Shows |
| --- | --- |
| a new brick | nothing: a single has its defaults, a collection is empty |
| a new field with a `default` | the default |
| a new optional field | no value |

Owners can fill the new parts only after the release. Run `npx ginko check` to see whether the platform accepts the change.
::

## Another platform for one run

`NUXT_PUBLIC_GINKO_PLATFORM` replaces `platform` from the config, for example to look at a test site:

```bash
NUXT_PUBLIC_GINKO_PLATFORM=https://test-platform.example.com npm run dev
```

## How fast a publish arrives

A site loads the content again at most every 60 seconds. A change that an owner publishes is on the live site within a minute.

To make it immediate, give the live site a token. In the Studio, open Team, then "Site token", and choose "Create token". Set it on your host as `NUXT_GINKO_REVALIDATE_TOKEN`. Then "Update website now" in the Studio reloads the site at once.
