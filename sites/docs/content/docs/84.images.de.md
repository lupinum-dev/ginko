Diese Anleitung gibt einem Eintrag ein Foto und zeigt es auf der Seite. Am Ende hat das Foto eine Beschreibung, behält beim Laden seinen Platz, und Handys laden eine kleine Datei.

Ein Bild hat zwei mögliche Orte: ein Feld des Bausteins und den Markdown-Text.

## Ein Foto als Feld

::steps
#### Ein Bildfeld ergänzen

```ts [ginko.config.ts]
fields: {
  title: f.text('Titel'),
  photo: f.image('Foto', { optional: true, aspect: '3:2' }),
  body: f.markdown('Text'),
},
```

`aspect` ist die Form, in der die Seite das Foto zeigt. Die Einstellung ist freiwillig.

#### Das Foto an einem Eintrag setzen

Bei einem Baustein in Dateien legst du das Bild in `public/` und nennst es im Frontmatter mit seiner Beschreibung:

```markdown [content/news/1.opening.md]
---
title: We are open
photo:
  src: /img/kitchen.jpg
  alt: The kitchen in morning light
---
```

`src` ist der Pfad unter `public/`. `alt` beschreibt das Foto für Menschen, die es nicht sehen. In der Hauptsprache ist `alt` Pflicht.

Auf der Plattform lädt die Inhaberin das Foto im Studio hoch und schreibt die Beschreibung dort.

#### Es mit GinkoImage zeigen

```vue
<GinkoImage v-if="post.data.photo" :image="post.data.photo" />
```

Die Komponente schreibt die Größe des Fotos in die Seite. So springt der Text nicht, während das Foto lädt. Sie schneidet das Foto auf das `aspect` des Feldes zu. Der Browser lädt das Foto erst, wenn es in die Nähe des Bildschirms kommt. Das erste Bild einer Seite lädt sofort.

#### Das Ergebnis prüfen

Öffne die Seite und sieh dir das Bild im Inspektor des Browsers an. Das `<img>` hat `width`, `height`, `alt` und ein `srcset` mit kleineren WebP-Dateien.
::

## Ein Foto in mehreren Formen

Steht dasselbe Foto in einer Karte und in einem Seitenkopf, gib dem Feld benannte Formen:

```ts
photo: f.image('Foto', { aspect: { card: '3:2', header: '21:9' } }),
```

```vue
<GinkoImage :image="post.data.photo" frame="card" />
```

Im Studio sieht die Inhaberin das Foto in jeder Form und setzt den Punkt, der im Bild bleiben muss.

## Ein Foto im Text

Leg das Bild neben die Markdown-Datei und schreib seinen relativen Pfad:

```markdown [content/news/1.opening.md]
![The kitchen in morning light](./kitchen.jpg)
```

Ginko liest die Größe aus der Datei und setzt `width` und `height`. Fehlt die Datei, bricht der Build ab und nennt Datei und Pfad.

Um das Bild in einer festen Form zu zeigen, häng `aspect` an:

```markdown
![The kitchen in morning light](./kitchen.jpg){aspect="4:3"}
```

Ein Pfad, der mit `/` beginnt, sucht in `public/`. Ein Bild von einem anderen Server (`https://…`) bleibt, wie es ist.

## Was Ginko mit jedem Bild tut

- **Kleinere Kopien.** Ein Build schreibt WebP-Kopien mit 480, 960 und 1600 Pixeln Breite, jede nur, wenn das Bild breiter ist. Die Seite bietet sie im `srcset` an. SVG- und GIF-Bilder bleiben, wie sie sind.
- **Übersetzungen.** Eine Übersetzung ändert nur die Beschreibung: Ihre Datei gibt `alt` an, nicht `src`.
