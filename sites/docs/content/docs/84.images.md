This guide adds a photo to an entry and shows it on the page. At the end, the photo has a description, keeps its place while the page loads, and phones download a small file.

There are two places for an image: a field of the brick, and the Markdown text.

## Before you start

Images in content files need the package `sharp`. Ginko uses it to write the smaller copies. Some templates have it. Install it if `package.json` does not list it:

```bash
npm install sharp
```

Without it, the dev server and the build stop at the first image and say so:

```text
[ginko-content] Images in your content need the sharp package to make WebP copies. Fix: npm install sharp
```

## A photo as a field

::steps
#### Add an image field

```ts [ginko.config.ts]
fields: {
  title: f.text('Title'),
  photo: f.image('Photo', { optional: true, aspect: '3:2' }),
  body: f.markdown('Text'),
},
```

`aspect` is the shape in which the site shows the photo. It is optional.

#### Set the photo on an entry

For a brick in files, put the image into `public/` and name it in the frontmatter with its description:

```markdown [content/news/1.opening.md]
---
title: We are open
photo:
  src: /img/kitchen.jpg
  alt: The kitchen in morning light
---
```

`src` is the path below `public/`. `alt` describes the photo for people who cannot see it. It is required in the main language.

On the platform, the owner uploads the photo in the Studio and writes the description there.

#### Show it with GinkoImage

```vue
<GinkoImage v-if="post.data.photo" :image="post.data.photo" />
```

The component writes the size of the photo into the page, so the text does not jump while the photo loads. It crops the photo to the `aspect` of the field. The browser loads the photo only when it comes near the screen. The first image of a page loads at once.

#### Check the result

Open the page and look at the image in the browser's inspector. The `<img>` has `width`, `height`, `alt` and a `srcset` with smaller WebP files.
::

## One photo in several shapes

When the same photo appears in a card and in a page header, give the field named shapes:

```ts
photo: f.image('Photo', { aspect: { card: '3:2', header: '21:9' } }),
```

```vue
<GinkoImage :image="post.data.photo" frame="card" />
```

In the Studio, the owner sees the photo in each shape and sets the point that must stay in view.

## A photo in the text

Put the image next to the Markdown file and write its relative path:

```markdown [content/news/1.opening.md]
![The kitchen in morning light](./kitchen.jpg)
```

Ginko reads the size from the file and sets `width` and `height`. If the file is missing, the build stops and names the file and the path.

To show the image in a fixed shape, add `aspect` after it:

```markdown
![The kitchen in morning light](./kitchen.jpg){aspect="4:3"}
```

A path that starts with `/` looks in `public/`. An image from another server (`https://…`) stays as it is.

## What Ginko does with each image

- **Smaller copies.** A build writes WebP copies 480, 960 and 1600 pixels wide, each only when the image is wider. The page offers them in `srcset`. SVG and GIF images stay as they are.
- **Translations.** A translation changes only the description: its file gives `alt`, not `src`.
