This page lists what `@lupinum/ginko-preset-gastro` exports. The guide is [Build a restaurant site]($docs.restaurant-site). Everything not on this page is internal and can change in any release.

```bash
npm install @lupinum/ginko @lupinum/ginko-preset-gastro
```

## Bricks

| Function | Kind | Content | Quick tasks of the owner |
| --- | --- | --- | --- |
| `hours()` | single | The usual week, closures, what happens on public holidays | Closed today |
| `hourPlans()` | collection | Other weekly hours for a date range, also every year | |
| `notices()` | collection | Short lines, each until a date | Fully booked today |
| `lunch()` | single | The lunch menu of the week | The lunch week |
| `lunchPlans()` | collection | Lunch weeks planned ahead | |
| `menu()` | collection | One dish per entry: category, name, description, price, allergens, vegetarian or vegan | Dish sold out today, change a price |
| `events()` | collection | Events with a date, a start time, a price and a page (its address is a line in `entries`) | Event fully booked |
| `gallery()` | single | Photos | |

### Options

| Option | On | Default | Meaning |
| --- | --- | --- | --- |
| `plans` | `hours` | none | The key of the `hourPlans()` brick. The line for today in the Studio then follows the plan of that day. |
| `allergens` | `menu`, `lunch`, `lunchPlans` | `'EU'` | `'EU'`, `'none'` (no allergen field), or your own list `[{ value, label }]`. |
| `weekOf` | `lunch` | none | The Monday of the first lunch week, `YYYY-MM-DD`. Required for a platform `lunch()`. |
| `lunchBrick` | `lunchPlans` | `'lunch'` | The key of the `lunch()` brick that planned weeks belong to. |

Each function returns a brick of the site file's form: change one with `extend` of `@lupinum/ginko`, for example `extend(menu(), { preview: 'menu' })`. Where a brick lives is `studio.bricks` in the site file; without the platform, a brick named there makes the dev server answer 503.

### Stored fields

The field names are the data of your site. They do not change.

- **A day** has `day` (`mo` to `su`), `closed`, and at most two opening periods: `from1` to `to1` and `from2` to `to2`. This is the same in the week, in hour plans and in exceptions.
- **Hours** have `week`, `exceptions` (each with `when`, `reason`, `closed` or its own times), `closedOn` and `closedNote` (the task "Closed today"), `holidays` (`sunday`, `closed` or `normal`) and `holidayNoticeDays`.
- **A dish** has `onMenu` (off after its season; the dish stays saved), and `soldOutOn` (sold out on that day only). The task "Change a price" asks "Starts on": a price for a later day waits as a dated change, and the page reads it in `upcoming` (`timeline: { public: ['price'] }`).
- **An event** has `soldOut` (fully booked): show it in place of the booking link.

`onMenu`, `soldOutOn` and `soldOut` are optional. A missing field means on the menu, not sold out, and bookable.

## Opening-hours rules

Every rule takes a context `{ hours, plans?, calendar? }` and a date `YYYY-MM-DD`. `hours` is the data of the `hours` brick, `plans` the entries of `hourPlans`.

| Function | Returns |
| --- | --- |
| `hoursOn(ctx, date)` | What applies on a date: `{ closed, times, reason?, source, field?, holiday? }`. Every other rule builds on this one. |
| `todayState(ctx, today)` | `{ kind: 'open', times }`, `{ kind: 'closed', reason }`, `{ kind: 'holiday', holiday }` or `{ kind: 'restDay' }`. |
| `noticesOn(notices, ctx, today)` | The notices to show today. On a day the owner closed, a notice that ends today is left out, because the closure wins. |
| `upcomingClosures(ctx, today, days)` | The closures of the next `days` days: exceptions of the owner, a day set in `closedOn`, and public holidays that close the house. |
| `closedOnClosure(hours, today)` | Only the day set in `closedOn`, when it is after `today`. |
| `upcomingHolidayClosures(ctx, today, days)` | Only the public holidays that close the house. |
| `upcomingPlans(plans, today, days)` | Hour plans that start in the next `days` days, with `starts` and, if the plan ends, `ends`. |
| `weekFor(ctx, date)` | The seven days that apply on a date: `{ week, plan? }`. |
| `weekdayOf(date)` | The key of the weekday, `'mo'` to `'su'`. |
| `timesOf(day, and)` | The opening times of one day as text: `11:30–14:00 and 17:30–22:00`. Empty when closed. |
| `spansOf(times)`, `spansText(spans, and)` | The periods of a day, and the periods joined as text. |

Example results of `todayState` for a house that is closed on Mondays:

| Date | Result |
| --- | --- |
| Tuesday | `{ kind: 'open', times: [{ from: '11:30', to: '14:00' }, { from: '17:30', to: '22:00' }] }` |
| Monday | `{ kind: 'restDay' }` |
| 26 October, with `holidays: 'closed'` | `{ kind: 'holiday', holiday: { de: 'Nationalfeiertag', en: 'Austrian National Day' } }` |
| A day in the summer holiday | `{ kind: 'closed', reason: 'Summer holiday' }` |

## Public holidays

The rules count Austrian public holidays unless you say otherwise. Pass `calendar` in the context of every rule you call:

| `calendar` | Counts |
| --- | --- |
| `'AT'` | Austria. The default. |
| `'DE'` | Germany, the nationwide days only. |
| `'SG'` | Singapore. Its lunar, Islamic and Hindu holidays are a table for 2026 and 2027. |
| `'none'` | No public holidays. |
| a function `(year) => Holiday[]` | Your own days. |

Keep the value in one constant of your site, so all calls agree:

```ts
import type { HolidaysOption } from '@lupinum/ginko-preset-gastro'

export const calendar = 'DE' satisfies HolidaysOption

todayState({ hours: data, calendar }, today)
```

Set `country` in `ginko.config.ts` to the same country. The Studio and the reminder mail then count the same holidays as the site. You can pass `country` in the context in place of `calendar`; the value is `useRuntimeConfig().public.ginko.country`.

The stored field `holidays` is a different thing: the choice of the owner for those days (as on Sunday, closed, or normal).

## Menu and lunch

| Name | What it is |
| --- | --- |
| `menuCategories` | The categories of `menu()` in menu order: `starters`, `soups`, `mains`, `desserts`, `drinks`. Group the dishes by these. |
| `allergensEU` | The 14 EU allergens as options `{ value, label }`, with the letter codes A to R. |
| `allergenNames` | `{ de, en }`: the name of each allergen for visitors. `allergenNames.en.A` is `Gluten`. |
| `weekdayNames` | `{ de, en }`: the name of each weekday. |
| `dishOn(dish, date)` | `{ shown, soldOut }`. `shown` is false for a dish taken off the menu. `soldOut` is true on its `soldOutOn` day. |
| `lunchWeekOn(main, planned, today, week)` | The lunch week to show today: a planned week, the main `lunch` data, or nothing. |

Leave a dish with `shown: false` out of the menu, the allergen list and the JSON-LD.

## JSON-LD

| Function | Returns |
| --- | --- |
| `restaurantJsonLd(input)` | schema.org `Restaurant` data. It has no default currency or country: pass `currency` and `address.country`. |
| `eventJsonLd(input)` | schema.org `Event` data for one event. It needs `timeZone`, the time zone of the site from `useGinkoSite()`. With `soldOut: true` the offer says `SoldOut` and has no booking link. |

Both take prices as the site reads a money field: in minor units, so `1250` is `12.50`. In a content file you write `12.5`.

## Outside Austria

The defaults are Austrian. Change them per site:

- **Holidays.** Pass `calendar` or `country`, see above.
- **Allergens.** `allergens: 'none'`, or your own list.
- **Labels and prefilled texts.** They come in German and English. With another main language, the site starts without the prefilled texts. A platform `lunch()` cannot start without them: keep `lunch` in files there (leave it out of `studio.bricks`). A code with a region, such as `de-CH`, does not count as `de`.

```ts [ginko.config.ts]
export default defineSite({
  studio: { id: 'kopi-corner', bricks: 'all' },
  name: 'Kopi Corner',
  url: 'https://example.com',
  timeZone: 'Asia/Singapore',
  week: { firstDay: 'mo', workdays: ['mo', 'tu', 'we', 'th', 'fr'] },
  country: 'SG',
  locales: ['en'],
  currency: 'SGD',
  pages: { home: '/' },
  bricks: {
    hours: hours(),
    notices: notices(),
    lunch: lunch({ weekOf: '2026-10-05', allergens: 'none' }),
    menu: menu({ allergens: 'none' }),
  },
})
```
