---
title: Handle missing content
description: Show a sensible page when a value, an entry or the whole content is missing. Optional fields, empty lists, missing files, 404 and 503.

---

This guide makes pages hold up when content is missing. Each case has its own answer: a value that is not set, a list without entries, an entry that does not exist, and content that cannot be loaded at all.

## A value is not set

An optional field can be `undefined`. Show its part of the page only when it has a value:

```vue
<GinkoImage v-if="post.data.photo" :image="post.data.photo" />
<p v-if="post.data.until">Until {{ format.date(post.data.until) }}</p>
```

On the platform, a required field of a single starts with its `default`, so it has a value. In files, see "A file is missing" below.

## A list has no entries

A collection without visible entries returns an empty list. Say so on the page:

```vue
<ul v-if="news.items.length">
  <li v-for="item in news.items" :key="item.id">{{ item.data.title }}</li>
</ul>
<p v-else>No news at the moment.</p>
```

Do not read `news.items[0]` without a check. With an empty list it is `undefined`, and the page fails with an error 500.

## A file is missing

A single in files reads one file, such as `content/start.md`. When the file does not exist, every field of the single is `undefined`, also the required ones, and the page shows empty places. `ginko check` does not report this case.

Create the file of every file single, also when it holds only the required fields.

## An entry does not exist

`useGinkoEntry` answers with a 404 when no visible entry has the slug of the address. That covers a wrong address, an entry after its last day, a draft in a build, and an entry without a translation in this language.

Nuxt shows `app/error.vue` for it. A minimal error page:

```vue [app/error.vue]
<script setup lang="ts">
const props = defineProps<{ error: { statusCode: number } }>()
</script>

<template>
  <main>
    <h1>{{ props.error.statusCode === 404 ? 'Page not found' : 'Something went wrong' }}</h1>
    <a href="/">Go to the start page</a>
  </main>
</template>
```

::callout{type="warning" title="No content in the error page"}
Do not call `useGinko` or another function that reads content in `error.vue`. When the content cannot be loaded, the error page would fail too.
::

## The content cannot be loaded

A site with bricks on the platform loads its content from there. When that fails, the site answers with 503 and never with 404. On Vercel, a 503 keeps the last good page in the cache; a 404 would replace it.

A site whose bricks all come from files cannot have this case. Its content is part of the build.
