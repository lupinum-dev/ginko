This guide puts the content of a brick into files in the repository. At the end, the site shows the content of your files, and `ginko check` finds mistakes in them before a build does.

## Before you start

The package `@lupinum/ginko-content` is in the dependencies of the site. Every template has it. Without it, the build stops and says what to install.

## Steps

::steps
#### Set the source of the brick

```ts [ginko.config.ts]
news: collection({
  label: 'News',
  source: 'files',
  max: 100,
  order: { field: 'date', dir: 'desc' },
  fields: {
    title: f.text('Title'),
    date: f.date('Date'),
    body: f.markdown('Text'),
  },
}),
```

A brick has one source. With `source: 'files'`, the platform never sees it.

#### Create the file in the right place

All files live in `content/`, next to `nuxt.config.ts`.

| Brick | Where its content goes |
| --- | --- |
| a single `contact` | one file: `content/contact.md` |
| a collection `news` | one file per entry in a folder: `content/news/1.opening.md` |

The number at the start of a file name sets the order for `order: 'manual'`. It is not part of the address.

#### Write the fields and the text

```markdown [content/news/1.opening.md]
---
title: We are open
date: 2026-11-01
---

The new site is live.
```

The block between the two `---` is the frontmatter. Each line fills one field. The text below it fills the Markdown field of the brick. A brick has at most one Markdown field.

[Content from files]($docs.content-from-files#frontmatter) shows how to write each field type, for example a price, an image or a list.

#### Add a translation

A translation is a file with the same name and the language code before the extension:

```markdown [content/news/1.opening.de.md]
---
title: Wir haben geöffnet
---

Die neue Seite ist online.
```

It holds only the fields that have a value per language. The date stays in the main file. A translation file with such a field is an error:

```text
content/news/1.opening.de.md (date): “date” is set in the main-language file only.
```

#### Check the files

```bash
npx ginko check
```

The command reads every file and names each problem with its file and field. A build stops on the same problems.
::

## Content without running text

A brick without a Markdown field can also read YAML, JSON and CSV files. Use them for structured content such as a price list.

**YAML or JSON.** One file is one entry. The file holds what the frontmatter holds in Markdown:

```yaml [content/prices/1.coffee.yml]
title: Coffee
price: 3.5
vegan: true
```

**CSV.** One file holds many entries, one per row. The first row names the columns:

```text [content/prices/list.csv]
slug,locale,title,price,vegan
coffee,,Coffee,3.5,true
tea,,Tea,2.8,true
coffee,de,Kaffee,,
```

- `slug` is required. It is the name of the entry.
- `locale` is optional. An empty cell means the main language. The last row is the German translation of `coffee`.
- An amount is written in units of the currency. The site reads `3.5` as 350 cents.
- A cell cannot hold a list, an image or a date range. Use a YAML or Markdown file for those.
