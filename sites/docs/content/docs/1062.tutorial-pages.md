In [chapter 1]($docs.tutorial) the site got a home page. This chapter adds an About and a Contact page. Each one is a Markdown file with its own address, and a menu lists them. At the end, `http://localhost:3000/about` shows the About page.

## Steps

::steps
#### Add a collection

The home page is a single: one entry. Pages are a **collection**: many entries of the same kind. Add the brick `pages` to `ginko.config.ts`:

```ts [ginko.config.ts]
import { collection, defineSite, f, single } from '@lupinum/ginko'

export default defineSite({
  site: 'my-site',
  name: 'Studio Nord',
  url: 'https://example.com',
  timeZone: 'Europe/Vienna',
  locales: ['en'],
  currency: 'EUR',
  pages: { home: '/' },
  bricks: {
    home: single({
      label: 'Home page',
      source: 'files',
      fields: {
        title: f.text('Title'),
        body: f.markdown('Text', { profile: 'basic' }),
      },
    }),
    pages: collection({
      label: 'Pages',
      source: 'files',
      max: 50,                     // at most 50 entries
      order: 'manual',             // the order of the file numbers
      route: { en: '/[slug]' },    // each entry gets its own address
      fields: {
        title: f.text('Title'),
        slug: f.slug('Address', { from: 'title' }),
        summary: f.longtext('Summary', { optional: true }),
        body: f.markdown('Text', { profile: 'basic' }),
      },
    }),
  },
})
```

`route` gives each entry a page. It has one address per language, and `[slug]` stands for the value of the field `slug`. The slug field must be called `slug`. A field with `optional: true` may stay empty.

The dev server restarts by itself when `ginko.config.ts` changes.

#### Write two pages

A collection has a folder in `content/` with one file per entry:

```markdown [content/pages/1.about.md]
---
title: About
summary: Two designers, one workshop.
---

Studio Nord is Anna and Jonas. We work from a former print shop in the 7th district.
```

```markdown [content/pages/2.contact.md]
---
title: Contact
summary: Write to us.
---

Email us at hello@example.com. We answer within two days.
```

The number sets the order. The rest of the file name is the slug, so the pages answer at `/about` and `/contact`. To give a page another address, write `slug: our-studio` into its file.

#### Show one page

```vue [app/pages/[slug].vue]
<script setup lang="ts">
const route = useRoute()
const page = useGinkoEntry('pages', () => route.params.slug)
</script>

<template>
  <main>
    <h1>{{ page.data.title }}</h1>
    <p v-if="page.data.summary">{{ page.data.summary }}</p>
    <GinkoMarkdown :value="page.data.body" />
  </main>
</template>
```

`useGinkoEntry` finds the entry whose address matches the slug in the browser's address. You pass the slug as a function, so the page follows when Nuxt reuses it for another entry. For a slug that matches no entry, the site answers with a real 404.

#### Add a menu

`useGinko('pages')` returns the entries of the collection in `items`. Each entry carries its address in `url`:

```vue [app/app.vue]
<script setup lang="ts">
const pages = useGinko('pages')
</script>

<template>
  <header>
    <nav>
      <NuxtLink to="/">Home</NuxtLink>
      <NuxtLink v-for="page in pages.items" :key="page.id" :to="page.url">{{ page.data.title }}</NuxtLink>
    </nav>
  </header>
  <NuxtPage />
</template>

<style>
body { font-family: system-ui, sans-serif; line-height: 1.5; max-width: 40rem; margin: 2rem auto; padding: 0 1rem; }
nav { display: flex; gap: 1rem; }
</style>
```

Use `url` for links to entries, not an address you build yourself. It stays right when the slug or the route changes.
::

## Check that it works

- Open `http://localhost:3000`. The menu shows Home, About and Contact.
- Click About. The page shows "About", the summary and the text.
- Open `http://localhost:3000/nothing`. The site answers with Nuxt's error page: "404" and "Not found".
- Add `content/pages/3.work.md` with a `title` and a text. The menu shows it at once, and `/work` has the page.
