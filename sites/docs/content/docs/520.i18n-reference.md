This page lists what `@lupinum/ginko-i18n` offers. The guides start at [i18n quick start]($docs.i18n-quick-start).

## Options

The options go under `i18n` in `nuxt.config.ts`.

| Option | Default | Meaning |
| --- | --- | --- |
| `locales` | required | Language tags such as `'de-AT'`, or `{ language, code?, name? }`. The code in the address is the first part of the tag (`de-AT` gives `de`). The name is the native name of the language. |
| `defaultLocale` | the first locale | The code of the language without a prefix, and the language a missing message falls back to: `'de'`, not `'de-AT'`. |
| `strategy` | `'prefix_except_default'` | Or `'prefix'`: every language has a prefix, and `/` redirects. |
| `seo` | `true` | The head tags. `false` turns them off. |
| `baseUrl` | `runtimeConfig.public.siteUrl` | The address of the site, for complete canonical and `hreflang` links. Set it in production. |
| `params` | `{}` | Parameters every message can use, for example `{ tone: 'sie' }` for `{tone, select, …}`. |
| `exclude` | `[]` | More paths without a prefix. `/api/**` and the internal paths of Nuxt are always excluded. |
| `userLocale` | `[]` | Paths whose language comes from the user, see [Apps behind a login]($docs.i18n-apps-behind-a-login). |
| `timeZone` | `'UTC'` | The time zone of the site, such as `'Europe/Vienna'`, for times in `format.date` and in messages. |

A pattern in `exclude` and `userLocale` is an exact path (`'/studio'`) or a prefix that ends in `/**` (`'/app/**'` is `/app` and everything below it). No other `*` is allowed.

Any other option stops the setup with a message.

## useI18n

`useI18n(namespace?)` needs no import in components, pages and plugins.

| Return | Type | Meaning |
| --- | --- | --- |
| `t(key, params?, options?)` | text | The message in the current language. Keys and parameters are typed from the files of the default language. |
| `parts(key, params?, options?)` | list | The message as text parts and tag parts, to render `<tag>…</tag>` yourself. |
| `has(key)` | boolean | Whether the key exists in the current or the default language. |
| `locale` | computed text | The code of the current language: `'en'`. |
| `language` | computed text | The tag of the current language: `'en-GB'`. |
| `locales` | list | Every language: `{ code, language, name, dir }`. |
| `defaultLocale` | text | The code of the default language. |
| `localePath(path, code?)` | text | The same page in `code`, or in the current language. It takes a path written in any language. It takes no route objects. |
| `alternates` | computed list | The current page in every language: the language plus `path`, `current` and `translated`. Where the page has no translation, `translated` is false and `path` is the start page of that language. |
| `switchLocale(code)` | promise | Goes to the current page in `code`, or changes the language of the user inside a zone. An unknown code throws. |
| `format` | object | Formatting in the current language, see below. |

With a namespace, `useI18n('billing')` takes keys relative to it: `t('invoice')` for `billing.invoice`.

A missing key renders the key itself and warns in dev. A key that is missing in one language shows the text of the default language.

`localePath` translates the routes of the app. It does not know the addresses of content entries: link to those with the paths your content gives you.

### format

`format` formats in the current language and the `timeZone` of the site. The server and the browser produce the same text. The examples are for `de-AT`:

| Method | Example |
| --- | --- |
| `format.date(value, style?)` | `format.date('2026-10-08')` is `8. Oktober 2026`. `style` is `'short'`, `'medium'`, `'long'` (default), `'full'` or `Intl.DateTimeFormatOptions`. A calendar date never shifts a day. |
| `format.range(from, to, style?)` | `format.range('2026-06-20', '2026-06-21')` is `20.–21. Juni 2026`. |
| `format.relative(value, now?)` | `vor 5 Minuten`, `gestern`. Call it after mount or pass `now`, because the text depends on the current time. |
| `format.number(value, options?)` | `format.number(1234.5)` is `1 234,5`. |
| `format.currency(value, currency)` | `format.currency(12.5, 'EUR')` is `€ 12,50`. The amount is in major units. For a money field of Ginko, use `formatMoney`. |
| `format.list(items, type?)` | `format.list(['Äpfel', 'Birnen', 'Pflaumen'])` is `Äpfel, Birnen und Pflaumen`. `type` is `'conjunction'` or `'disjunction'`. |

## I18nT

`<I18nT>` renders a message that has tags. Each tag calls the slot of the same name with `{ text }`, the content of the tag as plain text. A tag without a slot renders its content.

```vue
<I18nT k="legal.consent" :params="{ site: 'Linden Inn' }">
  <template #link="{ text }"><NuxtLink to="/privacy">{{ text }}</NuxtLink></template>
</I18nT>
```

| Prop | Meaning |
| --- | --- |
| `k` | The full key. A key of a library includes its namespace. A missing key fails the type check. |
| `params` | The parameters of the message. They are not checked against the key; `t()` checks them. |

A parameter value stays text: `<b>` inside a value never renders as HTML.

## useLocaleSuggestion

The language never changes on its own. `useLocaleSuggestion()` returns the current page in the language of the browser, when that is another language and the page exists there. It is `null` on the server and until the page has mounted.

```vue
<script setup lang="ts">
const suggestion = useLocaleSuggestion()
</script>

<template>
  <p v-if="suggestion">
    <NuxtLink :to="suggestion.path">View in {{ suggestion.name }}</NuxtLink>
  </p>
</template>
```

## getI18n

`getI18n(event, namespace?)` needs no import in server routes. It returns `{ locale, language, t, parts, has, format }` for the language of the request, see [Server routes and server components]($docs.i18n-server-routes).

## Page options

Set them with `definePageMeta` in a page:

| Option | Meaning |
| --- | --- |
| `i18n: { paths: { de: '/ueber-uns' } }` | The address of the page in a language. |
| `i18n: { locales: ['de'] }` | The page exists only in these languages. |
| `i18n: false` | One page without languages, for example `/studio`. |
| `i18nAlternates: async (to, { locale, localePath }) => …` | For a page with a slug: returns the address of the page in each language. |

### Pages with a slug

A page whose content comes from a CMS says before the render which address it has in each language. Then the language switch, the `hreflang` links and the HTML from the server agree:

```ts [app/pages/blog/[slug].vue]
definePageMeta({
  i18nAlternates: async (to, { locale, localePath }) => {
    const post = await $fetch<{ slugs: Record<string, string> }>('/api/post', { query: { slug: to.params.slug, locale } })
    return Object.fromEntries(Object.entries(post.slugs).map(([code, slug]) => [code, localePath(`/blog/${slug}`, code)]))
  },
})
```

Return `undefined` to use the routes of the page itself. A language that is missing from the result counts as not translated.

A Nuxt module that owns many such routes registers one resolver in its plugin with `addAlternatesResolver(resolver)`. The resolver gets the route and `{ locale, localePath }`, and returns a path per language, or `undefined` when the route is not its own. The `i18nAlternates` of a page wins over it.

## Head tags and addresses

- Every page gets `<html lang dir>`, a canonical link, `hreflang` links with `x-default` for the default language, and `og:locale`. A language without a translation of the page gets no `hreflang`.
- Without `baseUrl` and `runtimeConfig.public.siteUrl`, the links are relative and the build warns.
- Error pages get `lang`, `dir` and `robots: noindex`, and no canonical link.
- Every page has one address. The server answers other spellings with a 301: repeated slashes (`//blog`), a slash at the end (`/blog/`), and a language code in another case (`/EN/about`).
- With `@nuxtjs/sitemap`, the module gives it the translated addresses of the static pages. Pages with a slug are not in that list: add them through your own sitemap source.
- With `strategy: 'prefix'`, `/` has no content. It redirects by cookie, then by browser language.

## Message syntax

Messages are ICU MessageFormat:

| Syntax | Example |
| --- | --- |
| Argument | `Hello {name}` |
| Plural (`#` is the number) | `{count, plural, =0 {No items} one {# item} other {# items}}` |
| Ordinal | `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` |
| Select | `{role, select, admin {Admin} other {Guest}}` |
| Number | `{total, number}`, `{share, number, percent}`, `{price, number, ::currency/EUR}` |
| Date and time | `{day, date, long}`, `{start, time, short}` |
| Tag | `I accept the <link>privacy policy</link>`, rendered with `<I18nT>` |
| Literal text | `'{'` and `'<'`: an apostrophe quotes |

Every `plural` and `select` needs an `other` case. A key must not contain a dot and must not be empty.

## CLI

The tool `ginko-i18n` finds and fixes missing, old and broken translations. It reads the message files and the manifest that Nuxt writes into `.nuxt`. If the manifest is missing, it runs `nuxt prepare` once.

```bash
npx ginko-i18n check
npx ginko-i18n todo --locale de
npx ginko-i18n apply translations.json
```

| Command | What it does |
| --- | --- |
| `check` | Reports missing and extra translations, wrong ICU, different parameters, missing plural forms, old translations, keys the code uses that no file has, and unused keys. |
| `check --locale <code>` | Lists the findings of one language. The exit code still counts all findings. |
| `check --html <folder>` | Checks the built HTML: canonical links, `hreflang` links in both directions, `x-default` and `lang`. |
| `todo --locale <code>` | Lists the texts to translate, each with its source text, its parameters and where the code uses it. `--only missing` or `--only stale` narrows the list. |
| `apply <file>` | Writes translations from a JSON file into the message files. `apply -` reads from stdin. |

Options for all commands: `--cwd <app>`, `--build-dir <dir>`, `--json`, `--help`, `--version`. To check a plain folder of `<code>.json` files without a Nuxt app, add `--dir <folder> --default-locale <code>`.

The input of `apply`:

```json
{
  "locale": "de",
  "items": [{ "key": "greeting", "text": "Hallo {name}" }]
}
```

`locale` must not be the default language: its files are the source. Each item must be valid ICU and use the parameters of the source. Valid items are saved even if others are refused. `i18n/i18n.lock.json` records a hash of each translated source text. When the source changes later, `check` reports the translation as `stale`.

`i18n/glossary.json` is a file of your own, in any shape, for brand names and tone. `todo --json` hands it to the translator.

Findings of `check`:

| Code | Severity | Meaning |
| --- | --- | --- |
| `missing` | error | A language has no translation for a key of the default language. |
| `stale` | warning | The source text changed after the translation was applied. |
| `extra` | warning | A language has a key that the default language does not have. |
| `plural-missing` | warning | A plural message lacks a form that the language needs. |
| `params-mismatch` | error | A translation uses other parameters than the source. |
| `invalid-icu` | error | A message is not valid ICU. |
| `unknown-key` | error | The code uses a key that no file has. |
| `unused` | warning | The tool found no use of a key in the code. |
| `seo-canonical`, `seo-hreflang-self`, `seo-hreflang-reciprocal`, `seo-x-default`, `seo-lang` | error | Problems that `check --html` finds. |

Exit codes: `0` for no errors, `1` for errors or refused items, `2` for a wrong command line. Warnings alone give `0`. With `--json`, the output is one JSON object: `{ ok, summary, findings }` for `check`, `{ ok, locale, items, … }` for `todo`, `{ ok, written, rejected, warnings }` for `apply`.

## Without Nuxt

The translator also runs without Nuxt: in Convex functions, emails, scripts or another framework. Compile the messages with `@lupinum/ginko-i18n/compile`, then translate with `@lupinum/ginko-i18n/core`, which has no parser:

```ts
import { compileCatalogs } from '@lupinum/ginko-i18n/compile'
import { defineCatalog, type KeysOf } from '@lupinum/ginko-i18n/core'
import de from './i18n/de.json'
import en from './i18n/en.json'

const catalog = defineCatalog<KeysOf<typeof en>>(compileCatalogs({ en, de }), { defaultLocale: 'en' })

catalog.t('de-AT', 'mail.invite.subject', { site: 'Linden Inn' }) // a full tag finds `de`
catalog.t(undefined, 'mail.invite.subject', { site: 'Linden Inn' }) // the default language
```

`compileCatalogs` runs the parser. Call it in a build step or on a server, not in the browser. Store your source files, not the compiled result: its form can change in any release.

| Export of `/core` | Meaning |
| --- | --- |
| `defineCatalog(trees, { defaultLocale, params? })` | A catalog with `t(locale, key, params?)`, `translator(locale)`, `locales`, `defaultLocale` and `isLocale(value)`. |
| `createTranslator({ messages, fallback?, language, timeZone?, … })` | A translator (`t`, `parts`, `has`) for one language. |
| `createFormatters(language, { timeZone? })` | The `format` object of `useI18n()`. |
| `resolveConfig({ locales, defaultLocale?, strategy?, exclude?, userLocale? })` | The language config for the functions below. |
| `localizePath(path, code, config)` | Adds the prefix: `/about` becomes `/de/about`. |
| `stripLocale(path, config)` | Removes it. |
| `localeFromPath(path, config)` | The code a path belongs to. |
| `negotiateLocale(header, config)` | The best code for an `Accept-Language` header. |
| `cleanPath(path, config)` | The one form of a path, or `undefined` when it is already right. |
| `alternatesOf(paths, config)` | The `hreflang` links of a page from its path per code. |
| `ogLocale(language)` | `de-AT` becomes `de_AT`. |
| `partsToString(parts)` | The plain text of a `parts()` result. |

| Export of `/compile` | Meaning |
| --- | --- |
| `compileCatalogs({ en, de })` | Compiles the source files of each language for `defineCatalog`. |
| `compileTree(raw)` | Compiles one language. |
| `MessageError` | Thrown for wrong ICU. `key` and `source` name the message. |

## Content Security Policy

The first page has the messages of its language in an inline `<script>`, so the browser needs no request for them. With `strategy: 'prefix'`, a static `/` also has a small inline redirect script. A strict policy must allow both with a nonce or a hash. If the inline script is blocked, the browser loads the messages as a script file.

## Errors

Every error starts with `[ginko-i18n]` and ends with `Fix: …`.

| Error | Cause and fix |
| --- | --- |
| `Unknown option(s) i18n.…` | An option of `@nuxtjs/i18n`. Remove it, see [Coming from @nuxtjs/i18n]($docs.i18n-from-nuxtjs-i18n). |
| `@nuxtjs/i18n is also installed.` | Remove one of the two modules. |
| `Two locales use the URL code "…".` | `de-AT` and `de-CH` both become `de`. Give one of them a `code`. |
| `Message "…" is not valid ICU` | The error names the message and its key. Every `plural` and `select` needs `other`. |
| The manifest is missing (CLI) | Add the module to `nuxt.config.ts` and run `nuxt prepare`. |
| A link by route name finds nothing | The routes are named `about__en` and `about__de`. Link with `localePath('/about')`. |

## Types

From `@lupinum/ginko-i18n`: `ModuleOptions`, `PageI18n`, `MessageSource`, `I18n` (what `useI18n` returns), `ServerI18n` (what `getI18n` returns), `Alternate`, `AlternatesResolver` and `TypedTranslator`.

From `/core`: `Translator`, `TranslateOptions`, `Params`, `Part`, `MessageTree`, `Catalog`, `Formatters`, `FormatterOptions`, `DateStyle`, `LocaleInfo`, `LocaleInput`, `LocaleConfig`, `Strategy`.
