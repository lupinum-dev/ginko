Diese Anleitung verlegt einen Baustein von Dateien auf die Plattform. Am Ende ändert die Inhaberin diese Inhalte im Studio, und die Seite zeigt eine Änderung innerhalb einer Minute, ohne Deploy.

## Bevor du beginnst

Lupinum betreibt die Plattform, der Zugang ist auf Einladung. Du brauchst drei Dinge:

- **Deine Seite auf der Plattform.** Frag Lupinum danach. Du bekommst eine Einladung als Inhaber der Seite.
- **Die Adresse der Plattform.** Du bekommst sie mit der Einladung.
- **Einen Schlüssel.** Öffne im Studio „Team“, dann „Publishing keys“, dann „New key“. Gib ihm einen Namen, wähle „Publish and back up“ und lege ihn an. Das Studio zeigt den Schlüssel einmal: „You see this key only now.“ Bewahre ihn als Geheimnis auf.

## Schritte

::steps
#### Der Seite sagen, wo die Plattform ist

```ts [ginko.config.ts]
export default defineSite({
  site: 'linde',
  platform: 'https://platform.example.com',
  // …
})
```

`site` ist die Id deiner Seite auf der Plattform. Die Seiten laden die Inhalte von Plattform-Bausteinen jetzt von dieser Adresse.

#### Die Quelle des Bausteins entfernen

```ts [ginko.config.ts]
promo: single({
  label: 'Aktion',
  // hier stand source: 'files'
  fields: {
    headline: f.text('Überschrift', { default: 'Frisch in dieser Woche' }),
    until: f.date('Zeigen bis', { optional: true }),
  },
}),
```

Ein Einzelstück auf der Plattform existiert vom ersten Moment an. Jedes Pflichtfeld braucht deshalb einen Startwert. Gib ihm ein `default` oder mach es optional. `f.markdown`, `f.image` und `f.file` haben kein `default`: Mach sie optional.

#### Die Änderung gegen die Plattform prüfen

Setz die Adresse und den Schlüssel in deiner Shell und lass die Prüfung laufen:

```bash
export GINKO_PLATFORM=https://platform.example.com
export GINKO_KEY=ginko_linde_…
npx ginko check
```

Die Prüfung vergleicht deine Konfiguration mit der Seite auf der Plattform und nennt, was sich ändern würde:

```text
Site “linde”: schema version 1, content 1.
Allowed changes:
  + New brick “promo”.
OK: A release with this schema would be accepted.
```

Ein Pflichtfeld ohne Startwert wird abgelehnt, mit der Lösung:

```text
✗ promo.headline: New single: required field “headline” needs a default.
  → Set a `default` or make the field optional.
```

#### Die Änderung freigeben

Committe und pushe die Konfiguration. Lass dann das Release laufen, in CI oder von Hand. [Eine Schema-Änderung freigeben]($docs.release-a-schema-change) zeigt beides.

Nach dem Release führt das Studio den Baustein unter „Content“.

#### Die Inhalte herüberholen

Die Plattform liest deine Dateien nicht. Der Baustein beginnt mit seinen Defaults, und eine Sammlung beginnt leer.

- Wenige Texte tippst du ins Studio.
- Bei vielen Einträgen bittest du Lupinum, sie zu importieren.

Lösch danach die Dateien des Bausteins aus `content/`. Die Seite liest sie nicht mehr.

#### Das Ergebnis prüfen

1. Ändere den Text im Studio und wähle „Publish“.
2. Lade die Seite neu. Sie zeigt den neuen Text innerhalb einer Minute.
::

## Was gleich bleibt

Die Seiten ändern sich nicht. `useGinko('promo')` liest den Baustein von der Plattform so, wie es ihn aus Dateien gelesen hat.
