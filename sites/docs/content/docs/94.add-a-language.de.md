Diese Anleitung fügt Französisch zu einer Seite hinzu, die Englisch und Deutsch hat. Am Ende hat jede Seite eine französische Adresse, der Sprachwechsel zeigt Französisch, und Suchmaschinen erfahren von den französischen Seiten.

Die Schritte nutzen das Template `starter` (`npm create ginko@latest meine-seite -- --template starter`). Sie gelten für jedes [Template]($docs.templates). Für eine Seite mit eigenem Aufbau lies den Hinweis am Ende von Schritt 1.

## Bevor du beginnst

- Die Seite läuft mit `npm run dev`.
- Ihre Inhalte kommen aus Dateien in `content/`. Für Inhalte auf der Plattform gelten die ersten zwei Schritte und Schritt 5 genauso, und die Inhaber übersetzen die Inhalte im Studio.

## Schritte

:::steps
#### Die Sprache in die Liste eintragen

Öffne `app/routes.ts` und ergänze das Sprachkürzel. Das erste Kürzel ist die Hauptsprache. Lass es vorne.

```ts [app/routes.ts]
export const locales = ['en', 'de', 'fr'] as const
```

Das Kürzel ist auch das Sprach-Tag der Seiten, nimm also ein Tag wie `fr` oder `it`.

Jede Adresse der neuen Sprache beginnt mit `/fr`. Die Templates bilden diese Adressen aus der Liste, du änderst also keine Adresse von Hand.

::callout{type="note" title="Eine Seite ohne die routes.ts der Templates"}
Die Liste ist `locales` in `ginko.config.ts`. Trag das Kürzel dort ein. Ergänze dann bei jedem Eintrag von `pages` und bei jeder `route` einer Sammlung einen Pfad für die neue Sprache, zum Beispiel `route: { en: '/news/[slug]', de: '/de/neuigkeiten/[slug]', fr: '/fr/actualites/[slug]' }`.
::

#### Den Dev-Server neu starten

Beende `npm run dev` und starte es neu. Der Dev-Server startet von selbst neu, wenn sich `ginko.config.ts` ändert, aber nicht, wenn sich eine Datei ändert, die die Konfiguration importiert. `app/routes.ts` ist so eine Datei.

Öffne `http://localhost:3000/fr`. Die Seite hat jetzt eine französische Fassung, mit diesen Lücken:

- Die Startseite zeigt den englischen Text. Ein Einzelstück ohne Übersetzung zeigt den Text der Hauptsprache.
- Die Seiten einer Sammlung fehlen: `/fr/about` antwortet mit 404. Ein Eintrag mit eigener Adresse erscheint in einer Sprache erst, wenn er dort eine Übersetzung hat.
- Buttons und Beschriftungen sind englisch. Das Terminal sagt, wie viele fehlen: `[ginko-i18n] fr: 29 message(s) missing, showing en text instead`.

Die nächsten drei Schritte schließen diese Lücken.

#### Die Einzelstücke übersetzen

Eine Übersetzung ist eine Datei neben dem Original, mit dem Sprachkürzel vor der Endung. Leg für die Startseite `content/home.fr.md` an:

```markdown [content/home.fr.md]
---
title: Des traductions qui se lisent comme l’original
lead: Je traduis entre l’allemand et l’anglais pour des musées et des éditeurs.
---

## Ce que je traduis

- Textes d’exposition et de catalogue
```

Eine Übersetzung enthält nur die Felder, die einen Wert pro Sprache haben: Texte, Markdown und die Beschreibung eines Bildes. Lass alles andere weg, zum Beispiel ein Datum, einen Preis oder das Foto selbst. Diese Werte kommen aus dem Original. [Feldtypen]($docs.field-types#alle-typen) nennt, welche Typen übersetzbar sind.

#### Die Einträge jeder Sammlung übersetzen

Mach dasselbe für jeden Eintrag, den die französische Seite braucht. Leg für die Seite „About“ `content/pages/1.about.fr.md` an:

```markdown [content/pages/1.about.fr.md]
---
title: À propos
slug: a-propos
summary: Klara Brenner, traductrice depuis 2014.
---

## Qui je suis

Je suis traductrice depuis 2014.
```

`slug` ist der letzte Teil der Adresse: Diese Seite liegt unter `/fr/a-propos`. Ohne `slug` nimmt die Adresse den Dateinamen, hier `/fr/about`.

Ein Eintrag ohne französische Datei bleibt aus der französischen Seite draußen. Du kannst die wichtigen Seiten zuerst übersetzen und die anderen später ergänzen.

#### Die Buttons und Beschriftungen übersetzen

Diese Texte liegen in `i18n/`, eine Datei pro Sprache. Lass dir zeigen, was fehlt:

```bash
npx ginko-i18n todo --locale fr
```

Jede Zeile nennt einen Schlüssel, die Datei, in die er gehört, und den englischen Text:

```text
site.nav.open (missing) → i18n/fr.json: Open navigation
```

Leg `i18n/fr.json` an und trag die Schlüssel ein. Ein Punkt im Schlüssel ist eine Ebene der Verschachtelung:

```json [i18n/fr.json]
{
  "home": { "more": "En savoir plus" },
  "site": {
    "skip": "Aller au contenu",
    "nav": { "open": "Ouvrir la navigation" }
  }
}
```

Der Dev-Server liest diese Dateien neu, wenn du sie speicherst. Ein Schlüssel ohne französischen Text behält seinen englischen Text.

#### Das Ergebnis prüfen

Starte den Dev-Server neu, damit er die neuen Inhaltsdateien liest. Lass dann beide Prüfungen laufen:

```bash
npm run check
npx ginko-i18n check
```

`npm run check` meldet ein Feld, das eine Übersetzung nicht haben darf, einen kaputten Link und einen Slug, den zwei Einträge teilen. `npx ginko-i18n check` nennt jeden Text, der noch keine französische Fassung hat.

Prüf im Browser drei Dinge:

1. `http://localhost:3000/fr` zeigt die französische Startseite.
2. Der Sprachwechsel auf der Seite „About“ führt zu `/fr/a-propos`.
3. Der Quelltext der englischen Seite „About“ hat eine Zeile mit `hreflang="fr"`. Suchmaschinen lesen daraus die französische Adresse. Die Sitemap unter `/sitemap.xml` nennt die französischen Seiten auch.
:::

## Was du nicht tun musstest

- **Keine neuen Seiten.** Jede Seitendatei in `app/pages/` bedient jede Sprache.
- **Keine Änderung am Sprachwechsel.** Er liest die Sprachen aus der Liste.
- **Keine Änderung für Suchmaschinen.** Das `lang`-Attribut, die `hreflang`-Links und die Sitemap folgen der Liste und den Übersetzungen.
