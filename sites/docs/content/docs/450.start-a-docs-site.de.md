Diese Anleitung legt eine Doku-Seite mit dem Doku-Kit `@lupinum/ginko-docs` an. Am Ende hast du eine Seite mit Suche, Navigation, hellem und dunklem Modus und deiner ersten eigenen Seite darin. Diese Doku ist genauso gebaut.

Ein Kit ist ein Paket, das eine ganze Art von Seite mitbringt. Du schreibst die Seiten als Markdown-Dateien. Das Kit ergänzt alles drumherum:

- eine Kopfzeile mit Suche, Sprachmenü und Hell-Dunkel-Schalter,
- die Navigation an der Seite mit Gruppen, Brotkrumen, Inhaltsverzeichnis und Links zur vorherigen und nächsten Seite,
- die [Komponenten]($docs.components) für Hinweise, Reiter, Schritte und Code,
- „Seite kopieren“ als Markdown, „Diese Seite bearbeiten“ und „Problem melden“,
- jede Seite als Markdown für KI-Agenten und einen MCP-Endpunkt, siehe [Seiten für KI-Agenten ausliefern]($docs.pages-for-agents).

## Bevor du beginnst

Du brauchst Node.js 22.18 oder neuer und npm, pnpm oder bun.

## Schritte

::steps
#### Die Seite anlegen

```bash
npm create ginko@latest my-docs -- --template docs
```

Das Template ist die Doku einer erfundenen Bibliothek, auf Englisch und Deutsch. `--locales en` behält nur Englisch.

#### Installieren und starten

```bash
cd my-docs
npm install
npm run dev
```

Öffne `http://localhost:3000`. Du siehst die Startseite. `/docs` öffnet die erste Doku-Seite.

#### Eine Seite hinzufügen

Jede Datei in `content/docs/` ist eine Seite. Die Zahl im Dateinamen legt die Reihenfolge fest. Die Adresse kommt aus dem Rest des Namens: Diese Seite liegt unter `/docs/rate-limits`.

```markdown [content/docs/12.rate-limits.md]
---
title: Rate limits
description: How many requests the API takes per minute, and what the client does when you reach the limit.
---

The API takes 600 requests per minute for each API key.

## When you reach the limit

The API answers with status 429.

::callout{type="info" title="Good to know"}
Reading a list counts as one request per page.
::
```

`title` und `description` sind Pflicht. Die Seite erscheint am Ende der Navigation, in der Gruppe der Seite davor.

#### Die Seite in der Navigation platzieren

Das Frontmatter legt fest, wo und wie die Seite erscheint:

```markdown [content/docs/12.rate-limits.md]
---
title: Rate limits
description: How many requests the API takes per minute, and what the client does when you reach the limit.
navTitle: Limits
section: Limits and errors
icon: lucide:gauge
badge: New
---
```

| Feld | Wirkung |
| --- | --- |
| `navTitle` | Ein kurzer Titel für die Navigation, die Brotkrumen und die Links zur vorherigen und nächsten Seite. |
| `section` | Beginnt eine Gruppe in der Navigation mit dieser Überschrift. Die Seiten danach gehören dazu, bis zur nächsten `section`. |
| `tab` | Beginnt einen Reiter über der Navigation, zum Beispiel „Anleitung“ und „Referenz“. Seiten folgen dem Reiter vor ihnen. |
| `parent` | Ordnet die Seite unter einer anderen ein: `parent: docs/<name>`. |
| `icon` | Ein Iconify-Name, vor dem Titel in der Navigation. Setz ihn nur in der Hauptsprache. |
| `badge` | Ein kurzes Etikett nach dem Titel. |

Die Lucide-Icons sind installiert. Ein anderer Icon-Satz geht nach `npm install -D @iconify-json/<set>`.

#### Die Seite übersetzen

Eine Übersetzung ist eine Datei mit dem Sprachcode vor `.md`. Sie enthält nur die Felder, die eine Übersetzung haben, und den Text:

```markdown [content/docs/12.rate-limits.de.md]
---
title: Limits
description: Wie viele Anfragen die API pro Minute annimmt.
---

Die API nimmt 600 Anfragen pro Minute und API-Schlüssel an.
```

Eine Seite ohne Übersetzung erscheint in dieser Sprache nicht.

#### Kopf- und Fußzeile einrichten

Die Einstellungen des Kits stehen in `app/app.config.ts`. Die Texte der Links kommen aus den Sprachdateien, also hat jede Sprache ihre eigenen:

```ts [app/app.config.ts]
export default defineAppConfig({
  docs: {
    logo: { light: '/logo.svg', dark: '/logo-dark.svg' },
    nav: [{ id: 'status', href: 'https://status.example.com' }],
    banner: { id: 'v2', href: '/docs/upgrading-to-v2' },
    repository: { url: 'https://github.com/me/docs', branch: 'main' },
    footer: { links: [{ id: 'source', href: 'https://github.com/me/docs' }] },
  },
})
```

```json [i18n/en.json]
{
  "docs": {
    "nav": { "status": "Status" },
    "banner": { "v2": "Version 2 is out." },
    "footer": { "source": "Source code" }
  }
}
```

Jede `id` wählt einen Text. Die [Doku-Referenz]($docs.docs-site-reference#optionen) listet alle Einstellungen.
::

## Prüfe, ob es funktioniert

- `/docs/rate-limits` zeigt die Seite, und die Navigation zeigt „Limits“ mit dem Etikett „New“ unter der Überschrift „Limits and errors“.
- Die Kopfzeile hat den Link „Status“, und ein Banner darüber sagt „Version 2 is out.“
- Unter der Seite öffnet „Diese Seite bearbeiten“ die Datei in deinem Repository.
- `npm run check` endet mit `OK: schema and links are fine.` Das Template setzt `linkCheck: { anchors: 'error' }`, also stoppt ein Link auf eine Überschrift, die es nicht gibt, die Prüfung.

## Ohne das Template starten

Um das Kit in ein leeres Nuxt-Projekt einzubauen, installiere die Pakete und schreib zwei Dateien:

```bash
npm install @lupinum/ginko @lupinum/ginko-content @lupinum/ginko-i18n @lupinum/ginko-docs
```

```ts [ginko.config.ts]
import { defineSite } from '@lupinum/ginko'
import { components, docsCollection } from '@lupinum/ginko-docs/config'

const locales = ['en', 'de'] as const

export default defineSite({
  site: 'my-docs',
  name: 'My docs',
  url: 'https://docs.example.com',
  timeZone: 'Europe/Vienna',
  locales,
  currency: 'EUR',
  pages: { home: { en: '/', de: '/de' } },
  components,
  bricks: { docs: docsCollection({ locales }) },
})
```

```ts [nuxt.config.ts]
import ginko from './ginko.config.ts'

export default defineNuxtConfig({
  compatibilityDate: '2026-10-01',
  extends: ['@lupinum/ginko-docs'],
  modules: ['@lupinum/ginko/nuxt'],
  ginko,
})
```

Leg dann Seiten in `content/docs/` an. Ohne Startseite öffnet `/` die erste Doku-Seite.

## Die Startseite

`docsHome()` fügt eine Startseite aus einer Datei hinzu. Das Frontmatter füllt den oberen Teil der Seite und die Karten. Der Text darunter folgt ihnen und kann jede Komponente nutzen.

```ts [ginko.config.ts]
import { components, docsCollection, docsHome, homePages } from '@lupinum/ginko-docs/config'

// …
  pages: { home: homePages({ locales }) },
  bricks: { home: docsHome(), docs: docsCollection({ locales }) },
```

```markdown [content/home.md]
---
title: Docs for my library.
description: One sentence on what it does.
install: npm install my-library
links:
  - label: Get started
    href: $docs.introduction
  - label: GitHub
    href: https://github.com/me/lib
features:
  - icon: lucide:zap
    title: Fast
    description: Why it is fast.
    href: $docs.speed
---
```

`install` zeigt einen Befehl mit einem Kopier-Knopf. `links` enthält bis zu zwei Knöpfe; der erste ist der wichtigste. Eine eigene Seite `app/pages/index.vue` gewinnt über die Startseite.
