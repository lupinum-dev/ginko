This page lists what a Ginko site serves beside your pages: the files for search engines and agents, the cache rules, and the addresses and headers that stay stable.

## What you get without code

The Nuxt module serves these addresses for every site. You write no code for them:

| Address | Content |
| --- | --- |
| `/sitemap.xml` | Every page and entry with an address, in every locale |
| `/robots.txt` | Crawling rules, with the sitemap |
| `/llms.txt` | An index of the site for AI agents |
| `/llms-full.txt` | All entries of the main locale as Markdown in one file |
| `<page>.md` | One entry as Markdown |

A file of the same name in `public/` wins: your own `public/robots.txt` or `public/llms.txt` replaces Ginko's.

## Sitemap

`/sitemap.xml` lists every page from `pages` and every visible entry that has an address, in every locale. Each address names its translations (`hreflang`, with `x-default`). Entries carry `lastmod` from their last change and up to 20 images.

A page that should stay out of search, for example the thank-you page after a form, goes in `seo.noindex` with its key from `pages`. It then leaves the sitemap and answers with `X-Robots-Tag: noindex` in every locale:

```ts [ginko.config.ts]
pages: { thanks: { de: '/danke', en: '/en/thanks' } },
seo: { noindex: ['thanks'] },
```

With `@nuxtjs/sitemap` (on its own or through `@nuxtjs/seo`), that module owns `/sitemap.xml`. Ginko gives it the same list as a source (`/__ginko/sitemap.json`) and turns off its page discovery (`excludeAppSources: ['nuxt:pages']`), which would list folders that are no pages. Your own sources in `sitemap` add to Ginko's.

## robots.txt

On the site's own address (`url` in `ginko.config.ts`), `/robots.txt` allows everything and names the sitemap. `www.` counts as the same address. On every other host, for example a preview deployment, staging or `localhost`, it forbids everything, and every response carries `X-Robots-Tag: noindex`. So a preview never lands in a search engine. With `@nuxtjs/robots` that module serves `/robots.txt`, and the same rule holds: Ginko marks every other host as not indexable for it.

## Nuxt SEO

Ginko needs none of the [Nuxt SEO](https://nuxtseo.com) modules. A site may install them anyway (Nuxt 4.6.1 or later), all at once with `@nuxtjs/seo` or one by one, in any order in `modules`. Then Ginko leaves each module its output and hands it the site's data:

| Module | What Ginko hands it |
| --- | --- |
| `nuxt-site-config` | Address, name, description and main language. Per request: the page's language, and "not indexable" on every host other than `url` |
| `@nuxtjs/sitemap` | Every page and entry with translations, `lastmod` and images (see Sitemap) |
| `@nuxtjs/robots` | The sitemap; preview hosts stay closed (see robots.txt) |
| `nuxt-schema-org` | The page's JSON-LD joins the module's graph (read once, when `useGinkoSeo` runs), and `seo.organization` becomes the identity. The module adds `WebSite` and `WebPage` |
| `nuxt-seo-utils` | Ginko's title, canonical URL, `og:url` and `<html lang>` win over the module's defaults, so nothing appears twice |
| `nuxt-og-image` | Ginko's share card (see [Reading content]($docs.reading-content)) |
| `nuxt-ai-ready` | Off: Ginko serves `/llms.txt` and the Markdown pages itself. With `agents: { enabled: false }` the module stays on |

Your own settings in `nuxt.config.ts` win over everything Ginko hands over. A list you set yourself, such as `sitemap.excludeAppSources` or `robots.sitemap`, replaces Ginko's; `sitemap.sources` adds to Ginko's source. A module you turn off (`sitemap: false`) stays off.

## The docs MCP endpoint

A docs site with `@lupinum/ginko-docs` also answers at `POST /__ginko/docs-mcp`. This is an [MCP](https://modelcontextprotocol.io) server (Streamable HTTP) with two read-only tools:

- `search_docs(query, locale?)`: the best matching pages and sections, with path and excerpt,
- `read_doc(path)`: one page as Markdown.

An agent connects with the address, for example in Claude Code:

```bash
claude mcp add --transport http my-docs https://docs.example.com/__ginko/docs-mcp
```

The endpoint needs no key and shows only what the public site shows. It needs a server: a static build (`nuxt generate`) has no endpoint.

## Cache rules

The module sets these cache rules for you (Vercel ISR). Your own `routeRules` in `nuxt.config.ts` win: Ginko fills only what you leave unset. The exception is `/__ginko/`: there Ginko always sets the cache rule and the `cache-control` and `x-robots-tag` headers, so the preview is never cached or indexed.

- Every page is cached and rendered again at most every **60 seconds**. Query parameters share one cache entry. The 60 seconds are a default, not a promise: with your own rule for `/**` (for example `routeRules: { '/**': { isr: 300 } }`), Ginko keeps yours. A rule for a narrower path, such as `/news/**`, wins anyway.
- `/api/**` is not cached, because your own server routes may depend on the language of the visitor.
- Ginko's own addresses under `/__ginko/` are never indexed. The build output among them, the search index `/__ginko/search/<language>.json` and the content of file bricks under `/__ginko/files/`, stays cached until the next deploy. On a site with platform bricks the search index holds platform content too, so it is cached like a page instead. Everything else there, such as the preview, is never cached. Which addresses are stable and which are internal: [Addresses and headers](#addresses-and-headers).
- If the platform does not answer, the page answers with **503** and Vercel keeps the last good page.
- The cache keeps one version per address and ignores `Vary`. So a page answers with the same HTML for everyone, and agents read its Markdown at its `.md` address. An error such as a missing page also always answers with the error page as HTML, even when `curl` or a monitor without `Accept: text/html` asks first. Only `/api/`, addresses ending in `.json` and `/__ginko/` keep Nuxt's choice between JSON and HTML.

Ginko also turns off `experimental.payloadExtraction`. With it, Nuxt fetches a `_payload.json` on client navigation, and the server renders the target page with the content of production for it. Pages read the content that is already in the browser instead. So the preview never shows production content, and a navigation costs no extra render.

Images from the Studio become files of the deployment at build time: the build asks the platform for the published content and stores every image it names. After a deploy, no image loads through a function, in any region. An image added later is fetched from the platform once, on its first request; after that Vercel serves it to every region from its cache. If the platform does not answer during the build, the build prints a warning and goes on, and images are served through the function as before.

## Addresses and headers

Agents, scripts and crawlers may rely on these addresses and headers. Until 1.0, a stable one changes its name or meaning only in a minor release, and the changelog names the change.

| Address or header | What it is |
|---|---|
| `<page>.md` | The entry as Markdown, `Content-Type: text/markdown; charset=utf-8`. Without an entry: 404, also in Markdown. |
| `Link: <page.md>; rel="alternate"; type="text/markdown"` | On pages of file entries. |
| `/llms.txt`, `/llms-full.txt` | The entries of the main locale: a list with links, and the full text. |
| `/sitemap.xml`, `/robots.txt` | See [Sitemap](#sitemap) and [robots.txt](#robotstxt). |
| `X-Robots-Tag: noindex` | On every host other than `url`, on every address under `/__ginko/`, and on the pages in `seo.noindex`. |
| `/__ginko/search/<locale>.json` | The search index (see below). Its format is `SearchIndexJson` of `@lupinum/ginko/search`. |
| `/__ginko/docs-mcp` | The MCP endpoint of a docs site. |
| `/_ginko/img/<hash>.<ext>` | Images next to content files, cached for a year. The hash comes from the content: treat it as opaque, and take the address from the entry, never build it yourself. |

Everything else is internal and can change in any release: the other addresses under `/__ginko/` (such as the preview and `/__ginko/files/`) and the headers `x-ginko-rev`, `x-ginko-min-rev` and `x-ginko-site-token`. The full list is in [Composables and components]($docs.reading-content#internal-do-not-use).
