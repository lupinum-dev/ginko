Eine Aufgabe ist eine Abkürzung im Studio für eine Änderung, die oft vorkommt: „Heute geschlossen“, „Preis ändern“, „Gericht hinzufügen“. Diese Anleitung gibt einem Baustein eine Aufgabe. Am Ende hat die Seite „Today“ des Studios einen Button, der ein Formular mit zwei Feldern öffnet, und „Publish“ stellt die Änderung online.

## Bevor du beginnst

Der Baustein liegt auf der Plattform. [Einen Baustein auf die Plattform verlegen]($docs.move-a-brick-to-the-platform) zeigt, wie. Ein Baustein in Dateien hat keine Aufgaben, weil niemand ihn im Studio pflegt.

## Schritte

::steps
#### Die Aufgabe am Baustein ergänzen

```ts [ginko.config.ts]
promo: single({
  label: 'Aktion',
  fields: {
    headline: f.text('Überschrift', { default: 'Frisch in dieser Woche' }),
    until: f.date('Zeigen bis', { optional: true }),
  },
  tasks: [
    { id: 'change', label: 'Aktion ändern', kind: 'edit', fields: ['headline', 'until'] },
  ],
}),
```

- `id` benennt die Aufgabe. Behalte sie, wenn du die Beschriftung änderst.
- `label` ist der Text auf dem Button.
- `kind` ist `'edit'`, `'create'` oder `'remove'`.
- `fields` nennt die Felder, die das Formular zeigt.

#### Prüfen und freigeben

```bash
npx ginko check
```

Eine Aufgabe gehört nicht zu den Daten. Die Prüfung nennt sie als erlaubte Änderung, und das Release erhöht die Schema-Version nicht:

```text
Allowed changes:
  + Tasks changed.
```

Committe, pushe und gib frei wie in [Eine Schema-Änderung freigeben]($docs.release-a-schema-change).

#### Das Ergebnis prüfen

1. Öffne das Studio. Die Seite „Today“ hat die Überschrift „Aktion“ mit dem Button „Aktion ändern“.
2. Klick den Button. Das Formular zeigt „Überschrift“ und „Zeigen bis“, sonst nichts.
3. Ändere die Überschrift und klick „Publish“. Das Studio antwortet „Published. On the website in about a minute.“
4. Lade die Seite neu. Sie zeigt die neue Überschrift.
::

## Die drei Arten von Aufgaben

| Art | Was sie tut | Hinweise |
| --- | --- | --- |
| `edit` | Ändert die Felder in `fields`. | Bei einer Sammlung ergänzt du `pick: true`: Die Person wählt zuerst einen Eintrag. |
| `create` | Fügt einer Sammlung einen Eintrag hinzu. | Mit `fields` fragt das Formular nur nach diesen. Jedes Pflichtfeld ohne Default muss in `fields` oder `prefill` stehen. |
| `remove` | Löscht einen Eintrag einer Sammlung. | |

## Ein Feld vorab füllen

`prefill` setzt einen Wert, bevor das Formular aufgeht:

```ts
{ id: 'closedToday', label: 'Heute geschlossen', kind: 'edit', fields: ['closedOn', 'closedNote'], prefill: { closedOn: '@today' } }
```

`'@today'` ist das heutige Datum in der Zeitzone der Seite. `'@workWeek'` und `'@nextWorkWeek'` sind der erste Tag dieser und der nächsten Arbeitswoche. Jedes braucht ein Datumsfeld.

## Vor dem Livegang ein Ja verlangen

Mit `needsApproval: true` wartet eine Änderung, die ein Mitarbeiter über die Aufgabe macht, bis eine Inhaberin sie freigibt:

```ts
{ id: 'lunch', label: 'Mittagsmenü dieser Woche', kind: 'edit', fields: ['days'], needsApproval: true }
```

## Wer eine Aufgabe nutzen darf

Eine Inhaberin darf auf der Seite alles. Ein Mitarbeiter darf nur die Aufgaben nutzen, die die Inhaberin ihm erteilt hat. Aufgaben sind deshalb auch der Weg, jemandem eine eng begrenzte Arbeit zu geben, etwa dem Koch, der das Mittagsmenü einträgt.
