Ginko verbindet eine Nuxt-Seite mit ihren Inhalten. Du baust die Seite mit normalem Nuxt-Code. Die Inhalte liegen außerhalb dieses Codes. So können die Menschen, denen die Seite gehört, sie ohne Entwickler ändern.

## Wo die Inhalte liegen

Eine Seite hat zwei mögliche Quellen für ihre Inhalte:

- **Dateien.** Texte sind Markdown- und Datendateien im Repository, neben dem Code. Entwickler ändern sie. Beispiele: diese Doku, ein Blog, Rechtstexte.
- **Plattform.** Inhaber und Mitarbeiter ändern die Inhalte in einer Web-App, dem Studio. Lupinum betreibt es, der Zugang ist auf Einladung. Beispiele: Öffnungszeiten, eine Speisekarte, Veranstaltungen.

Eine Seite kann beide zugleich nutzen. Die Seiten lesen beide gleich. Ein Text kann also als Datei beginnen und später auf die Plattform umziehen. Der Code der Seite ändert sich nicht.

## Die vier Begriffe

- Ein **Baustein** (englisch *brick*) ist eine Art von Inhalt, zum Beispiel „Speisekarte“. Du beschreibst ihn in `ginko.config.ts`.
- Ein **Feld** ist ein Wert in einem Baustein, zum Beispiel ein Name oder ein Preis.
- Ein **Eintrag** ist ein Datensatz eines Bausteins, zum Beispiel ein Gericht.
- Ein **Bundle** ist alles, was die Seite liest: alle Bausteine mit ihren Werten in einer Sprache, als eine JSON-Antwort.

```ts [ginko.config.ts]
bricks: {
  menu: collection({                      // ein Baustein
    label: 'Speisekarte',
    fields: {
      name: f.text('Name'),               // ein Feld
      price: f.money('Preis'),
    },
    max: 150,
    order: 'manual',
  }),
}
```

Aus dieser Beschreibung macht Ginko das Formular im Studio, die Prüfungen für jeden Wert, die Typen in deinem Code und das Bundle.

## Wann Ginko passt

Nimm Ginko, wenn eine Seite Inhalte hat, die sich oft ändern, und die Person, die sie ändert, keinen Code anfassen soll. Öffnungszeiten, ein Mittagsmenü, Veranstaltungen und Stellenanzeigen sind typisch.

Nimm es nur mit Dateien, wenn Entwickler alle Texte pflegen und du typisierte Inhalte, Übersetzungen und Suche ohne Plattform willst.

## Wann es nicht passt

- **Du willst einen Seitenbaukasten.** In Ginko legst du die Bausteine und ihre Felder fest. Das Layout bleibt Code in deiner Nuxt-Seite.
- **Die Inhalte ändern sich nie.** Eine Seite mit festen Texten braucht Ginko nicht.

[Vergleich und Umstieg]($docs.switching) stellt Ginko neben Nuxt Content, ein gehostetes CMS und einen Git-Editor.
