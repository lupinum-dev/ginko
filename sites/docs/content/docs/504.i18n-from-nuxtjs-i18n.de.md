Diese Anleitung bringt eine Nuxt-App von `@nuxtjs/i18n` zu `@lupinum/ginko-i18n`. Am Ende hat die App dieselben Seiten und Adressen, die Head-Tags kommen ohne Code, und die Übersetzungsprüfung läuft in der CI.

## Zuerst prüfen, ob es passt

Ginko i18n hat eine Regel: Die Sprache kommt aus der Adresse. Bleib bei `@nuxtjs/i18n`, wenn du eines davon brauchst:

- eine Domain pro Sprache (`example.de`, `example.com`),
- Seiten ohne Sprache in der Adresse (`no_prefix`), außerhalb einer App hinter einem Login,
- eine Weiterleitung nach Browsersprache auf jeder Seite.

| | Ginko i18n | @nuxtjs/i18n 10.6 |
| --- | --- | --- |
| Woher die Sprache kommt | Nur aus der Adresse. Die Browsersprache steuert nur einen Vorschlag. | Aus der Adresse, und standardmäßig leitet `/` nach Cookie und Browsersprache weiter. |
| Adressformen | `prefix_except_default`, `prefix` | Auch `no_prefix`, `prefix_and_default` und Domains. |
| Übersetzte Adressen | `definePageMeta({ i18n: { paths } })` | Dasselbe, oder die Einstellung `pages`. |
| Head-Tags | Auf jeder Seite, ohne Code. | `useLocaleHead()`, das du in deinem Layout aufrufst. |
| Textformat | ICU, beim Build kompiliert | vue-i18n-Syntax |
| Zusätzliches JavaScript im Browser | 5,4 KB gzip | 29,3 KB gzip |
| Übersetzungs-Tool | `ginko-i18n check`, `todo`, `apply` | keines |

Die Größen wurden am 12. Oktober 2026 gemessen, mit Nuxt 4.6.0, zwei Sprachen, drei Texten und einer Seite.

## Schritte

::steps
#### Das alte Modul entfernen

```bash
npm uninstall @nuxtjs/i18n
npm install @lupinum/ginko-i18n
```

Beide Module können nicht zusammen installiert sein. Das Setup stoppt mit:

```text
[ginko-i18n] @nuxtjs/i18n is also installed. Fix: remove one; two modules cannot both own the locale.
```

#### Die Einstellungen ändern

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-i18n'],
  i18n: {
    locales: ['en-GB', 'de-AT'],
    defaultLocale: 'en',
    baseUrl: 'https://example.com',
  },
})
```

| @nuxtjs/i18n | Ginko i18n |
| --- | --- |
| `locales: [{ code, language, file }]` | `locales: ['en-GB', { language: 'de-AT', code: 'de' }]`. Die Dateien sind immer `i18n/<code>.json`. |
| `defaultLocale` | `defaultLocale` |
| `strategy: 'prefix_except_default'` oder `'prefix'` | dasselbe |
| `strategy: 'no_prefix'`, `'prefix_and_default'`, `differentDomains` | Nicht unterstützt. Für eine App hinter einem Login nimm `userLocale`. |
| `detectBrowserLanguage` | Keine Weiterleitung. `useLocaleSuggestion()` bietet einen Link an. |
| `customRoutes: 'config'`, `pages: {…}` | `definePageMeta({ i18n: { paths } })` in jeder Seite |
| `baseUrl` | `baseUrl` |
| `vueI18n: './i18n.config.ts'` | Nicht nötig. Formate kommen aus `Intl`. |

Eine Einstellung, die Ginko i18n nicht kennt, stoppt das Setup und nennt sie:

```text
[ginko-i18n] Unknown option(s) i18n.detectBrowserLanguage. Fix: remove them; ginko-i18n is not @nuxtjs/i18n.
```

#### Die Sprachdateien verschieben

Leg eine JSON-Datei pro Sprache in `i18n/`, benannt nach dem Sprachkürzel: `i18n/en.json`, `i18n/de.json`. Ein Schlüssel ist ein Name, und Verschachtelung trennt Namen: `t('nav.about')` liest `{ "nav": { "about": … } }`. Ein Schlüssel darf keinen Punkt enthalten.

#### Die Texte umschreiben, die kein einfacher Text sind

Ginko i18n liest ICU, nicht die vue-i18n-Syntax. Einfacher Text und `{name}` bleiben, wie sie sind.

| vue-i18n | ICU |
| --- | --- |
| `Hello {name}` | `Hello {name}` |
| `no apples \| one apple \| {count} apples` | `{count, plural, =0 {no apples} one {one apple} other {# apples}}` |
| `{n} items` mit `$t(key, n)` | `{n, plural, other {# items}}` mit `t(key, { n })` |
| `@:common.brand` (ein verlinkter Text) | Nicht unterstützt. Schreib den Text aus, oder gib ihn als Parameter mit. |
| `{'@'}` | `@` braucht kein Escaping. Setz `{` als `'{'` in Anführungszeichen. |
| `@.lower:key` (ein Modifier) | Nicht unterstützt. Formatiere im Code. |

Jedes `plural` und `select` braucht einen Fall `other`.

#### Den Code ändern

| @nuxtjs/i18n | Ginko i18n |
| --- | --- |
| `$t('key')` in einem Template | `const { t } = useI18n()`, dann `t('key')` |
| `locale.value = 'en'`, `setLocale('en')` | `switchLocale('en')` |
| `localePath('about')` mit einem Routennamen, `localeRoute`, `<NuxtLinkLocale>` | `localePath('/about')` mit einem Pfad, und `<NuxtLink>` |
| `switchLocalePath('en')` | `alternates`, oder `localePath(route.path, 'en')` |
| `<i18n-t keypath="…">` | `<I18nT k="…">` mit einem Slot pro Tag |
| `useLocaleHead()` | Nichts. Die Head-Tags kommen ohne Code. |
| `$n`, `$d` | `format.number`, `format.date` |
| Routennamen `about___en` | `about__en`. Verlinke über den Pfad. |

Navigiere nicht über Routennamen. Das Modul legt eine Route pro Sprache an, mit dem Namen `<name>__<code>`. `navigateTo({ name: 'about' })` findet nichts.

#### Die Prüfungen laufen lassen

```bash
npx nuxt typecheck
npx ginko-i18n check
```

Die Typprüfung findet einen Schlüssel, den es nicht gibt, und einen fehlenden Parameter. Die Übersetzungsprüfung findet Texte, die einer Sprache fehlen, falsches ICU und unbenutzte Schlüssel.
::

## Prüfe, ob es funktioniert

- Jede Seite antwortet unter derselben Adresse wie vorher, in jeder Sprache.
- Der Quelltext einer Seite hat `lang`, einen Canonical-Link und einen `hreflang`-Link pro Sprache.
- `npx ginko-i18n check` endet mit `0 errors`.

## Was sich für Besucher ändert

- `/` leitet nicht mehr nach Browsersprache weiter. Ein Besucher mit einem deutschen Browser, der `/` öffnet, sieht die Hauptsprache. Biete mit `useLocaleSuggestion()` einen Link an, siehe [i18n-Referenz]($docs.i18n-reference#uselocalesuggestion).
- Andere Schreibweisen einer Adresse leiten auf die eine Adresse weiter: `/about/` und `/DE/ueber-uns` antworten mit 301.
