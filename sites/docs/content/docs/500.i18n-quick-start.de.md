`@lupinum/ginko-i18n` ist das Sprachmodul von Ginko. Es funktioniert auch allein, in jeder Nuxt-App. Dieses Tutorial gibt einer einfachen Nuxt-App Englisch und Deutsch. Am Ende sind `/about` und `/de/ueber-uns` dieselbe Seite in zwei Sprachen, mit einem Sprachwechsel und den richtigen Head-Tags.

Eine Seite mit Ginko hat das Modul schon. Beginne dort mit [Eine Sprache hinzufügen]($docs.add-a-language).

## Was es anders macht

- **Die Sprache kommt aus der Adresse und von nirgends sonst.** Kein Cookie und keine Browser-Einstellung ändert die Sprache einer Seite. So stimmen das HTML vom Server, die Seite im Browser und jeder Cache überein.
- **Übersetzte Adressen.** `/about` und `/de/ueber-uns` sind eine Seite.
- **Head-Tags ohne Code.** Jede Seite bekommt `lang`, einen Canonical-Link, `hreflang`-Links und `og:locale`.
- **ICU-Texte, beim Build kompiliert.** Plural, Zahlen, Datumsangaben und Tags. Der Browser lädt dafür weniger als 2 KB.
- **Typisierte Schlüssel.** Ein fehlender Schlüssel oder Parameter lässt die Typprüfung scheitern.

Es gibt zwei Adressformen: `/about` und `/de/about` (der Standard), oder `/en/about` und `/de/about`. Es gibt keine Domains pro Sprache und keine Sprache ohne Präfix. Brauchst du das, nimm `@nuxtjs/i18n`.

## Bevor du beginnst

Du brauchst eine Nuxt-App mit Nuxt 4.6 oder neuer und Node.js 22.18 oder neuer. In der App darf `@nuxtjs/i18n` nicht installiert sein.

## Schritte

::steps
#### Das Paket installieren

```bash
npm install @lupinum/ginko-i18n
```

#### Das Modul eintragen

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/ginko-i18n'],
  i18n: {
    locales: ['en-GB', 'de-AT'],
    defaultLocale: 'en',
    baseUrl: 'https://example.com',
  },
})
```

`locales` sind Sprach-Tags. Das Kürzel in der Adresse ist der erste Teil des Tags: `en` und `de`. Seiten der Hauptsprache haben kein Präfix. `baseUrl` macht die Links im Head zu vollständigen Adressen.

#### Eine Sprachdatei pro Sprache anlegen

Die Dateien liegen in `i18n/`, neben `nuxt.config.ts`. Der Dateiname ist das Sprachkürzel:

```json [i18n/en.json]
{
  "nav": { "home": "Home", "about": "About us" },
  "cart": { "items": "{count, plural, =0 {No items} one {# item} other {# items}}" },
  "legal": { "consent": "I accept the <link>privacy policy</link>." }
}
```

```json [i18n/de.json]
{
  "nav": { "home": "Start", "about": "Über uns" },
  "cart": { "items": "{count, plural, =0 {Keine Artikel} one {# Artikel} other {# Artikel}}" },
  "legal": { "consent": "Ich akzeptiere die <link>Datenschutzerklärung</link>." }
}
```

#### In einer Seite übersetzen

`useI18n` und `<I18nT>` brauchen keinen Import:

```vue [app/pages/about.vue]
<script setup lang="ts">
definePageMeta({ i18n: { paths: { de: '/ueber-uns' } } })

const { t, localePath } = useI18n()
</script>

<template>
  <main>
    <h1>{{ t('nav.about') }}</h1>
    <p>{{ t('cart.items', { count: 3 }) }}</p>
    <I18nT k="legal.consent">
      <template #link="{ text }">
        <NuxtLink :to="localePath('/privacy')">{{ text }}</NuxtLink>
      </template>
    </I18nT>
  </main>
</template>
```

- `definePageMeta` gibt der deutschen Seite eine eigene Adresse. Englisch behält `/about`.
- `t` liefert einen Text. `count` wählt die Pluralform.
- `<I18nT>` zeigt einen Text mit einem Tag. Der Slot `link` bekommt den Text zwischen `<link>` und `</link>`.
- `localePath('/privacy')` ist die Adresse einer Seite in der aktuellen Sprache.

#### Einen Sprachwechsel einbauen

`alternates` ist die aktuelle Seite in jeder Sprache:

```vue [app/components/LanguageSwitcher.vue]
<script setup lang="ts">
const { alternates } = useI18n()
</script>

<template>
  <nav>
    <NuxtLink
      v-for="a in alternates"
      :key="a.code"
      :to="a.path"
      :hreflang="a.language"
      :aria-current="a.current ? 'page' : undefined"
    >
      {{ a.name }}
    </NuxtLink>
  </nav>
</template>
```

```vue [app/app.vue]
<template>
  <LanguageSwitcher />
  <NuxtPage />
</template>
```
::

## Prüfe, ob es funktioniert

Starte die App mit `npm run dev`.

| Adresse | Ergebnis |
| --- | --- |
| `/about` | „About us“, „3 items“ und der Satz mit einem Link auf `/privacy` |
| `/de/ueber-uns` | „Über uns“, „3 Artikel“ und der Satz mit einem Link auf `/de/privacy` |
| `/de/about` | 404: Die deutsche Seite hat eine eigene Adresse |
| `/about/` | Eine Weiterleitung (301) auf `/about` |

Der Quelltext von `/de/ueber-uns` hat diese Head-Tags:

```html
<html lang="de-AT" dir="ltr">
<link rel="canonical" href="https://example.com/de/ueber-uns">
<link rel="alternate" hreflang="en-GB" href="https://example.com/about">
<link rel="alternate" hreflang="de-AT" href="https://example.com/de/ueber-uns">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_AT">
```

Der Sprachwechsel zeigt „English“ und „Deutsch“. Jeder Link führt zur selben Seite in der anderen Sprache.

## Fehlende Übersetzungen finden

Das Paket hat ein Kommandozeilen-Tool. Es listet Texte, die einer Sprache fehlen:

```bash
npx ginko-i18n check
```

Fehlt in `i18n/de.json` der Schlüssel `legal.consent`, gibt es das hier aus und endet mit Exit-Code 1:

```text
error missing de legal.consent i18n/en.json:4: Missing translation
1 errors, 0 warnings
```

Das Tool gibt den vollen Pfad der Datei aus. Ein fehlender Text erscheint in der Hauptsprache, und der Dev-Server warnt. [Buttons und Beschriftungen übersetzen]($docs.translate-buttons-and-labels) zeigt das Tool Schritt für Schritt, und die [i18n-Referenz]($docs.i18n-reference#cli) listet seine Befehle.
