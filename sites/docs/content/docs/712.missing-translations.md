On a site with more than one language, some content has no translation yet. Ginko has two answers, and the brick decides which one applies:

- **Fallback.** The text shows in the main language.
- **Hide.** The entry is not part of that language.

## The rule

| Content | Without a translation |
| --- | --- |
| A single | Each missing text shows in the main language. |
| A collection without a `route` | Each missing text shows in the main language. |
| A collection with a `route` | An entry with a missing required text leaves that language: no page, not in lists, not in the sitemap. |

The reason for the difference is the address. An entry with a `route` has a page of its own in every language, such as `/de/news/eroeffnung`. A German address with English text is wrong for visitors and for search engines: the page says `lang="de"` and holds English. So the entry is a page only in the languages it is translated into.

A dish in a menu has no page of its own. A German menu with one English dish name is better than a menu with a dish missing.

## What counts as missing

Only a **required** text that has **no** value in the language. These do not count:

- **An outdated translation.** The main text changed after the translation. The translation stays online, and the Studio marks it. A fixed typo in the main language must not take the translated page off the site.
- **An optional text.** It shows in the main language, and the entry stays.
- **A slug and the description of an image.** Both take the value of the main language.
- **A field with one value for all languages**, such as a date, a price or a number. It has nothing to translate.

## Change the rule for a brick

`untranslated` on a collection sets the answer:

```ts
news: collection({
  label: 'News',
  route: { en: '/news/[slug]', de: '/de/news/[slug]' },
  untranslated: 'fallback',
  // …
})
```

| Value | Default for | What happens |
| --- | --- | --- |
| `'hide'` | a collection with a `route` | The entry leaves the language. |
| `'fallback'` | a collection without a `route` | The texts show in the main language. |

With `'fallback'` on a collection with a `route`, the entry is in the lists of the language, with its texts in the main language. It still has no page in that language: its link leads to the page in the main language.

## What the site knows

Every item has a list `fallback`. It names the fields that come from the main language:

```ts
const news = useGinko('news')
news.value.items[0].fallback   // ['title', 'summary']
```

`useGinkoLang` uses this list to give you the right `lang` attribute, so that a screen reader pronounces the text in its real language. [Mark text that is not translated]($docs.mark-untranslated-text) has the steps.

## What visitors and search engines get

- **The language switch.** For an entry that has no page in a language, the switch has no address in that language. [Add a language switch]($docs.language-switch) shows what to do then.
- **hreflang and the sitemap.** They list only the languages in which the page exists.
- **A direct request.** The address of a hidden entry in that language answers 404.

## Buttons and labels are a different thing

This page is about content: the values of bricks. The fixed texts of your components, such as "Read more", are messages in `i18n/<code>.json`. A message without a translation is found by `ginko-i18n check`, see [Translate buttons and labels]($docs.translate-buttons-and-labels).
