In [chapter 2]($docs.tutorial-pages) the site got pages and a menu. This chapter adds a blog: posts with a date and an author, a list of all posts and a page for each one. At the end, `http://localhost:3000/blog` lists the posts, newest first.

You do not write the fields of a post yourself. `@lupinum/ginko/basics` has ready-made bricks for content most sites need, and `posts()` is one of them.

## Steps

::steps
#### Add the bricks

Add `posts` and `authors` to `ginko.config.ts`, and a fixed page `blog` for the list:

```ts [ginko.config.ts]
import { collection, defineSite, f, single } from '@lupinum/ginko'
import { authors, posts } from '@lupinum/ginko/basics'

export default defineSite({
  site: 'my-site',
  name: 'Studio Nord',
  url: 'https://example.com',
  timeZone: 'Europe/Vienna',
  locales: ['en'],
  currency: 'EUR',
  pages: { home: '/', blog: '/blog' },
  bricks: {
    home: single({
      label: 'Home page',
      source: 'files',
      fields: {
        title: f.text('Title'),
        body: f.markdown('Text', { profile: 'basic' }),
      },
    }),
    pages: collection({
      label: 'Pages',
      source: 'files',
      max: 50,
      order: 'manual',
      route: { en: '/[slug]' },
      fields: {
        title: f.text('Title'),
        slug: f.slug('Address', { from: 'title' }),
        summary: f.longtext('Summary', { optional: true }),
        body: f.markdown('Text', { profile: 'basic' }),
      },
    }),
    posts: posts({ source: 'files', route: { en: '/blog/[slug]' } }),
    authors: authors({ source: 'files' }),
  },
})
```

`posts()` is a collection with the fields `title`, `description`, `date`, `authors`, `image`, `tags`, `slug` and `body`. It lists the newest post first. `authors()` holds the people who write. [Use ready-made bricks]($docs.ready-made-bricks) lists the other bricks of `basics`.

#### Write an author and two posts

```yaml [content/authors/anna.yml]
name: Anna Berg
role: Book designer
```

```markdown [content/posts/hello.md]
---
title: Hello from the workshop
date: 2026-10-12
authors: [authors/anna]
---

The site is live. Here we write about new work.
```

```markdown [content/posts/new-poster-series.md]
---
title: A new poster series
date: 2026-11-02
description: Six posters for the city library.
authors: [authors/anna]
---

This autumn we made six posters for the city library. Each one shows a reading room.
```

A content file may also be YAML or JSON. `authors` names entries by their id: the folder and the file name without number, language and extension. `content/authors/anna.yml` is `authors/anna`.

#### List the posts

```vue [app/pages/blog/index.vue]
<script setup lang="ts">
const posts = useGinko('posts')
const { format } = useI18n()
</script>

<template>
  <main>
    <h1>Blog</h1>
    <article v-for="post in posts.items" :key="post.id">
      <h2><NuxtLink :to="post.url">{{ post.data.title }}</NuxtLink></h2>
      <time :datetime="post.data.date">{{ format.date(post.data.date) }}</time>
      <p v-if="post.data.description">{{ post.data.description }}</p>
    </article>
  </main>
</template>
```

A date field holds a text such as `2026-11-02`. `format.date` writes it for people: "November 2, 2026". [Show money, dates and today]($docs.money-dates-today) has the other formats.

#### Show one post

```vue [app/pages/blog/[slug].vue]
<script setup lang="ts">
const route = useRoute()
const post = useGinkoEntry('posts', () => route.params.slug)
const authors = useGinko('authors')
const { format } = useI18n()
const names = computed(() => authors.value.items
  .filter((author) => post.value.data.authors?.includes(author.id))
  .map((author) => author.data.name))
</script>

<template>
  <main>
    <h1>{{ post.data.title }}</h1>
    <p>
      <time :datetime="post.data.date">{{ format.date(post.data.date) }}</time>
      <span v-if="names.length"> · {{ names.join(', ') }}</span>
    </p>
    <GinkoMarkdown :value="post.data.body" />
  </main>
</template>
```

In `<script>`, a value of Ginko is a ref, so you read it with `.value`. In the template, Vue does that for you.

#### Link the blog in the menu

The list page has the key `blog` in `pages`. `useGinkoPath` gives its address, so the link follows when you change the address in `ginko.config.ts`:

```vue [app/app.vue]
<script setup lang="ts">
const pages = useGinko('pages')
const path = useGinkoPath()
</script>

<template>
  <header>
    <nav>
      <NuxtLink to="/">Home</NuxtLink>
      <NuxtLink :to="path('blog')">Blog</NuxtLink>
      <NuxtLink v-for="page in pages.items" :key="page.id" :to="page.url">{{ page.data.title }}</NuxtLink>
    </nav>
  </header>
  <NuxtPage />
</template>
```

Keep the `<style>` block of chapter 2 below it.
::

## Check that it works

- Open `http://localhost:3000/blog`. It lists "A new poster series" above "Hello from the workshop".
- Click a post. Its page shows the date and "Anna Berg".

## Keep a post as a draft

Add a post that is not ready yet:

```markdown [content/posts/next-book.md]
---
title: Our next book
date: 2026-11-20
draft: true
---

Not ready yet.
```

The dev server shows it in the list and on its page, so you can read it before it goes live. A build leaves it out: no list entry, no page, no line in the sitemap. Remove `draft: true` to publish it. A post dated after the day of the build waits in the same way until the first build on or after its date. [Keep a draft out of the live site]($docs.drafts) has the details.
